Curva característica de un motor DC

Continuación de la clase 68. Para identificar el motor (y luego hacerle un PID o control difuso) hay que registrar cómo sube su velocidad desde que arranca. HAL_Delay no es exacto (100 ms salen 101 ms), así que se crea un retardo con el TIM5 de 32 bits contando microsegundos y se cambia el toggle de HAL por el registro ODR. El motor es rápido, así que no se puede enviar cada dato: se guardan en un buffer a 500 µs y, al terminar, se mandan por la UART a un programa en LabVIEW que dibuja la curva.

Fase 1

Rango del motor

1.1

Velocidad máxima

▶ 1:05

Con el sistema de la clase anterior se envía el set point por la UART. El PWM va de 0 a 5000: con 1000 llega a unos 1540 y con 5000 a unos 2700-2800 de frecuencia de encoder. Ese será el rango de la gráfica (hasta 3000).

Fase 2

Muestreo exacto

2.1

HAL_Delay no es exacto

▶ 2:46

Para muestrear se necesita un periodo exacto. Midiendo con el analizador lógico un toggle cada HAL_Delay(100), el periodo sale de 101 ms: un milisegundo de más, y no permite microsegundos.

2.2

TIM5 de 32 bits como contador

▶ 4:42

TIM2 y TIM5 son de 32 bits. TIM2 ya está en el PWM, así que se usa TIM5: Clock Source = Internal Clock, sin canales, Prescaler = 84-1 (un paso por microsegundo a 84 MHz), periodo al máximo (4294967295) y auto-reload habilitado.

En el video primero quedó sin el 84-1 y los tiempos salían mal. Después de corregir, dale al engranaje para regenerar el código.

2.3

Librería delays con timer

▶ 5:49

En delays.h se elige el timer y que las funciones de retardo usen el timer en lugar del DWT. El retardo pone el contador en cero y espera.

// delays.h
#define TIMX   TIM5    // usa el timer 5 (de 32 bits)
#define TIMEX  htim5
#define delay_init delay_us_tim_init   // función usada para iniciar

// delays.c
void delay_us_tim(uint32_t us)
{
  TIMX->CNT = 0;            // resetea el timer
  while (TIMX->CNT < us);   // espera los us deseados
}

// main.c
#include "delays.h"
/* USER CODE BEGIN 2 */
delay_init();
2.4

Toggle por registro

▶ 9:53

Con el timer, 100 ms pasan a medir 100.02 ms. Para afinar más se cambia HAL_GPIO_TogglePin por un XOR directo sobre el registro de salida. Con delay_us(100) el periodo medido es de 100.1 µs.

// HAL_GPIO_TogglePin(led_GPIO_Port, led_Pin);
led_GPIO_Port->ODR ^= led_Pin;   // más rápido que la HAL
delay_us(100);

El LED cambia en cada muestra, así que el periodo que ves en el osciloscopio es el doble del periodo de muestreo (la frecuencia, la mitad).

Fase 3

Capturar y enviar

3.1

Variables

▶ 16:04

La UART se sube a 115200. Un buffer de 5000 datos float guarda la velocidad; si el motor es más lento o más rápido, ajusta el tamaño y el periodo.

/* USER CODE BEGIN PD */
#define buffer_size 5000

/* USER CODE BEGIN PV */
float buffer[buffer_size];
3.2

Esperar el set point y muestrear

▶ 15:00

El programa espera el set point por la UART, arranca el motor y cada 500 µs guarda la frecuencia del encoder (que se mide por interrupción con Input Capture). Al llenar el buffer, para el motor.

while (flag_rx == 0);                    // espera orden de inicio
salida_pwm = atoi((char*)trama_rx);      // pasa a número el pwm recibido
motorset(salida_pwm);                    // coloca la señal al motor

// muestrea la información y la almacena
for (uint32_t i = 0; i < buffer_size; i++)
{
  led_GPIO_Port->ODR ^= led_Pin;         // marca el muestreo
  if (frec1 != 0) frecuencia1 = frecmuestreo / frec1;
  else frecuencia1 = 0;
  buffer[i] = frecuencia1;
  delay_us(500);                         // periodo de muestreo
}
motorstop();

En el video se divide directo entre frec1; al arrancar el motor aún no hay pulsos y frec1 vale 0. Aquí se agregó la comprobación.

3.3

Enviar el buffer

▶ 16:46

Enviar 5000 floats (20000 bytes) de una vez por DMA es demasiado para la PC, así que se mandan uno a uno con un separador * y una pausa de 1 ms. Aquí la pausa ya no afecta el muestreo.

// envía por el puerto serial
// HAL_UART_Transmit_DMA(&huart1, &buffer, buffer_size*4);  // demasiado para la PC
for (uint32_t i = 0; i < buffer_size; i++)
{
  sprintf(texto, "D=%.2f*", buffer[i]);
  uartx_write_text(&huart1, texto);
  delay_ms(1);
}
Fase 4

Graficar

4.1

Programa en LabVIEW

▶ 18:59

Un evento del botón enviar manda el set point por el puerto serial. Otro ciclo espera datos, lee lo que llega cada 6 ms, separa cada valor por el * y lo agrega a un arreglo que se dibuja en un Waveform Graph.

4.2

La curva

▶ 20:43

Con set point 2000 la velocidad sube como una curva de primer orden hasta unos 2100. Con 600 llega a unos 700. El micro hay que resetearlo para cada prueba, porque la espera está antes del while.

4.3

Exportar a Excel

▶ 21:30

Desde el gráfico, Export, Export Data To Excel. Se agrega una columna de tiempo multiplicando el número de muestra por 0.0005 s (=A3*$E$2). Con estos datos se puede calcular la constante de tiempo del motor o llevarlos a MATLAB para identificar su función de transferencia.

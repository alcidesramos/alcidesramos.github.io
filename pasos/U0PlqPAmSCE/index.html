Programar, depurar y manejar un display de 7 segmentos

Se retoma el LED del primer proyecto para ver todas las maneras de programar la tarjeta real: solo con el cable USB usando el bootloader de fábrica (botones BOOT y RESET), con el programador ST-Link desde STM32CubeProgrammer (y cómo actualizarle el firmware) y con el depurador de VS Code paso a paso. Después se explica el display de 7 segmentos (cátodo y ánodo común, resistencias), se saca un número en Proteus pin por pin, luego escribiendo todo el puerto de una vez con el registro ODR, y se usa una aplicación para obtener el código de cada símbolo. Al final se inicializa un repositorio Git desde VS Code.

Fase 1

Programar solo con el cable USB

1.1

Entrar en modo BOOT

▶ 3:57

La Black Pill tiene dos botones: BOOT y RESET. Con la tarjeta desconectada, deja presionado BOOT, conéctala y en STM32CubeProgrammer cambia de ST-LINK a USB y pulsa actualizar: debe aparecer el puerto USB. Ya puedes soltar BOOT.

Truco sin desconectar: deja presionado BOOT, pulsa y suelta RESET, y luego suelta BOOT.

1.2

Cargar el archivo

▶ 7:57

Pulsa Connect, luego Open file y busca el .elf en build/Debug del proyecto. Pulsa Download y después RESET en la tarjeta.

1.3

Limitaciones

▶ 10:51

Es la forma más rústica: no permite depurar y el cable debe tener bien las líneas de datos. Si el micro está montado en un circuito, es mejor programarlo afuera porque el ruido puede impedir la programación. Si cambiaste un pin en CubeMX, recuerda generar el código y compilar antes de cargar.

Fase 2

Programar con el ST-Link

2.1

Los cuatro pines

▶ 11:56

En la tarjeta están 3.3V, SWDIO, SWCLK y GND, y hay que ubicar los mismos en el programador. En los ST-Link de colores la posición cambia de un modelo a otro: lee la serigrafía. En el programador recomendado el cable trae colores, pero hay dos versiones: guíate por el rojo (3.3 V) y por la etiqueta.

2.2

Actualizar el firmware del programador

▶ 15:49

La primera vez, en CubeProgrammer pulsa Firmware upgrade, Refresh device list, Open in update mode y Upgrade. Si no lo encuentra, desconecta, conecta y vuelve a buscar.

2.3

Cargar el programa

▶ 15:15

Con el USB conectado al programador (no a la tarjeta), elige ST-LINK, Connect, abre el .elf y Download. CubeProgrammer toma el archivo nuevo cada vez que compilas.

Fase 3

Depurar en VS Code

3.1

Run and Debug

▶ 17:32

En la pestaña de depuración pulsa Run and Debug y elige STM32Cube: STM32 Launch ST-Link GDB Server. Cierra CubeProgrammer antes: si está conectado al programador, VS Code no puede usarlo.

3.2

Paso a paso

▶ 19:51

El programa se detiene al inicio. Step Over ejecuta una función completa y pasa a la siguiente; Step Into entra a ver la función por dentro. Con Step Over en el while se ve el LED cambiar en cada paso. Play lo deja correr y el cuadro rojo termina la depuración.

Fase 4

Display de 7 segmentos

4.1

Cátodo común y ánodo común

▶ 26:39

Son siete LED (a a g) y a veces un punto. En cátodo común el común va a tierra y cada segmento enciende con 1. En ánodo común el común va a positivo y cada segmento enciende con 0.

4.2

Las resistencias

▶ 28:50

Lo correcto es una resistencia de unos 220 a 330 Ω por cada segmento. El atajo es una sola resistencia en el común: funciona, pero el brillo cambia según cuántos segmentos estén encendidos. En Proteus se usan unos 22 Ω para que se vea; en la vida real no bajes de 180 a 220 Ω.

4.3

Encender un pin

▶ 33:39

Con HAL se enciende o apaga cada pin. El LED de la tarjeta está invertido: enciende con 0.

HAL_GPIO_WritePin(LED1_GPIO_Port, LED1_Pin, 0);
4.4

Un número pin por pin

▶ 34:48

En Proteus busca DISPLAY, filtra por 7-Segment Displays y elige uno de siete entradas (el de cuatro es BCD y solo sirve en simulación). En CubeMX nombra los pines con dos o tres letras (LD1…LD7), no con una sola. Luego escribe cada segmento:

HAL_GPIO_WritePin(LD1_GPIO_Port, LD1_Pin, 0);
HAL_GPIO_WritePin(LD2_GPIO_Port, LD2_Pin, 1);
HAL_GPIO_WritePin(LD3_GPIO_Port, LD3_Pin, 0);
// ... hasta LD7
Fase 5

Todo el puerto de una vez

5.1

Remapear a un solo puerto

▶ 59:05

Si los siete segmentos quedan en el mismo puerto y en orden (PA0 = a, PA1 = b … PA6 = g), se pueden escribir todos con una sola instrucción. Usa Ctrl + arrastrar en CubeMX para moverlos. En Proteus, etiquetas A…G evitan el cableado.

5.2

Escribir el registro ODR

▶ 66:17

GPIOA->ODR es el registro de salida del puerto: se escribe directo, sin HAL, y es mucho más rápido. El bit menos significativo (derecha) es PA0, o sea el segmento a. Para un 5 en cátodo común se encienden a, c, d, f y g:

GPIOA->ODR = 0b1101101;   // g f e d c b a
// o en hexadecimal:
GPIOA->ODR = 0x6D;

Ojo con el orden de los bits: el segmento a va a la derecha. La IA sugirió el número al revés y también escribió mal GPIOA.

5.3

Generar los códigos con una aplicación

▶ 72:36

La aplicación 7-Segment muestra un display: haces clic en los segmentos, eliges cátodo o ánodo y el orden de los bits, y te da el código en hexadecimal, decimal y binario para copiar.

5.4

Escribir una palabra

▶ 76:35

Con un retardo entre letras se puede mostrar una palabra, por ejemplo CHAO. Puedes escribir cada código en binario, decimal o hexadecimal: para el micro es lo mismo.

GPIOA->ODR = codigo_C;  HAL_Delay(1000);
GPIOA->ODR = codigo_H;  HAL_Delay(1000);
GPIOA->ODR = codigo_A;  HAL_Delay(1000);
GPIOA->ODR = codigo_O;  HAL_Delay(1000);
5.5

Si Proteus no carga el cambio

▶ 81:19

Proteus a veces se cierra al recompilar. Guarda seguido; si se pierde, en la carpeta del proyecto hay una copia en Project Backups.

Commit y publicar

▶ 84:46

En Source Control inicializa el repositorio, escribe un mensaje y haz Commit. Con Publish Branch se sube a GitHub; si lo publicas como público, puedes compartir el enlace.

6.2

Clonar un proyecto

▶ 86:59

Con Clone Repository y el enlace de GitHub se descarga un proyecto completo para seguir trabajando desde ahí.

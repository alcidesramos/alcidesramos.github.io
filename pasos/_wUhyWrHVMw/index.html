Clase 141: monitorear sensores en Python con tramas desde el STM32

Armamos un proyecto con el STM32F411 que lee tres canales analógicos por DMA circular (simulando voltaje, temperatura y distancia con potenciómetros) y el pulsador de la placa, y lo envía en una trama de texto con inicio INI=, valores separados por / y fin *. En Python partimos de un programa básico con las librerías comunicacion.py e instrumentos.py y agregamos un gauge analógico, un termómetro vertical, una barra horizontal y un LED, que se actualizan al decodificar la trama. Al final sumamos el MPU6050 con timer y Kalman de las clases 139 y 140 para mover un horizonte artificial.

  • STM32F411 (Black Pill)
  • 3 potenciómetros en PA1, PA2 y PA3 y el pulsador KEY de la placa (PA0)

Fase 1

Proyecto en CubeMX

1.1

Reloj, UART e I2C

▶ 0:32

Partimos del STM32F411CEU con cristal externo a 100 MHz. Activamos USART1 para la comunicación y dejamos I2C1 a 400 kHz para el IMU que agregaremos al final.

1.2

Pulsador con pull-up

▶ 1:40

El pulsador de la placa está en PA0: lo ponemos como GPIO_Input con la etiqueta sw y activamos Pull-up, porque al presionarlo envía un 0 y el pin no tiene resistencia externa.

1.3

Tres canales con DMA circular

▶ 2:43

Activamos IN1, IN2 e IN3. DMA en modo Circular, Scan Conversion, Continuous Conversion y DMA Continuous Requests en Enabled, EOC al final de todas las conversiones y Number of Conversion = 3 (rank 1 canal 1, rank 2 canal 2, rank 3 canal 3).

1.4

Sampling Time

▶ 3:16

El ADC trabaja con PCLK2/4 (25 MHz con el micro a 100 MHz). Si el muestreo es muy rápido, con potenciómetros de 10 k el DMA se puede bloquear porque el capacitor interno no alcanza a cargarse.

Usamos 84 ciclos en cada rank. Con fuentes de menor impedancia se puede bajar a 56 o 15.

Si el programa se queda trabado después de arrancar el DMA, sube el Sampling Time.

2.3

Formato de la trama

▶ 9:00

La trama empieza con INI=, lleva los valores separados por / y termina en *: INI=VOLTAJE/TEMPERATURA/DISTANCIA/LED*.

Escalamos cada canal: voltaje de 0 a 3.3, temperatura de 0 a 100 y distancia de 0 a 500. El LED es la lectura del pulsador con PIN_READ(sw).

while (1)
{
    //INI=VOLTAJE/TEMPERATURA/DISTANCIA/LED*
    float voltaje = adc1_codigo[0]*3.3/4095.0;
    float temperatura = adc1_codigo[1]*100/4095.0;
    float distancia = adc1_codigo[2]*500/4095.0;
    uint8_t led = PIN_READ(sw);

    sprintf(texto, "INI=%.2f/%.2f/%.2f/%u*\r\n", voltaje, temperatura, distancia, led);
    uartx_write_text(&huart1, texto);
    HAL_Delay(2);
}

Debe haber un % por cada variable. Primero pruébalo con un retardo grande y luego bájalo a 2 ms.

3.4

Decodificar la trama

▶ 23:15

Se toma lo que hay entre INI= y *, se separa por / y, si llegan al menos 4 valores, se guardan en las variables globales.

def procesar_trama(trama):
    global distancia, temperatura, voltios, led1
    try:
        if "INI=" in trama and "*" in trama:
            datos = trama.split("INI=")[1].split("*")[0]
            valores = datos.split("/")
            if len(valores) >= 4:
                voltios = float(valores[0])
                temperatura = float(valores[1])
                distancia = float(valores[2])
                led1 = int(valores[3])
    except:
        pass

Si armas otra trama, cambia aquí cómo se decodifica.

3.5

Actualizar los instrumentos

▶ 24:55

En el ciclo actualizar() se refrescan los instrumentos con las variables, se lee la trama y se vuelve a llamar cada 20 ms.

def actualizar():
    # actualiza variables
    voltaje_gauge.actualizar(voltios)
    temp_gauge.actualizar(temperatura)
    DISTANCIA_GAUGE.actualizar(distancia)
    led.actualizar(led1)   # en el video tambien se pasa el color verde
    trama = app.obtener_trama()
    if trama:
        print("Rx:", trama)
        procesar_trama(trama)
    app.root.after(20, actualizar)

actualizar()

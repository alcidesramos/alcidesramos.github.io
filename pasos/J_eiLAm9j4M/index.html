HLK-RM04 e IoT con Ubidots

Cuarta parte de la serie del módulo HLK-RM04. Se toma un proyecto de monitoreo y control con Ubidots hecho antes con el ESP8266 (temperatura, un switch, un voltaje y un led) y se traduce a este módulo. Como el HLK-RM04 se configura con su herramienta, el micro ya no manda comandos AT: solo escribe por el UART la petición HTTP. El módulo es más rápido que el ESP8266 y el programa queda más simple.

▶ Ver el video completo (15:16) Empezar el paso a paso
  • MikroC PRO for PIC
  • PIC18F25K50 (o el micro del proyecto anterior)
  • Módulo HLK-RM04 y su programa de configuración
  • Cuenta de Ubidots con un dispositivo y sus variables
  • Proteus con Virtual Terminal y conversor USB serial

Fase 1

Configurar el módulo

1.1

Partir de lo que ya existe

▶ 0:00

El proyecto de Ubidots con el ESP8266 ya está explicado en otros videos del canal. Aquí solo se muestra qué hay que cambiar para usar el HLK-RM04.

1.2

El circuito

▶ 1:06

El micro lee una temperatura (LM35), un switch y un voltaje, maneja un led y se comunica por el serial con el módulo, que ya está como cliente WiFi conectado a la red.

1.3

Quitar los comandos AT

▶ 2:13

En el main del programa del ESP8266 se mandaban muchos comandos de configuración. Con este módulo se borran todos: la configuración se hace con el programa del fabricante.

1.4

IP y puerto de Ubidots

▶ 3:20

En la herramienta de configuración se lee el módulo, se deja en modo serial a WiFi como cliente TCP y en el campo remoto se pone la IP del servidor de Ubidots y el puerto 80. Con el nombre things.ubidots.com no funcionó, así que se busca su IP con una página que resuelve nombres de dominio.

1.5

Probar sin el micro

▶ 5:01

Con Hercules se pueden mandar a mano las peticiones al módulo y ver la respuesta de Ubidots. El dato cambia de inmediato en el tablero.

Fase 2

Cambiar el programa

2.1

Enviar solo por serial

▶ 6:09

La función que mandaba al ESP8266 se reemplaza por una que solo escribe la trama por el UART. Después de enviar se espera unos 2 segundos.

2.2

Armar la trama

▶ 6:41

La trama con temperatura y led se arma igual que antes con sprintf, y se cambian el nombre del dispositivo y el token por los de la cuenta propia de Ubidots. El token es privado: no lo publiques.

2.3

Revisar los nombres

▶ 12:29

La primera prueba falló porque las variables del programa no se llamaban igual que en Ubidots. Hay que revisar que cada nombre (switch, voltaje, led, temperatura) coincida con el del tablero.

Fase 3

Prueba

3.1

En la simulación

▶ 13:36

Al subir el voltaje o la temperatura cambian en Ubidots, y desde el tablero se prende y apaga el led, con unos 2 segundos de retardo.

3.2

El módulo real

▶ 14:42

El mismo esquema se usa con el módulo real. El HLK-RM04 responde más rápido que el ESP8266.

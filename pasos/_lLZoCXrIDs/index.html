Librerías en C y tonos con el STM32

Clase virtual del semestre 2024-I. Se crea una librería propia para el display (display.c y display.h) y se agrega su ruta de includes. Luego se explica la frecuencia y el rango audible, y con una librería de retardos en microsegundos basada en el contador DWT se genera una señal de 1 kHz que se mide con el contador y el osciloscopio de Proteus. Se ve por qué no se debe conectar un parlante al pin, cómo usar un transistor como interruptor, qué es la saturación y por qué conviene un Darlington como el TIP122. Al final se usa la librería de tonos para crear melodías.

Fase 1

Crear una librería propia

1.1

Por qué librerías

▶ 0:34

Los procedimientos organizan el código, pero llenan el main. Una librería (un .c con el código y un .h con las cabeceras) se puede copiar y reutilizar en cualquier proyecto.

1.2

Carpeta y archivos

▶ 1:52

Clic derecho en Core → New → Folder y créala (por ejemplo librerias). Puedes separar .c y .h en dos subcarpetas o, como en clase, tenerlos juntos.

Clic derecho en la carpeta → New → Header File → display.h; luego New → Source File → display.c (mismo nombre).

1.3

El .c lleva el código

▶ 5:23

Corta los procedimientos hola() y chao() del main.c y pégalos en display.c, debajo del comentario de cabecera.

Arriba incluye su propio .h (escribe #include "dis y Ctrl+Espacio para autocompletar).

#include "display.h"

void hola()
{
  GPIOA->ODR = 0x76;  HAL_Delay(200);
  // ...
}

void chao()
{
  // ...
}
1.4

Ruta de los includes

▶ 6:32

Clic derecho sobre la carpeta que tiene los .h → Add/Remove Include Path → OK (Debug y Release marcados). Así el compilador encuentra tus cabeceras.

1.5

El .h lleva las cabeceras

▶ 8:45

Dentro del #ifndef/#define pega solo las cabeceras de los procedimientos que llamará el main, terminadas en punto y coma.

Incluye main.h para que la librería conozca los pines y las funciones HAL.

#ifndef LIBRERIAS_DISPLAY_H_
#define LIBRERIAS_DISPLAY_H_

#include "main.h"

void hola();
void chao();

#endif /* LIBRERIAS_DISPLAY_H_ */
1.6

Incluirla en el main

▶ 10:31

En main.c, entre USER CODE BEGIN Includes y END Includes, agrega la librería. Compila: el programa hace lo mismo, pero ahora display.c/.h sirven en cualquier proyecto.

/* USER CODE BEGIN Includes */
#include "display.h"
/* USER CODE END Includes */

Si al descargar una librería Windows le añade .txt (display.c.txt), quítale esa extensión.

Fase 2

Frecuencia y sonido

2.1

Frecuencias audibles

▶ 16:21

Un LED que parpadea muy rápido se ve siempre encendido; a esas frecuencias el efecto deja de ser visual y pasa a ser audible.

El oído humano escucha de 20 Hz a 20 kHz. Por encima están el ultrasonido (ecografías, sonar, ahuyentadores), la radio AM/FM, el Wi-Fi y los microondas.

2.2

Una señal de 1 kHz

▶ 32:03

1 kHz = mil ciclos por segundo, así que el periodo es T = 1/f = 1 ms.

Para una onda cuadrada: 0.5 ms en alto y 0.5 ms en bajo. Como HAL_Delay no acepta decimales, se necesitan retardos en microsegundos: 500 µs.

Fase 3

Retardos en microsegundos

3.1

Cómo funciona la librería

▶ 39:59

Copia delays.c y delays.h a la carpeta de librerías (Ctrl+C / Ctrl+V directo en el IDE).

delay_us_init() activa el contador de ciclos del depurador (DWT) y calcula cuántos ciclos (pasos) dura un microsegundo según la frecuencia del reloj.

delay_us_dwt(n) espera hasta que el contador llega a pasos × n.

uint32_t pasos;

void delay_us_init()
{
  CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
  DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
  pasos = HAL_RCC_GetHCLKFreq() / 1000000;  // ciclos por microsegundo
}

void delay_us_dwt(uint32_t reta)
{
  DWT->CYCCNT = 0;
  while (DWT->CYCCNT < pasos * reta);
}
3.2

Generar 1 kHz

▶ 36:54

Configura un pin como salida con la etiqueta parlante (en clase PB0).

Incluye delays.h, llama delay_us_init() antes del while (configuración) y en el while alterna el pin cada 500 µs.

/* USER CODE BEGIN 2 */
delay_us_init();
/* USER CODE END 2 */

while (1)
{
  HAL_GPIO_WritePin(parlante_GPIO_Port, parlante_Pin, 1);
  delay_us_dwt(500);
  HAL_GPIO_WritePin(parlante_GPIO_Port, parlante_Pin, 0);
  delay_us_dwt(500);
}
3.3

Medir en Proteus

▶ 45:46

En Virtual Instruments coloca el COUNTER TIMER en el pin del parlante; doble clic y cambia el modo a Frequency. Marca unos 991 Hz, casi 1 kHz.

Agrega el OSCILLOSCOPE al mismo pin para ver la onda cuadrada.

El cristal configurado en CubeIDE y en Proteus debe ser el mismo (16 MHz en la simulación); si no, los microsegundos salen mal.

3.4

Escucharla

▶ 49:18

Busca SPEAKER y usa el que tiene barra de nivel verde, amarillo y rojo (suena por la tarjeta de audio). Un pin al parlante y el otro a tierra. En simulación suena con algo de retardo.

Fase 4

Circuito real del parlante

4.1

No conectes el parlante al pin

▶ 51:33

Un parlante tiene 4 u 8 Ω: con 3.3 V pediría casi un amperio y quemaría el pin (máximo unos 20–25 mA).

Usa un parlante o un buzzer pasivo (suena con la frecuencia que le des). El buzzer activo tiene su propio tono y no sirve para melodías.

4.2

Transistor como interruptor

▶ 61:50

Pin del micro → resistencia → base de un NPN (2N3904 o 2N2222).

Fuente externa → parlante → colector; emisor a tierra. Une las tierras de la fuente externa y de la tarjeta.

No alimentes el parlante con los 5 V del USB de la tarjeta: usa otra fuente (cargador, adaptador de 5, 9 o 12 V) con tierra común.

4.3

Saturación

▶ 66:33

Para que el transistor trabaje como interruptor debe saturarse (VCE ≈ 0 V y todo el voltaje en la carga).

Ib = (Vb − 0.7)/Rb, Ic = β·Ib. Si el cálculo da un voltaje en la carga mayor que la fuente ("ley del absurdo"), el transistor está saturado.

No puedes bajar mucho Rb (corriente del pin) ni cambiar la carga (el parlante): queda subir el β.

4.4

Darlington

▶ 75:01

Dos transistores en cascada: el emisor del primero a la base del segundo. El β total es β1 × β2.

Usa un Darlington comercial como el TIP122 (β mayor de 1000) para garantizar la saturación con una Rb de 1 kΩ.

Fase 5

Melodías

5.1

Tocar notas

▶ 77:49

Copia la librería de tono (tono.c / tono.h) a la carpeta de librerías e inclúyela en el main.

Sound_play(frecuencia, duración_ms) genera la frecuencia indicada durante el tiempo dado. Con HAL_Delay haces pausas entre notas.

Sound_play(1000, 200);
Sound_play(1500, 200);
Sound_play(800, 300);
HAL_Delay(100);   // pausa
Sound_play(1200, 200);

Para el parcial: ocho procedimientos (mensajes en el display, juegos de luces con 4 LED y melodías), seis llamados desde el main y uno de ellos repetido.

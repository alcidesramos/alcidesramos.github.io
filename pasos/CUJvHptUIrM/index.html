Clase 147: motores paso a paso con el DRV8825 y el SysTick

Controlamos motores paso a paso con el DRV8825 (o el DRV8824 o cualquier driver con pines STEP y DIR) desde un STM32F411. En lugar de PWM y un timer por motor, la librería usa la interrupción del SysTick, que llega cada milisegundo: cuenta hasta el factor de tiempo del motor y conmuta el pin STEP. Así cada motor puede ir en cualquier pin, con su velocidad, dirección y modo (número de pasos o giro continuo). Al final agregamos recepción serial por DMA para mandar órdenes desde una interfaz en LabVIEW.

Fase 1

El driver y el proyecto

1.1

Conexión del DRV8825

▶ 0:00

El micro maneja solo STEP (pulsos) y DIR (dirección). RESET y SLEEP van a 3.3 V (o 5 V) y ENABLE a tierra.

M0, M1 y M2 quedan sin usar: paso completo. Con ellos se elige medio paso o micropaso según la tabla de la hoja de datos.

El potenciómetro del módulo ajusta la corriente: gíralo hasta que el motor no vibre ni se frene, con la mínima corriente posible para que no se caliente.

Si el motor gira al revés, invierte una bobina o cambia la dirección por software.

1.2

Pines STEP y DIR en CubeMX

▶ 2:42

Activamos el cristal (HSE) y el reloj al máximo con el PLL. Cualquier pin sirve: se ponen como GPIO_Output y se nombran exactamente step1 y dir1 (y step2, dir2… para más motores). El proyecto se llama paso_paso_drv8825.

Los nombres van en minúscula: la librería usa step1_Pin, dir1_Pin, etc. con #ifdef para saber qué motores existen.

1.3

Agregar la librería

▶ 4:59

En la carpeta Librerias copiamos PASO_PASO_DRIVER.c/.h y pinout1.h (manejo rápido de pines) y la añadimos a las rutas de include. En PASO_PASO_DRIVER.h están las constantes de dirección y modo.

#define DER 1
#define IZQ 2
#define QUI 3

#define modo_pasos    0
#define modo_continuo 1
Fase 2

Cómo funciona la librería

2.1

Declarar los motores

▶ 6:19

En PASO_PASO_DRIVER.c se crea una variable por motor: número de motor, factor de tiempo en ms (1 es lo más rápido, 10 es diez veces más lento) y modo.

//MOTORES A USAR
//      motor_num, fac_tiempo(ms), modo
PASOS PASO_PASO1 = {1, 1, modo_pasos};

El factor de tiempo es entero: el mínimo es 1 ms entre conmutaciones. Para más velocidad habría que usar PWM.

2.2

Llamarla desde el SysTick

▶ 7:26

En stm32f4xx_it.c se incluye la librería y dentro de SysTick_Handler se llama PASO_Analisis para cada motor. Cada milisegundo incrementa un contador y, al llegar al factor de tiempo, genera el pulso.

/* USER CODE BEGIN Includes */
#include "PASO_PASO_DRIVER.h"

void SysTick_Handler(void)
{
  /* USER CODE BEGIN SysTick_IRQn 0 */
  PASO_Analisis(&PASO_PASO1);
  //PASO_Analisis(&PASO_PASO2);
  /* USER CODE END SysTick_IRQn 0 */
  HAL_IncTick();
}
2.3

Pulso, dirección y conteo de pasos

▶ 9:00

PASO_Interrupcion pone el pin DIR según DER o IZQ y, si el motor no está quieto, hace PIN_BLINK del pin STEP de ese motor.

En modo pasos cuenta las conmutaciones; cuando llega al doble de los pulsos pedidos (alto y bajo por pulso, pulsos<<1) deja el motor en QUI.

Para más motores se copia el bloque case con step6, step7…

if (pasi->modo == modo_pasos)
{
  pasi->pulso_cont++;
  //multiplico por 2: pulso alto y bajo
  if ((pasi->pulso_cont) > pasi->pulsos << 1)
  {
    pasi->dir = QUI;   //lo deja quieto
    pasi->pulso_cont = 0;
  }
}

En el video se corrige un error de la versión vieja: en los case 3, 4 y 5 los pines de dirección deben ser dir3, dir4 y dir5.

Fase 3

Usando la librería

3.1

Un motor en modo pasos

▶ 12:15

Antes del while se define la dirección y los pulsos, y se inicializa el motor. Con 5 pulsos se ven exactamente 5 en el analizador lógico; con 100 el motor gira un rato y se frena.

PASO_PASO1.dir = DER;
PASO_PASO1.pulsos = 5;
PASO_Init(&PASO_PASO1);
3.2

Modo continuo y velocidad

▶ 15:01

Con modo_continuo el motor gira sin parar. Subiendo el factor de tiempo (10, 50…) va más lento.

PASOS PASO_PASO1 = {1, 50, modo_continuo};
3.3

Segundo motor y cambios en ejecución

▶ 16:41

Creamos step2 y dir2 en CubeMX, la variable PASO_PASO2 y su llamada en el SysTick.

La velocidad se puede cambiar en cualquier momento: tras 2 segundos el motor 2 pasa a ir 10 veces más lento.

PASOS PASO_PASO1 = {1, 10, modo_continuo};
PASOS PASO_PASO2 = {2, 1, modo_continuo};

// en main
PASO_PASO1.dir = DER;
PASO_Init(&PASO_PASO1);
PASO_PASO2.dir = IZQ;
PASO_Init(&PASO_PASO2);

HAL_Delay(2000);
PASO_PASO2.fact_tiempo = 10;
Fase 4

Control por puerto serial

4.1

Recepción serial por DMA

▶ 20:01

Agregamos las librerías de UART con DMA en idle (vistas en clases anteriores) y en CubeMX activamos USART1 a 115200, su interrupción y un canal DMA de recepción.

En el while se revisa la bandera, se procesa la trama y se reinicia la recepción.

#include "uart.h"
#include "UARTRX.h"

while (1)
{
  if (UARTRX1.flag_rx == 1)
  {
    procesa_rx();
    uartRX_DMA_Re_init(&UARTRX1);
  }
}

No olvides inicializar la recepción DMA antes del while, como indica el .h de la librería.

4.2

Procesar las órdenes

▶ 22:17

Con strstr se buscan comandos como m1der, m1izq, m1stop; vel1= cambia el factor de tiempo, pas1= los pulsos y mod1= el modo (pasos o giro).

void procesa_rx(void)
{
  char procesa[100];
  if (strstr(UARTRX1.trama_rx, "m1der")) PASO_PASO1.dir = DER;
  else if (strstr(UARTRX1.trama_rx, "m2der")) PASO_PASO2.dir = DER;
  else if (strstr(UARTRX1.trama_rx, "m1izq")) PASO_PASO1.dir = IZQ;
  else if (strstr(UARTRX1.trama_rx, "m2izq")) PASO_PASO2.dir = IZQ;
  else if (strstr(UARTRX1.trama_rx, "m1stop")) PASO_PASO1.dir = QUI;
  else if (strstr(UARTRX1.trama_rx, "m2stop")) PASO_PASO2.dir = QUI;
  else if (strstr(UARTRX1.trama_rx, "vel1="))
  {
    strcpy(procesa, strtok(UARTRX1.trama_rx, "="));
    strcpy(procesa, strtok(0, "*"));
    PASO_PASO1.fact_tiempo = atoi(procesa);
  }
  else if (strstr(UARTRX1.trama_rx, "mod1="))
  {
    strcpy(procesa, strtok(UARTRX1.trama_rx, "="));
    strcpy(procesa, strtok(0, "*"));
    PASO_PASO1.modo = atoi(procesa);
  }
  // igual para vel2=, pas1=, pas2=, mod2=
}

Los nombres exactos de los comandos y del terminador están reconstruidos de la pantalla; revísalos con tu interfaz.

Motores paso a paso con interrupción y LabVIEW

Primero repasamos cómo funcionan los motores paso a paso: bipolares y unipolares (5, 6 u 8 cables), paso simple, paso doble, medio paso y micropasos con drivers como el A4988. Luego armamos en Proteus una BlackPill STM32F401 con dos motores manejados por ULN2003A. La librería Pasopaso usa la interrupción del SysTick (1 ms) para dar los pasos, así que no se gasta ningún timer y el programa principal queda libre. Cada motor puede girar a la derecha, a la izquierda o quedarse quieto, en modo continuo o dando un número de pasos, con velocidad de 0 a 100. Al final recibimos comandos por UART con DMA e IDLE y movemos los motores desde un panel en LabVIEW.

Fase 1

Teoría de motores paso a paso

1.1

Bipolar y unipolar

▶ 1:00

Casi todos dan 200 pasos por vuelta (1,8° por paso). Para manejarlos necesitamos cuatro señales, una por bobina.

En los unipolares de 8, 6 o 5 cables se unen los comunes a la alimentación del motor (12 V, 15 V) y quedan cuatro bobinas. Con el tester en resistencia se identifican: el común da la mitad del valor.

  • Paso simple: una bobina a la vez.
  • Paso doble: dos bobinas a la vez, más torque.
  • Medio paso: alterna una y dos bobinas, combina torque y suavidad.
1.2

Drivers

▶ 2:30

Se pueden manejar con transistores Darlington (TIP122), con ULN2003 (500 mA), ULN2803, o con puente H como el L298 (2 A por canal). Drivers como el A4988 usan solo dos pines (dirección y pasos) y permiten micropasos con MS1, MS2 y MS3.

Fase 2

Circuito y CubeMX

2.1

Circuito en Proteus

▶ 5:20

Motor 1 en PA4 a PA7 y motor 2 en PB0, PB1, PB2 y PB10, cada uno a través de un ULN2003A. El LED de la tarjeta y el puerto serial (COMPIM) completan el montaje.

2.2

Base de tiempo con SysTick

▶ 8:30

En System Core > SYS el Timebase Source queda en SysTick: es una interrupción de 1 ms que ya viene activa, así que no gastamos los timers del usuario.

2.3

UART y pines

▶ 10:00

USART1 asíncrono a 9600 baudios y PC13 como salida con etiqueta LED.

Las bobinas como salidas, con estos nombres exactos porque la librería los usa: M1B1, M1B2, M1B3, M1B4 y M2B1, M2B2, M2B3, M2B4.

Si un nombre queda mal escrito (por ejemplo M1B3) la compilación falla con «M1B3 no está declarada». Revisa las etiquetas y vuelve a generar código.

Fase 3

Librería Pasopaso

3.1

Copiar las librerías

▶ 12:10

En Core/Librerias pegamos Pasopaso.c/.h y bits.c/.h (Pasopaso ya incluye bits.h), las agregamos a los Include paths y en main.c incluimos solo Pasopaso.h.

#include "Pasopaso.h"
3.2

Modo de paso, factor y segundo motor

▶ 18:50

En Pasopaso.c se elige la secuencia (paso simple, doble o medio paso) dejando sin comentar la que se quiera usar. Con #define M2 se habilita el segundo motor; si solo usas uno, coméntalo y no hace falta configurar sus pines.

En Pasopaso.h, factor indica cada cuántos milisegundos se da un paso a velocidad 100 y vel_max es la velocidad máxima.

// Pasopaso.c
#define M2   // si se va a usar otro motor

// paso simple
char codigo1[] = {0b0001, 0b0010, 0b0100, 0b1000};
char codigo2[] = {0b0001, 0b0010, 0b0100, 0b1000};

// Pasopaso.h
#define factor  10   // a velocidad 100 da un paso cada 10 ms
#define vel_max 100

Si el motor se queda pegado a velocidades altas, sube factor (15, 20, 30). En Proteus la velocidad 100 con factor 10 ya es demasiado rápida.

3.3

Interrupción en stm32f4xx_it.c

▶ 17:20

Incluimos Pasopaso.h, declaramos fact_vel en las variables privadas y en SysTick_Handler llamamos a pasopaso_int() cada factor milisegundos.

/* USER CODE BEGIN Includes */
#include "Pasopaso.h"

/* USER CODE BEGIN PV */
uint16_t fact_vel = 0;

/* dentro de SysTick_Handler(void) */
fact_vel++;
if (fact_vel >= factor)
{
  pasopaso_int();
  fact_vel = 0;
}
3.4

Cómo funciona por dentro

▶ 21:30

En cada llamada se cuenta la velocidad; cuando llega a vel_max+1-velo_m1 se da un paso (por eso 100 es lo más rápido). En modo pasos, al completar n_pasos1 el motor pasa a quieto. Según estado_giro1 se avanza o retrocede en la secuencia y saca_secuenciaM1 lee cada bit del código y lo escribe en su bobina.

Fase 4

Usar la librería

4.1

Órdenes desde main

▶ 23:10

Todo funciona por interrupción: basta con cambiar las variables y el motor responde. Aquí el motor 1 gira continuo a la izquierda y el motor 2 da 5 pasos a la derecha.

/* USER CODE BEGIN 2 */
estado_giro1 = izquierda;   // derecha, izquierda o quieto
estado_giro2 = derecha;

velo_m1 = 50;                // 0 a 100
velo_m2 = 30;

n_pasos2 = 5;                // pasos a dar en modo pasos

estado_modo1 = continuo;     // continuo o pasos
estado_modo2 = pasos;
/* USER CODE END 2 */
4.2

Simulación

▶ 25:00

Cargamos el .hex en Proteus: el motor 1 gira sin parar y el motor 2 da sus 5 pasos y se detiene. Como no hay bloqueo, podemos cambiar las órdenes después (por ejemplo, tras un HAL_Delay(3000) pasar el motor 1 a la derecha con velo_m1 = 70).

Fase 5

Control por serial con LabVIEW

5.1

Activar DMA e interrupción

▶ 28:50

Copiamos la librería uart_int_idle_dma. En USART1 > DMA Settings agregamos un canal de recepción (RX) y en NVIC Settings activamos la interrupción global del USART1.

5.2

Variables e inicialización

▶ 29:30

En uart_int_idle_dma.h se define el puerto y el tamaño de la trama. En main.c incluimos la librería y declaramos sus variables; antes del while llamamos uartdat_it_idle_dma_init() y en el while revisamos la bandera.

#include "uart_int_idle_dma.h"

// variables recepción por idle
uint8_t trama_rx[trama_size];
char flag_rx = 0;
uint16_t num_datos;
// para procesarx
char procesa[30];
char dato;

/* USER CODE BEGIN 2 */
uartdat_it_idle_dma_init();

while (1)
{
  if (flag_rx == 1)
  {
    procesarx();
    flag_rx = 0;
    uartdat_it_idle_dma_init();
  }
}
5.3

Procesar los comandos

▶ 32:20

procesarx() busca cada comando en la trama con strstr. Los valores se capturan con strtok entre «=» y «*» y se convierten con atoi.

  • m1der*, m1izq*, m1stop*: giro del motor 1 (igual con m2 para el motor 2).
  • vel1=NN*: velocidad del motor 1 y lo pasa a modo continuo.
  • pap1=NN*: número de pasos del motor 1 y lo pasa a modo pasos (pap2 para el motor 2).
void procesarx(void)
{
  if (strstr(trama_rx, "m1der*")) estado_giro1 = derecha;
  else if (strstr(trama_rx, "m1izq*")) estado_giro1 = izquierda;
  else if (strstr(trama_rx, "m1stop*")) estado_giro1 = quieto;
  else if (strstr(trama_rx, "m2der*")) estado_giro2 = derecha;
  else if (strstr(trama_rx, "m2izq*")) estado_giro2 = izquierda;
  else if (strstr(trama_rx, "m2stop*")) estado_giro2 = quieto;
  else if (strstr(trama_rx, "vel1"))
  {
    strcpy(procesa, strtok(trama_rx, "="));  // inicia captura después del =
    strcpy(procesa, strtok(0, "*"));         // captura hasta el *
    dato = atoi(procesa);
    estado_modo1 = continuo;
    velo_m1 = dato;
  }
  else if (strstr(trama_rx, "pap2"))
  {
    strcpy(procesa, strtok(trama_rx, "="));
    strcpy(procesa, strtok(0, "*"));
    dato = atoi(procesa);
    pasos2 = 0;              // limpia el contador de pasos
    estado_modo2 = pasos;
    n_pasos2 = dato;         // número de pasos a dar
  }
  // vel2 y pap1 se hacen igual
  memset(trama_rx, 0, trama_size);
}
5.4

Panel de LabVIEW

▶ 35:00

Con un emulador de puertos virtuales conectamos Proteus (COMPIM) y LabVIEW. El panel tiene, por motor, botones de izquierda, derecha y parar, un control de velocidad y un campo de pasos. LabVIEW trabaja por eventos y envía el comando cada vez que cambia un control.

Si con velocidad alta el motor se queda quieto, no es un error de la librería: la bobina no alcanza a responder. Sube factor en Pasopaso.h.

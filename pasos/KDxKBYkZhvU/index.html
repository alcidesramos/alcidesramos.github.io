Hola mundo con el STM32C5 de WeAct en VS Code

La serie C5 de ST es de bajo costo y bajo consumo, y trae las nuevas librerías HAL2. Esta vez uso la tarjeta de WeAct Studio con el STM32C552VET6 de 100 pines (chip original, tarjeta china). Desde VS Code abro STM32CubeMX2, selecciono el micro por número de parte, configuro PH15 como salida con la etiqueta LED, dejo que CubeMX2 resuelva el reloj y genero el proyecto CMake. Luego lo abro en VS Code, habilito el proyecto de CMake, escribo el parpadeo con ayuda de Copilot y lo programo con el ST-Link (sirven también los clones).

Fase 1

Crear el proyecto en CubeMX2

1.1

Seleccionar el micro

▶ 2:25

Desde la pestaña STM32 de VS Code abrimos STM32CubeMX2. Como la tarjeta no es una board oficial de ST, se busca por el micro: STM32C552VET6 (LQFP100, Cortex-M33, 144 MHz, 512 KB de flash y 128 KB de RAM). Le damos Continue y nombramos el proyecto HOLA_MUNDO_CHINA.

1.2

PH15 como salida LED

▶ 3:35

En Pinout buscamos PH15, clic derecho, Assign signal → GPIO. En el panel de detalle se configura como salida y se le pone la etiqueta LED con el botón Add.

La etiqueta que vale para el código es la que se agrega en Labels del pin con Add. La que se pone en otras partes de la vista GPIO es solo informativa.

Fase 2

Generar el código

2.1

Opciones de generación

▶ 5:00

En Project settings el formato por defecto ya es CMake con GCC: los nuevos micros están pensados para trabajar con VS Code y no con el CubeIDE de antes.

2.2

Resolver el reloj

▶ 5:25

Al generar sale un error porque el reloj no está configurado. En la pestaña Clock se pulsa Resolve clock issues y CubeMX2 lo arregla solo. Con clic derecho sobre un bloque se puede resaltar el camino del reloj hasta cada periférico.

Fase 3

Abrir en VS Code

3.1

Abrir la carpeta del proyecto

▶ 6:40

Se abre la carpeta generada con VS Code. Ya no hay carpeta Core: el main.c queda en la raíz y no trae los bloques USER CODE BEGIN/END. Se pone el código antes del while para lo que se ejecuta una vez, y dentro del while lo que se repite.

VS Code abre en modo restringido: hay que confiar en la carpeta para habilitarlo.

int main(void)
{
  if (mx_system_init() != SYSTEM_OK)
  {
    return (-1);
  }
  else
  {
    while (1)
    {
      /* código que se repite */
    }
  }
}
3.2

Configurar el proyecto CMake

▶ 7:50

Cuando VS Code pregunta si configura el proyecto CMake descubierto como STM32Cube, responda siempre Yes. Si se le pasó, vaya a la pestaña STM32, Set Up STM32Cube project(s), revise que aparezca el micro y el Cortex-M33 con su proyecto, y pulse Save and close.

Fase 4

Parpadeo con HAL2

4.1

Escribir el parpadeo

▶ 9:05

Escribo el comentario //CODIGO PARA TITILAR LED y Copilot sugiere el código. Hay que corregir el nombre del pin: el puerto y el pin se llaman según la etiqueta, LED_PORT y LED_PIN.

while (1)
{
  //CODIGO PARA TITILAR LED
  HAL_GPIO_TogglePin(LED_PORT, LED_PIN);
  HAL_Delay(1000);
}

Con HAL2 cambian nombres (mayúsculas y minúsculas). Si sale error de compilación por el pin, revise los nombres que generó la etiqueta en el proyecto.

4.2

Programar con el ST-Link

▶ 10:40

Compilamos y con el botón de depuración (play con el bicho) elegimos ST-Link. Ahora también funcionan los clones. Si no se quiere ir paso a paso, se le da play y el LED queda parpadeando cada segundo.

4.3

Periféricos del C5

▶ 11:05

En la vista de periféricos de CubeMX2 se ven las opciones de este micro: dos ADC, comparadores y un DAC de 12 bits, entre otros. Los iremos usando en el curso.

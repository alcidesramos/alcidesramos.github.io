LAT o PORT para las salidas

Al escribir PORTB = ~PORTB el micro primero lee el estado de los pines y luego escribe; si un pin con carga no alcanza a cambiar de nivel, se lee mal y la salida falla (lectura, modificación, escritura). LAT lee el registro de salida, no el pin, así que siempre se invierte lo que se escribió. Por eso PORT se deja para leer entradas y LAT para escribir salidas. Los PIC16F viejos no tienen LAT.

Programa

▶ 1:03

Todo digital y ambos puertos como salida. En el ciclo el puerto B se invierte con PORT y el puerto D con LAT.

#include <xc.h>
#define _XTAL_FREQ 4000000

void main(void) {
  ADCON1 = 0b1111;
  TRISB = 0;
  TRISD = 0;
  PORTB = 0;
  LATD = 0;
  while (1) {
    PORTB = ~PORTB;
    LATD = ~LATD;
    __delay_ms(100);
  }
}
1.3

Qué cambia

▶ 6:49

En la simulación los dos hacen lo mismo, pero con PORT el micro lee el nivel real del pin antes de escribir. Si una carga lo mantiene en otro nivel, el resultado sale mal. Con LAT se lee lo que se escribió.

1.4

Regla

▶ 7:59

En los PIC18F y en los PIC16F nuevos: LAT para salidas y PORT para entradas. Se puede escribir en PORT, pero no es lo recomendado.

Leer cualquier control IR con un PIC

El receptor entrega la señal ya demodulada: pulsos de distinto ancho. Con el analizador lógico se ve que cada tecla es un tren de pulsos. El PIC (16F1824 a 16 MHz) interrumpe en cada flanco, alternando subida y bajada, y guarda el valor del Timer0; si el timer se desborda (unos 16 ms sin flancos) el código terminó. Con los tiempos por serial se ve que solo hay tres anchos (6, 10 y 22 cuentas aproximadamente), así que se normalizan a esos valores. Luego se comparan contra los códigos guardados en memoria de programa para prender LEDs. Al final se ve el problema de RAM y la idea del hash, que se usa en el video siguiente.

La señal IR

1.1

Receptor

▶ 0:00

El VS1838 tiene tres pines: salida, tierra y 5 V. Entrega la señal sin la portadora, lista para el micro. La salida está en alto y baja con cada pulso.

1.2

Ver el código

▶ 6:39

Con un analizador lógico se ve que cada tecla manda un tren de pulsos de distinto ancho. La idea es medir el tiempo de cada pulso y de cada espacio.

1.3

Timer0

▶ 8:19

Con 16 MHz y preescalador 256 el Timer0 se desborda a unos 16 ms, más que cualquier pulso. Ese desborde indica que el código terminó.

Fase 2

Capturar los tiempos

2.1

Configuración

▶ 13:16

Se inicia el UART, se envía INICIANDO y se habilita la interrupción INT por flanco de bajada, más la global.

UART1_Init(19200);
LATA = 0;
UART1_Write_Text("INICIANDO\r\n");
// configura el timer cero para medir tiempo mas de 16ms
OPTION_REG = 0;   // preescalador asignado al timer
PS2_bit = 1;      // preescalador 256
PS1_bit = 1;
PS0_bit = 1;
// habilitamos interrupcion
INTEDG_bit = 0;   // flanco de bajada
INTF_bit = 0;     // limpia la bandera
INTE_bit = 1;     // habilita la interrupcion por flanco
GIE_bit = 1;      // autoriza todas las interrupciones
2.2

Contar flancos

▶ 16:34

En cada flanco se cambia el flanco a detectar. Primero solo se cuentan los flancos para saber cuántos datos tiene un código.

2.3

Guardar tiempos

▶ 23:22

Se omite la primera interrupción (el timer ya venía corriendo). En las siguientes se guarda el Timer0 en el arreglo tiempo y se reinicia. Si el timer se desborda, el código terminó: se activa flag_codigo y se deshabilita la interrupción hasta procesarlo.

void Interrupcion() iv 0x0004 ics ICS_AUTO {
  if (INTF_bit == 1) {
    if (flag_codigo == 0) {           // el analisis se hace solo
      if (cuenta != 0) {              // omite el primer dato
        timer_aux = TMR0;             // captura el valor del timer
        TMR0 = 0;                     // resetea el timer para otra lectura
        tiempo[cuenta-1] = timer_aux; // carga un buffer con los datos
      }
      cuenta++;
      INTEDG_bit = ~INTEDG_bit;       // cambia el flanco a detectar
      if (TMR0IF_bit == 1) {          // mas de 16 ms: fin del codigo
        flag_codigo = 1;
        INTE_bit = 0;                 // deshabilita la interrupcion
      }
    }
  }
  // ... limpia banderas
}

Fase 3

Normalizar y comparar

3.1

Tres anchos

▶ 33:54

Los tiempos de varias lecturas de la misma tecla varían un poco, pero siempre rondan tres valores. Cada tiempo se cambia por el valor más cercano, con un margen (paso) para cada uno.

void normaliza() {
  for (cont = 0; cont < cuenta-1; cont++) {
    if ((tiempo[cont] >= cod1-paso1) && (tiempo[cont] <= cod1+paso1)) tiempo[cont] = cod1;
    else if ((tiempo[cont] >= cod2-paso2) && (tiempo[cont] <= cod2+paso2)) tiempo[cont] = cod2;
    else if ((tiempo[cont] >= cod3-paso3) && (tiempo[cont] <= cod3+paso3)) tiempo[cont] = cod3;
    else tiempo[cont] = 0;
  }
}

3.3

Falta RAM

▶ 45:55

Si los arreglos se declaran sin const, el compilador los pone en RAM y sale el error Not enough RAM. Con const quedan en la memoria de programa.

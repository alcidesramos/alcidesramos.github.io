Seguidor de línea sencillo con PIC

El robot tortuga de Proteus tiene solo tres sensores, juntos y en el centro de gravedad, lo que no es ideal. Un PIC16F1824 a 8 MHz con oscilador interno tiene los pines justos: tres sensores, dos pines de dirección por motor y los dos PWM (CCP1 y CCP2). Se definen negro = 1 y blanco = 0, se escriben funciones para cada motor (adelante, atrás, quieto) y se combinan en adelante, atrás, derecha e izquierda con una velocidad. Si un motor no gira como se espera, se cambian los 0 y 1 de su función. La lógica revisa las ocho combinaciones de los sensores: con negro a un lado gira hacia ese lado a velocidad de giro, con el centro avanza a velocidad de línea y en blanco sigue adelante. Funciona, pero lento y oscilando, y la línea debe ser del ancho de un sensor.

Fase 1

Montaje y pines

1.1

El robot

▶ 0:00

El robot tortuga de Proteus tiene tres sensores muy juntos y en el centro de gravedad. En la práctica conviene ponerlos más adelante para anticipar la línea.

1.2

El micro

▶ 0:32

Se usa un PIC16F1824, que tiene los pines necesarios: tres sensores, dos pines por motor y los dos PWM, CCP1 (RC5) y CCP2. Los demás pines pueden ser cualquiera.

1.3

Proyecto

▶ 2:16

Proyecto en MikroC a 8 MHz con oscilador interno, sin reloj externo, para usar todos los pines.

1.4

Definir pines

▶ 2:56

Negro vale 1 y blanco 0; si la pista es negra con línea blanca, se cambian estos dos valores. Sensores en RA2, RA4 y RA5 y el motor derecho en LATC0 y LATC1.

#define negro 1
#define blanco 0

// entrada de los 3 sensores CNY70
#define SI RA2_bit   // sensor de la izquierda
#define SC RA4_bit   // sensor del centro
#define SD RA5_bit   // sensor de la derecha
// configura pines
#define SI_DIR TRISA2_bit
#define SC_DIR TRISA4_bit
#define SD_DIR TRISA5_bit

// salida motor derecha
#define MD1 LATC0_bit
#define MD2 LATC1_bit
#define MD1_DIR TRISC0_bit
#define MD2_DIR TRISC1_bit
1.5

Funciones de cada motor

▶ 4:00

Cada motor tiene funciones para quieto, adelante y atrás. Si el motor gira al revés, solo se cambian los 0 y 1.

// gira atrás motor derecha
void md_atras() {
  MD1 = 0;
  MD2 = 1;
}

// motor izquierda quieto
void mi_quieto() {
  MI1 = 0;
  MI2 = 0;
}

// motor izquierda gira adelante
void mi_alante() {
  MI1 = 0;
  MI2 = 1;
}
Fase 2

Configuración y prueba

2.1

Configurar el micro

▶ 5:16

Oscilador interno a 8 MHz (con el PLL podría ir más rápido), todo digital, sensores como entrada y pines de motores como salida. El PWM arranca a baja frecuencia (250 Hz) con un ciclo útil de prueba.

2.2

Ver el PWM

▶ 6:22

Antes de seguir, con un osciloscopio se comprueba que los dos pines de PWM generan la señal.

2.3

Probar los motores

▶ 7:30

Se manda cada motor adelante o atrás y se mira si el robot avanza o gira hacia donde debe. Si no, se corrigen las funciones.

2.4

Movimientos agrupados

▶ 9:11

Con las funciones de cada motor se hacen adelante, atrás, derecha e izquierda, cada una con su velocidad por PWM.

Fase 3

La lógica

3.1

Analizar los sensores

▶ 10:52

Se definen una velocidad de línea y una de giro, un poco más lenta. Con negro a la izquierda gira a la izquierda, con negro a la derecha gira a la derecha, con el centro o todo blanco avanza.

void analiza_sensores() {
  if      ((SI==negro)  && (SC==negro)  && (SD==negro))  izquierda(velo_giro);
  else if ((SI==negro)  && (SC==negro)  && (SD==blanco)) izquierda(velo_giro);
  else if ((SI==negro)  && (SC==blanco) && (SD==negro))  alante(velo_giro);  // imposible
  else if ((SI==negro)  && (SC==blanco) && (SD==blanco)) izquierda(velo_giro);
  else if ((SI==blanco) && (SC==negro)  && (SD==negro))  derecha(velo_giro);
  else if ((SI==blanco) && (SC==negro)  && (SD==blanco)) alante(velo_linea);
  else if ((SI==blanco) && (SC==blanco) && (SD==negro))  derecha(velo_giro);
  else if ((SI==blanco) && (SC==blanco) && (SD==blanco)) alante(velo_linea);
}
3.2

Pista

▶ 13:37

En Paint se dibuja una elipse con un trazo del ancho de un sensor y se carga en el robot.

3.3

Prueba

▶ 14:45

Se ubica el robot sobre la línea. Por tener los sensores en el centro, un retardo de 1 ms ayuda a que no se quede pegado. Sigue la línea, pero lento y oscilando.

3.4

Ajustar la velocidad

▶ 15:55

Con 150 lo hace más rápido; con 200 se sale y se queda quieto. El valor adecuado depende de los motores y de la dinámica del robot.

3.5

Limitaciones

▶ 18:08

Con una línea más gruesa no funciona: con solo derecha e izquierda la línea debe tener el ancho de un sensor. En la parte 2 se mejora el control.

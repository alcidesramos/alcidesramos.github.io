Clase 128: TFT ILI9341 texto y figuras propias

En la clase 127 se usó una librería adaptada de un tercero. Aquí la pantalla ILI9341 pasa a usar las librerías propias del canal, con las mismas funciones que las otras TFT (ILI9488, ILI9225...). Se crea el proyecto con el nuevo flujo de STM32CubeMX separado de CubeIDE, se configura SPI1 a 50 Mbit/s y los pines de control, y se prueban líneas, rectángulos con borde de varios píxeles, elipses, caracteres y cadenas de texto. Al final se crea una fuente nueva con MikroElektronika GLCD Font Creator y se agrega a fonts.c.

Fase 1

Proyecto en CubeMX

1.1

Reloj al máximo

▶ 1:40

Desde CubeMX se elige el STM32F411CEU. En RCC se activa el cristal externo (HSE) y en Clock Configuration se lleva a 100 MHz.

1.2

Conexiones de la pantalla

▶ 2:30

SCK a PA5, SDO (MISO) a PA6, SDA (MOSI) a PA7, CS a PB0, RS/RST a PB1, D/C a PB2 y BL (luz) a PB10. Es la misma conexión del video anterior.

1.3

SPI1, pines y generar código

▶ 3:20

Connectivity > SPI1 en Full-Duplex Master (MISO no se usa por ahora, pero queda listo). Datos de 8 bits.

Con prescaler 2 el SPI queda a 50 Mbit/s, la máxima velocidad de este micro y la que soporta la pantalla.

PB0, PB1, PB2 y PB10 como GPIO_Output con las etiquetas TFT_CS, TFT_RST, TFT_DC y TFT_LED. TFT_LED es opcional: si conectas BL a 3.3 V queda siempre encendida; con un pin PWM podrías controlar el brillo.

En Project Manager se pone el nombre del proyecto y la ubicación. Ojo: CubeMX siempre crea una carpeta con el nombre del proyecto dentro de la ruta elegida.

En Toolchain/IDE se selecciona STM32CubeIDE y se genera el código. Conviene que CubeIDE esté cerrado: con Open Project, CubeMX lo abre y carga el proyecto.

No le des doble clic al .ioc dentro de CubeIDE porque abre otro CubeMX; los cambios de hardware se hacen en la ventana de CubeMX que ya está abierta.

Fase 2

Librerías

2.1

Configurar ILI9341.h

▶ 8:40

Se crea Core/Librerias, se agrega al include path y se pegan ILI9341.c/.h, fonts.c/.h y pinout.c/.h.

En ILI9341.h se indica el puerto SPI que usa la pantalla. Más adelante el touch usará otro SPI, por eso es configurable.

// Puerto SPI a usar
#define TFT_SPI hspi1

// Orientacion de la pantalla
#define Vertical        0
#define Horizontal      1
#define Vertical_Inv    2
#define Horizontal_Inv  3
2.2

Iniciar la pantalla

▶ 9:40

Se enciende la luz de fondo, se inicializa la pantalla, se elige la orientación (vertical, horizontal o sus invertidas) y se pinta el fondo azul para comprobar que funciona.

Si al compilar salen errores de funciones no declaradas, faltan los #include en el main.

/* USER CODE BEGIN Includes */
#include "ILI9341.h"
#include "fonts.h"
#include "pinout.h"
/* USER CODE END Includes */

/* USER CODE BEGIN 2 */
PIN_ON(TFT_LED);                 // encender la pantalla
HAL_Delay(50);
ILI9341_Init();                  // inicio pantalla
HAL_Delay(50);

ILI9341_direction(Horizontal);
ILI9341_Clear(COLOR_BLUE);
/* USER CODE END 2 */
Fase 3

Figuras

3.1

Línea y rectángulos con borde

▶ 12:00

drawFastHLine dibuja una línea horizontal: posición, largo y color.

draw_fill_rectangle hace un rectángulo relleno (con borde delgado) y draw_rectangle uno sin relleno, con un último parámetro para el grosor del borde en píxeles.

Si dos figuras comparten posición, una tapa a la otra. Cambia las coordenadas para verlas por separado.

drawFastHLine(50, 50, 50, COLOR_WHITE);                 // x, y, largo, color
draw_fill_rectangle(100, 100, 200, 200, COLOR_RED);     // x1, y1, x2, y2, color
draw_rectangle(150, 100, 200, 200, COLOR_YELLOW, 5);    // ... , grosor del borde
draw_fill_ellipse(100, 100, 40, 20, COLOR_DARKGRAY);    // centro x, y, radio x, radio y
3.2

Elipse y otras figuras

▶ 15:40

La librería también trae triángulos, círculos, arcos y rectángulos redondeados, rellenos o no.

En la elipse el punto es el centro: el radio tiene que caber desde ahí. En el video, con centro en (0,0) no aparecía; con (100,100) sí.

Fase 4

Texto y fuentes

4.1

Caracteres y cadenas

▶ 17:40

draw_char escribe un solo carácter y draw_string una cadena, ambas sin fondo (encima de lo que ya está).

draw_string_fondo recibe además el color de fondo del texto.

Las fuentes incluidas van de font1 a font4: font1 y font3 pequeñas, font2 mediana (19x24) y font4 muy grande.

draw_char(150, 200, 'A', COLOR_DARKRED, font2);                  // un caracter
draw_string_fondo(0, 0, "SUSCRIBETE", COLOR_RED, COLOR_BLACK, font2); // texto con fondo
draw_string(0, 60, "AL CANAL", COLOR_WHITE, font5);               // texto sin fondo
4.2

Crear una fuente con GLCD Font Creator

▶ 20:50

Se abre MikroElektronika GLCD Font Creator (gratuito) y en File > New Font > Import An Existing System Font se elige una fuente de Windows y el tamaño (14 en el video).

Se deja el rango 32 a 127 y se acepta. Puedes mover o editar cada carácter a mano si alguno queda mal ubicado.

Luego Export for GLCD, pestaña mikroC, y se copia el código.

4.3

Agregar la fuente a fonts.c

▶ 22:40

Se pega al final de fonts.c. Se cambia unsigned short por unsigned char y se le pone nombre, por ejemplo font5.

Al inicio del arreglo se escriben dos números: el ancho (19) y el alto dividido entre 8 redondeado hacia arriba (28/8 = 3.5, se pone 4).

En fonts.h se declara extern const unsigned char font5[];

// fonts.c (al final, despues de font4)
//GLCD FontName : Segoe_Print19x28
//GLCD FontSize : 19 x 28

const unsigned char font5[] = { 19, 4,     // ancho, alto/8 redondeado hacia arriba (28/8 = 3.5 -> 4)
    0x0A, 0x00, 0x00, 0x00, /* ... datos exportados ... */
};

// fonts.h
extern const unsigned char font5[];

En el video la fuente no aparecía porque al pegar se borró parte del encabezado del arreglo. Revisa que quede const unsigned char y los dos números de tamaño.

4.4

Usar la nueva fuente

▶ 24:10

Se escribe "AL CANAL" con font5 debajo de "SUSCRIBETE". Si el texto es muy grande puede no caber en la pantalla.

Clase 10: Blue Pill con bootloader USB

En esta clase cargamos en la Blue Pill (STM32F103C8) un bootloader USB HID adaptado del de MikroElektronika. Se graba una sola vez con el ST-Link desde STM32CubeProgrammer; después cualquier programa hecho en STM32CubeIDE se carga solo con el cable USB usando el programa mikroBootloader. Para que funcione hay que generar el .hex y crear los proyectos a partir del archivo .ioc base, que deja el reloj a 72 MHz y el USB a 48 MHz igual que el bootloader.

▶ Ver el video completo (12:14) Empezar el paso a paso
  • Blue Pill (STM32F103C8T6)
  • ST-Link V2 (solo para grabar el bootloader una vez)
  • Cable USB (micro USB o tipo C según la placa)
  • STM32CubeProgrammer y STM32CubeIDE
  • Carpeta "Blue pill" del curso: bootloader .hex, mikroBootloader USB HID.exe y el .ioc básico

Fase 1

Grabar el bootloader (una sola vez)

El bootloader ocupa un pedazo de la flash al inicio, pero a cambio ya no necesitas programador: los estudiantes pueden cargar sus programas solo con el USB.

1.1

Los archivos del bootloader

▶ 1:20

En la carpeta USB HID Bootloader están el driver, el programa mikroBootloader USB HID.exe y el proyecto original de mikroC para ARM, configurado a 72 MHz. El .hex ya compilado viene en la carpeta del curso.

1.2

Abrir el .hex en STM32CubeProgrammer

▶ 2:40
  • Conecta la Blue Pill con el ST-Link y pulsa Connect.
  • Pestaña Open file y elige el .hex del bootloader.
  • Pulsa Download para grabarlo.

Si sale "failed to erase memory", la flash está protegida: quita la protección (RDP) o haz un Full chip erase y vuelve a intentar.

1.3

Desde ahora basta el cable USB

▶ 4:00

Desconecta el ST-Link y conecta la placa directo al PC con el cable USB. Al energizarse, el bootloader espera unos 5 segundos una conexión; si no llega, arranca el programa del usuario.

Fase 2

Preparar el proyecto en CubeIDE

El bootloader solo acepta archivos .hex, y el reloj del programa debe coincidir con el del bootloader.

2.1

Activar la salida .hex

▶ 5:00
  • Clic derecho en el proyecto → Properties.
  • C/C++ Build → Settings → MCU Post build outputs.
  • Marca Convert to Intel Hex file (-O ihex) y aplica.
  • Compila: el .hex queda en la carpeta Debug del proyecto.
2.2

Crear el proyecto desde el .ioc básico

▶ 7:30

La forma recomendada es File → New → STM32 Project from an Existing STM32CubeMX Configuration File (.ioc) y elegir el .ioc "básico" que entrego. Así el cristal externo (HSE 8 MHz), el SYSCLK a 72 MHz y el USB a 48 MHz quedan iguales a los del bootloader.

2.3

Revisar pines y reloj

▶ 8:40

El .ioc ya trae el LED en PC13, el USART1 y el TIM4. En Clock Configuration comprueba HCLK = 72 MHz.

2.4

El código del parpadeo

▶ 10:20

En el while(1) de main.c va el parpadeo del LED (el pin tiene la etiqueta led):

while (1)
{
  HAL_GPIO_TogglePin(led_GPIO_Port, led_Pin);
  HAL_Delay(1200);
}
Fase 3

Cargar el programa por USB

3.1

Usar mikroBootloader

▶ 5:45
  • Abre mikroBootloader USB HID.
  • Desconecta y vuelve a conectar la placa, y antes de 5 s pulsa Connect.
  • Browse for HEX: elige el .hex de la carpeta Debug.
  • Begin uploading y espera "Completed successfully".
3.2

Resultado

▶ 11:30

Al terminar la carga la placa se reinicia y el LED de PC13 parpadea cada 1,2 s, todo sin programador.

Si tardas más de 5 s en dar Connect, el bootloader salta al programa anterior. Desconecta, reconecta y repite.

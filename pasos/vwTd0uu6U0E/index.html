Protocolo I2C y memoria 24LC512

Lección 40 del curso. Se explica el bus I2C (de Philips; en Atmel se llama TWI): dos líneas con resistencias pull-up de 4.7k a 10k, maestro y esclavos con dirección. En Proteus se monta un PIC16F1824 a 8 MHz con una memoria 24LC512 y el depurador I2C. Primero se prueba la librería de MikroC y se ve que se bloquea si el esclavo no contesta; luego se escribe una librería propia (I2C_ARZ.c) con los registros SSP1 que permite saber si hubo reconocimiento, y con ella funciones para escribir y leer la memoria.

Fase 1

El bus I2C

1.1

Qué es

▶ 0:00

I2C es un bus serie de dos hilos, SDA (datos) y SCL (reloj), creado por Philips. Atmel lo llamó TWI por temas de licencia. Un maestro genera el reloj y habla con esclavos que tienen dirección.

1.2

Pull-ups

▶ 0:32

Las dos líneas son de drenador abierto y necesitan resistencias pull-up. Lo recomendable está entre 4.7k y 10k.

1.3

Proteus

▶ 2:12

Algunos dispositivos I2C en Proteus solo funcionan si el depurador I2C está conectado al bus. Además sirve para ver cada byte, el start, el stop y los reconocimientos.

UART remapeado

El I2C usa RC0 y RC1, así que el UART se pasa a RC4 y RC5 con los bits de APFCON0, y se imprime "iniciando" para comprobar que el programa corre.

Fase 3

Librería de MikroC

3.1

Escribir en la memoria

▶ 7:27

Para escribir: condición de start, byte de control con la dirección del esclavo y el bit de escritura en 0, dos bytes de dirección de memoria, el dato y stop.

I2C1_Start();
I2C1_Wr(dir_esclavo & 0b11111110);
I2C1_Wr(0); I2C1_Wr(0);
I2C1_Wr(0xF);
I2C1_Stop();
3.2

Bit de lectura o escritura

▶ 9:17

El último bit del byte de dirección dice si se va a escribir (0) o a leer (1). Por eso se hace AND con 0b11111110 para escribir y OR con 1 para leer.

3.3

El problema

▶ 10:58

Funciona, pero si el esclavo no está o no responde, la librería se queda esperando y el programa se bloquea: el led deja de titilar. Por eso se hace una librería propia.

Fase 4

Librería propia

4.1

Archivo I2C_ARZ.c

▶ 12:38

Se crea un archivo nuevo en el proyecto con las funciones del maestro, hechas con los registros SSP1 según la hoja de datos.

4.2

Configuración

▶ 13:52

SSP1CON1 = 0b1000 pone el módulo en modo maestro I2C. La velocidad se calcula con el reloj del micro: SSP1ADD = (Fosc/4)/velocidad - 1.

const unsigned long cristal = Clock_MHz()*1e6/4;
void I2C_CONFIG_master(unsigned long i2c_velo){
  SSP1STAT = 0; SSP1CON1 = 0b1000; SSP1CON2 = 0;
  SSP1ADD = (cristal/i2c_velo) - 1;
  SSPEN_bit = 1;
}
4.3

Start, stop y repeated start

▶ 17:26

Cada condición se genera poniendo su bit en 1 (SEN, PEN o RSEN) y esperando a que el hardware lo limpie. ACKDT elige si se manda reconocimiento y ACKSTAT dice si el esclavo lo mandó.

void I2C_STARTBIT(){
  SSP1IF_bit = 0;
  SEN_bit = 1;
  while (SEN_bit == 1);
}
4.4

Escribir un byte

▶ 19:41

Se carga SSP1BUF, se espera la bandera SSP1IF y se revisa ACKSTAT. Retorna 1 si el esclavo respondió y 0 si no, así el programa no se bloquea.

char I2C_WRITE_BYTE(unsigned char dato_i2c){
  SSP1IF_bit = 0;
  SSP1BUF = dato_i2c;
  I2C_WAIT();
  if (ACKSTAT_bit == 0) return 1;
  else return 0;
}
4.5

Saber si el esclavo está

▶ 20:48

Con ese retorno se puede avisar cuando no hay reconocimiento en vez de quedar pegado.

if (I2C_WRITE_BYTE(dir_esclavo & 0b11111110) == 0)
  UART1_Write_Text("no hubo reconocimiento esclavo");
Fase 5

Escribir y leer la memoria

5.1

Escritura

▶ 23:44

memoria_i2c_write(dir_mem, dato_mem): start, dirección del esclavo, parte alta y baja de la dirección con Hi() y Lo(), el dato, stop y 5 ms para que la memoria grabe. Hi y Lo requieren el include que indica la ayuda (built_in.h).

5.2

Leer un byte

▶ 26:16

Se activa RCEN, se espera a que termine y se lee SSP1BUF. Luego el maestro manda reconocimiento si va a seguir leyendo, o no lo manda si es el último byte.

5.3

Lectura

▶ 27:27

memoria_i2c_read(dir_mem): start, dirección del esclavo para escribir, dirección de memoria, repeated start, dirección del esclavo con el bit de lectura, se lee un byte sin reconocimiento y stop.

5.4

Prueba

▶ 28:35

Se escriben los valores 10 a 14 en las posiciones 0 a 4 y se lee la posición 0. Para mostrarlo se incluye la librería de conversiones o se usa sprinti.

leido = memoria_i2c_read(0);
sprinti(texto, "leido0= %u \r\n", (unsigned int)leido);
UART1_Write_Text(texto);

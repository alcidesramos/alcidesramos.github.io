Clase en vivo: introducción a las interrupciones

Partimos del carrito de Proteus manejado desde LabVIEW. Como la lectura serial es bloqueante, un LED puesto en el while solo cambia cuando llega una orden. Para resolverlo usamos interrupciones: configuramos el TIM3 para interrumpir cada 200 ms y hacer titilar un LED, usamos un contador para un segundo LED cada segundo, compartimos variables con extern y, por último, leemos un pulsador con una interrupción externa (EXTI) por flanco de subida. Todo funciona a la vez mientras el carrito sigue respondiendo.

Fase 1

El problema: código bloqueante

1.1

El carrito desde LabVIEW

▶ 0:40

El programa lee órdenes por serial y mueve el carrito, el servo y la velocidad.

1.2

Un LED que no titila

▶ 3:00

Si pones HAL_GPIO_TogglePin en el while, el LED solo cambia cuando llega una orden, porque uartx_read_text espera el dato (es bloqueante).

Una interrupción hace que el micro deje un momento lo que está haciendo, atienda otra tarea muy rápido y regrese. Así parece multitarea.

Fase 2

Interrupción por timer

2.1

Activar el TIM3

▶ 5:30

En Timers selecciona TIM3 y Clock Source en Internal Clock. No hace falta configurar canales.

2.2

Calcular prescaler y periodo

▶ 8:50

Con 16 MHz y 200 ms, busca un prescaler que deje el periodo por debajo de 65 535 (timer de 16 bits).

En la clase: prescaler 300 → periodo 10 667.

2.3

Escribir los valores

▶ 11:30

Prescaler 300-1, Counter Period 10667 y auto-reload preload en Enable para que el conteo se repita.

Prescaler (PSC)          = 300 - 1
Counter Period (ARR)     = 10667
auto-reload preload      = Enable

El periodo no puede pasar de 65 535 en un timer de 16 bits. Solo TIM2 y TIM5 son de 32 bits.

2.4

Habilitar la interrupción y su prioridad

▶ 13:20

En NVIC Settings del TIM3 marca TIM3 global interrupt.

En System Core → NVIC eliges la prioridad: 0 es la más alta y 15 la más baja. En la clase se puso 3.

Priority Group permite repartir los 4 bits entre prioridad y subprioridad; con 4 bits para prioridad no hay subprioridad.

2.5

Arrancar el timer

▶ 16:40

El timer necesita un empujón: se arranca una sola vez, antes del while.

/* USER CODE BEGIN 2 */
HAL_TIM_Base_Start_IT(&htim3);
/* USER CODE END 2 */
2.6

Código en el manejador

▶ 18:30

Abre Core/Src/stm32f4xx_it.c y busca TIM3_IRQHandler (en el Outline).

Escribe allí lo que debe hacer cada 200 ms. Una interrupción debe ser corta.

void TIM3_IRQHandler(void)
{
  /* USER CODE BEGIN TIM3_IRQn 0 */
  HAL_GPIO_TogglePin(led1_GPIO_Port, led1_Pin);
  /* USER CODE END TIM3_IRQn 0 */
  HAL_TIM_IRQHandler(&htim3);
}
2.7

Probar

▶ 19:10

El LED titila solo y el carrito sigue respondiendo a LabVIEW.

Fase 3

Más tiempos con un solo timer

3.1

Un segundo LED cada segundo

▶ 22:50

No hace falta otro timer: cuenta las interrupciones. 5 × 200 ms = 1 s.

char contador = 0;   // arriba, en stm32f4xx_it.c

// dentro de TIM3_IRQHandler
contador++;
if (contador >= 5)
{
  contador = 0;
  HAL_GPIO_TogglePin(led2_GPIO_Port, led2_Pin);
}
3.2

Resultado

▶ 23:40

Ahora hay tres procesos a la vez: LED cada 200 ms, LED cada segundo y el carrito.

3.3

Usar la variable en main.c

▶ 26:40

Para usar en main.c una variable declarada en otro archivo, decláralo con extern y el mismo tipo, sin valor inicial.

extern char contador;

El tipo debe ser igual al de la declaración original; si no, el compilador da error.

Fase 4

Interrupción externa por flanco

4.1

Por qué no leer el pulsador con el timer

▶ 29:40

Leer el pulsador dentro del timer funciona, pero cada 200 ms se pierden pulsaciones rápidas, y bajar el tiempo carga al micro. Es mejor una interrupción por flanco.

4.2

Configurar el pin como EXTI

▶ 32:10

En el pin del pulsador (PB15) elige GPIO_EXTI15 y conserva la etiqueta sw.

En GPIO elige External Interrupt Mode with Rising edge trigger detection y Pull-up.

4.3

Habilitar en el NVIC

▶ 33:00

En NVIC marca EXTI line[15:10] interrupts y dale prioridad. Esta interrupción no necesita arrancarse en el código.

4.4

Código en EXTI15_10_IRQHandler

▶ 35:30

En stm32f4xx_it.c aparece EXTI15_10_IRQHandler. Allí cambia el LED cada vez que llega un flanco.

void EXTI15_10_IRQHandler(void)
{
  /* USER CODE BEGIN EXTI15_10_IRQn 0 */
  HAL_GPIO_TogglePin(led3_GPIO_Port, led3_Pin);
  /* USER CODE END EXTI15_10_IRQn 0 */
  HAL_GPIO_EXTI_IRQHandler(sw_Pin);
}
4.5

Prueba final

▶ 35:50

Cada vez que presionas el pulsador, el LED responde enseguida, mientras los otros LEDs titilan y el carrito sigue funcionando.

Crear librerías propias en STM32CubeIDE

Una librería tiene un .c (código y variables) y un .h (cabeceras: defines y prototipos). Creamos la carpeta, la agregamos a las rutas del compilador, movemos el código desde main.c y la hacemos dinámica: el DWT solo se compila si el núcleo no es Cortex-M0 y el retardo con timer solo si existe la constante TIMX.

Fase 1

Crear la librería

1.1

Carpeta Librerias

▶ 1:08

Clic derecho en Core → New → Folder y llámala Librerias. Ahí pegas los .c y .h que ya tengas, o creas nuevos.

1.2

Archivos retardos.c y retardos.h

▶ 1:43

Clic derecho en la carpeta: New → Source File (retardos.c) y New → Header File (retardos.h).

1.3

Agregar la ruta de include

▶ 2:49

Clic derecho en el proyecto → Properties → C/C++ Build → Settings → MCU GCC Compiler → Include paths. Agrega una ruta nueva desde Workspace: Core/Librerias. Apply and Close.

1.4

Incluirla en main.c

▶ 2:16
#include "retardos.h"
Fase 2

Llenar el .c y el .h

2.1

Mover el código al .c

▶ 4:58

Corta de main.c todas las funciones de retardo y la variable pasos, y pégalas en retardos.c. El .c incluye su propio .h.

#include "retardos.h"
uint32_t pasos;
// ... delay_us_C, delay_us_ASM, delay_us_ASM_IT,
//     delayus_tim_init, delay_us_tim,
//     delay_us_dwt_init, delay_us_dwt, Delay_ms

Si una variable se usa en main.c y en la librería, declárala como extern en el .h.

2.2

El .h: guardas, main.h y prototipos

▶ 6:05

Incluye main.h (así la librería ve la HAL y los nombres de pines) y pon los prototipos de las funciones que usarás desde main. Con un #define eliges qué retardo usa delay_us:

#ifndef LIBRERIAS_RETARDOS_H_
#define LIBRERIAS_RETARDOS_H_
#include "main.h"
// DEFINE CUAL SERA USADO COMO DELAY_US
#define delay_us delay_us_dwt
#define Delay_us delay_us   // acepta mayuscula o minuscula
#define delay_ms Delay_ms
void delay_us_C(uint32_t reta);
void delay_us_ASM(uint32_t us);
void delay_us_ASM_IT(uint32_t us);
void delayus_tim_init(void);
void delay_us_tim(uint32_t us);
void delay_us_dwt_init(void);
void delay_us_dwt(uint32_t reta);
void Delay_ms(uint32_t ms);
#endif /* LIBRERIAS_RETARDOS_H_ */
Fase 3

Librería dinámica

3.1

DWT solo si no es Cortex-M0

▶ 8:22

El contador DWT no existe en los Cortex-M0. El compilador define __CORTEX_M según el micro (4 en la F401), así que se puede compilar ese código solo cuando corresponda:

#if __CORTEX_M != 0
void delay_us_dwt_init()
{
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
    DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
    pasos = HAL_RCC_GetHCLKFreq() / 1000000;  // ciclos por us
}
void delay_us_dwt(uint32_t reta)
{
    DWT->CYCCNT = 0;
    while (DWT->CYCCNT < pasos * reta);
}
#endif
3.2

Delay_ms usa el delay_us elegido

▶ 9:32
void Delay_ms(uint32_t ms)
{
    uint32_t us = ms * 1000;
    delay_us(us);   // el que fue definido en el .h
}
3.3

Timer solo si existe TIMX

▶ 10:04

Si no configuraste un timer con la constante TIMX en CubeMX, el código del timer daría error. Envuélvelo:

#ifdef TIMX
void delayus_tim_init() { TIMX->CR1 |= 1<<0; }
void delay_us_tim(uint32_t us)
{
    TIMX->CNT = 0;
    while (TIMX->CNT < us);
}
#endif

Prueba: deshabilita TIM1 y borra las constantes en CubeMX. Si en main llamas a funciones del timer, el compilador te avisa; si no, compila sin problema.

Clase 21: Multiplexación de 4 displays 7 segmentos

Cuatro displays de 8 pines serían 32 pines. Con multiplexación los segmentos A–G y DP de todos los displays se unen (8 pines) y con 4 pines más (H1–H4) se habilita uno a la vez. Si se cambia rápido, el ojo ve la palabra fija. Usamos un STM32F401 y Proteus, y vemos todas las variantes: datos con ODR o en forma atómica, habilitadores en otro puerto o en el mismo, cátodo y ánodo común, y el montaje real con transistores.

Fase 1

La idea

1.1

Algoritmo de multiplexación

▶ 0:33
  • Apagar todos los displays.
  • Sacar el dato (la letra) por el puerto de segmentos.
  • Habilitar solo el display que corresponde.
  • Esperar unos milisegundos (1 a 10 ms) y repetir con el siguiente.

Con un retardo muy corto la palabra se ve opaca; con uno largo (500 ms) se ven las letras una por una.

Fase 2

Configuración

2.1

Pines

▶ 1:39
  • PB0–PB7 como salida para los segmentos A–G y DP; al primero ponle la etiqueta display.
  • 4 pines de otro puerto (PA12, PA11, PA10, PA9) como salida con las etiquetas H1, H2, H3, H4 (los nombres importan).
2.2

Defines y procedimientos base

▶ 2:44

Con #define se elige si los datos salen por ODR o en forma atómica, y el registro de los habilitadores. display_dato carga el byte en forma atómica: deja solo los 8 bits bajos y pone en 0 los demás con la parte alta de BSRR.

#define display  GPIOB->ODR    // datos por registro ODR
#define habilita GPIOA->BSRR   // habilitadores en forma atómica

void display_dato(uint32_t dato)
{
  dato = dato & 0x000000ff;          // toma solo la parte baja
  GPIOB->BSRR = dato | (~dato << 16);
}

void apagatodo()
{
  habilita = H1_Pin | H2_Pin | H3_Pin | H4_Pin;   // CÁTODO: se apaga con 1
  // habilita = (H1_Pin|H2_Pin|H3_Pin|H4_Pin) << 16;  // ÁNODO: se apaga con 0
}
Fase 3

Mostrar HOLA (cátodo común)

3.1

Con ODR

▶ 4:28

En el while(1) se llama catodo_ODR();.

void catodo_ODR()
{
  apagatodo();
  display = 0x76;            // H
  habilita = H1_Pin << 16;   // habilita con 0
  HAL_Delay(5);

  apagatodo();
  display = 0x3F;            // O
  habilita = H2_Pin << 16;
  HAL_Delay(5);

  apagatodo();
  display = 0x38;            // L
  habilita = H3_Pin << 16;
  HAL_Delay(5);

  apagatodo();
  display = 0x77;            // A
  habilita = H4_Pin << 16;
  HAL_Delay(5);
}
3.2

En forma atómica

▶ 5:34

Es igual, pero el dato sale con display_dato(0x76); en vez de escribir ODR. Así no se alteran los otros pines del puerto. Es la forma recomendada.

Fase 4

Habilitadores en el mismo puerto

4.1

Mover H1–H4 al puerto B

▶ 8:18

Si los habilitadores pasan a PB15, PB11, PB13 y PB12 (mismo puerto que los datos), la versión anterior deja de funcionar: al habilitar uno con 0 hay que dejar explícitamente los otros en 1.

apagatodo();
display_dato(0x76);   // H
habilita = H1_Pin << 16 | (H2_Pin | H3_Pin | H4_Pin);
HAL_Delay(5);
4.2

Llamarlo

▶ 10:00
while (1)
{
  catodo_ATO_port();
}

Esta versión funciona tanto si los habilitadores están en otro puerto como en el mismo.

Fase 5

Montaje real y ánodo común

5.1

Transistores en los comunes

▶ 10:35

En la vida real el pin del micro no aguanta la corriente de todo un display. Cada habilitador (H1M…H4M) va por una resistencia de 220 Ω a la base de un transistor 2N3904; el colector (con 10 kΩ a positivo, necesaria en Proteus) va al común del display. Además, cada segmento lleva su resistencia (220 Ω) para no quemar el pin.

5.2

La lógica se invierte

▶ 12:53

Con el transistor, un 1 en el pin pone un 0 en el común: ahora se apaga con 0 y se habilita con 1, sin tocar los demás. Por eso hay un procedimiento aparte para el montaje real (catodo_ATO_port_REAL).

apagatodo();   // ahora apaga con 0
display_dato(0x76);
habilita = H1_Pin;   // habilita con 1
HAL_Delay(5);
5.3

Display de ánodo común

▶ 16:58

En ánodo común los segmentos encienden con 0 (el código de cada letra se invierte con ~) y los comunes se habilitan con 1. Con los procedimientos anodo_ODR, anodo_ATO y anodo_ATO_port se prueba cada caso.

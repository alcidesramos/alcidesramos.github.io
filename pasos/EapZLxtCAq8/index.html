Procedimientos en C

Séptima lección del curso. Con un PIC16F877A, LEDs en el puerto B, un display de 7 segmentos en el puerto D y un parlante, se crean procedimientos sin parámetros: uno que escribe HOLA en el display, dos melodías, una cuenta regresiva y un efecto de luces. Se muestra que un procedimiento no hace nada si no se llama, que llamarlo varias veces ahorra memoria frente a copiar el código, cómo usar el prototipo cuando el procedimiento está debajo del main y que un procedimiento puede llamar a otro solo si este ya fue declarado antes.

Fase 1

Preparar el proyecto

1.1

Circuito y proyecto nuevo

▶ 0:00

El circuito de prueba tiene LEDs en el puerto B, un parlante para melodías y un display para letras y números en el puerto D. Se crea el proyecto procedimientos en la carpeta clase 7, con el PIC16F877A a 4 MHz (XT), y se ponen nombres a los puertos.

#define luces PORTB
#define display PORTD
1.2

Librería de sonido

▶ 2:48

Se activa la librería Sound en el Library Manager, como en la lección anterior, y se indica el pin del parlante (RC6).

Fase 2

Crear y llamar procedimientos

2.1

Escribir el procedimiento hola()

▶ 3:23

Un procedimiento se declara con void, un nombre y paréntesis vacíos (por ahora sin parámetros). Por ahora se escribe arriba del main. Los códigos de cada letra se sacan con el Seven Segment Editor de MikroC: H = 118, O = 63, L = 56, A = 119.

void hola() {
  display = 118;  Delay_ms(300);   // H
  display = 63;   Delay_ms(300);   // O
  display = 56;   Delay_ms(300);   // L
  display = 119;  Delay_ms(300);   // A
  display = 0;    Delay_ms(300);   // apagado
}
2.2

Si no se llama, no se ejecuta

▶ 5:40

El micro siempre empieza por el main. Si un procedimiento no se llama, no hace nada. Para llamarlo se escribe su nombre con paréntesis y punto y coma; con Ctrl + espacio MikroC lo muestra en la lista.

while (1) {
  hola();
  hola();
}
2.3

Por qué usar procedimientos

▶ 7:55

Organizan el código con nombres que se entienden y ahorran memoria: si se llama tres veces, el micro va al mismo código y regresa, en vez de tener tres copias. Así se crean también melodia1() y melodia2() con Sound_Play.

2.4

Cuenta regresiva baja()

▶ 8:27

Se crea baja(), que muestra 5, 4, 3, 2, 1 y 0 en el display (109, 102, 79, 91, 6 y 63).

2.5

Reemplazar solo en la selección

▶ 11:18

Para hacer más lenta la cuenta se seleccionan las líneas y con Edit > Replace se cambia Delay_ms(300) por Delay_ms(500) marcando Selected text only, para no tocar el resto del programa.

2.6

Efecto de luces

▶ 12:55

Se agrega efecto1(), que alterna los LEDs del puerto B, y se llama las veces que haga falta. En el Code Explorer aparecen todos los procedimientos y con doble clic se va a cada uno.

Fase 3

Procedimientos debajo del main

3.1

Declarar el prototipo

▶ 15:13

Si el procedimiento se escribe debajo del main, el compilador da error de identificador no declarado. Hay que poner arriba su prototipo: la misma línea con punto y coma. No es un llamado, solo avisa que existe.

void melodia1();   // prototipo

void main() {
  ...
  melodia1();
}

void melodia1() {
  ...
}
3.2

Un procedimiento que llama a otro

▶ 16:53

Un procedimiento puede llamar a otro, por ejemplo baja() puede empezar llamando a hola(). El que se llama tiene que estar escrito o declarado más arriba en el código.

Si se llama un procedimiento que está más abajo y sin prototipo, el compilador marca error.

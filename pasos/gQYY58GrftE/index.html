Conceptos básicos: compilador, firmware, bootloader y debugger

El vocabulario que se usa en todo el curso. Cómo se organiza la memoria de un micro, cómo pasamos de un lenguaje que entendemos a los ceros y unos que guarda la Flash, y qué papel juegan el compilador, el programador o quemador, el bootloader y el depurador.

Fase 1

Memorias del micro

1.1

Programa y datos

▶ 0:00
  • Memoria de programa: Flash, no volátil; ahí queda el programa aunque se quite la energía.
  • Memoria de datos: RAM, para lo que se procesa en el momento (temperaturas, cálculos…).
  • Algunos micros traen una pequeña EEPROM para datos que no se deben perder (por ejemplo una clave que el usuario cambió). Otros no la tienen y hay que usar parte de la Flash o una memoria externa.
Fase 2

Del código a la Flash

2.1

Niveles de lenguaje

▶ 1:04
  • Código máquina: los ceros y unos que entiende el micro (antes se programaba con códigos en hexadecimal).
  • Ensamblador: instrucciones como ADD A,B o MOV A,40. Muy poderoso, pero lento de desarrollar y distinto para cada familia.
  • Alto nivel: BASIC, Pascal, C/C++ y ahora MicroPython.
  • Sistema operativo (RTOS): ya cargado en el micro; se programa encima de él.
2.2

Compilar

▶ 2:42

Pasar de un lenguaje de nivel superior a código máquina se llama compilar. El software del PC con el que se programa (STM32CubeIDE, Keil, etc.) se llama compilador, no programador. El resultado es un archivo .hex o .bin que va a la Flash.

MicroPython es distinto: es un intérprete ya instalado en el micro.

2.3

Firmware

▶ 4:24

Es el código en lenguaje máquina, el programa guardado en la memoria de programa del micro. Es tu idea, y conviene protegerlo para que no la copien; en el curso veremos cómo.

Fase 3

Cargar y depurar

3.1

Quemador o programador

▶ 4:57

Para pasar el .hex al micro se necesita un hardware programador (quemador) y su software. A veces el software viene dentro del compilador si es de la misma empresa. Compilador, programador y micro deben ser coherentes entre sí.

3.2

Bootloader (gestor de arranque)

▶ 6:02

Es un firmware o preprograma en el micro que le permite programarse a sí mismo, sin programador externo (como Arduino).

  • Si lo grabas tú una vez, ocupa espacio de la memoria de programa.
  • Los STM32 traen uno de fábrica en una memoria aparte (no ocupa espacio) por serial, USB, SPI, I2C…
  • Con bootloader normalmente no hay depuración: para eso hace falta el programador.
3.3

Debugger (depurador)

▶ 8:09

Permite correr el programa paso a paso y ver variables, registros del micro, funciones y timers, para encontrar errores u optimizar el código. Normalmente es por hardware, con el mismo programador (ST-Link). También existe por software: por ejemplo en Proteus se depura sin tener el micro conectado.

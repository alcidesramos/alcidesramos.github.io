Tipos de variables en C con STM32CubeIDE

Cada compilador puede cambiar el tamaño de algunos tipos (en STM32CubeIDE el long es de 4 bytes y el long double de 8). Para no depender de eso, C trae la librería stdint.h con tipos de tamaño fijo. En el video declaramos variables de todos los tipos, vemos en el Build Analyzer cuántos bytes ocupa cada una, y con el depurador comprobamos qué pasa al poner un valor fuera de rango. La regla: declarar cada variable según el rango máximo que va a tener, ni más (gasta memoria y tiempo) ni menos (se desborda).

Fase 1

La tabla de tipos

1.1

Enteros: C clásico vs stdint.h

▶ 0:00
  • bool (stdbool.h): 0 o 1, pero ocupa 1 byte.
  • unsigned char / uint8_t: 0 a 255 · signed char / int8_t: −128 a 127.
  • unsigned short / uint16_t: 0 a 65 535 · short / int16_t: −32 768 a 32 767.
  • unsigned int / uint32_t: 0 a 4 294 967 295 · int / int32_t: ±2 147 483 647.
  • long: en C debería ser de 8 bytes, pero en CubeIDE es de 4. Para 8 bytes usa uint64_t / int64_t.

Con uint8_t, int16_t, uint32_t… sabes siempre el tamaño exacto, sin importar el compilador.

1.2

Flotantes

▶ 16:32
  • float: 4 bytes, ~7 decimales de precisión.
  • double: 8 bytes, ~15 decimales.
  • long double: en C son 16 bytes y ~19 decimales, pero en CubeIDE se comporta como double (8 bytes).
Fase 2

Declarar y medir

2.1

Incluir las librerías

▶ 2:12

En main.c, dentro de USER CODE BEGIN Includes:

#include <stdint.h>
#include <stdbool.h>
2.2

Variables globales

▶ 2:46

Se declaran en USER CODE BEGIN PV (Private variables): tipo, nombre y opcionalmente un valor. Varias del mismo tipo se separan con coma.

bool bit1 = true, bit2;
unsigned char charn = 45;   // o uint8_t
signed char   chars = -6;   // o int8_t
unsigned short shortn = 525; // o uint16_t
unsigned int  intn = 100000; // o uint32_t
uint64_t      unit64n = 10;
float  nota;
double doublen;
2.3

Usarlas para que existan

▶ 4:26

Si una variable no se usa, el compilador la elimina y no aparece en memoria. Para la prueba las incrementamos dentro del while(1):

charn++;
shortn++;
intn++;
unit64n++;
nota++;
2.4

Ver el tamaño en el Build Analyzer

▶ 5:33

Tras compilar, en Build Analyzer → Memory Details → RAM → .data / .bss aparece cada variable con su tamaño. Ahí se confirma: bool 1 B, char 1 B, short 2 B, int y long 4 B, uint64_t 8 B, float 4 B, double y long double 8 B.

Fase 3

Elegir bien el tipo

3.1

Según el rango máximo

▶ 10:28
  • Encender/apagar una luz → bool.
  • Alumnos en un salón (menos de 255) → uint8_t.
  • Temperatura con negativos pequeños → int8_t.
  • Lo que gasta un alumno en pasaje (miles de pesos) → uint16_t.
  • Una noche de rumba (cientos de miles) → uint32_t.
  • Lo que quisiera tener en el banco (miles de millones) → uint64_t.
3.2

Comprobarlo con el depurador

▶ 13:47
  • Run → Debug Configurations: en Debugger escanea el ST-Link la primera vez.
  • Inicia el Debug (bicho verde) y en Expressions agrega las variables.
  • bool: si escribes 89 lo toma como true (todo lo distinto de 0 es verdadero).
  • uint8_t con 200: bien. Con 300: se desborda y muestra otro valor (300 − 256 = 44).
3.3

Por qué importa

▶ 16:00

Una variable muy pequeña se desborda y da valores erróneos. Una muy grande gasta memoria y además el micro tarda más en sumar, multiplicar o calcular un seno con 8 bytes que con 1.

Usa float solo cuando necesites decimales: aunque ocupa 4 bytes como un int, las operaciones en flotante son mucho más lentas. Y nunca compares flotantes con ==; usa rangos (temp > 25.4 && temp < 25.6).

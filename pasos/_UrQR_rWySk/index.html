Tips para transmitir por UART

Lección 27 del curso. Primero se explica la trama serial: bit de inicio, 8 bits de datos, paridad opcional y bit de parada, y por qué la velocidad se mide en baudios. Luego, con un PIC16F877A a 8 MHz, se inicializa el UART a 9600 baudios y se envían a un Virtual Terminal el voltaje de un potenciómetro y la temperatura de un LM35, terminando cada línea con \r\n. Se muestra que UART1_Write_Text recibe un puntero a variable, así que para textos fijos conviene una función con const char que gasta menos RAM. Por último se pasa el programa a un PIC18F2550, donde sprintf deja mandar flotantes en una línea, y se envían los datos a un programa del PC por un puerto serial virtual.

Fase 1

El puerto serial

1.1

La trama

▶ 0:00

Cada dato viaja en una trama: un bit de inicio (start), 8 bits de datos, un bit de paridad opcional que cuenta los unos, y un bit de parada (stop) que puede durar 1, 1.5 o 2 bits. Lo más común es 1 start, 8 datos y 1 stop: 10 bits como mínimo. Como la trama varía, la velocidad se mide en baudios y no en bytes por segundo.

1.2

RS232 y TTL

▶ 3:19

El RS232 del PC trabaja con +12 V y -12 V, y antes se necesitaba un MAX232 para hablar con el micro. En el PIC los pines son RC6 (TX) y RC7 (RX) y trabajan a niveles del micro (5 V o 3.3 V).

Fase 2

UART en el 16F877A

2.1

Iniciar y enviar

▶ 4:26

Proyecto con un PIC16F877A a 8 MHz con Power-up Timer. Se inicia el UART con la velocidad, UART1_Write manda un carácter y UART1_Write_Text manda un texto.

TRISC6_bit = 0;   // salida TX
TRISC7_bit = 1;   // entrada RX
UART1_Init(9600);
UART1_Write_Text("INICIANDO\r\n");
2.2

Virtual Terminal

▶ 6:41

En Proteus se pone un Virtual Terminal cruzado: TX del micro con RX del terminal. Se le pone la misma velocidad, 9600; si no coinciden la velocidad o el cristal, salen caracteres raros.

2.3

Saltos de línea

▶ 8:55

Para que cada dato quede en una línea nueva se termina el texto con \r\n (retorno de carro y nueva línea).

2.4

Voltaje y temperatura

▶ 10:01

Se configuran AN0 y AN1 como análogos con ADCON1 (lección 19). El voltaje se convierte con float_to_str_ y se manda por partes; la temperatura entera se arma en una línea con sprinti.

ADCON1 = 0b0100;   // 3 análogos en el 16F877A
TRISA0_bit = 1;
TRISA1_bit = 1;

codigo = ADC_Read(0);
voltaje = codigo * 5.0 / 1023.0;
floattostr_(voltaje, texto, 2);
UART1_Write_Text("Voltaje=");
UART1_Write_Text(texto);
UART1_Write_Text(" V\r\n");

codigo = ADC_Read(1);
temperatura = codigo * 500.0 / 1023.0;
sprinti(texto, "Temperatura=%u \r\n", temperatura);
UART1_Write_Text(texto);
Fase 3

Ahorrar memoria

3.1

Write_Text usa un puntero a variable

▶ 17:46

En la ayuda se ve que UART1_Write_Text recibe un char *, un puntero a variable. Si se le pasa un texto fijo, el compilador lo copia a RAM, gasta más memoria y en los 16F con bancos puede causar errores.

3.2

Una función para constantes

▶ 18:49

Para textos fijos se usa una función que recibe un puntero a constante y manda carácter por carácter. Así el texto se queda en la memoria de programa.

void Uart1_write_text_const(const char *info)
{
  while (*info) UART1_Write(*info++);
}

Uart1_write_text_const("Voltaje=");
UART1_Write_Text(texto);   // variable
Uart1_write_text_const(" V\r\n");

Use la función con const para textos fijos y UART1_Write_Text para variables. Compare el uso de memoria en View > Statistics.

Fase 4

UART en el 18F2550

4.1

Cambiar de micro

▶ 22:07

El programa pasa al PIC18F2550 cambiando ADCON1 a 0b1101 para tener AN0 y AN1 análogos. Los 18F tienen memoria lineal, sin bancos, y dan menos problemas con Write_Text, pero se recomienda la función con const por buena costumbre.

ADCON1 = 0b1101;   // 2 análogos en el 18F2550
4.2

sprintf con flotantes

▶ 24:24

En los 18F, sprintf acepta flotantes, así que cada dato se arma y se manda en una línea. En un 16F solo hay sprinti para enteros.

sprintf(texto, "Voltaje=%4.2f V\r\n", voltaje);
UART1_Write_Text(texto);

codigo = ADC_Read(1);
temperatura = codigo * 500.0 / 1023.0;
sprintf(texto, "Temperatura=%4.1f \r\n", temperatura);
UART1_Write_Text(texto);
4.3

Enviar al PC

▶ 27:39

Para recibir los datos en un programa del PC se usa el componente COMPIM de Proteus con el puerto COM y 9600 baudios. Para simular se crea un par de puertos seriales virtuales con un emulador y se abre el otro puerto en una terminal como Hercules. Desde ahí se pueden graficar en LabVIEW u otro programa.

Lo básico de STM32CubeMX

Recorrido por STM32CubeMX antes de empezar a programar: cómo buscar el micro por núcleo, paquete o nombre, iniciar desde una tarjeta o un ejemplo, comparar con micros de otras marcas, configurar pines y periféricos, y pasar un proyecto a otro micro compatible.

Fase 1

HAL y registros

1.1

Cuándo usar la HAL y cuándo los registros

▶ 0:35

La configuración inicial se ejecuta una sola vez, fuera del while(1), y para eso la HAL que genera CubeMX es adecuada. Cuando algo necesita velocidad, como un protocolo 1-Wire o un sensor que cambia el pin de entrada a salida muy rápido, se configuran los registros. Para USB o Ethernet, en cambio, conviene la librería. Hay que saber ambas cosas.

Fase 2

Crear un proyecto

2.1

Tres formas de empezar

▶ 2:15

En la pantalla de inicio: desde un micro (MCU Selector), desde una tarjeta de ST (Board Selector) o desde un ejemplo (Example Selector). En Help hay tutoriales y videos.

2.2

Buscar el micro por filtros

▶ 2:47

Se puede filtrar por núcleo (M0, M3, M4…), por paquete (TSSOP20, LQFP48…) o escribir el nombre, por ejemplo STM32F103C8. Escoge el mismo paquete que tiene tu micro.

2.3

Desde una tarjeta o un ejemplo

▶ 4:26

Al escoger una tarjeta Nucleo, CubeMX carga los pines ya configurados (botón, LED, etc.). Con el Example Selector se abre un ejemplo para esa tarjeta y se adapta el código.

2.4

Cross Selector: comparar con otras marcas

▶ 5:33

Escribes un micro de Microchip, Texas Instruments o NXP y te muestra los STM32 más parecidos, con el porcentaje de coincidencia y la comparación de memoria, núcleo, ADC y timers.

Fase 3

Configurar pines

3.1

Cristal y pines de salida

▶ 6:42

En RCC, si la tarjeta tiene cristal, se escoge Crystal/Ceramic Resonator y aparecen ocupados los pines OSC. Luego, clic sobre un pin (por ejemplo PA10) y GPIO_Output. También puedes buscar el pin con el buscador de abajo.

3.2

Remapear periféricos (Ctrl + clic)

▶ 8:30

Con Ctrl presionado y clic sobre un pin, CubeMX muestra a dónde se puede mover esa función. Al activar USART1 en modo asíncrono, usa PA9/PA10. Si ahí había un GPIO, lo borra.

Ojo: al remapear o activar un periférico, CubeMX puede borrar pines que ya habías configurado.

3.3

Fijar un pin (Signal Pinning)

▶ 9:46

Clic derecho sobre el pin → Signal Pinning (aparece un pin de alfiler). Un pin fijado se respeta: CubeMX no lo mueve y te avisa si un periférico no cabe. Sin fijar, CubeMX mueve tu GPIO a otro pin para hacer espacio. En el menú Pinout está Keep Current Signals Placement, que conserva lo que ya está.

3.4

Configurar cada GPIO

▶ 11:29

En System Core → GPIO se escoge para cada pin el nivel inicial, el modo (push-pull u open drain), pull-up/pull-down y la velocidad. Al pasar el mouse sobre un periférico aparecen enlaces a su documentación.

3.5

Etiquetas con aclaración entre corchetes

▶ 15:51

Clic derecho → Enter User Label. Si escribes LED1[MOTOR], en el código el pin se llama LED1, pero en CubeMX ves qué maneja.

Fase 4

Cambiar de micro

4.1

List Pinout Compatible MCUs

▶ 12:34

En Pinout → List Pinout Compatible MCUs aparece la lista de micros a los que puedes pasar el proyecto: Full compatible o HW compatible. Se pueden ignorar los pines fijados, de potencia o de sistema. Doble clic y el proyecto pasa al otro micro.

4.2

Importar un proyecto a un micro muy distinto

▶ 14:13

Para un cambio grande, por ejemplo de un F103 a un Cortex-M0 de 20 pines: crea un proyecto vacío con el micro nuevo y usa File → Import Project. Trae los pines y periféricos que se puedan y avisa qué no (por ejemplo, el reloj).

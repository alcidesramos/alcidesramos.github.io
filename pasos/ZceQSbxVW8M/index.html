Servidor web con ENC28J60

El ENC28J60 es un módulo Ethernet económico que se comunica por SPI. Con la librería de MikroC se arma un servidor que responde peticiones en el puerto 80. La página se diseña en un editor HTML (KompoZer), se pasa a cadenas de C y se guarda en el micro. Para no recargar toda la página, un script pide solo las variables (temperatura, voltaje, pulsadores) y los enlaces mandan órdenes como led1=on. Luego se hace lo mismo en Arduino, guardando las cadenas en la memoria de programa.

  • Módulo ENC28J60
  • MikroC PRO for PIC con la librería SPI_Ethernet y PIC18F25K20 a 32 MHz

Fase 1

Proyecto

1.1

El módulo

▶ 0:01

El servidor queda dentro del micro: desde un navegador en la red se ve la página y se controlan salidas. El ENC28J60 se conecta por SPI (SCK, MOSI, MISO) más CS y RST, que pueden ir en cualquier pin.

1.2

Variables y pines

▶ 9:22

Se definen las cabeceras HTTP, las variables de voltaje y temperatura, las tramas de recepción y envío, los pulsadores en RB0 y RB1 y los leds en RB6 y RB7.

const char httpHeader[] = "HTTP/1.1 200 OK\nContent-type: ";
const char httpMimeTypeHTML[] = "text/html\n\n";
const char httpMimeTypeScript[] = "text/plain\n\n";
unsigned codigo;
float temperatura, voltaje;
char trama_rx[30];
char trama_tx[30];
1.3

MAC e IP

▶ 15:05

Se le da al módulo una MAC y una IP fija acorde a la red (en el ejemplo 192.168.0.37), además de la puerta de enlace y la máscara.

1.4

Iniciar

▶ 18:22

Pulsadores como entrada con pull-up, leds como salida, serial a 115200 para depurar, SPI y luego SPI_Ethernet_Init con la MAC, la IP y modo full duplex. En el ciclo principal se leen voltaje y temperatura y se llama SPI_Ethernet_doPacket.

UART1_Init(115200);
UART1_Write_Text("OK INICIANDO\r\n");
SPI1_Init();
SPI_Ethernet_Init(myMacAddr, myIpAddr, Spi_Ethernet_FULLDUPLEX);
Fase 2

Atender peticiones

2.1

SPI_Ethernet_UserTCP

▶ 22:21

La librería llama esta función cuando llega una petición TCP. Solo se atiende el puerto 80 y se leen los primeros 30 bytes, suficientes para saber qué pide el navegador.

if (localPort != 80) return 0;
for (cuent = 0; cuent < 30; cuent++)
  trama_rx[cuent] = SPI_Ethernet_getByte();
trama_rx[cuent] = 0;
if (memcmp(trama_rx, "GET /", 5)) return 0;  // solo GET
2.2

Probar la conexión

▶ 26:12

Al conectarse desde el navegador, la terminal muestra la petición GET que llegó. Hay que esperar a que el módulo esté listo (led verde) antes de probar.

Fase 3

La página

3.1

Diseñarla

▶ 27:55

La página se arma en un editor visual como KompoZer (gratis): título, una tabla con voltaje, temperatura y pulsadores, y enlaces ENCENDER y APAGAR para cada led que apuntan a led1=on, led1=off, etc.

3.2

Pasarla a C

▶ 36:25

El HTML se copia a Notepad++, se quitan las líneas vacías, se agrega una barra invertida al final de cada línea y se ajustan las comillas para que todo quede como una cadena constante de C.

3.3

Actualizar solo los datos

▶ 45:53

La cabecera de la página se recarga cada 3 segundos y pide un script en /$. Cuando el micro ve el '$' responde solo con las variables en JavaScript y la página las escribe con document.write. Así no se manda toda la página cada vez.

<meta http-equiv="refresh" content="3;url=http://192.168.0.37">
<script src=/$></script>
...
<script>document.write(volt)</script>
3.4

Responder variables u órdenes

▶ 47:05

Si trama_rx[5] es '$' se manda la cabecera de script y las variables (voltaje y temperatura con dos decimales, y pul1/pul2 en ON u OFF). Si no, se buscan órdenes como led1=on en la trama y se manda la página.

3.5

Partir la página

▶ 57:51

El buffer del módulo es limitado, así que la página se divide en pagina1 y pagina2 y se envían por partes.

Fase 4

En Arduino

4.1

UIPEthernet

▶ 61:07

Se instala la librería UIPEthernet, se define la MAC, la IP y un servidor en el puerto 80. El programa sigue la misma lógica: leer 30 bytes, revisar si pide $ o una orden, y responder.

byte mac[] = { 0xDE, 0xAD, 0xBE, 0xEF, 0xFE, 0xED };
IPAddress ip(192, 168, 0, 37);
EthernetServer server(80);
4.2

Órdenes

▶ 67:51

Los pulsadores se mandan como variables de JavaScript y las órdenes se buscan con strstr, igual que en el PIC.

if (digitalRead(pulsador2) == 0) client.print("var pul2=\"ON\";");
else client.print("var pul2=\"OFF\";");

if (strstr(trama_rx, "led1=")) {
  if (strstr(trama_rx, "on")) digitalWrite(led_amarillo, HIGH);
  else digitalWrite(led_amarillo, LOW);
}
4.3

Memoria RAM llena

▶ 69:30

Con las páginas como variables globales se llena la RAM del Arduino. Se guardan en la memoria de programa con PROGMEM y se mandan con un macro que usa __FlashStringHelper.

#define mandame(x) (__FlashStringHelper*)(x)
...
client.print(mandame(pagina1));
4.4

Prueba

▶ 74:12

La página muestra voltaje, temperatura y pulsadores actualizados, y los enlaces encienden y apagan los leds.

Controlador difuso en un PIC

Con los datos del PID se ven los rangos: el error va de -1500 a 1500 y su cambio de unos -20 a 20. En Xfuzzy se definen las dos entradas con cinco conjuntos triangulares (muy negativo a muy positivo) y la salida PWM con cinco valores (mínimo a máximo). Las reglas se llenan en forma de matriz pensando qué hacer en cada caso y se revisa la superficie de control. Xfuzzy genera controlador.c y controlador.h, que se agregan al proyecto en lugar de la función pid.

▶ Ver el video completo (42:16) Empezar el paso a paso
  • Xfuzzy 3.5 (requiere Java)
  • MikroC PRO for PIC
  • PIC18F2550 a 20 MHz
  • Proteus con el horno del video del PID
  • Excel para revisar los datos

Fase 1

Los datos

1.1

La planta

▶ 0:00

Es el mismo circuito del PID: horno, transistor, potenciómetro de set point, LCD y PIC18F2550 con USB.

1.2

Rangos del error

▶ 2:00

Con los datos guardados de la planta se calculan el error (set point menos salida) y el cambio del error entre muestras. Así se ve que el error va hasta ±1500 y el cambio ronda ±20.

Fase 2

Diseño en Xfuzzy

2.1

Sistema y operadores

▶ 5:00

Xfuzzy se abre con xfuzzy.bat. Se crea el sistema controlador y un conjunto de operadores (and, or, implicación, defuzzificación).

2.2

Entrada error

▶ 7:20

El tipo T_error va de -1500 a 1500 con cardinalidad 256 y una familia de cinco funciones triangulares: muynegativo, negativo, cero, positivo y muypositivo. Los parámetros de cada triángulo se ajustan a mano.

2.3

Entrada cambio del error

▶ 14:30

T_Cambio_e va de -20 a 20 con los mismos cinco conjuntos.

2.4

Salida PWM

▶ 16:20

T_pwm va de 0 a 255 con cinco singletons: mínimo, bajo, medio (127.5), alto y máximo.

2.5

Reglas

▶ 18:20

En Rulebase Edition, forma de matriz, cada cruce de error y cambio del error lleva una salida. Por ejemplo, error muy positivo (la temperatura está muy por debajo) da PWM máximo; si el error es negativo, PWM mínimo.

2.6

Superficie de control

▶ 23:52

Xfplot dibuja la salida PWM contra las dos entradas para revisar que el controlador sea suave y vaya en la dirección correcta.

Fase 3

En el PIC

3.1

Proyecto base

▶ 25:40

Se parte del proyecto del PID: lectura de temperatura y set point, LCD y PWM.

3.2

Generar el código

▶ 28:20

En Synthesis se genera código C: controlador.c y controlador.h. Se copian a la carpeta del proyecto y se agregan en MikroC. El código evalúa las funciones de pertenencia y las reglas.

3.3

Usar el controlador

▶ 31:03

En vez de llamar pid, se calcula el error y su cambio, se llama controladorInferenceEngine con esas entradas y la salida va al PWM.

3.4

Prueba

▶ 34:39

La temperatura sigue al set point. Moviendo los conjuntos o las reglas en Xfuzzy y generando de nuevo se puede mejorar la respuesta.

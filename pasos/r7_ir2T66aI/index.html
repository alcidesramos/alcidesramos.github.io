Motores paso a paso con Arduino y LabVIEW

Dos motores paso a paso se mueven con un Arduino Uno y se mandan órdenes desde una interfaz en LabVIEW: dirección, modo continuo o por pasos, número de pasos y velocidad de 0 a 255. Las variables, las secuencias, las funciones de derecha e izquierda y el procesamiento de la trama se copian casi iguales del programa de MikroC. Lo que cambia: los pines se definen con #define, cada bobina se escribe con digitalWrite según el bit de la secuencia, la interrupción del timer usa el Timer1 (el Timer0 lo usan millis y micros) y la recepción serial usa serialEvent. Ojo: al usar el Timer1 se pierden el PWM de los pines 9 y 10 y la librería Servo.

1.1

El circuito

▶ 0:00

En Proteus hay un Arduino Uno con dos motores paso a paso, un LED en el pin 2 y el puerto serial conectado a la interfaz. La idea es pasar el programa de MikroC a Arduino usando que los dos son C estándar.

1.2

Librería del Timer1 y macros

▶ 0:36

Se incluye la librería TimerOne (se descarga de internet). No se usa el Timer0 como en el PIC porque en Arduino lo usan millis, micros y delay.

Ojo: con el Timer1 ya no se puede usar PWM en los pines 9 y 10 ni la librería Servo (ver el video de conflictos de librerías).

Se pegan las macros para poner, borrar, invertir y preguntar por un bit.

#include "TimerOne.h"

#define sbi(x, y) x |= _BV(y)    // set bit
#define cbi(x, y) x &= ~(_BV(y)) // clear bit
#define tbi(x, y) x ^= _BV(y)    // toggle bit
#define is_high(x, y) ((x & _BV(y)) == _BV(y))

Secuencias y variables

Fase 2

Lo que cambia en Arduino

2.1

Sacar la secuencia

▶ 5:05

En MikroC se le asignaba a cada pin el bit de la secuencia directamente. En Arduino eso no se puede: se pregunta si el bit está en alto y se escribe un 1 o un 0 en la bobina con digitalWrite. El bit 0 va a la bobina 1, el bit 1 a la bobina 2, y así.

void saca_secuencia1()
{
  pasos1++;
  if (is_high(codigo1[secuencia1], 0)) digitalWrite(m11,1); else digitalWrite(m11,0);
  if (is_high(codigo1[secuencia1], 1)) digitalWrite(m12,1); else digitalWrite(m12,0);
  if (is_high(codigo1[secuencia1], 2)) digitalWrite(m13,1); else digitalWrite(m13,0);
  if (is_high(codigo1[secuencia1], 3)) digitalWrite(m14,1); else digitalWrite(m14,0);
}
// saca_secuencia2() es igual con codigo2, secuencia2 y m21..m24
2.2

Derecha, izquierda y procesar

▶ 6:05

Las funciones de derecha, izquierda y la que procesa la trama se copian tal cual de MikroC y compilan sin cambios.

void derecha1()
{
  secuencia1++;
  if (secuencia1>n_pasos) secuencia1=0;
  saca_secuencia1();
}

void izquierda1()
{
  secuencia1--;
  if (secuencia1<0) secuencia1=n_pasos;
  saca_secuencia1();
}
// derecha2() e izquierda2() igual con secuencia2
2.3

Setup

▶ 6:39

Los pines de los motores y el del LED van como salida, el serial a 9600 y se envía «Iniciando» para comprobar la comunicación. Al simular en Proteus aparece la palabra en el terminal.

Los dos motores arrancan a la derecha en modo continuo con velocidad 180. El Timer1 se configura para interrumpir cada 10 ms (en el PIC eran unos 8,3 ms).

void setup()
{
  pinMode(m11,OUTPUT);
  // ... m12 a m24 igual
  pinMode(2,OUTPUT);//salida el led

  Serial.begin(9600);
  Serial.println("Iniciando");

  estado_giro1=derecha;
  estado_giro2=derecha;
  estado_modo1=continuo;
  estado_modo2=continuo;
  velo_m1=180;
  velo_m2=180;

  Timer1.initialize(10000); // que se interrumpa cada 10.000 microsegundos o sea 10ms
  Timer1.attachInterrupt( interrupcion_timer ); // attach the service routine here
  digitalWrite(2,0);
}

Interrupción del timer

▶ 8:53

Se crea la función interrupcion_timer arriba del setup y adentro se pega el código de la interrupción de MikroC (solo el código, no la parte de limpiar banderas, que en Arduino la hace la librería).

2.5

Interrupción serial

▶ 9:57

En Arduino la recepción serial ya tiene su función, serialEvent. Va guardando cada dato en trama_rx; si pasa de 30 reinicia el puntero, y cuando llega el asterisco activa la bandera de trama válida.

void serialEvent()
{
  while (Serial.available())
  {
    datorx= (char)Serial.read();
    trama_rx[puntero]=datorx;
    puntero++;
    if (puntero>=30)
    {
      puntero=0;
    }
    if (datorx== '*')
    {
      flag_rx=1;
    }
  }
}
2.6

El loop

▶ 11:03

Si hay trama válida la procesa y limpia la bandera, el puntero y el vector. Además hace titilar el LED del pin 2 cada medio segundo invirtiendo el bit del puerto D.

void loop()
{
  if (flag_rx==1)
  {
    procesarx();
    flag_rx=0;// borra la bandera
    puntero=0;  //reseta contador de datos
    memset(trama_rx,0,30);  // borra el vector de datos recibidos en la trama
  }
  //pone a titilar el led
  tbi(PORTD, 2);
  delay(500);
}
Fase 3

Prueba con LabVIEW

3.1

Corregir el sentido

▶ 12:20

Al correr, los motores se mueven, pero al pedir derecha giran a la izquierda. Si pasa eso, se intercambian los nombres de las funciones derecha e izquierda de cada motor y se compila de nuevo.

3.2

Controlar los motores

▶ 13:57

Desde LabVIEW se sube la velocidad, se cambia el sentido, se piden 5 pasos (el motor da 5 pasos y se queda quieto) o se para.

Si la velocidad es muy alta (cerca de 255) el motor se queda pegado porque las bobinas no alcanzan a energizarse; hay que buscar el rango de cada motor. El LED sigue titilando mientras se reciben las órdenes.

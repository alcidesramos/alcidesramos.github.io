Clase 116: Adquirir y graficar los datos del motor

Tercer capítulo de la serie del motor DC. En la industria la velocidad se maneja en RPM, así que la frecuencia del encoder se convierte con los datos del motor (CPR del encoder y relación de la caja). Se mide la velocidad máxima (unos 222 RPM), se escala el potenciómetro a ese rango como set point y se mapea a la salida PWM de 500 a 4200. Luego se envían RPM y salida desde la interrupción del timer a dos programas: Serial Oscilloscope, que grafica hasta 9 canales y guarda un log de datos ordenado (ideal para identificar el sistema), y la extensión Teleplot de VS Code, muy buena para ver en tiempo real.

Fase 1

De frecuencia a RPM

1.1

Ajustar el arranque

▶ 0:00

El mínimo del mapeo se baja de 1300 a 500: cuando haya controlador, será él quien decida la salida. El 1300 solo servía para que el motor arrancara apenas se moviera el potenciómetro.

1.2

Convertir a RPM

▶ 1:39

Para pasar la frecuencia a RPM se necesitan los CPR del encoder (48 en este motor) y la relación de transmisión de la caja (131), y se multiplica por 60.

Si no tienes los datos, se puede sacar empíricamente: mueve el motor muy lento, cronometra una vuelta y relaciona la frecuencia leída con 1 RPM.

Se crea la variable RPM como extern en timer.c y como global en el main.

extern float RPM;
extern float salida;

// dentro del callback del TIM3
if (FREC1.frec_leida==0) frecuencia1=0;
else
  frecuencia1=FREC1.frec_muestreo/FREC1.frec_leida;
RPM=frecuencia1*60/750;   // factor de este motor
FREC1.frec_leida=0;

El factor 750 es el que se usó para este motor; calcula el tuyo con el CPR y la relación de tu motorreductor.

Fase 2

Set point y salida

2.1

Velocidad máxima

▶ 4:27

Con el PWM al máximo el motor llega a unos 220-222 RPM. Ese valor fija el rango del set point.

El set point debe estar en las mismas unidades que lo que se mide, porque el controlador trabaja con el error = set point - medición.

2.2

Escalar el potenciómetro

▶ 5:02

El potenciómetro se convierte a set point de 0 a 222 RPM y ese valor se mapea a la salida del motor de 500 a 4200.

Para usar la variable setpoint hay que incluir la librería PID (se usará en el próximo capítulo). El PWM ahora recibe salida, no el código del ADC.

setpoint=ADC_Read(&hadc1)*222.0/4095.0;
salida=map(setpoint,0,222.0,500,4200);
//PID_Control(...);   // próximo capítulo
PWM_valor(&PWM1, salida);
2.3

Ver entrada y salida

▶ 7:51

En el main se imprime la entrada del sistema (RPM leídas) y la salida aplicada al motor. Estos dos datos son los que sirven para identificar el sistema.

sprintf(texto,"IN=%.1f  SAL=%.1f\r\n\r\n",RPM,salida);
uartx_write_text(&huart1, texto);
Fase 3

Serial Oscilloscope

3.1

Enviar desde la interrupción

▶ 10:14

Cada 300 ms es muy lento: los datos se envían desde el callback del timer, en tiempo real. Ya se verificó que este envío no supera el tiempo de muestreo.

El formato son los valores separados por coma, terminados en \r. Se pueden enviar hasta 9 canales (3 ventanas de 3).

En timer.c hay que declarar extern el puerto serial y la cadena de texto.

extern UART_HandleTypeDef huart1;
extern char texto[];

// al final del callback
sprintf(texto,"%.1f,%.1f\r",RPM,salida);
uartx_write_text(&huart1, texto);

Lo ideal es subir el puerto a 921600 baudios en el micro y en el programa. En el video se dejó en 115200 porque la grabación se quedaba sin recursos.

3.2

Graficar

▶ 14:40

En Serial Oscilloscope se escoge el puerto y los baudios, se abre el puerto (cierra antes Hercules) y en Oscilloscope se abre la ventana de canales 1, 2 y 3.

La señal verde es la salida aplicada y la roja la velocidad.

3.3

Guardar el log

▶ 15:47

La ventaja de este programa es Log To File > Start Logging: guarda todos los datos mientras mueves el potenciómetro.

El archivo siempre tiene los 9 canales; las dos primeras columnas son entrada y salida, siempre en pareja. Esos datos se llevan a MATLAB para identificar el motor.

Fase 4

Teleplot en VS Code

4.1

Formato de Teleplot

▶ 17:58

En VS Code se instala la extensión Teleplot desde el buscador de extensiones; queda un botón en la barra inferior.

Cada variable se envía por separado con el formato >nombre:valor|g. Se comenta el envío del Serial Oscilloscope para no mezclar formatos.

sprintf(texto,">IN:%.1f|g\n",RPM);
uartx_write_text(&huart1, texto);

sprintf(texto,">OUT:%.1f|g\n",salida);
uartx_write_text(&huart1, texto);
4.2

Ver y exportar

▶ 20:49

Se escoge el puerto y los baudios y se da Open. Aparecen IN y OUT, y se pueden arrastrar a la misma gráfica para verlas juntas.

Al exportar a CSV quedan filas con datos vacíos porque cada variable se envía por separado. Por eso Teleplot es mejor para ver en tiempo real y Serial Oscilloscope para el data log.

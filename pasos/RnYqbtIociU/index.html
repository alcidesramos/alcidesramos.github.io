CubeIDE 2.0: CubeMX vuelve a ser aparte

En la última versión STMicroelectronics separó otra vez STM32CubeMX de STM32CubeIDE, como era hace años. El IDE ya no abre el .ioc por dentro: la configuración de pines, relojes y periféricos se hace en CubeMX, que genera el código y lo pasa al IDE. En el video se muestra cómo abrir un proyecto existente, cómo crear uno nuevo con este flujo y algunas novedades de CubeMX: instalar los paquetes de los micros que más usas, el comparador de proyectos y el Cross Selector, que sugiere un STM32 equivalente a un micro de otro fabricante. También se resumen las razones que da ST en su foro.

  • STM32CubeIDE 2.0 o superior
  • STM32CubeMX (instalación aparte)

Fase 1

Qué cambió

1.1

Abrir un proyecto existente

▶ 1:20

En CubeIDE se usa File > Import (o Open Projects from File System) y se busca la carpeta del proyecto. Se cargan el main.c y el resto de archivos como siempre.

Lo nuevo: si das doble clic al archivo .ioc, ya no se abre dentro del IDE, sino que se lanza STM32CubeMX aparte.

1.2

Generar código desde CubeMX

▶ 2:30

En CubeMX haces la configuración y presionas GENERATE CODE. Al terminar aparece el aviso con la ruta del proyecto y los botones Open Folder y Open Project.

Con Open Project, CubeIDE (que titila en la barra de tareas) recibe el proyecto con los cambios de hardware para seguir con el software.

Fase 2

Novedades útiles de CubeMX

2.1

Instalar los paquetes de tus micros

▶ 3:35

La primera vez que abras CubeMX ve a Help > Manage embedded software packages y marca las familias que más usas (por ejemplo STM32F4 para las Blackpill, STM32F1 para la Bluepill). Install.

Así no se descargan sobre la marcha cada vez que empiezas un proyecto.

2.2

Comparar proyectos

▶ 4:10

En la pestaña Tools aparece Compare Projects, que muestra en qué difieren las configuraciones de dos proyectos.

2.3

Cross Selector: buscar un STM32 equivalente

▶ 4:50

Al crear un proyecto, la pestaña Cross Selector permite escribir un micro de otro fabricante (Microchip, Texas, Renesas, Infineon...).

Por ejemplo, para un PIC18F4550 en DIP40 sugiere candidatos como el STM32G0B1 con 79 % de coincidencia y compara parámetro por parámetro: 8 bit contra 32 bit, ADC de 10 contra 12 bits, número de timers, comparadores, RAM, flash y rango de voltaje.

Muy útil para migrar proyectos viejos a STM32.

2.4

Por qué lo separaron

▶ 7:00

Según un empleado de ST en el foro oficial: cualquier versión de CubeIDE puede trabajar con cualquier versión de CubeMX, hay más flexibilidad (proyectos Makefile o CMake para otros IDE como VS Code), arranque más rápido y más estabilidad, y CubeIDE ya no pide iniciar sesión.

También ayuda con los micros nuevos con IA y redes neuronales, que necesitan herramientas de configuración más pesadas.

Fase 3

Crear un proyecto nuevo

3.1

Empezar en CubeMX

▶ 8:35

Se abre CubeMX y se elige Start My project from MCU (ACCESS TO MCU SELECTOR). Se busca el micro, en el video STM32F401CCU6, y se marca como favorito para encontrarlo rápido.

3.2

Configurar, nombrar y generar

▶ 9:00

Se configura el reloj, los pines y los periféricos como siempre.

Antes de generar es obligatorio ir a Project Manager, ponerle nombre y ubicación al proyecto y elegir STM32CubeIDE como Toolchain/IDE. Luego GENERATE CODE.

3.3

Abrirlo en CubeIDE

▶ 9:20

Con Open Project el proyecto se importa al workspace de CubeIDE. Se abre Core/Src/main.c y se empieza a programar.

Para cambiar algo de hardware no le des doble clic al .ioc (abre otra ventana de CubeMX): vuelve a la ventana de CubeMX que ya tienes abierta, haz el cambio y genera código de nuevo.

Conectores para el proyecto e interrupción de timer

La clase empieza con un repaso de conectores para que la tarjeta del proyecto quede ordenada y fácil de mantener. Luego se explica qué es una interrupción (con el ejemplo de atender a alguien que llega en medio de la clase y volver a lo que se estaba haciendo) y qué son las prioridades. Con un LED parpadeando cada 500 ms en el main, se configura el TIM1 con el prescaler y el periodo calculados para 100 ms, se habilita su interrupción en el NVIC y se cambia otro LED dentro del procedimiento de interrupción.

Fase 1

Conectores para la tarjeta

1.1

Borneras enchufables

▶ 0:00

Las borneras de tornillo son fáciles de conseguir. Las enchufables son mejores para el mantenimiento: se retira el bloque con los cables sin desatornillar y se vuelve a conectar sin errores. Hay versiones industriales con tornillos laterales para equipos con vibración. No llenes la tarjeta de borneras: ocupan mucho espacio.

1.2

Dupont y extensores de servo

▶ 1:36

Los Dupont (paso 2,54 mm, el mismo de los servos) se arman crimpando terminales macho o hembra. Para alargar el cable de un servo no hagas empalmes: compra un extensor de servo del largo que necesites. Si hay vibración, asegura el conector con cinta.

1.3

JST, cable ribbon y Molex KF2510

▶ 3:15
  • JST XH: polarizados y con traba; muy usados para señales de sensores en equipos biomédicos. Se consiguen también con el cable ya armado.
  • Cable ribbon: para extender sensores; el de colores ayuda a no invertir conexiones.
  • KF2510 (Molex): baratos y fáciles de conseguir; hay que crimpar bien la grapa y revisar continuidad para evitar falsos contactos.
1.4

Conectores de batería

▶ 6:02

Las baterías de alta corriente traen conectores XT30, XT60 o XT90. No cortes el conector: compra la pareja y suéldala a la tarjeta. La tarjeta debe verse ordenada, sin cables sueltos ni cinta.

Fase 2

Qué es una interrupción

2.1

El problema del retardo

▶ 21:30

Con un LED parpadeando cada 500 ms con HAL_Delay, el micro queda detenido esos 500 ms. Si se quiere otro LED cada 100 ms, otro retardo no sirve: se suman. Las interrupciones permiten atender varias cosas, una tras otra, tan rápido que parece al mismo tiempo.

2.2

Interrupción y prioridad

▶ 22:38

Una interrupción es un evento que se sabe que puede pasar, pero no cuándo. Cuando ocurre, el micro deja lo que hace, ejecuta su procedimiento y vuelve donde estaba. Si llega otra de mayor prioridad, deja la actual y atiende la nueva. Ese procedimiento no se llama desde el código: se ejecuta solo cuando ocurre el evento, y debe ser corto.

Hay interrupciones de timer, de flanco, de puerto serial y otras. Hoy, de timer.

Fase 3

Interrupción de timer

3.1

Elegir el timer

▶ 34:19

Un timer es un contador que cuenta de cero hasta un valor y vuelve a empezar; al llegar puede generar una interrupción. Los de 16 bits cuentan hasta 65535 y los de 32 bits (TIM2 y TIM5) hasta unos 4 mil millones. En CubeMX, en Timers, activa por ejemplo TIM1 con Clock Source: Internal Clock, que es el reloj con que trabaja el micro (16 MHz con el interno, 84 MHz con el cristal).

3.2

Calcular prescaler y periodo

▶ 36:32

El prescaler divide la frecuencia. A 16 MHz, dividiendo entre 16 se cuenta a 1 MHz (1 µs por cuenta), pero 100 ms serían 100000 cuentas, más de lo que cabe en 16 bits. Dividiendo entre 16000 cada cuenta es de 1 ms y para 100 ms el periodo es 100. A ambos se les resta 1 porque el conteo arranca en cero.

Prescaler (PSC)        = 16000 - 1
Counter Period (ARR)   = 100 - 1
16 MHz / 16000 = 1 kHz  -> 1 ms por cuenta
100 cuentas x 1 ms = 100 ms
3.3

Hoja de cálculo para timers

▶ 41:36

Una hoja de Excel hace la cuenta: frecuencia del micro, tiempo deseado y prescaler, y entrega el valor del contador. Ninguno de los dos puede pasar de 65535 en un timer de 16 bits. Hay muchas combinaciones válidas; para PWM sí importa que el contador sea grande para tener resolución.

3.4

Auto-reload y NVIC

▶ 44:34

Habilita auto-reload preload para que el timer se recargue. En NVIC Settings (Nested Vectored Interrupt Controller) marca TIM1 update interrupt and TIM10 global interrupt. El TIM1 comparte esa interrupción con el TIM10.

3.5

Código en la interrupción

▶ 46:22

Al generar código, en stm32f4xx_it.c está TIM1_UP_TIM10_IRQHandler, al que el micro salta cada 100 ms. Ahí se cambia el otro LED. La IA sugiere cambiar el mismo LED del main: hay que corregirla.

/* USER CODE BEGIN TIM1_UP_TIM10_IRQn 1 */
HAL_GPIO_TogglePin(LED2_GPIO_Port, LED2_Pin);
/* USER CODE END TIM1_UP_TIM10_IRQn 1 */
3.6

Arrancar el timer

▶ 48:05

Antes del while hay que arrancar cada timer con interrupción. Con eso, mientras el main espera sus 500 ms, cada 100 ms el micro cambia el otro LED y vuelve.

/* USER CODE BEGIN 2 */
HAL_TIM_Base_Start_IT(&htim1);
/* USER CODE END 2 */

while (1)
{
  HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
  HAL_Delay(500);
}

CCS, MikroC y XC8: memoria usada por el mismo programa

Comparación ilustrativa, no competitiva, a partir de un reto en un grupo de Facebook. Con un PIC16F1824 se escribe el mismo programa: un for que desplaza un bit de 1 a 0b10000000 en el puerto C cada 100 ms. Se compila en CCS (con su asistente), en MikroC (configurando los registros a mano), en XC8 con el MPLAB Code Configurator y en XC8 configurando a mano. Se anotan los datos (RAM) y el programa (ROM) de cada uno y se prueban las opciones de optimización. La conclusión: conocer el micro y sus registros siempre da programas más pequeños que dejar que un asistente lo configure todo.

Fase 1

El programa de prueba

1.1

CCS

▶ 0:00

En CCS se crea el proyecto con el asistente (PIC16F1824, cristal) y se escribe un for que desplaza un 1 por el puerto C. El asistente configura solo las entradas, salidas y pines digitales.

unsigned char cuenta;

void main()
{
  while (TRUE)
  {
    for (cuenta = 1; cuenta != 0b10000000; cuenta = cuenta << 1)
    {
      output_c(cuenta);
      delay_ms(100);
    }
  }
}
1.2

Resultado en CCS

▶ 3:21

CCS informa el uso de memoria al compilar: 17 bytes de datos y 58 palabras de programa. Se prueba también su opción de optimización.

Fase 2

MikroC

2.1

Configurar a mano

▶ 5:31

En MikroC hay que declarar a mano el puerto C como salida y como digital, porque esos pines son análogos.

unsigned char cuenta;

void main()
{
  TRISC = 0;    // puerto C salida
  ANSELC = 0;   // puerto C digital
  while (1)
  {
    for (cuenta = 1; cuenta != 0b10000000; cuenta = cuenta << 1)
    {
      LATC = cuenta;
      delay_ms(100);
    }
  }
}
2.2

Resultado en MikroC

▶ 7:51

En View > Statistics se ve el uso: 1 byte de datos y 29 palabras de programa, con la optimización en el nivel máximo. En el listado en ensamblador se ve qué instrucciones generó el compilador.

Fase 3

MPLAB XC8

3.1

XC8 con MCC

▶ 11:07

En MPLAB X se crea el proyecto y con el MPLAB Code Configurator se configuran el oscilador y los pines del puerto C como salidas digitales. Es muy cómodo, pero genera más código: 4 bytes de datos y 85 palabras de programa. Con la optimización por tamaño baja a 69.

3.2

XC8 configurado a mano

▶ 17:58

Se crea un proyecto nuevo sin MCC: se escriben los bits de configuración (con la ventana de Configuration Bits), se define la frecuencia del cristal y se configuran TRISC y ANSELC a mano. Así el programa queda en 4 bytes de datos y 30 palabras.

#define _XTAL_FREQ 4000000

unsigned char cuenta;

void main(void)
{
  TRISC = 0;    // puerto C salida
  ANSELC = 0;   // puerto C digital
  while (1)
  {
    for (cuenta = 1; cuenta != 0b10000000; cuenta = cuenta << 1)
    {
      LATC = cuenta;
      __delay_ms(100);
    }
  }
}
Fase 4

Conclusión

4.1

La tabla final

▶ 21:36

El mismo programa gasta distinta memoria según el compilador y la forma de configurarlo:

  • CCS: 17 datos, 58 programa.
  • MikroC: 1 dato, 29 programa.
  • XC8 con MCC: 4 datos, 85 programa (69 optimizando por tamaño).
  • XC8 configurado a mano: 4 datos, 30 programa.
4.2

Conocer el micro

▶ 22:45

No se trata de cuál compilador es mejor: en otros programas puede ganar otro, y las opciones de optimización cambian el resultado. Lo que sí se ve es que conocer el micro y sus registros siempre gasta menos recursos que dejar que el asistente configure todo.

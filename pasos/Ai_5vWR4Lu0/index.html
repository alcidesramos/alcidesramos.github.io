Leer frecuencia con Input Capture

Parte del proyecto para identificar un motor DC y luego controlarlo con PID o lógica difusa. El TIM1 corre a una frecuencia de muestreo fija (1 MHz con prescaler 16-1 a 16 MHz) y en cada flanco de subida la interrupción guarda el valor del contador. La diferencia entre dos capturas da los pasos del periodo, y frecuencia = frecuencia de muestreo / pasos. Se prueba en Proteus con generadores de 300 Hz, 1 kHz, 2 kHz y 4 kHz, se discute el teorema de Nyquist en este caso de muestreo sincronizado y al final se lee la señal del encoder de un motor.

1.2

Proyecto nuevo

▶ 4:44

En STM32CubeIDE se elige el STM32F401CCU6. El nombre del proyecto y la ruta no deben tener espacios, tildes ni eñes, y la carpeta debe estar vacía. Por defecto trabaja con el oscilador interno de 16 MHz, que es lo que simula Proteus; el timer clock también queda en 16 MHz.

Fase 2

Configurar el TIM1

2.1

Input Capture en el canal 1

▶ 5:52

En Timers, TIM1: Clock Source = Internal Clock y Channel1 = Input Capture direct mode. Se habilita PA8 como TIM1_CH1, que es la entrada de la señal.

2.2

Prescaler: la frecuencia de muestreo

▶ 6:26

El prescaler define a qué frecuencia cuenta el timer. Con la hoja de Excel: para 1 MHz a 16 MHz el prescaler es 16; para 1 kHz es 16000. Siempre se escribe el valor menos 1.

  • Prescaler = 16-1 → 1 MHz (un paso por microsegundo).
  • Counter Period = 65535 (el máximo; está sobrado).
  • auto-reload preload = Enable, por si el contador se desborda.
  • Polarity Selection = Rising Edge (flanco de subida).

Si después subes el micro a 84 MHz, el prescaler para 1 MHz pasa a 84-1.

2.3

Interrupción y UART

▶ 11:56

En NVIC Settings se activa TIM1 capture compare interrupt: es la que da el tiempo real. USART1 asíncrono a 9600 (PA9 es TX).

3.2

Frec1_Init: calcula la frecuencia de muestreo

▶ 17:29

La función calcula sola la frecuencia de muestreo a partir del prescaler (16 MHz / 16 = 1 MHz) y arranca la captura con interrupción.

extern TIM_HandleTypeDef htim1;
uint16_t cap1 = 0, cap2 = 0, cap3 = 0, cap4 = 0;
uint32_t frec1;
uint32_t frec1_1, frec1_2;
uint32_t frecmuestreo;

void Frec1_Init()
{
  // inicia el TIM1 en Input Capture con interrupción de flanco
  frecmuestreo = SystemCoreClock / ((TIM1->PSC) + 1);
  HAL_TIM_IC_Start_IT(&htim1, TIM_CHANNEL_1);
}
3.3

Frec1_Interrupt: resta dos capturas

▶ 18:00

En el primer flanco se guarda el contador en frec1_1; en el siguiente, en frec1_2. La resta da los pasos del periodo. Si el contador se desbordó entre los dos flancos, la segunda captura es menor y hay que sumar el ARR.

// se debe incluir #include "Frecuencia.h" en stm32f4xx_it.c
void Frec1_Interrupt()
{
  // si es el canal 1
  if (__HAL_TIM_GET_FLAG(&htim1, TIM_FLAG_CC1) == 1)
  {
    if (cap1 == 0)
    {
      cap1 = 1;
      frec1_1 = TIM1->CCR1;          // primer flanco
    }
    else if (cap1 == 1)
    {
      cap1 = 0;
      frec1_2 = TIM1->CCR1;          // segundo flanco

      if (frec1_2 > frec1_1)
        frec1 = (frec1_2 - frec1_1);
      else                           // el timer se desbordó
        frec1 = (TIM1->ARR - frec1_1) + frec1_2;
    }
    __HAL_TIM_CLEAR_FLAG(&htim1, TIM_FLAG_CC1);  // limpia la bandera
  }
}
3.4

Llamarla desde la interrupción del TIM1

▶ 21:52

En Core/Src/stm32f4xx_it.c se incluye Frecuencia.h y dentro de TIM1_CC_IRQHandler se llama a la función.

/* USER CODE BEGIN Includes */
#include "Frecuencia.h"

void TIM1_CC_IRQHandler(void)
{
  /* USER CODE BEGIN TIM1_CC_IRQn 0 */
  Frec1_Interrupt();
  /* USER CODE END TIM1_CC_IRQn 0 */
  HAL_TIM_IRQHandler(&htim1);
}
3.5

main.c

▶ 23:33

Las variables de Frecuencia.c se declaran extern. Al iniciar se envía la frecuencia de muestreo y en el while se divide entre los pasos medidos. El HAL_Delay no afecta la medición porque se hace por hardware e interrupción.

/* USER CODE BEGIN PV */
char texto[50];
extern uint32_t frecmuestreo;
extern uint32_t frec1;
float frecuencia1;

/* USER CODE BEGIN 2 */
Frec1_Init();
sprintf(texto, "frec_muestreo=%lu \r\n", frecmuestreo);
uartx_write_text(&huart1, texto);

while (1)
{
  HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
  if (frec1 != 0) frecuencia1 = frecmuestreo / frec1;
  else frecuencia1 = 0;
  frec1 = 0;       // limpia: si se quita la señal no queda el valor viejo
  sprintf(texto, "RPM=%.1f\r\n", frecuencia1);
  uartx_write_text(&huart1, texto);
  HAL_Delay(300);
}

En el video se divide directo entre frec1. Aquí se agregó la comprobación frec1 != 0 para no dividir por cero cuando no hay señal.

Fase 4

Pruebas

4.1

Frecuencia de muestreo

▶ 25:13

Al correr, la terminal muestra frec_muestreo=1000000. Si la terminal muestra basura, revisa que la UART esté en 9600 y no 96000, que el micro esté a 16 MHz en Proteus y pon el pin de reset a positivo.

Después de cambiar algo en el .ioc, dale al engranaje (Generate Code) antes de compilar; si no, el .hex puede quedar viejo.

4.2

Leer las señales

▶ 29:46

Con muestreo de 1 MHz lee bien 4 kHz, 2 kHz, 1 kHz y 300 Hz moviendo el switch rotativo.

4.3

Nyquist con muestreo sincronizado

▶ 32:00

Bajando el muestreo a 2 kHz (prescaler 8000-1): lee 1 kHz bien, 300 Hz con poca precisión (no es múltiplo) y, sorpresa, también 2 kHz, porque la captura está sincronizada con los flancos y la señal es cuadrada. Con 4 kHz ya no puede y sigue marcando 2 kHz: ahí sí se cumple Nyquist.

4.4

Señal del encoder del motor

▶ 34:53

Volviendo a 16-1 y conectando la salida del encoder, se lee la velocidad del motor: sube a medida que se le da más voltaje (8 V, 12 V) y se estabiliza por la inercia. Con esto ya se puede identificar el motor.

Para capturar el arranque completo hace falta más velocidad que la UART: eso se resolverá con DMA.

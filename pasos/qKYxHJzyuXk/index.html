Pantalla LCD por I2C

Lección 16 del curso. El módulo con el PCF8574 convierte la LCD a I2C y permite manejarla con dos pines. Se usa una librería propia con I2C por software (en cualquier par de pines): primero se pega todo el código arriba del main, luego se pasa a un archivo .h incluido con #include y finalmente se separa en .h (cabeceras) y .c (código) agregando el .c al proyecto. Las funciones son iguales a las de la librería LCD de MikroC con el prefijo I2C_. Al final se prueba en una tarjeta real con un PIC18F2550 y bootloader USB.

Fase 1

El módulo I2C

1.1

Qué hace el PCF8574

▶ 0:00

El PCF8574 es un expansor de puertos por I2C: con solo dos pines (SDA y SCL) maneja todos los pines de la LCD. El módulo que se vende ya trae el chip y las resistencias pull-up. El 16F877A tiene I2C por hardware en RC4 (SDA) y RC3 (SCL), pero aquí se usa I2C por software para poder usar cualquier pin, algo útil en micros pequeños.

1.2

Proyecto y librería Software I2C

▶ 1:38

Se crea el proyecto lcd2 con el PIC16F877A a 8 MHz. En el Library Manager se activa Software_I2C y, de la librería LCD, solo las Lcd_Constants.

Fase 2

La librería propia

2.1

Pines y dirección del módulo

▶ 3:22

Se pega la librería arriba del main y se cambian los pines de SDA y SCL. La dirección del módulo con PCF8574 es 0x4E; algunos módulos traen el PCF8574A y usan 0x7E. Si la pantalla no responde, se prueba con la otra.

sbit Soft_I2C_Sda at RB0_bit;
sbit Soft_I2C_Scl at RB1_bit;
sbit Soft_I2C_Sda_Direction at TRISB0_bit;
sbit Soft_I2C_Scl_Direction at TRISB1_bit;

#define LCD_ADDR 0x4E    // PCF8574 (0x7E si es PCF8574A)
2.2

Mismas funciones con prefijo I2C_

▶ 6:44

Las funciones se hicieron compatibles con las de MikroC: solo se antepone I2C_. Se copia el programa de la clase anterior y con Edit > Replace (solo en la selección) se cambia Lcd_ por I2C_LCD_.

I2C_LCD_Init();
I2C_LCD_Cmd(_LCD_CLEAR);
I2C_LCD_Cmd(_LCD_CURSOR_OFF);
I2C_LCD_Out(1, 5, "ESTO ES UNA");
I2C_LCD_Out(2, 1, "    PRUEBA");
I2C_LCD_Out(3, 1, "temp=30");
I2C_LCD_Chr_CP(223);
2.3

Pasar la librería a un archivo .h

▶ 9:37

Para no tener todo ese código en el programa, se guarda en un archivo soft_i2c_lcd.h en la carpeta del proyecto (con los pines como extern) y se incluye. En el programa solo quedan los pines y el main.

#include "soft_i2c_lcd.h"
2.4

Separar en .h y .c

▶ 11:58

Lo recomendado es que el .c tenga el código y el .h solo las cabeceras: constantes, variables externas y los nombres de las funciones que se usan afuera. En MikroC, además de incluir el .h, se agrega el .c al proyecto: Project Manager > Sources > clic derecho > Add Existing File.

// soft_i2c_lcd.h
extern sbit Soft_I2C_Sda;
extern sbit Soft_I2C_Scl;
#define LCD_ADDR 0x4E
void I2C_LCD_Cmd(char out_char);
void I2C_LCD_Init();
void I2C_LCD_Chr(char row, char column, char out_char);
void I2C_LCD_Chr_Cp(char out_char);
void I2C_LCD_Out(char row, char col, char *text);
void I2C_LCD_Out_Cp(char *text);

Si solo se incluye el .h y no se agrega el .c al proyecto, el compilador dice que no encuentra las funciones.

2.5

Caracteres propios

▶ 14:49

Los caracteres especiales de la clase anterior funcionan igual: se copian las direcciones, los vectores y la función CustomChar, cambiando las llamadas a las versiones I2C.

Fase 3

Prueba en una tarjeta real

3.1

PIC18F2550 con bootloader USB

▶ 17:10

Se usa una tarjeta propia con un PIC18F2550 a 48 MHz y bootloader USB, con el módulo conectado a 5 V, tierra, SDA y SCL. Se crea el proyecto cargando el esquema de configuración de la tarjeta, se copian el .h y el .c, se incluye el .h, se agrega el .c y se activan Software_I2C y Lcd_Constants. En el main se ponen los pines digitales.

ADCON1 = 0x0F;   // todo digital en el 18F2550
I2C_LCD_Init();
I2C_LCD_Cmd(_LCD_CLEAR);
I2C_LCD_Cmd(_LCD_CURSOR_OFF);
I2C_LCD_Out(1, 2, "ESTO ES UNA");
I2C_LCD_Out(2, 5, "PRUEBA");
3.2

Cargar con el bootloader USB

▶ 21:48

En Tools > USB HID Bootloader: resetear la tarjeta, conectar, buscar el .hex y cargar. Si el programa no se actualiza, hay que revisar que no haya otra ventana del bootloader abierta.

Si queda abierta una ventana vieja del bootloader, la nueva entra en conflicto y no programa.

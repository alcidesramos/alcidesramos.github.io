STM32 desde MATLAB: programar la Black Pill

Se repite todo el proceso de la parte 2, pero grabando la tarjeta física con el programador ST-Link V2 (sirve el clon). En CubeMX se usa el cristal externo y el PLL a la velocidad máxima, TIM10 como base de tiempo, sin generar main y con librerías LL. En Simulink se guarda primero el modelo, se arma Pulse Generator más Digital Port Write en PC13 y en Target hardware resources se enlaza el .ioc con la acción Build, load and run. Cambiando el periodo del pulso y volviendo a desplegar se ve cómo cambia el parpadeo del LED.

Fase 1

Proyecto en CubeMX 6.4

1.1

La tarjeta

▶ 0:00

La Black Pill ya tiene un programa que hace parpadear el LED cada segundo. Con MATLAB lo vamos a cambiar para que se note que la tarjeta quedó programada desde Simulink. El ST-Link V2 se conecta por SWD.

1.2

Pin, cristal y reloj

▶ 0:33

Se abre el CubeMX antiguo (6.4) y se elige el STM32F401CC. PC13 como GPIO_Output. Como ahora es la tarjeta real, en RCC el HSE va en Crystal/Ceramic Resonator y en Clock Configuration se lleva el PLL a la velocidad máxima, útil cuando el micro ejecute algoritmos pesados como lógica difusa.

1.3

Base de tiempo: TIM10

▶ 1:42

MATLAB usa el SysTick, así que en SYS el Timebase Source se cambia a otro timer que no se vaya a usar, por ejemplo TIM10.

1.4

Project Manager

▶ 1:50

Nombre MATLAB2, guardado en la carpeta de trabajo (CubeMX crea dentro la carpeta MATLAB2) y Toolchain STM32CubeIDE.

  • Do not generate the main() marcado.
  • Generate Under Root desmarcado.
  • Advanced Settings: GPIO y RCC en LL en lugar de HAL.
  • Advanced Settings: quitar Visibility (Static).
  • No hace falta generar código: basta con guardar el proyecto (File, Save Project).
Fase 2

Modelo en Simulink

2.1

Carpeta de trabajo y modelo

▶ 2:49

En MATLAB, con Browse, la carpeta actual debe ser la del proyecto (MATLAB2). Luego se crea un modelo en blanco y se guarda de una vez dentro de esa carpeta (aquí STM32SIMULINK).

2.2

Bloques

▶ 3:56

En el Library Browser, STM32F4xx Based Boards (no las Discovery ni las Nucleo, porque la Black Pill no es una tarjeta de ST). Se agrega Digital Port Write en el puerto C, pin 13, y un Pulse Generator conectado a su entrada.

Lo interesante es que se combinan los periféricos del micro con cualquier bloque de MATLAB: hoy un pulso, más adelante un controlador PID.

2.3

Pulso más rápido

▶ 5:02

Para notar el cambio frente al programa que ya tenía la tarjeta, el Pulse Generator se configura con amplitud 1, periodo de 0.3 s y ancho de pulso del 50 %.

Fase 3

Configurar y grabar

3.1

Model Settings

▶ 5:36

En Modeling, Model Settings:

  • Solver: Fixed-step, que consume menos recursos.
  • Hardware Implementation: Hardware board = STM32F4xx Based.
  • Operating system/scheduler: Baremetal (más eficiente) o FreeRTOS.
  • Target hardware resources, Build options: Browse para elegir el .ioc del proyecto. Build action = Build, load and run; Connectivity mode = st-link; Connection port = SWD.
3.2

Build, Deploy & Start

▶ 6:44

En la pestaña Hardware se usa Build, Deploy & Start (para Proteus solo se compilaba). MATLAB carga el .ioc, genera el código, compila y graba la tarjeta. La primera vez tarda más.

Mientras MATLAB compila, la tarjeta sigue con el programa viejo. Solo cambia cuando termina la descarga: el LED se apaga un momento y arranca con el nuevo parpadeo.

3.3

Cambiar el periodo

▶ 7:55

Con el LED parpadeando rápido, se cambia el periodo del Pulse Generator a 1 s y se vuelve a dar Build, Deploy & Start. La segunda vez es más rápido y el LED pasa a parpadear cada segundo.

Así se puede usar todo lo de MATLAB (controladores, lógica difusa) junto con los periféricos del micro: ADC, puertos digitales, UART, timers e interrupciones.

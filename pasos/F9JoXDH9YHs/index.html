Clase 149: MQTT con STM32, DT-06 y ThingsBoard

Monitoreo y control por internet. Un STM32F401 lee dos potenciómetros (temperatura simulada y voltaje) y un pulsador, y los publica cada 2 segundos en ThingsBoard por MQTT usando el módulo Wi-Fi DT-06. Desde el dashboard, un switch prende el LED de la tarjeta y un slider mueve un servo mediante métodos RPC. Al final el dashboard se hace público para compartirlo con un enlace o un código QR.

Fase 1

Preparar el dashboard en ThingsBoard

1.1

Ajustar los widgets

▶ 1:09

El dashboard se armó en un video anterior; aquí solo se ajusta: medidor de temperatura de 0 a 100, medidor de voltaje de 0 a 5 (se medirá de 0 a 3.3 V), un slider para el servo y un switch para el LED.

Después de cada cambio hay que darle Apply en el widget y luego Save en el dashboard. Si no, no se guarda.

1.2

Nombrar los métodos RPC

▶ 1:34

Cada widget de control llama un método RPC. El nombre que va después de set/get es el que se usa en el código del micro: switch del LED getLedStatus / setLedStatus → LedStatus; slider del servo getServoAngle / setServoAngle → ServoAngle.

1.3

Copiar el token del device

▶ 10:07

En Devices se abre el device y se pulsa Copy access token. Ese token va en MQTT.h.

Fase 2

Configurar el micro en CubeMX

2.1

Reloj y GPIO

▶ 2:42

Reloj interno a 84 MHz. led (LED de la tarjeta) como GPIO_Output y sw en PA0 (pulsador de la tarjeta) como GPIO_Input con pull-up.

2.2

ADC con dos canales

▶ 3:06

ADC1 con los canales IN1 (voltaje) e IN2 (temperatura simulada) y 84 ciclos de muestreo para que no bloquee tanto.

2.3

USART1 para el DT-06

▶ 3:51

USART1 asíncrono a 115200 con interrupción global y DMA de recepción. Opcional: USART6 a 115200 para monitorear por el PC lo que llega.

2.4

TIM2 en PWM para el servo

▶ 6:58

Prescaler 84-1 (frecuencia en MHz menos uno), periodo 20000-1 (20 ms, 50 Hz del servo), auto-reload activado y PWM Generation CH1, donde va el servo. Luego Generate Code y se abre la carpeta con VS Code.

Fase 3

Configurar el módulo DT-06

3.1

Serial a 115200

▶ 5:46

Conéctese a la red Wi-Fi que crea el módulo y entre desde el navegador a 192.168.4.1 (si no abre, resetee el módulo). En Module → Serial ponga 115200, igual que USART1, y guarde.

3.2

Wi-Fi: nombre propio y estación

▶ 4:15

Cambie el SSID que crea el módulo para no dejar el de fábrica. En Station Settings habilite la estación, escoja su red y ponga la clave.

3.3

Networks: cliente hacia ThingsBoard

▶ 5:01

Socket Type TCP Client, servidor mqtt.thingsboard.cloud y puerto 1883 (MQTT).

mqtt.thingsboard.cloud
1883
Fase 4

Librerías en VS Code

4.1

Copiar e incluir las librerías

▶ 8:09

Se pega la carpeta LIBRERIAS (ADC, pinout, servos, uart, UARTRX y la nueva MQTT), se agregan con el botón CMake ARZ y se incluyen en main.c.

#include "stdio.h"
#include "string.h"
#include "stdlib.h"
#include "math.h"
#include "uart.h"
#include "adc_x.h"
#include "UARTRX.h"
#include "MQTT.h"
#include "pinout.h"
#include "servos.h"
4.2

Configurar servo, ADC y MQTT

▶ 9:20

En servos.c el servo usa TIM2 canal 1, en adc_x.h se ponen 2 canales y en MQTT.h el nombre del device y su token.

#define MQTT_CLIENT_ID     "ARZ"            // nombre del device
#define MQTT_TOKEN         "TU_TOKEN_AQUI"  // access token del device en ThingsBoard
#define MQTT_TX_SIZE       512
#define MQTT_TOPIC_SIZE    128
#define MQTT_PAYLOAD_SIZE  512

Use su propio token; nunca lo publique.

4.3

Recepción serial del DT-06

▶ 10:30

En UARTRX.c se indica qué UART usa MQTT (aquí la 1) y el tamaño del buffer, que es MQTT_PAYLOAD_SIZE. Si usa la 2 o la 6, cambie los dos números.

UARTRXS MQTT_UARTRX = {&huart1, USART1, MQTT_PAYLOAD_SIZE};

Si sale que no encuentra el .h: F1 → CMake: Delete Cache and Reconfigure y compile de nuevo.

Fase 5

El programa en main.c

5.1

Variables

▶ 12:39

Voltaje, temperatura, estado del LED, ángulo del servo, estado del pulsador y un texto para la UART6.

5.2

Probar el servo

▶ 13:55

Primero se prueba que el servo se mueva. Si no se mueve, falta SERVO_init o la fuente del servo está apagada.

SERVO_init(&SERVO1);
SERVO_ANG(&SERVO1, 90);
HAL_Delay(1000);
SERVO_ANG(&SERVO1, -90);
HAL_Delay(1000);
PIN_ON(led);   // apaga el LED (lógica invertida)
5.3

Iniciar MQTT

▶ 16:37

Antes del while se inicia la recepción, se espera a que el DT-06 se conecte, se conecta al broker y se suscribe a las órdenes RPC.

MQTT_Init();                       // inicia recepción DMA del MQTT_UARTRX
HAL_Delay(3000);                   // tiempo para que el DT06 se conecte
MQTT_Connect();                    // si falla, MQTT_Loop reintenta cada 5 s
MQTT_Subscribe(TB_RPC_REQUEST);    // recibir comandos RPC desde ThingsBoard
uint32_t t_envio = 0;
5.4

Callback de la UART

▶ 17:05

En la interrupción de recepción se llama MQTT_Interrupt y en la de errores el manejo de errores de MQTT. Con más puertos seriales se agrega un bloque por cada uno.

5.5

Leer entradas y procesar MQTT

▶ 18:17

En el while se lee el ADC y el pulsador, y se llama MQTT_Loop(), que siempre debe estar en el bucle para guardar lo que llega del DT-06.

ADC_Read_All(&hadc1, adc1_canales, adc1_codigo);
voltaje     = (float)adc1_codigo[0] * 3.3   / 4095.0;
temperatura = (float)adc1_codigo[1] * 100.0 / 4095.0;
suiche = PIN_READ(sw);   // lee PA0
MQTT_Loop();             // SIEMPRE en el bucle

Opcional: reenviar a la UART6 lo que llega por MQTT cuando MQTT_flag_msg == 1, para monitorear.

5.6

Publicar cada 2 segundos

▶ 20:53

Cada 2 segundos se arma una trama JSON con temperatura, voltaje y el estado del pulsador y se publica como telemetría.

if ((HAL_GetTick() - t_envio) >= 2000)
{
  t_envio = HAL_GetTick();
  sprintf(MQTT_TX_BUFF,
    "{\"temperatura\":%.2f,\"voltaje\":%.2f,\"led\":%s}",
    temperatura, voltaje, suiche ? "false" : "true");
  MQTT_Telemetria(MQTT_TX_BUFF);
}

El pulsador es de lógica invertida, por eso 1 se envía como false.

5.7

Recibir órdenes RPC

▶ 23:40

MQTT_RPC_Bool lee booleanos y MQTT_RPC_Float flotantes. El texto debe coincidir con el método del widget sin el set. Para otra variable se agrega otra línea igual.

// LECTURA DE THINGSBOARD
led_estado   = MQTT_RPC_Bool("LedStatus", led_estado);      // switch
servo_angulo = MQTT_RPC_Float("ServoAngle", servo_angulo);  // slider
SERVO_ANG(&SERVO1, servo_angulo);
HAL_GPIO_WritePin(led_GPIO_Port, led_Pin, led_estado ? 0 : 1);
// mensajes que ninguna función RPC atendió
if (MQTT_flag_msg == 1) MQTT_flag_msg = 0;
Fase 6

Probar y compartir

6.1

Dashboard público

▶ 22:07

En Groups se hace público el dashboard y da un enlace que cualquiera puede abrir para ver los datos en tiempo real. Al mover los potenciómetros los medidores cambian cada 2 s.

6.2

Prueba completa

El switch prende y apaga el LED azul de la tarjeta, el slider mueve el servo y el pulsador prende el LED del dashboard a los 2 s. El enlace se puede convertir en código QR para compartirlo.

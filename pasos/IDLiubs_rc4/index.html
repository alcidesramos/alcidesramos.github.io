Control PID de velocidad con Arduino

Es el mismo control que se hizo con PIC y MikroC, ahora en Arduino. El PWM sale por el pin 3 y el encoder entra por el pin 2 con interrupción. Medir el tiempo entre pulsos con micros() da lecturas malas porque tiene resolución de 4 µs, así que se usa el Timer1 directamente con preescalador de 8. Con el motor al mínimo y al máximo se mide el rango de frecuencias (unos 42 a 390 Hz) y en Excel se saca la ecuación del set point. Luego se pega el PID del proyecto de MikroC y se ajustan kp, ki y kd viendo la respuesta en LabVIEW. Al final se muestra que si el PWM se pone en el pin 10, que es del Timer1, el control se daña.

1.1

El circuito

▶ 0:00

El motor DC con encoder se maneja con un transistor desde el pin 3 (PWM). El encoder entra al pin 2 para leer por interrupción, un potenciómetro da el set point y el serial va a la interfaz. Se trabaja en revoluciones por segundo (Hz); para RPM se multiplica por 60.

Potenciómetro al PWM

▶ 2:20

El lazo abierto es leer el canal análogo y sacarlo por el PWM (el ADC es de 10 bits y el PWM de 8, por eso se corre dos bits). Al mover el potenciómetro la señal en el osciloscopio cambia de ancho.

Fase 2

Medir la frecuencia

2.1

Primer intento con micros()

▶ 3:29

Se crea la interrupción del pin 2 y se mide cuántos microsegundos pasan entre un pulso y otro con micros(). La frecuencia leída no coincide con la del motor: micros() tiene resolución de 4 µs y no sirve para esto.

2.2

Usar el Timer1

▶ 6:55

Se hace como con el PIC: se configura el Timer1 a mano y se crean funciones para leerlo y escribirlo (read_tmr1 y write_tmr1). En cada pulso del encoder se lee el timer, se pone en cero y se activa una bandera.

void interrupcion()
{
  contador=read_tmr1();
  write_tmr1(0);
  flag_cero=1;
}

void setup()
{
  pinMode(pwm_pin,OUTPUT);
  pinMode(rpm_pin,INPUT);

  pinMode(interruptPin, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(interruptPin), interrupcion, RISING);

  Serial.begin(19200);
  Serial.println("INICIANDO");
  analogWrite(pwm_pin,0);

  //Configura registroA
  TCCR1A=0;
  //configura registroB
  TCCR1B=0;
  TCCR1B=0b010;// Configura el preescalador a 8
  write_tmr1(0);
  sbi(TIFR1,TOV1); // pone un uno para limpiar bandera de desborde
}
2.3

Escoger el preescalador

▶ 9:50

Con preescalador de 64 se leían frecuencias desde unos 3 Hz; con 8 se leen desde unos 30 Hz con mejor resolución. Se escoge según la frecuencia más baja que entregue el motor. La tabla de Excel ayuda a ver el rango de cada preescalador.

La frecuencia se calcula con el cristal de 16 MHz y el preescalador: 16000000 / (8 · contador).

Fase 3

El control PID

3.1

El loop con PID

▶ 14:34

Se pega la función pid del proyecto de MikroC (es C estándar). En el loop se calcula la frecuencia si hubo pulso, se escala el set point, se aplica el PID y su salida ut va al PWM. Se envían el set point y la frecuencia por el serial para graficarlos.

void loop() {
  codigo=analogRead(0);

  // se lee la frecuencia
  if (flag_cero!=0) frecuencia=(16000000/(8*contador)); //16.0 ES EL CRISTAL DE LA ARDUINO
  flag_cero=0;
  //rpm=frecuencia*60.0;

  set_point=0.3402*codigo + 42.0;// escala en rango de min frec y max frec

  pid(frecuencia);
  salida=ut;
  analogWrite(pwm_pin,ut);

  floattostr_(set_point,texto,2);
  Serial.print("SP=");
  Serial.print(texto);
  Serial.print("/");

  floattostr_(frecuencia,texto,2);
  Serial.print("RPM=");
  Serial.print(texto);
  Serial.println("/");
}
3.2

Ajustar las constantes

▶ 16:53

Con las constantes del PIC el sistema oscila. Se quita la parte derivativa y se baja la integral más o menos a la mitad; luego se agrega un poco de proporcional y se ajusta hasta que llega al set point sin sobreimpulso.

Al cambiar el set point con el potenciómetro, la velocidad sube y se mantiene: el PID queda calibrado.

3.3

Ojo con los timers

▶ 20:18

Timer0 lo usan millis y micros, Timer1 la librería Servo y Timer2 la función tone; además analogWrite usa los pines 5 y 6 (Timer0), 9 y 10 (Timer1) y 3 y 11 (Timer2).

Como aquí el Timer1 mide la frecuencia, si el PWM se pone en el pin 10 la respuesta se daña. Con el PWM en el pin 3 todo funciona bien.

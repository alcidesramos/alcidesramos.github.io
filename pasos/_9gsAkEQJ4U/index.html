Pantalla Nextion con PIC o Arduino

La pantalla Nextion se comunica por el puerto serial y casi todo lo que envía o recibe termina con tres bytes 0xFF. Por eso el programa del micro guarda lo que llega en una trama hasta detectar FF FF FF, la decodifica con strstr y, en sentido contrario, envía órdenes de texto como pa1.te2.val=25 seguidas de FF FF FF. Como la aguja y la barra no usan la misma escala que el valor medido, se linealizan en Excel antes de enviarlas.

Fase 1

Preparar la interfaz

1.1

Repaso de la interfaz

▶ 0:00

La página 0 tiene un velocímetro (aguja y valor digital), un pulsador que enciende o apaga un LED del micro y un botón para pasar de página. La página 1 tiene un termómetro análogo y digital, un LED que muestra el estado de un pulsador del micro y un slider que fija la velocidad del motor.

1.2

Objetos globales

▶ 2:16

Todo objeto que el micro va a cambiar debe quedar como global (vscope = global). Así el micro puede escribir «en la página 1, el objeto te2» sin importar qué página se esté mostrando.

1.3

Evento del pulsador

▶ 4:29

En Touch Release del pulsador de dos estados se envía un texto distinto según su estado, seguido de los tres 0xFF que marcan el final de trama.

if(...)   // según el estado del pulsador
{
  print "led1=on"
  printh ff ff ff
}else
{
  print "led1=off"
  printh ff ff ff
}
1.4

Evento del slider

▶ 5:41

En Touch Move del slider se copia su valor al otro slider (para verlo enseguida) y se envía «pw1=» seguido del valor con get. Get manda 0x71, el valor en 4 bytes y FF FF FF: por eso en el micro el dato útil queda en la posición 5 de la trama. Como el PWM es de 8 bits, el slider va de 0 a 255.

sl2.val=sl1.val
print "pw1="
get sl1.val
1.5

Probar en el simulador

▶ 6:48

Con Debug se ve abajo lo que enviaría la pantalla: al tocar el pulsador aparece led1=on con FF FF FF, y al mover el slider aparece pw1= con el valor. En la página 0 se configura bauds=9600 en Preinitialize.

Fase 2

Circuito y linealización

2.1

Circuito en Proteus

▶ 9:02

El PIC16F877A tiene el LED en RB0, el pulsador en RB1, un sensor de temperatura en AN0, un potenciómetro de velocidad en AN1 y el motor en la salida PWM (RC2). TX y RX van a un puerto serial virtual que se conecta con el simulador de Nextion (o a la pantalla real). Otro terminal virtual sirve solo para monitorear.

2.2

Linealizar la aguja y la barra

▶ 13:38

El valor 0 de la aguja no coincide con el 0 del dibujo, así que se arma una tabla en Excel con el valor medido y el valor que debe recibir la pantalla para marcarlo bien. Se hace un gráfico de dispersión, se agrega la línea de tendencia y se muestran la ecuación y R² (0,99: casi una recta).

Termómetro: y = 0,8654x + 10,032. Velocímetro: como la aguja pasa por 360/0, se hacen dos tramos: por encima de 20, y = 3,152x − 65,949; hasta 20, y = 2,92x + 298,6.

Fase 3

Programa del PIC en MikroC

3.1

Interrupción serial

▶ 21:28

Cada dato que llega se guarda en la trama. Cuando ya hay más de tres datos y los tres últimos son 0xFF, la trama está completa: se activa la bandera y se pausan la recepción y las interrupciones para procesarla. Si llegan 30 datos sin el final de trama, se reinicia para que el micro no se trabe.

void interrupt() {
  if (RCIF_bit == 1) {
    dato = RCREG;
    trama[cuenta] = dato;
    if ((cuenta > 3) && ((unsigned char)trama[cuenta] == 0xff)
        && ((unsigned char)trama[cuenta-1] == 0xff)
        && ((unsigned char)trama[cuenta-2] == 0xff)) {
      flag_rx = 1;      // llegó una trama completa
      CREN_bit = 0;     // pausa la recepción
      GIE_bit = 0;      // y las interrupciones
    }
    cuenta++;
    if (cuenta >= 30) { flag_rx = 0; cuenta = 0; }   // seguridad: sin FF FF FF en 30 datos
    RCIF_bit = 0;
  }
}
3.2

Procesar la orden

▶ 23:44

procesa_rx busca en la trama el texto de cada orden con strstr: enciende o apaga el LED, o toma trama[5] como ciclo útil del PWM. Después limpia la trama y vuelve a habilitar la recepción. manda_serial_const envía cadenas constantes, como los tres 0xFF.

Para enviar números con decimales se usa una función floattostr_ que convierte un float a texto con la cantidad de decimales que se pida.

void procesa_rx() {
  if (flag_rx == 1) {
    if (strstr(trama, "led1=on")) led = 1;
    else if (strstr(trama, "led1=off")) led = 0;
    else if (strstr(trama, "pw1=")) {
      dato = trama[5];          // byte bajo del valor del slider
      PWM1_Set_Duty(dato);
    }
    memset(trama, 0, 30);
    cuenta = 0; flag_rx = 0;
    RCIF_bit = 0; CREN_bit = 1; GIE_bit = 1;   // vuelve a recibir
  }
}

void manda_serial_const(const char *info) {
  while (*info) UART1_Write(*info++);
}
3.3

Programa principal

▶ 26:58

Se configuran entradas y salidas, la UART a 9600, la interrupción de recepción y el PWM. En el ciclo se leen los sensores y se envía cada valor con su orden: el valor digital de la temperatura, el valor linealizado para la barra, la aguja del velocímetro, el texto con dos decimales (entre comillas) y la imagen del LED según el pulsador (imagen 1 encendido, 2 apagado). Cada orden termina con FF FF FF.

void main() {
  TRISA.B0 = 1; TRISA.B1 = 1;     // sensores en AN0 y AN1
  TRISB.B0 = 0;                   // led
  TRISB.B1 = 1;                   // pulsador
  TRISC.B6 = 0; TRISC.B7 = 1;     // TX y RX
  TRISC.B2 = 0;                   // salida PWM (CCP1)
  ADCON1 = 0;
  INTCON = 0b01000000;
  UART1_Init(9600);
  led = 0;
  memset(trama, 0, 30);
  RCIF_bit = 0; RCIE_bit = 1; GIE_bit = 1;
  PWM1_Init(500); PWM1_Set_Duty(100); PWM1_Start();

  while (1) {
    codigo = ADC_Read(0); temperatura = codigo * 500.0 / 1023.0;
    codigo = ADC_Read(1); velocidad = codigo * 100.0 / 1023.0;

    sprinti(envia, "pa1.te2.val=%d", (unsigned int)temperatura);   // valor digital
    UART1_Write_Text(envia); manda_serial_const("\xFF\xFF\xFF");
    temperatura = 0.8654 * temperatura + 10.032;                    // linealizado para la barra
    sprinti(envia, "pa1.te1.val=%d", (unsigned int)temperatura);
    UART1_Write_Text(envia); manda_serial_const("\xFF\xFF\xFF");

    if (velocidad > 20) velocidad_grafica = 3.152 * velocidad - 65.949;
    else                velocidad_grafica = 2.92 * velocidad + 298.6;
    sprinti(envia, "pa0.vel.val=%d", velocidad_grafica);            // aguja
    UART1_Write_Text(envia); manda_serial_const("\xFF\xFF\xFF");

    floattostr_(velocidad, envia, 2);                               // texto con 2 decimales
    manda_serial_const("pa0.ve2.txt=\"");
    UART1_Write_Text(envia);
    manda_serial_const("\"");
    manda_serial_const("\xFF\xFF\xFF");
    Delay_ms(1);

    if (pulsador == 1) manda_serial_const("pa1.led.pic=1");
    else               manda_serial_const("pa1.led.pic=2");
    manda_serial_const("\xFF\xFF\xFF");

    procesa_rx();
    Delay_ms(30);
  }
}

Fase 4

Versión con Arduino

4.1

Recepción con serialEvent

▶ 36:00

En Arduino la recepción se hace en serialEvent con la misma lógica de buscar FF FF FF. Es importante convertir el dato a unsigned char: si no, 0xFF se lee como −1 y la comparación nunca se cumple. procesa_rx usa digitalWrite para el LED y analogWrite para el PWM.

4.2

Ciclo principal

▶ 40:27

El loop es casi igual al del PIC: analogRead, sprintf y Serial.print de cada orden seguida de los tres 0xFF.

char led = 13;
char pulsador = 2;
// ... (pwm, trama[30], cuenta, flag_rx, envia, variables de medida)

void serialEvent() {
  while (Serial.available()) {
    dato = (unsigned char)Serial.read();
    trama[cuenta] = dato;
    if ((cuenta > 3) && ((unsigned char)trama[cuenta] == 0xff)
        && ((unsigned char)trama[cuenta-1] == 0xff)
        && ((unsigned char)trama[cuenta-2] == 0xff))
      flag_rx = 1;
    cuenta++;
    if (cuenta >= 30) { memset(trama, 0, 30); cuenta = 0; }
  }
}

void procesa_rx() {
  if (flag_rx == 1) {
    if (strstr(trama, "led1=on")) digitalWrite(led, HIGH);
    else if (strstr(trama, "led1=off")) digitalWrite(led, LOW);
    else if (strstr(trama, "pw1=")) analogWrite(pwm, trama[5]);
    memset(trama, 0, 30); cuenta = 0; flag_rx = 0;
  }
}

void loop() {
  codigo = analogRead(A0); temperatura = codigo * 5.0 * 100.0 / 1023.0;
  codigo = analogRead(A1); velocidad = codigo * 100.0 / 1023.0;
  sprintf(envia, "pa1.te2.val=%d", (unsigned int)temperatura);
  Serial.print(envia); Serial.print("\xFF\xFF\xFF");
  // ... igual que en el PIC: te1 linealizado, pa0.vel, pa0.ve2.txt y pa1.led.pic
  procesa_rx();
  delay(30);
}

STM32 en VS Code de forma visual: un botón y un script de Python

Cuarta parte de la serie y la forma definitiva de trabajar. Creamos el proyecto VSC_DEFINITIVO con LED y USART1 a 115200, lo abrimos en VS Code y probamos el blink. Luego instalamos la extensión VsCode Action Buttons y en el settings.json del usuario agregamos un botón que ejecuta un script de Python. Ese script detecta el proyecto y, con casillas, agrega al CMakeLists.txt las librerías, el soporte de float, la generación de .hex y .bin y la optimización de Release, y cambia la FPU entre hardware y software. Después solo hay que pegar las librerías en una carpeta Librerias y compilar.

Fase 1

Proyecto base

1.1

Crear el proyecto desde VS Code

▶ 0:33

Desde la pestaña de STM32 en VS Code abrimos CubeMX. Un pin como salida LED, USART1 asíncrono a 115200 (es para el micro real) y el proyecto VSC_DEFINITIVO con toolchain CMake.

En el video el LED quedó primero en PC14 por error y se movió arrastrándolo con Ctrl a PC13; luego se regenera el código y no hace falta reabrir la carpeta.

1.2

Abrir, confiar y configurar CMake

▶ 1:41

Abrimos la carpeta con Abrir con Code, damos Trust si sale Restricted Mode y respondemos Yes a configurar CMake. Si no salió, en las opciones de CMake está Clean Rebuild.

1.3

Blink y depuración

▶ 3:25

Con el autocompletado escribimos el blink, compilamos y con Run and Debug (ST-Link) programamos la tarjeta.

HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(500);
Fase 2

El botón de configuración

2.1

Instalar VsCode Action Buttons

▶ 6:52

En extensiones buscamos e instalamos VsCode Action Buttons (Seun LanLege). Permite poner botones en la barra de estado que ejecutan comandos.

2.2

Agregar el botón en settings.json

▶ 6:52

Con F1 (o Ctrl+Shift+P) abrimos Preferences: Open User Settings (JSON). Antes de la última llave ponemos una coma y pegamos el bloque actionButtons: nombre del botón, color y el comando que ejecuta el script con pythonw.

La ruta del script se obtiene con clic derecho > Copiar como ruta de acceso; en JSON cada \\ se escribe doble (una IA te la puede convertir).

"actionButtons": {
    "defaultColor": "white",
    "loadNpmCommands": false,
    "commands": [
        {
            "name": "⚙ CMake ARZ",
            "color": "yellow",
            "command": "pythonw \"D:\\ruta\\a\\cmakelist_Python.py\""
        }
    ]
}

Cambia la ruta por la de tu archivo cmakelist_Python.py. Guarda con Ctrl+S, cierra VS Code y vuelve a abrirlo (o usa Refresh Buttons) para ver el botón.

Fase 3

Usar el script

3.1

Opciones del generador

▶ 10:20

Al pulsar el botón se abre el Generador CMake, que detecta la carpeta del proyecto. Opciones para CMakeLists.txt:

Incluir ruta de librerías automáticas (addlib).

Usar librerías float para sprintf y math.h (-lm).

Generar archivos de salida .HEX y .BIN.

Optimización de Release: -O2 recomendado, -O3 máximo rendimiento, -Os menor tamaño.

En gcc-arm-none-eabi.cmake: modo FPU hardware (micro real) o software (Proteus).

Si una opción ya estaba agregada, el script lo indica y no la duplica.

3.2

Agregar librerías y compilar

▶ 12:01

En Core creamos la carpeta Librerias (mayúsculas o minúsculas) y pegamos uart.c y uart.h. Al compilar ya las detecta, sin tocar el CMakeLists.txt, y genera .elf, .hex y .bin.

#include "uart.h"

uartx_write_text(&huart1, "INICIANDO\r\n");

while (1)
{
  HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
  HAL_Delay(500);
  uartx_write_text(&huart1, "suscribete al canal\r\n");
}
3.3

Flotantes y Proteus

▶ 17:37

Con una variable float y sprintf, Proteus se quedaba en cero. Abriendo el botón y eligiendo FPU: Software, compila y la simulación cuenta bien. Para el micro real se vuelve a Hardware, que es más rápido.

#include <stdio.h>
#include <string.h>

char buffer[50];
float cont = 0.1;

cont += 0.2;
sprintf(buffer, "contador=%.2f\r\n", cont);
uartx_write_text(&huart1, buffer);

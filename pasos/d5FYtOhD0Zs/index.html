Entradas, pull-up/pull-down, if y rebote

Clase del semestre 2024-I sobre entradas digitales. Se revisan las opciones de las salidas (nivel inicial, push-pull y open drain) y se conectan dos pulsadores en Proteus, uno a tierra con pull-up y otro a positivo con pull-down. Se lee cada entrada con HAL_GPIO_ReadPin, se acorta con #define y se corrige la lógica invertida con la negación. Luego se usan las resistencias internas del STM32 y, con el condicional if, se cambia el estado del LED en cada pulsación, eliminando el rebote con un retardo y usando else.

Fase 1

Opciones de las salidas

1.1

Dos salidas con etiqueta

▶ 4:33

Crea un proyecto para el STM32F401 y configura PA1 y PA2 como GPIO_Output con las etiquetas LED1 y LED2.

1.2

Ventana de configuración GPIO

▶ 5:18

En System Core → GPIO aparecen todos los pines usados. Al seleccionar uno puedes elegir el GPIO output level: si arranca en alto o en bajo sin escribir código.

1.3

Push-pull u open drain

▶ 5:52

Output Push Pull: el micro saca tanto el 0 como el 1 (3.3 V). Es lo normal.

Output Open Drain: el micro solo saca el 0. Con una resistencia externa a 5 o 12 V, el 1 lo pone esa fuente: sirve para dar niveles lógicos mayores a un PLC o a un MOSFET sin conversor de nivel.

Open drain es para señales lógicas, no para alimentar cargas de potencia.

Fase 2

Entradas con pull-up y pull-down

2.1

Dos entradas

▶ 10:54

Configura PB0 y PB1 como GPIO_Input con las etiquetas SW1 y SW2.

2.2

Pulsadores en Proteus

▶ 15:13

Coloca dos BUTTON: uno de PB0 a tierra y otro de PB1 a positivo.

Un pulsador solo garantiza un estado: el de tierra da 0 al cerrar, pero abierto la entrada queda flotante (no se sabe si es 0 o 1).

2.3

Resistencia pull-up

▶ 18:03

Si el pulsador va a tierra, pon una resistencia al positivo: pull-up. Cerrado lee 0, abierto lee 1. Valores de 1 kΩ a 47 kΩ.

2.4

Resistencia pull-down

▶ 19:48

Si el pulsador va a positivo, pon una resistencia a tierra: pull-down. Cerrado lee 1, abierto lee 0. Recomendado entre 330 Ω y 1 kΩ.

Algunos libros usan pull-down de 10 kΩ: funciona en el aula, pero en un equipo real deja una tierra débil que deja entrar ruido.

Fase 3

Leer una entrada

3.1

El LED copia la entrada

▶ 27:10

Agrega dos LED con resistencia de 220–330 Ω a PA1 y PA2.

En el while escribe en el LED lo que lees del pulsador con HAL_GPIO_ReadPin.

HAL_GPIO_WritePin(LED1_GPIO_Port, LED1_Pin,
                  HAL_GPIO_ReadPin(SW1_GPIO_Port, SW1_Pin));
3.2

Nombres cortos con #define

▶ 35:32

Esa línea es larga. Define un nombre corto para cada lectura arriba del main (por ejemplo en USER CODE BEGIN PD).

#define SW1 HAL_GPIO_ReadPin(SW1_GPIO_Port, SW1_Pin)
#define SW2 HAL_GPIO_ReadPin(SW2_GPIO_Port, SW2_Pin)

/* en el while */
HAL_GPIO_WritePin(LED1_GPIO_Port, LED1_Pin, SW1);
HAL_GPIO_WritePin(LED2_GPIO_Port, LED2_Pin, SW2);

En el #define no va signo igual ni punto y coma.

3.3

Invertir la lógica

▶ 41:32

Al simular, un LED arranca encendido y el otro apagado: uno de los pulsadores está con pull-up (lee 1 en reposo).

Para que ambos arranquen apagados, niega la lectura del que tiene pull-up con ! (negación de un solo bit).

HAL_GPIO_WritePin(LED1_GPIO_Port, LED1_Pin, !SW1);
3.4

Pull-up y pull-down internos

▶ 44:47

El STM32 trae resistencias internas: quita las externas y en GPIO → GPIO Pull-up/Pull-down elige Pull-up para el pulsador a tierra y Pull-down para el que va a positivo.

Útil para ahorrar espacio en el PCB. Arduino solo tiene pull-up interna; el STM32 tiene ambas.

Fase 4

El condicional if y el antirrebote

4.1

Sintaxis del if

▶ 48:49

if (condición) acción; Si hay una sola acción las llaves son opcionales; con varias son obligatorias.

Comparadores: == igual, >, <, >=, <= y != diferente.

Un solo = asigna; para comparar se usa ==. Es uno de los errores más comunes.

4.2

Toggle al presionar

▶ 52:18

Ahora el LED no copia el pulsador: cada vez que presionas cambia de estado con HAL_GPIO_TogglePin.

if (SW1 == 1)
  HAL_GPIO_TogglePin(LED1_GPIO_Port, LED1_Pin);
4.3

Rebote y antirrebote

▶ 55:18

Al simularlo a veces cambia y a veces no: las láminas del pulsador vibran y cierran muchas veces en pocos milisegundos (rebote).

Por software se elimina con un retardo de 150 ms o más después de detectar la pulsación (en clase 500 ms para verlo mejor). Ahora son dos acciones, así que van llaves.

if (SW1 == 1)
{
  HAL_GPIO_TogglePin(LED1_GPIO_Port, LED1_Pin);
  HAL_Delay(500);   // antirrebote
}
4.4

if con else

▶ 68:41

Con else el segundo bloque solo se ejecuta cuando la condición es falsa: si presionas, cambia LED1; si no, LED2 sigue parpadeando.

if (SW1 == 1)
{
  HAL_GPIO_TogglePin(LED1_GPIO_Port, LED1_Pin);
  HAL_Delay(500);
}
else
{
  HAL_GPIO_TogglePin(LED2_GPIO_Port, LED2_Pin);
  HAL_Delay(100);
}

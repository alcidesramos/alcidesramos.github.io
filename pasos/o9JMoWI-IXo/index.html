Tipos de variables en C

Décima lección del curso. Con la tabla de la ayuda de MikroC se repasan los tipos de variables, su tamaño y su rango, y con ejemplos cotidianos se muestra cómo escoger el tipo justo para no gastar memoria ni tiempo de cálculo. Luego se declara una variable contador que alterna dos procedimientos, un vector con un juego de luces que se recorre con el contador, y al final se convierte el vector en constante para pasarlo de la RAM a la ROM, comprobándolo en las estadísticas de MikroC.

Fase 1

Los tipos de variables

1.1

La tabla en la ayuda

▶ 0:00

Un microcontrolador tiene muy poca memoria, así que hay que escoger bien cada variable. En la ayuda de MikroC, buscando arithmetic types, está la tabla con los tipos, su tamaño y su rango.

1.2

bit y sbit

▶ 0:34

bit ocupa un solo bit (0 o 1) y sirve como bandera. sbit también vale 0 o 1, pero está asociado a un pin del micro. Los dos son propios de MikroC, no del C estándar.

1.3

char: un byte

▶ 2:12

unsigned char ocupa un byte y va de 0 a 255; sirve, por ejemplo, para contar alumnos de un salón. signed char usa un bit para el signo y va de −128 a 127, por ejemplo para una temperatura entera.

Se recomienda usar char en vez de short: en Arduino un unsigned short ocupa 2 bytes, y al pasar código de un compilador a otro puede dar problemas.

1.4

int y long

▶ 5:33

unsigned int ocupa 2 bytes (0 a 65.535) y int va de −32.768 a 32.767. unsigned long ocupa 4 bytes (hasta unos 4.294 millones) y long va de unos −2.147 a 2.147 millones.

Usar un tipo más grande del necesario no solo gasta memoria: las multiplicaciones y divisiones también son más lentas.

1.5

float y double

▶ 8:51

Para números con decimales, como una nota, se usa float, de 4 bytes. Las operaciones con float son mucho más lentas que con enteros, así que solo se usa cuando hace falta. En estos micros de 8 bits, double es igual que float.

Fase 2

Declarar y usar variables

2.1

Cómo se declaran

▶ 10:28

Se escribe el tipo, el nombre y punto y coma, o el tipo, el nombre y un valor inicial. Las variables globales sirven en cualquier parte del programa y se recomienda declararlas al inicio, antes de los procedimientos.

char contador;
unsigned int transporte = 15000;
unsigned long rumba;
float nota = 2.4;
2.2

Programa con un contador

▶ 14:29

Se crea el proyecto variables en la carpeta clase 10 (PIC16F877A a 4 MHz, XT) y se copian los procedimientos hola() y baja(). Una variable contador hace que se muestre la cuenta regresiva varias veces y luego HOLA, y vuelve a empezar.

#define display PORTD
char contador = 0;   // variable con valor inicial

while (1) {
  if (contador >= 3) hola();
  else baja();
  if (contador >= 5) contador = 0;   // reinicia el conteo
  contador = contador + 1;           // o contador++;
}
Fase 3

Vectores y constantes

3.1

Declarar un vector

▶ 20:54

Un vector (arreglo) se declara con el tamaño entre corchetes y sus posiciones empiezan en 0. Se le pueden dar valores iniciales entre llaves, en decimal, binario o hexadecimal; si se dan los valores, el tamaño se puede omitir porque el compilador lo cuenta.

char luces[3];
luces[0] = 5;
char efecto[] = {0, 0b00000001, 0x0F};

Si el tamaño es menor que la cantidad de valores, el compilador da el error "Too many initializers".

3.2

Juego de luces con un vector

▶ 23:38

Se guarda cada paso del juego de luces en un vector y se recorre con el contador. Para cambiar el efecto solo se cambian los valores y el límite.

char luces[] = {0, 0b00000001, 0b00000010, 0b00000100,
                0b00001000, 16, 32, 64, 128};

while (1) {
  PORTB = luces[contador];
  Delay_ms(200);
  contador++;
  if (contador > 8) contador = 0;
}
3.3

const para ahorrar RAM

▶ 28:12

Los datos que nunca cambian conviene declararlos con const: así se guardan en la ROM (unas 8.000 palabras en este micro) y no en la RAM (solo unos 350 bytes). Una constante siempre debe tener valor y no se puede cambiar durante el programa.

const char luces[] = {0, 0b00000001, 0b00000010, 0b00000100,
                      0b00001000, 16, 32, 64, 128};
3.4

Comprobar con las estadísticas

▶ 29:51

En el botón de Statistics de MikroC se ve el uso de memoria: sin const la RAM usada era 12; con const bajó a 3, mientras la ROM subió un poco.

Ocho servos con CCS

Un usuario pidió llevar a CCS el programa de 8 servos que antes se hizo en MikroC. Se crea el proyecto con el asistente de CCS (PIC16F877A a 4 MHz, Timer1 con prescaler 1 y su interrupción, pines de los servos en los puertos B y C). Luego se adapta la librería: en CCS el int es de 8 bits, así que las variables pasan a int16 e int32; los valores del timer se cargan directo con set_timer1 porque una variable temporal dentro de la interrupción daba retardos, y las constantes se vuelven variables normales porque CCS no dejaba usarlas igual que MikroC. Al final se simula en Proteus con el osciloscopio y se compara cuánta memoria gasta cada compilador.

Fase 1

Proyecto con el asistente

1.1

El circuito

▶ 0:00

Es el mismo montaje del video de MikroC: un PIC16F877A con ocho servos, seis en RB0 a RB5 y dos en RC0 y RC1. La idea es ver qué cambia al pasar el código a CCS.

1.2

Timer1 e interrupción

▶ 2:45

En el asistente se elige el PIC16F877A a 4 MHz y se habilita el Timer1 con prescaler 1: cada paso es 1 µs y desborda en unos 65,5 ms. También se marca la interrupción del Timer1.

1.3

Pines de salida

▶ 3:55

En la pestaña de entradas y salidas se ponen como salida RB0 a RB5 y RC0, RC1, y se les da nombre. El asistente guarda todo en un archivo .h.

1.4

El archivo .h que crea CCS

▶ 4:52

El .h trae el micro, el cristal, los pines fijos y los nombres de los servos.

#include <16F877A.h>
#device ADC=10
#use delay(crystal=4MHz)
#use FIXED_IO( B_outputs=PIN_B5,PIN_B4,PIN_B3,PIN_B2,PIN_B1,PIN_B0 )
#use FIXED_IO( C_outputs=PIN_C1,PIN_C0 )
#define SERVO1 PIN_B0
// ... SERVO2 a SERVO6 en PIN_B1 a PIN_B5
#define SERVO7 PIN_C0
#define SERVO8 PIN_C1
Fase 2

Pasar la librería a CCS

2.1

Tipos de datos distintos

▶ 6:02

En MikroC las variables eran unsigned int de 16 bits. En CCS el int es de 8 bits, el long de 16 y el long long de 32, así que todas se cambian a int16 e int32.

int16 servos[8];
const int32 cristal=4000; //colocar e valor del cristal en kiloHZ
float tmr1_reg=65536.0 -((cristal*2.5)/(4.0));
float tmr1_reg_ini=65536.0 -((cristal*1.5)/(4.0));
int16 tmr1_1_5ms=tmr1_reg_ini;
int16 tmr1_2_5ms=tmr1_reg;
int32 tmr1_periodo=65536+ tmr1_2_5ms;
2.2

Arranque de la librería

▶ 7:17

init_servos recibe el pulso mínimo y máximo en milisegundos, calcula la pendiente para pasar de grados a tiempo y pone todos los pines en cero con output_bit.

void init_servos(float pwm_min_,float pwm_max_){
  if(pwm_max_>=2.5) pwm_max_=2.49;
  _m=(pwm_max_-pwm_min_)/180.0;
  pwm_min=pwm_min_;
  //COLOC LOS PINES EN CERO
  output_bit(SERVO1,0);
  // ... igual para SERVO2 a SERVO8
}
2.3

La máquina de estados

▶ 7:55

Cada interrupción sube o baja un servo. En MikroC el valor del timer pasaba por una variable temporal, pero en CCS eso metía retardos dentro de la interrupción, así que se carga directo con set_timer1.

case hi_1: {
  output_bit(SERVO1,1);
  set_timer1(servos[0]);
  estado_servos=lo_1;
}break;
case lo_1: {
  output_bit(SERVO1,0);
  set_timer1(tmr1_periodo-servos[0]);
  estado_servos=hi_2;
}break;
// ... igual hasta hi_8 / lo_8
Fase 3

Programa principal y prueba

3.1

Interrupción y main

▶ 9:32

La interrupción del Timer1 solo llama a servos_interrupcion. En el main se ponen los puertos como salida, se configura el timer con prescaler 1, se inicia la librería entre 0,5 y 2,5 ms y se habilitan las interrupciones. El while es el mismo del programa de MikroC: un servo_valor por cada servo.

#include <servoscc.h>
#include <Servos_T1.h> //incluye la libreroa de servo

#INT_TIMER1
void TIMER1_isr(void){
  servos_interrupcion();
}

void main(){
  //salida port b y c
  set_tris_b(0);
  set_tris_c(0);
  output_c(0);
  setup_timer_1(T1_INTERNAL|T1_DIV_BY_1); //65,5 ms overflow
  init_servos(0.5,2.5);
  set_timer1(0);
  enable_interrupts(INT_TIMER1);
  clear_interrupt(INT_TIMER1);
  enable_interrupts(GLOBAL);
  while(TRUE){
    // servo_valor(...) para cada servo, igual que en MikroC
  }
}
3.2

Constantes como variables

▶ 13:42

En MikroC algunos valores eran constantes para guardarlos en la memoria de programa. CCS daba conflictos con eso, así que se dejan como variables normales en RAM.

3.3

Simulación

▶ 14:16

En el osciloscopio de Proteus salen las señales de los servos. Si un servo no llega al ángulo exacto, se ajustan los límites de init_servos, por ejemplo 0,6 y 2,4 ms.

3.4

MikroC contra CCS

▶ 15:10

En las estadísticas, CCS usa cerca del 25 % de la RAM y MikroC el 12,5 %. CCS trabaja con funciones ya hechas para cada periférico, y eso suele gastar algo más de memoria que escribir en los registros directamente.

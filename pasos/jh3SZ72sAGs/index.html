else if y lectura de puertos: resumen

Versión corta y narrada de nuevo de la clase de condicionales y lectura de puertos (el audio original salió mal). Se combinan dos pulsadores con && y se optimiza con else if cuando los casos son excluyentes. Luego se lee un thumbwheel BCD con GPIOB->IDR, se enmascaran los bits con AND y se desplazan con >> cuando el dato está en PB12–PB15 o PB3–PB6. También se muestra cuándo no aplica else if: si las condiciones pueden cumplirse a la vez.

Fase 1

if, else if y casos excluyentes

1.1

Condiciones con && y ||

▶ 0:33

Para agrupar condiciones se usan los operadores dobles: && (Y) y || (O).

Casos del ejercicio: ambos en 1 → titila LED1; SW1=1 y SW2=0 → titila LED2; ambos en 0 → titilan los dos; solo SW2 → se apagan.

1.2

Corregir la lógica de un pulsador

▶ 1:41

En Proteus un pulsador tiene pull-up y otro pull-down. Para leer ambos igual, niega en el #define el que está al revés.

#define in1 HAL_GPIO_ReadPin(in1_GPIO_Port, in1_Pin)
#define in2 !(HAL_GPIO_ReadPin(in2_GPIO_Port, in2_Pin))
1.3

Por qué else if

▶ 4:09

Los casos son mutuamente excluyentes: solo uno puede cumplirse. Con if separados el procesador evalúa todos; con else if se detiene en el primero que se cumple.

if ((in1 == 1) && (in2 == 1))
{
  HAL_GPIO_TogglePin(led1_GPIO_Port, led1_Pin);
  HAL_Delay(500);
  HAL_GPIO_WritePin(led2_GPIO_Port, led2_Pin, 0);
}
else if ((in1 == 1) && (in2 == 0))
{
  HAL_GPIO_TogglePin(led2_GPIO_Port, led2_Pin);
  HAL_Delay(500);
  HAL_GPIO_WritePin(led1_GPIO_Port, led1_Pin, 0);
}
else if ((in1 == 0) && (in2 == 0))
{
  HAL_GPIO_TogglePin(led1_GPIO_Port, led1_Pin);
  HAL_GPIO_TogglePin(led2_GPIO_Port, led2_Pin);
  HAL_Delay(500);
}
else
{
  HAL_GPIO_WritePin(led1_GPIO_Port, led1_Pin, 0);
  HAL_GPIO_WritePin(led2_GPIO_Port, led2_Pin, 0);
}
Fase 2

Leer el puerto completo

2.1

Thumbwheel en los pines bajos

▶ 5:17

En Proteus busca THUMBSWITCH-BCD y conéctalo a PB0–PB3. Configura esos pines como entradas (no necesitan etiqueta porque se lee el puerto completo).

2.2

Registro IDR

▶ 6:26

Escribe GPIOB->IDR dentro del while para que el autocompletado te ayude; luego córtalo y llévalo a un #define.

#define lecturas (GPIOB->IDR)
2.3

Comparar con máscara

▶ 7:34

Guarda la lectura en una variable de 16 bits. Comparar directo no funciona porque el resto del puerto también aparece en IDR.

Pon en 0 lo que no interesa con una AND (un solo &, no el && de las condiciones).

uint16_t codigo;
codigo = lecturas & 0x0F;
if (codigo == 7)
{
  HAL_GPIO_TogglePin(led1_GPIO_Port, led1_Pin);
  HAL_Delay(500);
}
Fase 3

Datos en otros pines

3.1

Thumbwheel en PB12–PB15

▶ 9:49

Si el número entra por los pines altos, ya no vale 7 sino 0x7000. Se podría comparar así, pero es más claro desplazarlo.

Desplaza 12 posiciones a la derecha y luego aplica la máscara de 4 bits.

codigo = lecturas >> 12;
codigo = codigo & 0b1111;
if (codigo == 7) { /* ... */ }

Conocer el micro evita soluciones como usar otra placa solo porque una librería espera los datos en los primeros pines.

3.2

Condiciones que no son excluyentes

▶ 14:41

Agrega if (codigo <= 8) para LED2. Aquí no sirve else if: el 7 cumple las dos condiciones, así que van dos if independientes.

if (codigo == 7)
{
  HAL_GPIO_TogglePin(led1_GPIO_Port, led1_Pin);
  HAL_Delay(500);
}
if (codigo <= 8)
{
  HAL_GPIO_TogglePin(led2_GPIO_Port, led2_Pin);
  HAL_Delay(500);
}
3.3

Datos en PB3–PB6

▶ 16:24

Si los pines están en el centro del puerto, se desplaza solo 3 posiciones. Si el dato está repartido en dos puertos, desplaza cada parte y únelas con OR.

codigo = (lecturas >> 3) & 0b1111;

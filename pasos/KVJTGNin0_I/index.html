Clase 15: Ahorrar RAM con Heap y Stack

Con micros grandes no nos fijamos en la RAM, pero en uno pequeño como el STM32L010F4 (Cortex-M0+, 16 KB de Flash, 128 B de EEPROM y solo 2 KB de RAM) importa mucho. Por defecto STM32CubeMX reserva Minimum Heap Size = 0x200 (512 B) y Minimum Stack Size = 0x400 (1 KB): 1,5 KB usados sin escribir una línea. Si no usamos memoria dinámica (malloc/free) el Heap puede ir en 0x0; el Stack se puede reducir, pero con cuidado porque depende de cuántas funciones se llaman unas a otras.

Fase 1

El problema

1.1

Un micro con 2 KB de RAM

▶ 0:15

El STM32L010F4P6 es un Cortex-M0+ de bajo costo: 16 KB de Flash, 128 bytes de EEPROM y 2 KB de RAM.

1.2

Los valores por defecto

▶ 1:20

En Project Manager → Linker Settings CubeMX pone Minimum Heap Size = 0x200 (512 B, memoria dinámica) y Minimum Stack Size = 0x400 (1 KB, la pila para llamadas a funciones).

1.3

Proyecto vacío y ya sin RAM

▶ 2:00

Generamos el código sin agregar nada y compilamos. El Build Analyzer muestra 1,5 KB de RAM usados y solo 464 bytes libres.

Fase 2

Reducir Heap y Stack

2.1

Heap en cero

▶ 2:12

Si tu programa no usa malloc, calloc ni free (memoria dinámica), el Heap puede ir en 0x0. Se usa sobre todo con sistemas operativos de tiempo real o programación más avanzada; para declarar variables normales no hace falta.

Al regenerar y compilar, la RAM usada baja a cerca de 1 KB.

Escríbelo siempre en hexadecimal: 0x0, no 0.

2.2

Stack más pequeño, con cuidado

▶ 3:48

La pila guarda las llamadas a funciones: si una rutina llama a otra que llama a otra, se puede desbordar. En el video se baja a 0x40 (64 bytes). Funciona para programas sencillos; si usas muchas librerías de terceros o mucha HAL (con muchas llamadas internas), deja más espacio.

Minimum Heap Size  = 0x0
Minimum Stack Size = 0x40
2.3

Resultado

▶ 4:53

Tras regenerar y compilar, la RAM usada queda en 112 bytes (los 64 de la pila más lo que usa la HAL). Casi los 2 KB quedan libres para tu programa. Después prueba bien que todo funcione.

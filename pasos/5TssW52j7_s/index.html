Usar el watchdog para encontrar bloqueos

El watchdog es un contador con su propio oscilador, independiente del cristal, que resetea el micro si llega al final de su tiempo. Además de evitar que el micro quede bloqueado, sirve para analizar el código: saber dónde se queda pegado o cuánto tarda un ciclo. Con un PIC16F1824 se prueba primero con el watchdog siempre activo (unos 2 s por defecto) y luego controlado por software: se fija el tiempo con los bits WDTPS, se prende el watchdog con SWDTEN antes del ciclo a analizar y se apaga al salir. Si el micro se resetea, ese ciclo tarda más de lo permitido o nunca termina.

Fase 1

El watchdog

1.1

Qué es

▶ 0:00

El watchdog es un contador que, al terminar su tiempo, resetea el micro. Se puede activar siempre desde los bits de configuración o manejar por software. Tiene un oscilador propio, independiente del cristal, así que su base de tiempo no cambia con el cristal.

1.2

Registro WDTCON

▶ 1:05

En el PIC16F1824, los bits WDTPS<4:0> escogen el tiempo, desde 1 ms hasta 256 s (por defecto unos 2 s). El bit SWDTEN lo prende (1) o lo apaga (0) cuando se controla por software.

Fase 2

Prueba básica

2.1

Watchdog siempre activo

▶ 2:46

Proyecto a 4 MHz con el watchdog habilitado en Edit Project. Al iniciar, el programa prende un LED un momento y manda "INICIANDO" por el serial: si eso se repite, el micro se está reseteando.

TRISA = 0;
TRISC = 0;
UART1_Init(9600);
LATC1_bit = 1;   // LED de reinicio
Delay_ms(100);
LATC1_bit = 0;
UART1_Write_Text("INICIANDO\r\n");

while (1) {
  UART1_Write_Text("WHILE\r\n");
  LATC0_bit = ~LATC0_bit;
  Delay_ms(100);
}
2.2

Resultado

▶ 6:19

Con el watchdog siempre activo y sin limpiarlo, el micro se resetea cada 2 s aproximadamente: aparece de nuevo "INICIANDO".

Fase 3

Control por software

3.1

Tiempo y SWDTEN

▶ 6:53

En Edit Project se deja el watchdog controlado por SWDTEN. Al inicio se apaga y se fija el tiempo, por ejemplo 4 s (WDTPS = 01100). Antes del ciclo a analizar se prende.

SWDTEN_bit = 0;   // apaga el perro guardián
// preescalado del watchdog: 4 s
WDTPS4_bit = 0;
WDTPS3_bit = 1;
WDTPS2_bit = 1;
WDTPS1_bit = 0;
WDTPS0_bit = 0;
3.2

Medir un ciclo

▶ 9:18

Se prende el watchdog antes de un for y se apaga al salir. Si el micro se resetea, el ciclo tarda más que el tiempo del watchdog. Con 2 s se resetea y con 4 s no: el ciclo dura entre 2 y 4 s.

while (1) {
  UART1_Write_Text("WHILE\r\n");
  Delay_ms(300);
  SWDTEN_bit = 1;   // prende el perro
  for (cont = 0; cont <= 10; cont++) {
    UART1_Write_Text("for\r\n");
    LATC0_bit = ~LATC0_bit;
    Delay_ms(100);
  }
  SWDTEN_bit = 0;   // apaga el perro
}
3.3

Detectar un bucle infinito

▶ 13:44

Se cambia el for por un while que nunca termina. Como el watchdog nunca se apaga, el micro se resetea. Poniendo el watchdog al inicio y al final de cada ciclo se encuentra cuál deja el programa bloqueado, por ejemplo uno que espera respuesta de un GPS o un módem que no llega.

SWDTEN_bit = 1;   // prende el perro
while (1 == 1) {
  UART1_Write_Text("for\r\n");
  LATC0_bit = ~LATC0_bit;
  Delay_ms(100);
}
SWDTEN_bit = 0;   // nunca llega aquí

Si el puerto serial está ocupado con otro equipo, un LED que se prende al iniciar sirve para ver si el micro se está reseteando.

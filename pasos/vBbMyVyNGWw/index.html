Leer cuatro frecuencias con CCP

Lección 38 del curso. El modo captura del módulo CCP guarda el valor del Timer1 en cada flanco de subida; con dos capturas seguidas se saben los pasos entre flancos y de ahí la frecuencia. Se usan los cuatro CCP de un PIC16F1824 de 14 pines, se remapean pines, se activan pull-ups y en la interrupción se usan banderas para no reprocesar un dato. La frecuencia se calcula en el programa principal y se pone en cero cuando la señal desaparece.

Fase 1

El circuito

1.1

Cuatro CCP

▶ 2:10

El PIC16F1824 tiene CCP1 a CCP4. CCP2 y el UART se pueden remapear a otros pines. Las cuatro entradas de frecuencia van a CCP1 a CCP4 y un led parpadea lento para mostrar que el programa sigue libre.

1.2

Señales de prueba

▶ 3:52

En Proteus hay generadores de 100 Hz, 500 Hz y 1 kHz, y con selectores se elige qué frecuencia entra en cada canal o se deja abierto.

1.3

En la práctica

▶ 4:27

Con sensores reales conviene usar pull-up en cada entrada y un capacitor pequeño a tierra para evitar ruido, sobre todo con cables largos.

1.4

Proyecto

▶ 6:05

Proyecto con el PIC16F1824 y oscilador interno a 8 MHz. A mayor frecuencia de reloj se pueden leer frecuencias más altas, pero no tan bajas.

Fase 2

Cómo se mide

2.1

Variables y banderas

▶ 8:15

Para cada canal hay una frecuencia, los pasos y dos capturas. Las banderas se agrupan como bits de una sola variable con sbit.

sbit led at LATC0_bit;
char texto[50];   // mandar informacion serial
float frecuencia1 = 0, frecuencia2 = 0, frecuencia3 = 0, frecuencia4 = 0;
unsigned int pulsos1 = 0, pulsos2 = 0, pulsos3 = 0, pulsos4 = 0;
unsigned int pulsos1_1 = 0, pulsos1_2 = 0;   // y asi para cada canal

char interrupcionfrec_flag = 0;
// banderas de procesamiento de pulsos
sbit procesa1flag at interrupcionfrec_flag.B0;
// banderas de procesamiento de frecuencia
sbit flag_frec1 at interrupcionfrec_flag.B4;
2.2

Modo captura

▶ 8:49

El CCP está ligado al Timer1 de 16 bits. Con CCPxM en 0101 captura el valor del timer en cada flanco de subida.

2.3

Dos casos

▶ 11:01

Si la segunda captura es mayor que la primera, los pasos son la resta. Si el timer se desbordó entre las dos, se resta la primera de 65535 y se suma la segunda.

Fase 3

Configurar

3.1

Main

▶ 18:16

Se fija el oscilador interno, PEIE, todo digital y como entrada salvo TX y el led. Se remapean RX a RA1 y TX a RA0, y CCP2 a RA5.

TRISC0_bit = 0;   // salida led
UART1_Init(9600);
TRISA0_bit = 0;   // salida TX
// remapeo pines
RXDTSEL_bit = 1;   // RX en RA1 sino RC5
TXCKSEL_bit = 1;   // TX en RA0 sino RC4
3.2

Configurar cada captura

▶ 21:07

Para cada CCP: el pin como entrada, el Timer1 con prescalador 1:1 y en cero, el modo de captura por subida, la bandera limpia, la interrupción habilitada y el timer prendido. Si se usa prescalador hay que incluirlo en la fórmula.

void config_captura4()
{
  TRISC1_bit = 1;   // pin de captura como entrada
  T1CON = 0;        // configuracion del timer
  T1CKPS1_bit = 0;  // preescalador 1:1
  T1CKPS0_bit = 0;
  TMR1L = 0;        // limpia registros del timer
  TMR1H = 0;
  CCP4CON = 0;      // configuracion ccp
  CCP4M3_bit = 0;   // captura cada flanco de subida (0101)
  CCP4M2_bit = 1;
  CCP4M1_bit = 0;
  CCP4M0_bit = 1;
  CCP4IF_bit = 0;   // limpia la bandera
  CCP4IE_bit = 1;   // activa interrupcion del modulo ccp4
  TMR1ON_bit = 1;   // arranca el timer
}

Pull-ups

Se habilitan las pull-ups internas en los cuatro pines de captura y luego GIE. El programa principal solo cambia el led cada segundo.

Fase 4

Interrupción y cálculo

4.1

Evitar reprocesar

▶ 27:13

Todas las interrupciones del PIC16 entran por una sola función. Si mientras se procesa un CCP entra otro, al volver se podría procesar de nuevo el primero. Una bandera propia en 1 al entrar y en 0 al salir lo evita.

4.2

Captura en la interrupción

▶ 30:00

Se arma el valor de 16 bits con CCPR1H y CCPR1L, se calculan los pasos según el caso, la captura nueva pasa a ser la anterior y se avisa al programa principal. Se repite para CCP2, CCP3 y CCP4 con sus variables.

if (CCP1IF_bit == 1)   // si es del ccp1
{
  if (procesa1flag == 0)   // solo entra si el dato ya fue procesado
  {
    procesa1flag = 1;   // para evitar bug de reprocesamiento
    pulsos1_2 = (CCPR1H << 8) | CCPR1L;   // captura el valor timer
    TMR1ON_bit = 1;   // toca arrancar de nuevo el timer
    if (pulsos1_2 > pulsos1_1) pulsos1 = pulsos1_2 - pulsos1_1;
    else pulsos1 = (65535 - pulsos1_1) + pulsos1_2;
    pulsos1_1 = pulsos1_2;
    flag_frec1 = 1;   // habilita bandera de dato valido de frecuencia 1
    procesa1flag = 0;
  }
  CCP1IF_bit = 0;
}
4.3

Calcular la frecuencia

▶ 34:24

Las frecuencias se ponen en cero al empezar, así que si una señal se quita el valor cae a cero. Antes de dividir se revisa que los pasos no sean cero. La frecuencia es el reloj entre los pasos por 4.

void procesa_frecuencias()
{
  // pone en cero para poder resetear cuando no hay senal
  frecuencia1 = 0; frecuencia2 = 0; frecuencia3 = 0; frecuencia4 = 0;
  if (flag_frec1 == 1)
  {
    if (pulsos1 != 0) frecuencia1 = Clock_kHz() * 1e3 / (pulsos1 * 4.0);   // convierte a Hercios
    flag_frec1 = 0;
  }
  // igual para las frecuencias 2, 3 y 4
}
4.4

Resultado

▶ 38:21

Las cuatro frecuencias se mandan por serial con dos decimales. Al mover los selectores cambian los valores, y al abrir un canal su frecuencia pasa a cero, mientras el led sigue a su ritmo.

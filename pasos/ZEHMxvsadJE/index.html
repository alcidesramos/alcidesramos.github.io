Clase 20: Retardos en microsegundos y melodías

El oído humano escucha de 20 Hz a 20 kHz. Para generar esos tonos necesitamos retardos en microsegundos, que HAL no trae. Usamos el contador de ciclos DWT de los Cortex-M3 en adelante (visto en la clase 18) para crear delay_us_dwt(), lo comprobamos con un analizador lógico y luego armamos Sound_play() para generar una frecuencia durante un tiempo. Con ella se toca cualquier melodía. Al final, cómo conectar el parlante con un transistor Darlington.

Fase 2

Retardo en microsegundos

2.1

Variable y procedimientos

▶ 3:52

En USER CODE BEGIN PV la variable uint32_t pasos; (ciclos por microsegundo). En USER CODE BEGIN 0 los procedimientos:

uint32_t pasos;

// retardos usando el timer del debugger
void delay_us_init()
{
  CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
  DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
  pasos = (HAL_RCC_GetHCLKFreq() / 1000000); // ciclos en 1 us
}

// retardo por debugger
void delay_us_dwt(uint32_t reta)
{
  DWT->CYCCNT = 0;
  while (DWT->CYCCNT <= pasos * reta);
}
2.2

Cómo funciona

▶ 4:24

HAL_RCC_GetHCLKFreq() devuelve la frecuencia del reloj; dividida entre un millón da los ciclos por microsegundo (72 a 72 MHz). delay_us_dwt borra el contador y espera hasta llegar a pasos × reta ciclos. Es más preciso con relojes altos; a frecuencias bajas pesa la multiplicación.

Funciona en Cortex-M3 en adelante (tienen DWT). Para M0 hay otra opción que veremos después.

2.3

Inicializar una vez

▶ 7:09

Va en USER CODE BEGIN 2, antes del while(1):

delay_us_init();
Fase 3

Comprobarlo

3.1

Pulsos de 10 µs

▶ 6:04

Para apagar se usa BSRR con el pin desplazado 16 (así sirve también en la Black Pill, que no tiene BRR):

void prueba()
{
  parlante_GPIO_Port->BSRR = parlante_Pin;
  delay_us_dwt(10);
  parlante_GPIO_Port->BSRR = parlante_Pin << 16;
  delay_us_dwt(10);
  // ... repetido 3 veces
}
3.2

Una frecuencia de 1 kHz

▶ 9:22

1 kHz es un periodo de 1 ms: 500 µs en alto y 500 µs en bajo. El analizador mide 997,7 Hz.

parlante_GPIO_Port->BSRR = parlante_Pin;
delay_us_dwt(500);
parlante_GPIO_Port->BSRR = parlante_Pin << 16;
delay_us_dwt(500);
Fase 4

Tonos y melodías

4.1

Procedimiento Sound_play

▶ 12:18

Recibe la frecuencia en Hz y la duración en ms. Medio periodo = 500 000 / frec µs; repeticiones = frec × dura / 1000.

void Sound_play(uint32_t frec, uint32_t dura)
{
  uint32_t dela = 500000 / frec;          // la mitad de un periodo en us
  uint32_t repe = frec * dura / 1000;     // cuántas veces se repite
  while (repe--)
  {
    parlante_GPIO_Port->BSRR = parlante_Pin;
    delay_us_dwt(dela);
    parlante_GPIO_Port->BSRR = parlante_Pin << 16;
    delay_us_dwt(dela);
  }
}
4.2

Usarlo

▶ 13:58

La melodía de Mario Bros es una lista de Sound_play(frecuencia, duración) y HAL_Delay(pausa), por ejemplo Sound_play(660, 100); HAL_Delay(75);…

Sound_play(1000, 200);
Sound_play(2000, 100);
Sound_play(3000, 200);
HAL_Delay(200);
Sound_play(5000, 100);
HAL_Delay(80);
Sound_play(500, 300);

En Proteus simula con el reloj a 8 MHz y activa la salida .hex (Properties → C/C++ Build → Settings → MCU Post build outputs).

4.3

Conectar el parlante

▶ 17:28

Nunca conectes el parlante directo al pin: se daña el micro. Usa un transistor Darlington como el TIP122 (se satura fácil) con una resistencia de base; así puedes alimentar un parlante grande con 12 V para una alarma o sirena.

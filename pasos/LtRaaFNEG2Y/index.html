Conflictos de librerías en Arduino

El ATmega328 del Arduino Uno tiene tres timers y cada uno maneja el PWM de dos pines: Timer0 en D5 y D6 (976 Hz), Timer1 en D9 y D10 (490 Hz) y Timer2 en D3 y D11 (490 Hz). Con analogWrite se generan ondas del 50 % y se ven en el osciloscopio. Luego se cambia la frecuencia del Timer1 a unos 31 kHz con TCCR1B. Al agregar la librería Servo, que usa el Timer1, el PWM del pin 9 se cae y el servo tampoco queda bien; al quitar el analogWrite del pin 9 el servo funciona. Con tone() pasa lo mismo en el Timer2 y los pines 3 y 11. La conclusión: hay que conocer los registros y los recursos que usa cada librería.

Fase 1

PWM y timers del Arduino Uno

1.1

El circuito

▶ 0:00

En Proteus hay un Arduino Uno con salidas PWM llevadas a un osciloscopio y un servo. La idea es ver qué pasa cuando se usan librerías sin saber qué recursos del micro ocupan.

1.2

Qué es una señal PWM

▶ 0:34

Una señal PWM tiene frecuencia fija y lo que cambia es el ancho del pulso positivo: con analogWrite(0) no hay pulso, con 127 es la mitad (50 %) y con 255 está siempre en alto.

Sirve para controlar motores, intensidad de LEDs, fuentes conmutadas, etc.

1.3

El PWM de un servo

▶ 1:06

Un servo usa una señal de 50 Hz (periodo de 20 ms) y la posición depende del ancho del pulso, más o menos entre 0,5 y 2,5 ms según el fabricante.

1.4

Cada timer maneja dos pines

▶ 1:39

El ATmega328 tiene Timer0, Timer1 y Timer2, y cada uno genera el PWM de dos pines:

La frecuencia por defecto la fija el preescalador de cada timer; con las funciones básicas de Arduino no se puede cambiar.

  • Timer0: pines D5 y D6, 976 Hz
  • Timer1: pines D9 y D10, 490 Hz
  • Timer2: pines D3 y D11, 490 Hz
Fase 2

Generar y cambiar el PWM

2.1

Tres señales con analogWrite

▶ 2:45

Los pines se ponen como salida y con analogWrite(pin, 127) se sacan tres señales del 50 % en los pines 5, 3 y 9 (uno de cada timer).

void setup()
{ // put your setup code here, to run once:
 pinMode(0,OUTPUT);
 pinMode(1,OUTPUT);
 // pines PWM1
 pinMode(3,OUTPUT);
 pinMode(5,OUTPUT);
 pinMode(9,OUTPUT);
}

void loop()
{ // put your main code here, to run repeatedly:
 analogWrite(5,127); //crea una onda con ciclo util de 50%
 analogWrite(3,127); //crea una onda con ciclo util de 50%
 analogWrite(9,127); //crea una onda con ciclo util de 50%
}
2.2

Ver las frecuencias

▶ 3:54

En el osciloscopio el pin 5 tiene más frecuencia (976 Hz) que los pines 9 y 3 (490 Hz). El ancho de pulso se puede cambiar, pero la frecuencia es la que trae Arduino.

2.3

Cambiar la frecuencia del Timer1

▶ 4:27

Hay una tabla con los valores de los registros para cada timer. Para el Timer1 con divisor 1 la frecuencia sube a unos 31 kHz; se copia esa línea en el setup.

Al simular, el pin 9 ya sale con la nueva frecuencia. Es útil, por ejemplo, para fuentes conmutadas, motores o convertidores, donde 490 Hz es muy poco.

// Timer1 (pines D9 y D10), divisor 1: 31372.55 Hz
TCCR1B = TCCR1B & B11111000 | B00000001;
Fase 3

El conflicto con las librerías

3.1

Agregar un servo

▶ 6:49

Se incluye la librería Servo, se crea servo1 en el pin 0 (que no tiene nada que ver con los timers) y se le ordena ir a 100 grados.

#include "Servo.h"
Servo servo1; // inicializa un servo llamado servo1

void setup()
{
  // ... pines como antes
  servo1.attach(0); //coloca un servo en el pin cero
}

void loop()
{
  // ... analogWrite como antes
  servo1.write(100); // mueve el servo 100 grados
}
3.2

Se cae el PWM del pin 9

▶ 7:21

La librería Servo trabaja con el Timer1, así que entra en conflicto con cualquier cosa en los pines 9 y 10. Al simular, la señal del pin 9 se cae y la del servo tampoco es estable: los dos se dañan.

Si no se sabe esto, uno cambia de pin o pone otro Arduino sin entender el problema.

3.3

Quitar el conflicto

▶ 9:04

Al quitar el analogWrite del pin 9 y compilar, la señal del servo queda perfecta. Las dos cosas no pueden usar el Timer1 al tiempo.

3.4

Lo mismo con tone()

▶ 9:37

La función tone() (por ejemplo tone(0,1000) para 1 kHz) usa el Timer2, así que daña el PWM de los pines 3 y 11. Al simular, se cae también la señal del pin 3.

tone(0,1000);
3.5

Conclusión

▶ 10:44

Las librerías de Servo, tone y PWM pelean entre sí por los timers. La solución no es poner más tarjetas: hay que conocer los registros del micro y, cuando haga falta, hacer una librería propia con otro timer.

Códigos IR con hash

Es la continuación de la clase de detección IR. FNV parte de un valor base y, por cada dato, multiplica el acumulado por un número primo y hace XOR con el dato. Cualquier secuencia distinta da un número distinto y la misma secuencia da siempre el mismo. Así cada tecla queda como un unsigned long y se libera memoria. Luego se cambia la normalización: en vez de conocer los anchos (6, 10, 22), se compara cada tiempo con el siguiente y se guarda 0, 1 o 2. Con eso sirve cualquier control sin analizarlo.

Fase 1

Hash FNV

1.1

La idea

▶ 0:00

Antes cada tecla era un arreglo de más de 60 datos normalizados. El hash convierte toda la secuencia en un número único y repetible de 32 bits.

1.2

Constantes y función

▶ 2:12

El primo y la base de FNV de 32 bits están definidos por sus autores. La función recorre los tiempos guardados.

#define FNV_PRIME 16777619
#define FNV_BASIS 2166136261

unsigned long codigo_ir;   // almacena el codigo unico

unsigned long hash_algoritmo() {
  unsigned long hash_acum = FNV_BASIS;
  for (cont = 0; cont < cuenta; cont++) {
    hash_acum = (hash_acum * FNV_PRIME) ^ tiempo[cont];
  }
  return hash_acum;
}
1.3

Mostrar el código

▶ 3:18

Después de normalizar, codigo_ir = hash_algoritmo(). Se pasa a hexadecimal con LongIntToHex y se envía por serial. Cada tecla da un número distinto y siempre el mismo.

Fase 2

Usar los códigos

2.1

Comparar

▶ 6:08

Se copia el código de cada tecla y se compara con if. Ya no hacen falta los arreglos y la memoria de datos queda más libre.

if (codigo_ir == 0x00000000) {        // codigo de la tecla 1
  led1 = ~led1;
  UART1_Write_Text("COMANDO1");
}
else if (codigo_ir == 0x00000000) {   // codigo de la tecla 2
  led2 = ~led2;
  UART1_Write_Text("COMANDO2");
}
2.2

Variables

▶ 7:59

Los LEDs van en LATC0 a LATC2. Se mantienen cuenta, el arreglo tiempo y la bandera flag_codigo de la clase anterior.

Fase 3

Normalización automática

3.1

Comparar con el siguiente

▶ 10:09

La nueva función compara cada tiempo con el siguiente: si están dentro de un rango (alrededor de 0.8) son iguales; si no, se marca cuál es mayor. Se guarda 0, 1 o 2. Así no hay que conocer los anchos del control.

3.2

Dos datos más

▶ 11:52

Con este método el arreglo debe tener dos posiciones más que el número de datos leídos. Después de procesar se limpia el buffer para que no quede un código anterior.

3.3

Prueba

▶ 12:58

Se leen otra vez los códigos de cada tecla (se verifica que salgan dos veces iguales), se pegan en el programa y el control prende y apaga los LEDs. Se quitan los mensajes de prueba.

3.4

Aplicación

▶ 20:22

Con cualquier control, incluso el del televisor y con teclas que no se usan, se puede prender la luz o un ventilador.

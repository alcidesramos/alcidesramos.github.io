Clase 140: MPU6050 con muestreo por timer y horizonte artificial en Python

Continuación de la clase 139. El problema de los filtros era depender de retardos en el while. Ahora la lectura del sensor, los ángulos y los filtros complementario y Kalman se ejecutan dentro de la interrupción del TIM3 cada 5 ms, sin importar lo que haga el programa principal. Configuramos el timer con una regla sencilla (prescaler = MHz × 10 − 1, periodo = ms × 100 − 1), medimos con el contador DWT que los procedimientos tardan unos 0.42 ms y enviamos pitch y roll de Kalman y el yaw del giroscopio en una trama INI=p/r/y* que lee un programa en Python con horizonte artificial y brújula.

Fase 1

Librería de timer

1.1

Quitar el muestreo del while

▶ 0:01

En la clase anterior todo se hacía en el while con delay_ms; cualquier retardo extra dañaba el ángulo del giroscopio y los filtros.

Ahora en la librería del MPU6050 cambiamos la opción de tiempo de muestreo para que lo maneje el timer y agregamos la librería timer a LIBRERIAS.

Revisa en MPU6050.h el define de tiempo_muestreo según indica la librería: con timer el tiempo lo calcula la librería timer.

1.2

Escoger el timer y los procedimientos

▶ 1:07

En timer.h se indica el timer a usar (aquí TIM3) y se incluye el sensor.

En timer.c, dentro de TIMER_PROCEDIMIENTOS(), ponemos todo lo que antes estaba en el while: leer, calcular, ángulos y filtros. El callback del timer lo llama en cada periodo.

// timer.c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    // mira si el timer deseado
    if (htim->Instance == TIM_INT)
    {
        TIMER_PROCEDIMIENTOS();
    }
}

void TIMER_PROCEDIMIENTOS()
{
    // IMU
    MPU6050_lee_datos();
    MPU6050_calcula_flotantes();
    MPU6050_Ace_angulos();
    MPU6050_Giro_angulos();
    Filtro_Complementario(0.95);
    filtro_kalman();
}

Los procedimientos deben tardar menos que el periodo del timer.

1.3

Iniciar el timer y medir el tiempo

▶ 2:13

TIMER_INIT() arranca el timer con interrupción.

TIMER_MIDE() usa el contador de ciclos DWT para medir cuánto tardan los procedimientos, en µs y ms.

void TIMER_INIT()
{
    HAL_TIM_Base_Start_IT(&htim_INT);
}

// MIDO TIEMPO DE ESOS PROCEDIMIENTOS
void TIMER_MIDE()
{
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
    DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
    pasos1 = (HAL_RCC_GetSysClockFreq()/1000000);
    // INICIA CONTADOR
    DWT->CYCCNT = 0;
    TIMER_PROCEDIMIENTOS();
    tmicros = (DWT->CYCCNT / pasos1);  // retorna los us
    tmilis = tmicros/1000.0;
}
Fase 2

Configurar el TIM3

2.1

Cálculo del prescaler y el periodo

▶ 2:46

Regla práctica: Prescaler = frecuencia del micro en MHz × 10 − 1 y Counter Period = milisegundos × 100 − 1.

Con 100 MHz: prescaler 1000 − 1. Para 5 ms: periodo 500 − 1 (10 ms sería 1000 − 1).

Con 100 MHz / 1000 el timer cuenta a 100 kHz, es decir, cada cuenta son 10 µs.

2.2

TIM3 en CubeMX

▶ 3:50

Activamos TIM3 con Clock Source Internal Clock, Prescaler 1000-1, Counter Period 500-1 y auto-reload preload Enable.

En NVIC Settings habilitamos la interrupción global del TIM3 y generamos código.

3.2

Medir cuánto tardan los cálculos

▶ 6:26

Para comprobar el tiempo, llamamos una vez a TIMER_MIDE, enviamos el resultado y dejamos el programa quieto. Declaramos char texto[100].

El resultado fue unos 0.42 ms, muy por debajo de los 5 ms: el F411 tiene FPU y hace estos cálculos muy rápido.

TIMER_MIDE();
sprintf(texto, "Tus=%lu us    Tms=%.2f ms\r\n", tmicros, tmilis);
uartx_write_text(&huart1, texto);
while(1);   // se queda aqui; luego se comenta

Después de medir, comenta estas líneas. Para robots 10 a 50 ms está bien; para un dron, 5 ms o menos.

5.2

Decodificar la trama

▶ 10:58

Los datos llegan con el formato INI=valor/valor/valor*. Se toma lo que hay entre INI= y *, se separa por / y se convierten a float. El yaw negativo se pasa a 0-360.

def procesar_trama(trama):
    global pitch, roll, yaw
    try:
        if "INI=" in trama and "*" in trama:
            # Extraer datos entre INI=y/y/y *
            datos = trama.split("INI=")[1].split("*")[0]
            # Separar por /
            valores = datos.split("/")
            if len(valores) >= 3:
                pitch = float(valores[0])
                roll = float(valores[1])
                yaw = float(valores[2])
                if yaw < 0:
                    yaw = yaw + 360.0
    except:
        pass

Si envías más datos, agrega más campos separados por / y ajusta el número esperado.

5.3

Enviar la trama desde el STM32

▶ 12:35

En el while enviamos pitch y roll del Kalman y el yaw del giroscopio cada 10 ms.

while (1)
{
    delay_ms(10);
    sprintf(texto, "INI=%.2f/%.2f/%.2f*", kalman_pitch, kalman_roll, giro_yaw);
    uartx_write_text(&huart1, texto);
}

El yaw solo con giroscopio deriva con el tiempo; para una brújula real conviene un magnetómetro.

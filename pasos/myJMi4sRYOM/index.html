Interrupciones por Timer en STM32

Se arma en Proteus una BlackPill con 4 LEDs. LED1 parpadea en el main con HAL_Delay, mientras que TIM1 se configura con base de tiempo de 200 ms y su interrupción de actualización (update) se habilita en el NVIC. Dentro del manejador TIM1_UP_TIM10_IRQHandler se conmuta LED2 en cada interrupción y LED3 cada 3 interrupciones (600 ms) usando un contador. Se explican las prioridades del NVIC (0 a 15, donde 0 es la más alta), los bits de grupo de prioridad y la subprioridad, y la idea de que un solo timer base sirve para generar varios periodos sin bloquear el programa.

Fase 1

Montaje y proyecto base

1.1

Circuito en Proteus

▶ 2:40

BlackPill con 4 LEDs (220 Ω): LED1 en B0, LED2 en A7, LED3 en A2 y LED4 en A0. Alimentación a 3.3 V y VDDA unido a la red de 3.3 V para que la simulación arranque.

1.2

Pines y reloj a 16 MHz

▶ 5:50

En CubeMX se configuran los 4 pines como GPIO_Output con etiquetas LED1..LED4. El reloj se deja en 16 MHz (HSI), por lo que el reloj de timers de APB2 también queda en 16 MHz.

1.3

Salida .hex, printf float y pinout.h

▶ 8:40

En las propiedades del proyecto se habilita la generación del .hex (para cargarlo en Proteus) y el uso de float en printf. Se copia la librería pinout.h dentro de Core/Librerias y se agrega la ruta de include.

1.4

LED1 en el while

▶ 10:50

En el main se deja parpadeando LED1 con un retardo bloqueante, para comparar luego con lo que hace la interrupción:

#include "pinout.h"

while (1)
{
    PIN_BLINK(LED1);
    HAL_Delay(2000);
}
Fase 2

Configurar TIM1 y el NVIC

2.1

Cálculo de PSC y ARR

▶ 12:00

Con reloj de 16 MHz y un periodo deseado de 200 ms: T = (PSC+1)·(ARR)/f. Con PSC = 100-1 y ARR = 16000 se obtiene 100·16000/16 MHz = 0.2 s.

2.2

TIM1 en Internal Clock

▶ 13:20

TIM1 → Clock Source: Internal Clock. Prescaler 100-1, Counter Period 16000 y auto-reload preload habilitado.

Prescaler (PSC)      = 100-1
Counter Period (ARR) = 16000
auto-reload preload  = Enable
2.3

Habilitar la interrupción en el NVIC

▶ 15:50

En la pestaña NVIC Settings de TIM1 se marca "TIM1 update interrupt and TIM10 global interrupt".

  • Las prioridades van de 0 a 15; 0 es la más alta.
  • Los bits de grupo de prioridad reparten entre prioridad (preemption) y subprioridad.
  • Si dos interrupciones tienen la misma prioridad, decide la subprioridad.
  • En este ejemplo la prioridad se deja en 1.
Fase 3

Código de la interrupción

3.1

Rutina en stm32f4xx_it.c

▶ 18:30

En stm32f4xx_it.c se incluye pinout.h, se declara un contador en las variables privadas y dentro de TIM1_UP_TIM10_IRQHandler (antes de HAL_TIM_IRQHandler) se conmutan los LEDs:

/* USER CODE BEGIN Includes */
#include "pinout.h"

/* USER CODE BEGIN PV */
uint8_t contador = 0;

void TIM1_UP_TIM10_IRQHandler(void)
{
  /* USER CODE BEGIN TIM1_UP_TIM10_IRQn 0 */
  PIN_BLINK(LED2);          // cada 200 ms
  contador++;
  if (contador >= 3)        // cada 600 ms
  {
    PIN_BLINK(LED3);
    contador = 0;
  }
  /* USER CODE END TIM1_UP_TIM10_IRQn 0 */
  HAL_TIM_IRQHandler(&htim1);
}
3.2

Arrancar el timer con interrupción

▶ 20:10

En el main, antes del while, se inicia el timer en modo interrupción:

HAL_TIM_Base_Start_IT(&htim1);
3.3

Simulación

▶ 20:40

Al simular, LED1 cambia cada 2 s desde el while, LED2 cada 200 ms y LED3 cada 600 ms desde la interrupción, sin que el HAL_Delay del main afecte a los LEDs del timer.

3.4

Ideas clave

▶ 23:20

Un solo timer base puede generar varios periodos usando contadores dentro de la interrupción.

Las rutinas de interrupción deben ser cortas: nada de HAL_Delay ni procesos largos dentro de ellas.

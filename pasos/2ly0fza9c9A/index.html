SPI y DAC MCP4922 en XC8

Primero se explica el protocolo SPI: SDO, SDI, SCK y el habilitador CS, y la equivalencia con MOSI y MISO. Con un PIC18F4550 a 4 MHz se configura el MSSP directamente con los registros SSPSTAT y SSPCON1 (muestreo, flanco, polaridad del reloj y velocidad Fosc/16) y se envía un byte de prueba que se ve en el analizador de Proteus. Luego se maneja el DAC MCP4922: cada dato de 16 bits lleva el canal, la ganancia y el bit de apagado, y se envía en dos bytes con CS y LDAC. Se leen dos potenciómetros con el ADC (escalando de 10 a 12 bits) y se sacan por los dos canales del DAC. Al final se reemplaza el SPI del micro por uno hecho por software en RC0 y RC1.

Cómo funciona SPI

El maestro da el reloj (SCK). SDO del maestro va a SDI del esclavo y al revés; CS habilita al esclavo. MOSI va con MOSI y MISO con MISO.

#define _XTAL_FREQ 4000000
#define cs1  LATB3
#define ldac LATB2

void UNO(unsigned int *port, char bit1)
{
  *port |= (1 << bit1);
}

void CERO(unsigned int *port, char bit1)
{
  *port &= ~(1 << bit1);
}

unsigned char spi_write(unsigned char spi_dat)
{
  SSPBUF = spi_dat;
  while (BF == 0);
  return (SSPBUF);
}
Fase 3

DAC MCP4922

3.1

El circuito

▶ 27:35

El MCP4922 recibe SCK, SDI, CS y LDAC. Sus dos salidas se miden con voltímetros.

3.2

El dato de 16 bits

▶ 31:07

Los 4 bits altos son de configuración: el 15 elige el canal, el 13 la ganancia y el 12 debe ir en uno para no apagar la salida. Los 12 bajos son el dato.

3.3

dac_write

▶ 34:20

Se ponen los bits de configuración, se separa el dato en dos bytes y se envían con CS en bajo. Luego un pulso en LDAC actualiza la salida.

void dac_write(unsigned int dat, char canal)
{
  unsigned char low_b, hig_b;

  UNO(&dat, 12);   // deja habilitado el shutdown
  UNO(&dat, 13);   // sin ganancia

  if (canal == 2) UNO(&dat, 15);   // saca por el canal b

  low_b = dat & 0x00FF;   // captura byte bajo
  hig_b = dat >> 8;       // captura el byte alto

  cs1 = 0;
  spi_write(hig_b);
  spi_write(low_b);
  cs1 = 1;
  ldac = 0;
  __delay_us(100);
  ldac = 1;
}
Fase 4

ADC y SPI por software

4.1

Leer el ADC

▶ 39:27

El ADC se configura bit a bit, justificado a la derecha (ADFM en uno). La función de lectura elige el canal, espera la adquisición y arma el resultado.

Como el ADC es de 10 bits y el DAC de 12, el valor se multiplica por 4.

unsigned int ADC_GetConversion(char channel)
{
  // select the A/D channel
  ADCON0bits.CHS = channel;
  // Turn on the ADC module
  ADCON0bits.ADON = 1;
  // Acquisition time delay
  __delay_us(5);
  // Start the conversion
  ADCON0bits.GO_nDONE = 1;
  // Wait for the conversion to finish
  while (ADCON0bits.GO_nDONE)
  {
  }
  // Conversion finished, return the result
  return ((unsigned int)((ADRESH << 8) + ADRESL));
}

4.3

SPI por software

▶ 47:45

El reloj va en RC0 y el dato en RC1. Por cada bit se mira el más alto, se rota el dato y se da un pulso de reloj. Así se liberan los pines del MSSP.

#define spi_ck  LATC0
#define spi_dat LATC1

void spi_s_write(unsigned char dato_)
{
  unsigned char cont_s = 0;

  for (cont_s = 0; cont_s < 8; cont_s++)
  {
    if ((dato_ & 0x80) != 0) spi_dat = 1;
    else spi_dat = 0;
    dato_ <<= 1;   //rota
    //genera un pulso del reloj
    spi_ck = 1;
    __delay_us(10);
    spi_ck = 0;
    __delay_us(10);
  }
}

// dac_write_s es igual a dac_write pero llama a spi_s_write

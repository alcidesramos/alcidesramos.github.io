STM32 en Visual Studio Code con CubeMX 1 o CubeMX 2

En un computador limpio instalamos Python, STM32CubeMX (MX1), STM32CubeMX2 (para las series nuevas como la C5) y Visual Studio Code, todos ejecutándose como administrador. En VS Code creamos un perfil STM32, instalamos las extensiones de Python y STM32CubeIDE for VS Code, los drivers del ST-Link, y enlazamos los dos CubeMX. Generamos un proyecto CMake para la Black Pill F411 desde MX1 y otro para la Nucleo C562 desde MX2, los abrimos en VS Code, compilamos y depuramos un LED parpadeando. Al final probamos el chat de IA del editor sobre el código.

Fase 1

Instalación

1.1

Instalar los programas

▶ 0:45

Instala Python, STM32CubeMX (MX1), STM32CubeMX2 y Visual Studio Code. Para descargar los de ST necesitas una cuenta de ST.

En el instalador de VS Code marca las dos opciones Agregar la acción "Abrir con Code" al menú contextual (archivos y directorios).

1.2

Ejecutar como administrador

▶ 4:08

En cada programa: clic derecho > Propiedades > Compatibilidad > Ejecutar este programa como administrador, para que puedan comunicarse entre ellos.

La primera vez VS Code pide asociar la cuenta de Google y la de GitHub; conviene hacerlo.

Fase 2

Preparar VS Code

2.1

Perfil STM32

▶ 7:26

En el engranaje > Profiles > New Profile, lo llamamos STM32_ y lo creamos. Cada plataforma (Python, Arduino, STM32) puede tener su perfil con sus extensiones.

Si al reabrir no queda por defecto, se selecciona a mano en Profiles.

2.2

Extensiones

▶ 9:05

Dentro del perfil instalamos la extensión Python (de Microsoft) y STM32CubeIDE for Visual Studio Code de STMicroelectronics, que trae el pack completo: core, CMake, build analyzer, project manager y debug. Acepta todo lo que pregunte.

2.3

Drivers del ST-Link

▶ 10:26

Con solo la Black Pill conectada, se instalan los drivers del ST-Link (una sola vez). Luego se desconecta y conecta el ST-Link hasta que aparezca en STM32Cube Devices and Boards.

2.4

Enlazar CubeMX

▶ 12:05

Desde la pestaña STM32 se abre CubeMX. Si no lo encuentra, con Abrir la ubicación del archivo copias la ruta del ejecutable y se la indicas. El MX2 normalmente lo detecta solo.

Fase 3

Proyecto con CubeMX 1

3.1

Pin y proyecto CMake

▶ 13:43

Elegimos el STM32F411CEU6, ponemos PC13 como GPIO_Output con la etiqueta LED.

En Project Manager: nombre LED1, ubicación C:\CODIGOS y Toolchain/IDE: CMake (no STM32CubeIDE).

La primera vez CubeMX descarga el paquete del micro y tarda; después es rápido.

3.2

Abrir en VS Code y modo restringido

▶ 22:02

Tras generar el código, en el explorador vamos a la carpeta del proyecto, clic derecho > Abrir con Code. Después, al regenerar, ya no hace falta volver a abrirla.

Si abajo aparece Restricted Mode, pulsa Trust. Deshabilita la extensión C/C++ de Microsoft: choca con la de ST.

Si la primera compilación da muchos errores, cierra VS Code, regenera el código y vuelve a abrir la carpeta: la primera vez aún está instalando lo de CMake.

3.3

Código del LED

▶ 24:20

En Core/Src/main.c, dentro del while, conmutamos el pin y esperamos. El autocompletado sale con Ctrl+Espacio.

Los inlay hints (nombres de parámetros en gris) se pueden apagar en Settings buscando inlay > Editor › Inlay Hints: off.

while (1)
{
  HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
  HAL_Delay(500);
}
3.4

Compilar y depurar

▶ 27:46

Build pide el preset: Debug para pruebas, Release para el producto final.

En Run and Debug elegimos el ST-Link; con Continue (play) se programa la tarjeta y el LED parpadea.

Fase 4

Proyecto con CubeMX 2

4.1

Proyecto desde la tarjeta

▶ 16:23

El MX2 es la herramienta para las series nuevas (C5 en adelante). Creamos el proyecto desde la tarjeta NUCLEO-C562RE, nombre LEDMX2, en C:\CODIGOS.

4.2

Pin del LED y generación

▶ 18:36

Seleccionamos PA5: MX2 muestra sus funciones y características (por ejemplo, tolerante a 5 V). Le quitamos el estado Reserved, lo ponemos como salida y la etiqueta LED.

En Project settings > IDE Project Generation el formato es CMake (u Open-CMSIS o IAR): ya no hay salida directa a STM32CubeIDE.

4.3

main.c y prueba

▶ 31:33

En los proyectos de MX2 el main.c queda en la raíz del proyecto y el código del usuario va en el while después de mx_system_init(). Tras compilar una vez con la tarjeta elegida, ya funciona el autocompletado.

while (1)
{
  HAL_GPIO_TogglePin(LED_PORT, LED_PIN);
  HAL_Delay(80);
}

La HAL de las series nuevas cambió: los nombres del puerto y pin del LED (LED_PORT, LED_PIN) salen de la etiqueta que le diste.

Fase 5

IA en el editor

5.1

Pedirle cosas al chat

▶ 35:39

Seleccionando el código y abriendo el chat se le puede preguntar qué hace o pedirle cambios, como pasar el delay a 500 ms. También hay extensiones de Claude, Gemini o ChatGPT con agentes.

Revisa siempre lo que cambia la IA: en el video agregó una línea en lugar de modificar la existente.

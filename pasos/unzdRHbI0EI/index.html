Multiplexar displays y depurar con .cof

Con lo visto de puertos y pines se arma un display de cuatro dígitos multiplexado: los segmentos van a un puerto y cada dígito se habilita con un transistor 2N3904. Así en vez de 28 pines se usan 11, y el software hace el trabajo mostrando cada letra unos milisegundos. Luego se pasa el programa al PIC16F877A cambiando solo los #define, se explica el brown-out reset y se activa la generación del archivo .cof para ejecutar el código paso a paso dentro de Proteus.

Fase 1

Circuito

1.1

NPN o PNP

▶ 0:33

Un truco para distinguir los transistores BJT: en el NPN la flecha del emisor sale (no penetra) y en el PNP la flecha entra (penetra).

1.2

Por qué multiplexar

▶ 2:10

Cuatro displays sin multiplexar necesitan 7 × 4 = 28 pines. Multiplexados solo hacen falta 7 para los segmentos y 4 para habilitar cada dígito: 11 pines. Se muestra cada letra tan rápido que el ojo ve la palabra fija.

1.3

Transistores para cada dígito

▶ 2:42

Cada común del display va al colector de un 2N3904, con el emisor a tierra y una resistencia de 330 Ω en la base desde el pin del micro. Los segmentos llevan su resistencia de 220 Ω. En la vida real se agrega una resistencia de pull-up en el colector.

Fase 2

Programa

2.1

Nombres con #define

▶ 6:02

Los habilitadores, el puerto del display y el puerto que apaga los dígitos se definen con nombres. Así es más fácil leer el programa y pasarlo a otro micro.

#define H1 RA0_bit
#define H2 RA1_bit
#define H3 RA2_bit
#define H4 RA3_bit
#define display PORTB
#define port_off PORTA
2.2

Secuencia de multiplexación

▶ 7:45

Para cada dígito: apagar todos, sacar el dato, habilitar el dígito y esperar el tiempo de visualización. Los valores de cátodo común salen del Seven Segment Editor: H = 118, O = 63, L = 56, A = 119.

TRISA = 0;
TRISB = 0;
while (1)
{
  port_off = 0b00000000;   // apaga todos
  display = 118;           // H
  H1 = 1;                  // habilita display 1
  Delay_ms(5);

  port_off = 0b00000000;
  display = 63;            // O
  H2 = 1;
  Delay_ms(5);

  port_off = 0b00000000;
  display = 56;            // L
  H3 = 1;
  Delay_ms(5);

  port_off = 0b00000000;
  display = 119;           // A
  H4 = 1;
  Delay_ms(5);
}
2.3

El tiempo de visualización

▶ 8:17

Cada dígito debe mostrarse entre 1 y 10 ms. Con 500 ms se ve cómo van saltando las letras; con 5 ms el ojo ve HOLA fijo.

Fase 3

Cambiar al PIC16F877A

3.1

Nuevo micro

▶ 12:44

El PIC16F877A tiene más pines, entradas análogas y más periféricos, y es fácil de conseguir. Se cambia el micro en Project → Edit Project y se ajustan los #define: el display al puerto C y los habilitadores al puerto B.

3.2

Brown-out reset y otros bits

▶ 14:58

Aparece el Brown-out Reset: el micro se reinicia si el voltaje cae a un nivel no confiable, lo que evita bloqueos y acciones erróneas. La programación en bajo voltaje (LVP) se deja deshabilitada por compatibilidad con los programadores. También se pueden proteger la memoria de programa y la EEPROM.

3.3

Probar

▶ 17:07

La primera vez no funcionó porque faltaba cambiar los TRIS a los nuevos puertos (B y C). Corregido, la palabra HOLA aparece igual.

Fase 4

Depurar en Proteus

4.1

Generar el archivo .cof

▶ 17:40

En Project → Edit Project se activa Generate COFF file. Al compilar se crea un .cof, que se carga en el micro de Proteus en vez del .hex.

4.2

Paso a paso

▶ 18:15

Se inicia con el botón de pausa (no con play) y Proteus abre el código fuente de MikroC. Se ejecuta línea por línea viendo cómo se saca cada letra y se habilita cada dígito, lo que ayuda a encontrar errores.

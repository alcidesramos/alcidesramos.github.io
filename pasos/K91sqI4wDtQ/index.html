Botones para programar y proteger el STM32 desde VS Code

Partiendo del botón CMake ARZ que configuramos con la extensión VsCode Action Buttons, agrego dos botones más: PROG, que programa el .elf más reciente con STM32_Programmer_CLI, y FUSE, que abre una ventana para elegir la protección de lectura RDP (AA, BB o CC). Todo queda en la carpeta C:\EMBEBIDOS. Como en otro PC el script no encontraba el programador, uso Copilot con un prompt para que repare prog.py y fuse.py con la ruta del CLI. Después muestro cómo pasar de Debug a Release (el .elf de Release pesa mucho menos) y cómo activar la navegación con breadcrumbs.

▶ Ver el video completo (17:41) Empezar el paso a paso
  • VS Code con VsCode Action Buttons y la extensión STM32CubeIDE
  • Python instalado
  • STM32CubeProgrammer (trae STM32_Programmer_CLI.exe)
  • Carpeta EMBEBIDOS con cmakelist_Python.py, prog.py, fuse.py y prompt (recursos del video)
  • Placa STM32 con ST-Link

Fase 1

Los botones en settings.json

1.1

Recordar el botón CMake ARZ

▶ 2:30

Con F1 → Preferences: Open User Settings (JSON) se abre settings.json. Al final, antes de la última llave, se pone una coma y se pega el bloque actionButtons. Las rutas en JSON llevan doble barra invertida.

Si copia la carpeta EMBEBIDOS en C:\ las rutas le quedan iguales a las del video; si no, cámbielas por la suya.

1.2

Agregar PROG y FUSE

▶ 3:20

Se copia el bloque del botón entre llaves, coma y se pega dos veces. Se renombran PROG y FUSE, se cambian los íconos (emojis) y los colores, y cada uno apunta a su script. PROG no tiene ventana, así que usa python (sin w); FUSE sí tiene ventana y usa pythonw.

"actionButtons": {
  "defaultColor": "white",
  "loadNpmCommands": false,
  "commands": [
    {
      "name": "🛠 CMake ARZ",
      "color": "yellow",
      "command": "pythonw \"C:\\EMBEBIDOS\\cmakelist_Python.py\""
    },
    {
      "name": "💾 PROG",
      "color": "white",
      "command": "python \"C:\\EMBEBIDOS\\prog.py\""
    },
    {
      "name": "⚡ FUSE",
      "color": "yellow",
      "command": "pythonw \"C:\\EMBEBIDOS\\fuse.py\""
    }
  ]
}

Los íconos son emojis copiados del archivo de botones; puede usar los que quiera. Guarde con Ctrl+S y reinicie VS Code para ver los tres botones abajo.

Fase 2

Programar desde VS Code

2.1

Primer intento

▶ 5:40

Hay que compilar primero y luego pulsar PROG. En este PC salió: No se encontró herramienta de programación. Instala openocd, STM32_Programmer_CLI o st-flash.

2.2

Ubicar STM32_Programmer_CLI

▶ 6:40

Desde el acceso de STM32CubeProgrammer se abre la ubicación del archivo: en la carpeta bin está STM32_Programmer_CLI.exe. Copiamos esa ruta.

2.3

Reparar prog.py con Copilot

▶ 7:30

Abrimos prog.py en VS Code y en el chat pegamos el prompt con la ruta. Copilot ajusta la detección de la herramienta (usa la ruta o una variable de entorno) y lo prueba.

tengo mi STM32_Programmer_CLI
en la direccion  C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeProgrammer\bin
repera mi archivo prog.py para que funcione el boton de prog que tengo en mi barra inferior de vsc

El prompt también viene en la carpeta EMBEBIDOS\prompt. Ajuste la ruta a donde quedó instalado su CubeProgrammer.

2.4

Probar el botón

▶ 9:40

Compilamos, pulsamos PROG y la terminal muestra Download verified successfully y Programación completada correctamente. Con un toggle y un delay el LED ya parpadea.

Fase 3

Proteger el micro

3.1

Reparar fuse.py

▶ 10:50

Se abre fuse.py y se le pide a Copilot haz lo mismo con fuse.py. El script define los niveles de protección RDP.

RDP_MAP = {
    "AA": "0xAA",  # Level 0
    "BB": "0xBB",  # Level 1
    "CC": "0xCC",  # Level 2 (irreversible)
}
3.2

Ventana de protección

▶ 11:20

El botón FUSE abre la ventana Protección RDP: AA sin protección, BB nivel 1 (protegido) y CC nivel 2 (permanente). Con BB, al intentar programar sale error de memoria; con AA se quita la protección (tarda más porque borra la flash) y se vuelve a programar.

3.3

Nivel CC: cuidado

▶ 12:15

Al elegir CC el botón se pone rojo y pide confirmación, porque el nivel 2 es permanente: el micro ya no se puede volver a programar.

No use CC en pruebas. Solo para el producto final, y sabiendo que es irreversible.

Fase 4

Debug, Release y breadcrumbs

4.1

Cambiar a Release

▶ 14:00

Con Ctrl+K Ctrl+S se abren los atajos y se busca el comando de seleccionar configuración (debug/release) para asignarle una tecla. En Release el .elf de la prueba pasó de unos 650 KB a 19 KB. PROG programa el .elf más reciente, sea Debug o Release.

El atajo exacto que asigné no se ve claro en el video; asigne la combinación que prefiera.

4.2

Activar breadcrumbs

▶ 16:00

En File → Preferences → Settings se busca bread y se habilitan Breadcrumbs: Enabled y sus opciones. Arriba del editor aparece la ruta main.c → función, para navegar el código igual que con el Outline.

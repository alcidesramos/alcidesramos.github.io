Memoria SD por SPI con FatFs

En esta clase conectamos una memoria SD a la BlackPill STM32F401 por SPI y activamos el middleware FatFs en CubeMX. Agregamos la librería fatfs_sd, hacemos los cambios en stm32f4xx_it.c y user_diskio.c, y probamos en Proteus con una imagen de memoria que se puede revisar con UltraISO. Al final armamos un pequeño datalogger que guarda un contador y la temperatura del LM35 en Data.txt, con un pulsador para retirar la memoria sin dañar los archivos.

Fase 1

Configuración en CubeMX

1.1

Proyecto y archivos de Proteus

▶ 3:10

Creamos el proyecto (STM32F401CCU) en una carpeta vacía. Luego copiamos ahí el archivo de Proteus y la imagen de la memoria sdcard_image.mmc.

1.2

LED, pulsador, UART y ADC

▶ 4:10

PC13 (LED de la tarjeta) como salida con etiqueta LED.

PB10 como entrada con etiqueta sw y pull-up, porque el pulsador va a tierra. Servirá para expulsar la memoria.

USART1 en modo asíncrono a 9600 baudios para ver mensajes, y ADC1 IN0 para el sensor de temperatura.

1.3

SPI y pin SD_CS

▶ 5:35

PA4 como salida con etiqueta obligatoria SD_CS (habilitador de la memoria).

SPI1 en Full-Duplex Master. Ajustamos el prescaler a 8 para tener 2 MBits/s, ideal para Proteus.

En la vida real la memoria aguanta más velocidad: con estas librerías se llegó a 10–12 MHz.

1.4

Activar FatFs

▶ 7:10

En Middleware > FATFS marcamos User-defined. Dejamos MAX_SS en 512 (el sector mínimo) y la opción Tiny habilitada para ahorrar memoria. Luego generamos código con el engranaje.

2.2

Configurar fatfs_sd.h

▶ 11:05

En fatfs_sd.h se indica el SPI usado (hspi1) y el pin de habilitación. Como SD_CS ya se definió en CubeMX, esas líneas quedan comentadas.

#define SPI_TIMEOUT 100
extern SPI_HandleTypeDef hspi1;
#define HSPI_SDCARD &hspi1
2.3

Temporizadores en stm32f4xx_it.c

▶ 11:40

En las variables privadas del archivo de interrupciones declaramos Timer1 y Timer2, y los descontamos cada milisegundo dentro de SysTick_Handler. Son el time-out que evita que la lectura de la memoria se bloquee.

/* variables privadas */
extern uint16_t Timer1, Timer2;

/* dentro de SysTick_Handler(void) */
if (Timer1 > 0) Timer1--;
if (Timer2 > 0) Timer2--;
2.4

Cambios en user_diskio.c

▶ 14:30

En FATFS/Target/user_diskio.c incluimos fatfs_sd.h y cambiamos el return de cada función por la función de la librería. Con Ctrl+Espacio el editor las autocompleta.

#include "fatfs_sd.h"

/* USER_initialize */ return SD_disk_initialize(pdrv);
/* USER_status */     return SD_disk_status(pdrv);
/* USER_read */       return SD_disk_read(pdrv, buff, sector, count);
/* USER_write */      return SD_disk_write(pdrv, buff, sector, count);
/* USER_ioctl */      return SD_disk_ioctl(pdrv, cmd, buff);

Es mejor hacer estos cambios a mano que reemplazar el archivo: CubeMX lo regenera y una versión nueva puede cambiar.

3.2

Función SD_PRUEBA

▶ 18:50

Monta la memoria, crea el archivo ARZ.txt, escribe tres líneas, lo cierra y lo vuelve a abrir para leerlo línea por línea con f_gets, enviando cada línea por el puerto serial.

void SD_PRUEBA()
{
  HAL_Delay(500);  // retardo de inicialización
  if (f_mount(&memsd, "", 1) == FR_OK) uartx_write_text(&huart1, "memoria encontrada\r\n");
  else uartx_write_text(&huart1, "memoria no encontrada\r\n");

  // abre un archivo y si no existe lo crea
  if (f_open(&archivo, "ARZ.txt", FA_OPEN_ALWAYS | FA_READ | FA_WRITE) != FR_OK)
    uartx_write_text(&huart1, "Archivo no creado\r\n");
  else uartx_write_text(&huart1, "Archivo creado\r\n");

  f_puts("PROBANDO\r\n", &archivo);
  f_puts("FUNCIONANDO\r\n", &archivo);
  f_puts("mas datos\r\n", &archivo);
  f_close(&archivo);

  // lectura línea por línea
  f_open(&archivo, "ARZ.txt", FA_READ);
  while (f_gets(texto, sizeof(texto), &archivo))
    uartx_write_text(&huart1, texto);
  f_close(&archivo);
}

Cada archivo que se abre se debe cerrar con f_close; si no, la memoria se puede corromper. f_mount(NULL, "", 1) desmonta la memoria.

3.3

Modos de apertura de f_open

▶ 21:10
  • FA_READ: lectura.
  • FA_WRITE: escritura.
  • FA_OPEN_EXISTING: abre un archivo existente; si no existe da error.
  • FA_CREATE_NEW: crea un archivo; si ya existe da error.
  • FA_CREATE_ALWAYS: crea el archivo y si existe lo sobrescribe.
  • FA_OPEN_ALWAYS: abre el archivo y si no existe lo crea.
  • FA_OPEN_APPEND: abre para agregar al final y si no existe lo crea.
3.4

Simulación y revisión con UltraISO

▶ 25:30

En main llamamos SD_PRUEBA() antes del while y dentro del while ponemos PIN_BLINK(LED) con HAL_Delay(200) para ver que el programa no se bloqueó.

En Proteus cargamos sdcard_image.mmc en la memoria (32 MB) y el .hex en el micro. El terminal muestra lo leído; con UltraISO abrimos la imagen y vemos el archivo ARZ.txt creado.

Fase 4

Agregar datos y datalogger

4.1

Agregar texto a un archivo

▶ 27:20

Con FA_OPEN_APPEND el archivo no se borra: cada vez que el micro arranca agrega las líneas al final. Con FA_CREATE_ALWAYS se crea Data.txt nuevo en cada arranque.

// abre un archivo existente para agregar datos
if (f_open(&archivo, "suscribete.txt", FA_OPEN_APPEND | FA_READ | FA_WRITE) == FR_OK)
{
  HAL_Delay(1);
  f_puts("AL MEJOR\r\n", &archivo);
  f_puts("CANAL\r\n", &archivo);
  f_puts("EMBEBIDOS\r\n", &archivo);
  f_close(&archivo);
}

// crea el nuevo archivo para almacenar los datos
f_open(&archivo, "Data.txt", FA_CREATE_ALWAYS | FA_READ | FA_WRITE);
f_close(&archivo);
4.2

Guardar temperatura y retirar la memoria

▶ 31:20

En el while leemos el ADC, convertimos a grados (LM35), armamos la línea con sprintf y la agregamos a Data.txt. Si se presiona el pulsador, se deja de escribir y hay 3 segundos para retirar la memoria con seguridad.

uint16_t codigo;
float temperatura;
uint16_t cont = 0;

while (1)
{
  PIN_BLINK(LED);
  codigo = ADC_Read();
  temperatura = codigo * 3.3 * 100.0 / 4095.0;
  sprintf(texto, "%u\t%.1f\r\n", cont, temperatura);
  cont++;
  if (PIN_READ(sw) == 1)
  {
    f_open(&archivo, "Data.txt", FA_OPEN_APPEND | FA_READ | FA_WRITE);
    HAL_Delay(1);
    f_puts(texto, &archivo);
    f_close(&archivo);
  }
  else
  {
    uartx_write_text(&huart1, "puede retirar la memoria\r\n");
    HAL_Delay(3000);
  }
  HAL_Delay(200);
}

Para que sprintf imprima flotantes hay que activar en Properties > C/C++ Build > Settings > MCU Settings la opción Use float with printf. Sin eso, la temperatura no aparece en el archivo.

IoT con DT-06 y Ubidots: enviar, recibir y eventos

El DT-06 se configura (clase 95) para conectarse a internet y a things.ubidots.com por el puerto 80, de modo que lo que el micro escribe por serial llega al servidor. La librería UBIDOTS arma las peticiones HTTP: Ubidots_POST construye en una sola trama el encabezado y el JSON con las variables, y Ubidots_GET pide el último valor de una variable; Ubidot_GET_Valor lo extrae de la respuesta. La recepción usa DMA + IDLE en USART1 (Ubidots) y queda USART2 libre para monitorear. La espera de respuesta no es bloqueante: se sale apenas el servidor responde. En el tablero se ven el LED y la temperatura, y desde la web se manejan el LED de la placa y el ancho de pulso. Por último se crea un evento que manda un correo cuando la temperatura supera 32 °C y se comparte el dashboard con un enlace público.

Fase 1

Librería UBIDOTS

1.1

Qué se va a hacer

▶ 0:00

Desde cualquier parte del mundo se va a prender el LED de la tarjeta, cambiar un PWM, ver la temperatura de un DS18B20 y el estado de un pulsador. El DT-06 ya debe estar conectado a la red y apuntando a Ubidots por el puerto 80 (explicado en la clase 95).

1.2

Configurar UBIDOTS.h

▶ 2:09

En el .h se pone el token de su cuenta, el nombre del device, los tiempos máximos de espera y el puerto serial donde está el DT-06:

#define Token  "BBUS-xxxxxxxxxxxxxxxxxxxxxxxx"  // su token de Ubidots
#define Device "SUSCRIBETE"                     // nombre del device
#define TIME_POST 4   // tiempo de espera respuesta POST (s)
#define TIME_GET  3   // tiempo de espera respuesta GET (s)

#define ubidot_tramatx_size   500   // largo max trama a enviar
#define uartubidotreg  USART1        // puerto del DT-06
#define uartubidot     huart1
#define trama_rx_ubidots_size 1000   // la respuesta del GET es larga

El token es personal: no lo publique ni lo comparta.

1.3

Dos puertos seriales

▶ 3:48

La librería uart_int_idle_dma se deja en USART2 para monitorear o recibir otras órdenes, y UBIDOTS usa USART1. Si no va a usar el segundo puerto, puede poner el mismo y comentar su análisis en el callback.

#define uartdatosreg USART2   // en uart_int_idle_dma.h
#define uartdatos    huart2
Fase 2

Cómo funciona por dentro

2.1

Callback compartido

▶ 5:29

El mismo HAL_UARTEx_RxEventCallback atiende los dos puertos; para Ubidots llama a Ubidots_Interrupt, que detiene el DMA y levanta su bandera:

void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
    if ((flag_rx == 0) && (huart->Instance == uartdatosreg))
    {
        HAL_UART_DMAStop(&uartdatos);
        num_datos = Size;
        flag_rx = 1;
    }
    // solo si se usa ubidots
    Ubidots_Interrupt(huart);
}

void Ubidots_Interrupt(UART_HandleTypeDef *huart)
{
    if ((flag_rx_ubidots == 0) && (huart->Instance == uartubidotreg))
    {
        HAL_UART_DMAStop(&uartubidot);
        flag_rx_ubidots = 1;
    }
}
2.2

Espera que no bloquea

▶ 10:00

En vez de esperar siempre el tiempo completo, se espera en pasos de 1 ms y se sale apenas el servidor responde:

void Ubidot_delay(uint16_t tiem)
{
    for (uint16_t cuen = 0; cuen < tiem * 1000; cuen++)
    {
        HAL_Delay(1);
        if (flag_rx_ubidots == 1) break;
    }
}
2.3

El POST en una sola trama

▶ 7:46

Ubidots_POST arma el encabezado HTTP con el device, el token y el largo del JSON, y añade el JSON con las variables:

void Ubidots_POST()
{
    ubidots_dma_init();
    memset(ubidots_tx, 0, ubidot_tramatx_size);
    sprintf(ubidots_tx,
        "POST /api/v1.6/devices/%s/?token=%s HTTP/1.1\r\n"
        "Host: things.ubidots.com\r\n"
        "Content-Type: application/json\r\n"
        "Content-Length: %d\r\n"
        "\r\n"
        "%s",
        Device, Token, ubidot_tramavar_size, ubidot_var);
    flag_rx_ubidots = 0;
    uartx_write_text(&uartubidot, ubidots_tx);
    Ubidot_delay(TIME_POST);
}
Fase 3

Enviar datos (POST)

3.1

Variables y arranque

▶ 11:08

En el main se declaran temperatura (float) y led (uint8_t), se inicializan retardos y PWM y se apaga el LED (en la BlackPill es invertido).

float temperatura;
uint8_t led;
char texto[100];

delay_Init();
PWM_init(&PWM1);
PWM_valor(&PWM1, 0);
PIN_ON(LED);   // apaga el LED (logica invertida)
3.2

Armar el JSON y enviar

▶ 11:41

Se arma la trama de variables con sus nombres en Ubidots (%u para enteros, %.1f para decimales), se calcula su largo y se llama al POST:

temperatura = DS18b20_temp();
led = PIN_READ(SW);

// ARMA TRAMA DE VARIABLES
sprintf(ubidot_var, "{\"led\": %u,\"temperatura\": %.1f}", led, temperatura);
ubidot_tramavar_size = strlen(ubidot_var);
// LLAMA POST
Ubidots_POST();

Prueba del POST

▶ 13:54

En el dashboard el indicador LED sigue al pulsador y el termómetro a la temperatura, casi en tiempo real, porque la espera termina en cuanto responde el servidor.

Fase 4

Recibir datos (GET)

4.1

La petición GET

▶ 15:35

Ubidots_GET arma la petición con el device, la variable a leer y el token, y espera la respuesta. Ubidot_GET_Valor busca en la respuesta la palabra value", captura desde los dos puntos hasta la coma y retorna ese número (−2 si no encontró el valor, −1 si el servidor no respondió).

sprintf(ubidots_tx,
    "GET /api/v1.6/devices/%s/%s/values?page_size=1&token=%s HTTP/1.1\r\n"
    "Host: things.ubidots.com\r\n\r\n",
    Device, lee_var, Token);
4.2

Slider al PWM y switch al LED

▶ 19:02

Se pide cada variable y se aplica. El valor siempre llega como float; el LED se niega porque es invertido:

// analiza el get
Ubidots_GET("pwm");
ubidot_float = Ubidot_GET_Valor();
PWM_valor(&PWM1, (uint32_t)ubidot_float);

Ubidots_GET("suiche");
ubidot_float = Ubidot_GET_Valor();
PIN_PUT(LED, !(uint8_t)ubidot_float);

HAL_Delay(100);

Fase 5

Eventos y compartir

5.1

Evento por temperatura

▶ 22:58

En Events se crea uno nuevo: variable temperatura, condición mayor o igual a 32 (no use igual con decimales). En Actions se elige enviar un correo con el mensaje deseado. En el plan gratuito el correo es limitado.

Clase 19: Procedimientos y #define en C

Sobre el proyecto del display de 7 segmentos (STM32F401) agregamos 4 LEDs en PB12–PB15 y aprendemos a usar procedimientos: bloques de código con nombre que se escriben una vez y se llaman cuantas veces se quiera. Con #define damos nombres fáciles a los puertos, y con parámetros hacemos que un mismo procedimiento funcione a distintas velocidades. Los juegos de luces usan el registro BSRR en modo atómico de la clase pasada.

Fase 2

Procedimientos

2.1

Crear un procedimiento

▶ 2:59

Recomiendo crearlos en USER CODE BEGIN PFP (o 0), después de las variables. Se escribe void, el nombre, paréntesis y llaves; dentro va el código. Sin parámetros, los paréntesis van vacíos.

void hola()
{
  // aquí el código que muestra HOLA en el display
}
2.2

Llamarlo

▶ 4:03

Si no se llama, no se ejecuta. Se llama por su nombre con punto y coma, tantas veces como se quiera, sin copiar el código:

while (1)
{
  chao();
  chao();
  baja();   // conteo regresivo 3, 2, 1
}

Si lo escribes después del main, declara antes su prototipo: void baja();

Fase 3

#define

3.1

Nombres para los puertos

▶ 5:05

En USER CODE BEGIN PD (Private define). El preprocesador cambia el nombre por su valor antes de compilar, así no hay que memorizar registros.

#define leds GPIOB->ODR
3.2

Luces 1: invertir con NOT

▶ 9:05
void luces1()
{
  leds = ~leds;
  HAL_Delay(200);
  leds = ~leds;
  HAL_Delay(200);
  leds = ~leds;
  HAL_Delay(200);
  leds = ~leds;
  HAL_Delay(200);
}
Fase 4

Juegos de luces atómicos

4.1

Luces 2: encender en secuencia

▶ 10:46
void luces2()
{
  leds = 0;   // apaga
  HAL_Delay(200);
  GPIOB->BSRR = LED1_Pin;
  HAL_Delay(200);
  GPIOB->BSRR = LED2_Pin;
  HAL_Delay(200);
  GPIOB->BSRR = LED3_Pin;
  HAL_Delay(200);
  GPIOB->BSRR = LED4_Pin;
  HAL_Delay(200);
}
4.2

Luces 3: auto fantástico

▶ 11:54

Enciende en orden y luego apaga en sentido inverso. El STM32F401 no tiene registro BRR, así que para apagar se usa la parte alta de BSRR: el pin desplazado 16 posiciones.

// apaga en sentido inverso
GPIOB->BSRR |= LED4_Pin << 16;
HAL_Delay(200);
GPIOB->BSRR |= LED3_Pin << 16;
HAL_Delay(200);
GPIOB->BSRR |= LED2_Pin << 16;
HAL_Delay(200);
GPIOB->BSRR |= LED1_Pin << 16;
HAL_Delay(200);
Fase 5

Parámetros

5.1

Un parámetro de velocidad

▶ 13:32

Los parámetros son variables locales que solo existen dentro del procedimiento. Reemplaza los 200 por el parámetro (Ctrl+F → Replace, solo en lo seleccionado) y llámalo con distintos valores:

void luces3(uint8_t velo) { ... HAL_Delay(velo); ... }

luces3(200);
luces3(100);
luces3(50);
5.2

Varios parámetros

▶ 15:53

Se separan con coma. Uno para la subida y otro para la bajada. Con uint8_t el máximo es 255, por eso para 500 ms se cambia a uint16_t.

void luces3(uint16_t velosub, uint16_t veloba)
{
  // ... HAL_Delay(velosub) al encender
  // ... HAL_Delay(veloba) al apagar
}

luces3(200, 100);
luces3(100, 200);
luces3(80, 500);

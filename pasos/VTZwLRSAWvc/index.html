Clase 135: gráfica del voltaje en la ILI9341 con TouchGFX

Partiendo del proyecto TouchGFX con la ILI9341 táctil (pantalla 1 con voltaje y pantalla 2 con slider), en esta clase agregamos en la pantalla 2 un widget Dynamic Graph de 200 puntos con rango 0 a 4, líneas horizontales y etiquetas en el eje Y. Creamos una interacción que cada 5 ticks llama a una función virtual GRAFICAR, la implementamos en Screen2View.cpp usando la variable externa voltaje que calcula el main, y la convertimos de escala 0-100 a 0-3.3 V. Al final corregimos un error típico: haber marcado la pantalla 2 como Startup Screen.

Fase 1

Diseñar la gráfica en TouchGFX

1.1

Agregar un Dynamic Graph en la pantalla 2

▶ 0:33

En TouchGFX Designer abrimos Screen2 y desde los widgets agregamos un Graph de tipo Dynamic: se alimenta punto a punto, ideal para una señal en tiempo real (el estático es para varios puntos ya conocidos).

Lo hacemos pequeño para que quepa junto al botón BACK y al slider.

1.2

Número de puntos y rango de valores

▶ 1:05

En Data Points ponemos 200 puntos, y en Value Range Min 0 y Max 4 (vamos a graficar de 0 a 3.3 V).

No usamos el mapeo de índices; los valores entran directamente en el rango de la gráfica.

Con muchos puntos la gráfica tarda más en llenarse, así la señal se ve más continua.

1.3

Líneas horizontales y color

▶ 1:39

En Elements agregamos Horizontal Grid Lines (Major Division) con la línea delgada y un color claro, para que se vean las divisiones.

El intervalo de la división define cuántas líneas aparecen.

1.4

Etiquetas del eje Y y márgenes

▶ 2:11

Agregamos un Label solo en el eje Y para que aparezcan los números 0 a 4.

Con Graph Area Margin (Top, Left, Bottom) movemos el área de la gráfica para que los números queden visibles y bien ubicados.

Si los números se ven cortados, ajusta el margen izquierdo y el superior.

Fase 2

Interacción que llama a GRAFICAR

2.1

Crear la interacción cada N ticks

▶ 3:24

En Interactions creamos una nueva: Trigger On every N tick, con 5 ticks entre disparos para que los 200 puntos no se gasten tan rápido.

Si el sistema solo grafica y la señal es rápida, se puede dejar en 1 tick.

2.2

Acción: Call new virtual function

▶ 3:55

En Action escogemos Call new virtual function y la llamamos GRAFICAR (en mayúscula).

Luego damos Generate Code.

2.3

Nombrar la gráfica

▶ 7:15

Ojo: el widget queda con el nombre por defecto (dynamicGraph1). Le cambiamos el nombre a GRAFICA1 para usarlo en el código y volvemos a generar código.

El nombre del widget es el nombre del objeto en C++; si no coincide, el código no compila.

Fase 3

Código en CubeIDE

3.1

Copiar la función virtual al View

▶ 4:26

Compilamos y en generated/gui_generated/include/gui_generated/screen2_screen/Screen2ViewBase.hpp buscamos la nueva función GRAFICAR.

La copiamos en gui/include/gui/screen2_screen/Screen2View.hpp como virtual.

// Screen2View.hpp (dentro de la clase)
virtual void GRAFICAR();
3.2

Implementarla en Screen2View.cpp

▶ 5:01

En gui/src/screen2_screen/Screen2View.cpp agregamos la función vacía y compilamos para verificar.

Si salen errores, revisa la sintaxis Screen2View::GRAFICAR() (en el video faltaba un carácter).

void Screen2View::GRAFICAR()
{

}
3.3

Traer la variable externa voltaje

▶ 6:09

El voltaje ya lo usábamos en la pantalla 1 como extern float voltaje. Copiamos esa declaración también en Screen2View.cpp.

En el main el voltaje se calcula en escala de 0 a 100 a partir del ADC de 12 bits.

// main.c, en el while(1)
voltaje = ADC_Read(&hadc1)*100.0/4095.0;

// Screen1View.cpp y Screen2View.cpp
extern float voltaje;
3.4

Agregar el punto e invalidar

▶ 8:22

Dentro de GRAFICAR agregamos un punto con addDataPoint, convirtiendo de 0-100 a 0-3.3 V, y al final invalidate() para que se redibuje.

extern float voltaje;

void Screen2View::GRAFICAR()
{
    GRAFICA1.addDataPoint((float)(voltaje*3.3/100.0));
    GRAFICA1.invalidate();
}

La variable se llama voltaje; en el video primero escribió voltios y salieron errores.

Fase 4

Prueba y error de pantalla inicial

4.1

Programar y ver la gráfica

▶ 9:33

Compilamos, programamos y al mover el potenciómetro la gráfica sube y baja entre 0 y 3.3 V.

4.2

La pantalla 2 arrancaba primero

▶ 10:40

Al reiniciar aparecía directo la pantalla de la gráfica: sin querer se marcó Screen2 como Startup Screen.

Seleccionamos Screen1, damos Set as Startup Screen, generamos código y reprogramamos.

Revisa siempre cuál pantalla es la inicial si el equipo arranca en una que no esperabas.

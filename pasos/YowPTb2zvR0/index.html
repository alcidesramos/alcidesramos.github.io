Teclado USB HID con PIC

Se usa un PIC18F4550 (sirve el 2550 o el 45K50) a 48 MHz con el USB habilitado. Con la herramienta HID Terminal de MikroC se genera el descriptor USB con el nombre del dispositivo y se modifica para que sea un teclado: tamaño del reporte, clase y el descriptor de reporte de teclado. En el programa se declaran los buffers de lectura y escritura de 8 bytes en posiciones fijas, se llama USB_Interrupt_Proc en la interrupción y con HID_Write se envía el código de la tecla en la tercera posición del buffer. Luego se envía cero para que la tecla deje de repetirse. Los códigos de cada tecla están en la tabla de uso de teclado del estándar USB.

Fase 1

El circuito

1.1

La idea

▶ 0:00

Con un PIC que tenga USB se puede emular un teclado, un mouse u otro dispositivo HID. Así se puede hacer un control propio para juegos de computador que usan el teclado.

1.2

Proyecto

▶ 1:40

PIC18F4550 a 48 MHz con cristal de 20 MHz y PLL, USB habilitado y la parte análoga deshabilitada. Los pulsadores van en los cuatro primeros pines del puerto B con pull-up interna.

Fase 2

Descriptor USB

2.1

Generarlo

▶ 2:46

En Tools, HID Terminal, pestaña Descriptor, se ponen el VID, el PID, el nombre del fabricante y del producto (así lo muestra Windows) y el tamaño del reporte en 8. Se guarda en la carpeta del proyecto.

2.2

Cambios para teclado

▶ 4:50

El descriptor generado es genérico. Se cambia el tamaño del reporte (USB_HID_RPT_SIZE) a 63 y en el descriptor del dispositivo el valor de la clase por 0x01, que identifica un teclado.

2.3

Descriptor de reporte

▶ 7:20

Se reemplaza el reporte por el del teclado del estándar USB: Usage Page Generic Desktop, Usage Keyboard, las teclas modificadoras (Ctrl, Shift, Alt) y 6 bytes de teclas.

Fase 3

El programa

3.1

Buffers e interrupción

▶ 9:05

Los buffers de 8 bytes van en posiciones fijas de memoria. En la interrupción se atiende el USB. Se activa la librería USB y se agrega el archivo del descriptor al proyecto.

unsigned char readbuff[8] absolute 0x500;
unsigned char writebuff[8] absolute 0x508;

void interrupt()
{
  USB_Interrupt_Proc();   // INTERRUPCION POR USB
}
3.2

Mandar una tecla

▶ 11:59

El byte 0 es el modificador (Shift, Ctrl), el byte 1 siempre es cero y en el byte 2 va el código de la tecla: 4 es la A. Si solo se envía la tecla, se sigue repitiendo; hay que enviar después un cero.

3.3

Códigos de teclas

▶ 15:24

En la tabla Keyboard/Keypad Page del estándar USB están todos los códigos: 4 la A, 7 la D, 26 la W, y así con las flechas y las demás teclas.

3.4

Programa final

▶ 16:29

Cada pulsador manda su tecla, espera el tiempo de repetición y luego manda cero. El retardo de 500 ms da un movimiento más fluido en el juego.

void main(void)
{
  //Initialize ports
  ADCON1 = 0b1111;   // todo digital
  TRISC.B6 = 0;
  TRISB = 0x0F;      // RB0 -RB3 ENTRADAS
  NOT_RBPU_bit = 0;  //HABILITA PULL UPS
  HID_Enable(readbuff, writebuff);
  LATB = 0;
  while (1)
  {
    memset(writebuff, 0, 8);
    writebuff[0] = 0;  // modificador modifier keys (SHIFT, CTRL, etc)
    writebuff[1] = 0;  // relleno o padding siempre cero
    if (RB0_bit == 0)
    {
      writebuff[2] = 4;                     //manda la 'A'
      while (!HID_Write(writebuff, 8));
      Delay_ms(500);
      writebuff[2] = 0;
      while (!HID_Write(writebuff, 8));     // deja de mandar
    }
    if (RB1_bit == 0)
    {
      writebuff[2] = 7;                     //manda la 'D'
      while (!HID_Write(writebuff, 8));
      Delay_ms(500);
      writebuff[2] = 0;
      while (!HID_Write(writebuff, 8));     // deja de mandar
    }
    // ... igual con las otras teclas
  }
}

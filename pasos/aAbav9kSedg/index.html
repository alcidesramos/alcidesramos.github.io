Entradas digitales y condicional if

Primera clase de entradas. Se revisa en el pinout que los pines de la F401 toleran 5 V (en la F411 hay dos que solo aceptan 3.3 V). En Proteus se conectan dos pulsadores y se explica por qué un pulsador abierto deja la entrada en el aire y cómo lo resuelven las resistencias pull-up y pull-down. Luego se lee el pulsador con HAL_GPIO_ReadPin dentro de un if, se ve el problema del rebote y cómo evitarlo con un retardo, se simplifica la lectura con #define, se activan las resistencias internas desde CubeMX y se terminan las cuatro combinaciones de dos pulsadores con if, else if y else.

Fase 1

Pulsadores y resistencias

1.1

¿Puedo conectar sensores de 5 V?

▶ 0:35

En el pinout de la Black Pill dice: All pins are 5V tolerant on F401. Con la F401 puedes conectar entradas digitales de 0 a 5 V aunque el micro se alimente a 3.3 V.

En la F411, los pines 10 y 41 (PA0 y PB5) solo aceptan 3.3 V. Para sensores de 5 V usa los demás.

1.2

El pulsador en el aire

▶ 2:23

En Proteus busca BUTTON. Un extremo va a un pin del micro y el otro a tierra o a positivo.

Si va a tierra, al presionar el micro lee 0; pero suelto, el pin queda en el aire y no se sabe qué lee. En electrónica no se puede dejar esa incertidumbre: se garantiza el estado con una resistencia.

1.3

Pull-up y pull-down

▶ 6:23

Pull-up: pulsador a tierra y resistencia del pin a positivo. Suelto lee 1, presionado lee 0. Valor recomendado de 1 kΩ a 10 kΩ (máximo 47 kΩ; más alto capta ruido en la industria).

Pull-down: pulsador a positivo y resistencia del pin a tierra. Suelto lee 0, presionado lee 1. Por experiencia, de 330 Ω a 1 kΩ: con 10 kΩ la tierra queda casi flotante y hay falsos contactos.

Fase 2

Leer el pulsador con if

2.1

Configurar el pin

▶ 12:15

En CubeMX pon el pin del pulsador (en la clase PB12) como GPIO_Input y ponle una etiqueta, por ejemplo SW1.

Tras un cambio de hardware pulsa el engranaje y luego compila.

2.2

La estructura if

▶ 14:01

if (condición) { acción; }: si la condición se cumple, hace lo que está entre llaves. El if no lleva punto y coma.

Si la acción es una sola instrucción las llaves son opcionales; con dos o más son obligatorias.

Para leer el pin usa HAL_GPIO_ReadPin(puerto, pin). Con pull-up, presionado es 0.

while (1)
{
  if (HAL_GPIO_ReadPin(SW1_GPIO_Port, SW1_Pin) == 0)
  {
    hola();   // cualquier procedimiento
  }
}
2.3

Igual (=) no es lo mismo que igual igual (==)

▶ 18:54

= es asignación: le da un valor a una variable. == es comparación: pregunta si son iguales.

Operadores de comparación en C: == igual, != diferente, >, <, >=, <=.

Si escribes un solo = dentro del if, a veces el compilador lo acepta y el programa hace algo distinto sin avisar.

2.4

Cambiar un LED y el rebote

▶ 20:32

Dentro del if pon HAL_GPIO_TogglePin para que cada pulsación invierta el LED.

Verás que a veces queda prendido, a veces apagado o titila: es el rebote. Las láminas del pulsador vibran al cerrar y el micro, tan rápido, lee varias pulsaciones.

La forma más simple de evitarlo es un retardo de 150 a 400 ms después de la acción.

if (HAL_GPIO_ReadPin(SW1_GPIO_Port, SW1_Pin) == 0)
{
  HAL_GPIO_TogglePin(AMARILLO_GPIO_Port, AMARILLO_Pin);
  HAL_Delay(300);   // antirrebote
}
Fase 3

Simplificar y mejorar

3.1

Ponerle nombre a la lectura con #define

▶ 28:25

Para no escribir toda la función en cada if, defínela arriba con un nombre corto.

Truco: escribe la función en el while (ahí sí autocompleta), córtala y pégala en el #define.

/* USER CODE BEGIN PD */
#define SW1 HAL_GPIO_ReadPin(SW1_GPIO_Port, SW1_Pin)
#define SW2 HAL_GPIO_ReadPin(SW2_GPIO_Port, SW2_Pin)
/* USER CODE END PD */

// en el while:
if (SW1 == 0) { ... }

En la clase se usó el nombre switch, pero switch es una palabra reservada de C. Usa nombres como SW1 o BOTON1.

3.2

La lectura no es instantánea

▶ 31:23

Si después del if llamas a otro procedimiento largo (por ejemplo una melodía), el programa solo lee el pulsador cuando vuelve al if. Hay que mantenerlo presionado hasta que pase por ahí.

Con else haces una cosa si se cumple la condición y otra si no.

if (SW1 == 0)
{
  HAL_GPIO_TogglePin(AMARILLO_GPIO_Port, AMARILLO_Pin);
  HAL_Delay(300);
}
else chao();
3.3

Resistencias internas del micro

▶ 34:14

Los STM32 tienen pull-up y pull-down internas: puedes quitar la resistencia del circuito y conectar el pulsador directo a tierra o a positivo.

En CubeMX: System Core → GPIO, selecciona el pin (PB12) y en GPIO Pull-up/Pull-down elige Pull-up (pulsador a tierra) o Pull-down (pulsador a positivo).

Fase 4

Dos pulsadores

4.1

Unir condiciones

▶ 39:17

Con dos pulsadores hay 2² = 4 combinaciones.

Para unir condiciones: && es Y (las dos deben cumplirse) y || es O (basta una). Se escriben dobles; uno solo es una operación de bits.

Como las combinaciones son excluyentes se usa else if: en cuanto una se cumple, el micro no revisa las demás. La última puede ser un simple else.

if (SW1 == 0 && SW2 == 0)
{
  HAL_GPIO_TogglePin(AMARILLO_GPIO_Port, AMARILLO_Pin);
  HAL_Delay(2000);
}
else if (SW1 == 1 && SW2 == 0) cancion();
else if (SW1 == 0 && SW2 == 1) conteo();
else chao();

Con varios if sueltos el micro evalúa todos aunque ya encontró el caso. Con else if es más eficiente.

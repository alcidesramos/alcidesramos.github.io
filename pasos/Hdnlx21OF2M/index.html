Recepción serial con DMA + IDLE line en STM32

Primero se prueba la transmisión básica por USART1 a 9600 baudios con el terminal virtual de Proteus. Luego se habilita la interrupción del USART1 y un canal DMA para RX, y se usa HAL_UARTEx_ReceiveToIdle_DMA: el DMA guarda los bytes automáticamente y la detección IDLE avisa cuando la trama terminó, generando el callback HAL_UARTEx_RxEventCallback (que se encuentra como función __weak en stm32f4xx_hal_uart.c). Después todo se organiza en la librería uart_int_idle_dma, que limpia la trama y los flags, inicia la recepción y levanta una bandera flag_rx para procesar en el main. Con un puerto serial virtual (COM1-COM2) y Hercules se envían órdenes como ledaon / ledaoff / ledvon / ledvoff y VELO=20/ para cambiar el ciclo útil de un PWM con la librería PWMB, todo mientras siguen funcionando las interrupciones de timer y de pulsadores de las clases anteriores.

Fase 1

Serial básico

1.1

USART1 asíncrono a 9600

▶ 0:30

En Connectivity → USART1 se elige modo Asynchronous y 9600 baudios (para no sobrecargar la simulación). Los pines quedan en PB7 (RX) y PA9 (TX).

1.2

Conexión en Proteus

▶ 1:20

Se conecta un Virtual Terminal cruzado: TX del micro al RX del terminal y RX del micro al TX del terminal.

1.3

Probar la transmisión

▶ 2:42

Con la librería uart.h del canal se envía un texto cada 500 ms:

uartx_write_text(&huart1, "OKS\r\n");
HAL_Delay(500);

Si en el terminal salen caracteres extraños, revise los baudios y, en Proteus, refresque las propiedades del componente (botón del engranaje) para que tome los cambios.

Fase 2

Recepción con DMA e IDLE

2.1

IDLE line detect + DMA: habilitarlos

▶ 5:59

El USART detecta inactividad en la línea de recepción y así sabe que la trama está completa. Combinado con DMA (acceso directo a memoria), los bytes se guardan solos en el buffer y solo hay una interrupción por trama, no una por carácter.

En USART1 → NVIC Settings se habilita USART1 global interrupt. En DMA Settings se agrega USART1_RX en modo Normal, ancho de dato Byte. En System Core → NVIC se pueden ajustar las prioridades frente al timer.

2.2

El callback correcto

▶ 8:48

En stm32f4xx_it.c aparece USART1_IRQHandler, pero ese no es el que se usa. La función a implementar es HAL_UARTEx_RxEventCallback, que está declarada como __weak en Drivers/STM32F4xx_HAL_Driver/Src/stm32f4xx_hal_uart.c. Se copia al main quitando __weak.

2.3

Arrancar la recepción y responder

▶ 10:00

Se crea el buffer, se inicia la recepción antes del while y en el callback se responde y se vuelve a activar el DMA:

char trama_rx[100];

void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
    uartx_write_text(&huart1, "LLEGO ");
    uartx_write_text(&huart1, trama_rx);
    HAL_UARTEx_ReceiveToIdle_DMA(&huart1, (uint8_t*)trama_rx, 100);
}

/* en main(), antes del while */
HAL_UARTEx_ReceiveToIdle_DMA(&huart1, (uint8_t*)trama_rx, 100);
2.4

Puerto virtual y Hercules

▶ 12:56

Se reemplaza el terminal por un COMPIM (aquí TX con TX y RX con RX, sin cruzar). Con un emulador de puertos serie se crea el par COM1-COM2: Proteus en COM1 y Hercules en COM2, ambos a 9600. Al escribir "hola" en Hercules el micro responde con lo que llegó.

No una varias salidas TX al RX del micro: un terminal extra solo puede quedar para monitorear.

Fase 3

Librería uart_int_idle_dma

3.1

Configurar la librería

▶ 17:04

Se copian uart_int_idle_dma.c/.h a Core/Librerias y se incluyen junto con stdio.h, stdlib.h y string.h. En el .h se define el puerto, el nombre y el tamaño de la trama:

#define trama_rx      Trama_RX   // nombre de la trama
#define uartdatosreg  USART1     // puerto serial a analizar
#define uartdatos     huart1
#define trama_size    100        // tamaño del buffer

extern char flag_rx;
extern uint16_t num_datos;
extern uint8_t trama_rx[];
extern char procesa[];
3.2

Cómo trabaja por dentro

▶ 19:51

La función de inicio borra la trama, limpia los flags del USART para no arrastrar datos viejos y arranca la recepción. El callback detiene el DMA, guarda cuántos datos llegaron y levanta la bandera:

// en STM32F
uartdatosreg->SR &= ~(UART_FLAG_RXNE | UART_FLAG_ORE);
uint8_t dummy = uartdatosreg->DR;
HAL_UARTEx_ReceiveToIdle_DMA(&uartdatos, (uint8_t*)trama_rx, trama_size);

void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
    if ((flag_rx == 0) && (huart->Instance == uartdatosreg))
    {
        HAL_UART_DMAStop(&uartdatos);
        num_datos = Size;
        flag_rx = 1;
    }
}
3.3

Uso en el main

▶ 21:33

Se inicializa una vez y en el while se procesa cuando hay trama, se baja la bandera y se reinicia la recepción:

uartdat_it_idle_dma_init();

while (1)
{
    if (flag_rx == 1)
    {
        procesa_rx();
        flag_rx = 0;
        uartdat_it_idle_dma_init();
    }
    PIN_BLINK(LED1);
    HAL_Delay(500);
}

Si olvida poner flag_rx en 0 o reiniciar la recepción, solo se recibirá la primera trama.

Fase 4

Procesar órdenes

4.1

Órdenes puntuales para LEDs

▶ 23:20

Se agregan dos LEDs (verde y amarillo) y una función que busca palabras clave en la trama con strstr. Como las órdenes son excluyentes se encadenan con else if:

void procesa_rx()
{
    if (strstr(trama_rx, "ledaon"))       { PIN_ON(leda);  }
    else if (strstr(trama_rx, "ledaoff")) { PIN_OFF(leda); }
    else if (strstr(trama_rx, "ledvon"))  { PIN_ON(ledv);  }
    else if (strstr(trama_rx, "ledvoff")) { PIN_OFF(ledv); }
}

Crear la función no basta: hay que llamarla dentro del if (flag_rx == 1).

4.2

PWM en TIM1 canal 4

▶ 30:25

Se activa PWM Generation CH4 en TIM1 (PA11). Con 16 MHz se usa Prescaler 16000-1 (1 ms por cuenta) y Counter Period 500 (≈500 ms). En PWMB.c la escala se deja en 100 (0 a 100 %) y se declara la salida:

float escala = 100;
PWMS PWM1 = {&htim1, &(TIM1->CCR4), TIM_CHANNEL_4};

/* en main() */
PWM_init(&PWM1);
4.3

Orden con valor: VELO=20/

▶ 38:41

Para cambiar un parámetro se envía la palabra clave con el valor entre "=" y "/". Con strtok se captura el número, atoi lo convierte y se aplica al PWM:

//VELO=20/
else if (strstr(trama_rx, "VELO"))
{
    strcpy(procesa, strtok(trama_rx, "="));  // inicia captura
    strcpy(procesa, strtok(0, "/"));          // captura hasta /
    uint16_t valor = atoi(procesa);
    PWM_valor(&PWM1, valor);
}
4.4

Resultado

▶ 40:54

Desde Hercules se envía VELO=10/, VELO=90/… y el osciloscopio muestra el cambio de ancho de pulso; ledaon/ledaoff prenden y apagan los LEDs. Todo convive con el main, el timer y los pulsadores: varios procesos gracias a las interrupciones.

SIM800 y GPS con PIC (parte 2)

Es la continuación de la parte 1. El Timer0 da el tiempo límite de la lectura por software: si se cumple, se activa flag_timer y la lectura retorna. Una máquina de estados busca los caracteres G, G, A y guarda la trama hasta el asterisco. La función de coordenadas copia la trama, revisa que el fix sea válido, separa los campos con strtok y pasa grados y minutos a grados decimales (los minutos se dividen entre 60 y el sur o el oeste quedan negativos). El programa envía los datos a Ubidots cada 5 segundos. También se deja una función para enviar un SMS.

Fase 1

Leer sin bloquear

1.1

Timer de espera

▶ 1:40

El Timer0 con preescalador 256 y TMR0H = 72, TMR0L = 228 interrumpe cada cierto tiempo. timer_enable recibe cuánto esperar y enciende el timer.

1.2

Variables

▶ 4:50

Se agregan las tramas del GPS, el estado de su máquina, la bandera flag_timer y las variables de grados, minutos, latitud, longitud y fix.

1.3

Lectura con límite

▶ 6:20

Soft_UART_Read espera un dato; si el timer se cumple antes, la bandera hace que retorne y el programa sigue.

Fase 2

Capturar la trama

2.1

Máquina de estados

▶ 7:50

lee_trama_soft lee dato por dato. Si llega la secuencia de la trama GGA pasa de estado en estado; en el estado final guarda los datos hasta el asterisco y retorna 1.

2.2

Fin de la trama

▶ 12:20

Al llegar el asterisco se apaga el timer, se limpia la bandera y se sale del procedimiento. Si el buffer pasa de 100 datos se reinicia el contador.

2.3

Probar la lectura

▶ 13:50

En un ciclo de prueba, si lee_trama_soft retorna 1 se envía la trama por serial; si no, se envía nada. En Proteus el GPS virtual se conecta al pin del puerto por software y el COMPIM al conversor serial.

Fase 3

Coordenadas y envío

3.1

SMS

▶ 16:40

manda_mensaje usa AT+CMGF=1, AT+CMGS con el número de destino y el texto, y termina con Ctrl+Z. El número se pone en el código.

3.2

Separar campos

▶ 18:10

La trama se copia a otro buffer porque primero hay que leer el fix. Con strtok se saltan las comas hasta el campo del fix y solo se sigue si vale 1 o 2.

3.3

Grados decimales

▶ 19:40

Los dos primeros dígitos son grados y el resto minutos. Los minutos se dividen entre 60 y se suman. Si la orientación es S (o W en la longitud) el valor queda negativo.

fix = atoi(captu_GPS);
if ((fix == 1) || (fix == 2)) {        // solo si ya tiene un dato valido
  strcpy(captu_GPS, strtok(trama_GPS1, ","));  // captura 1 coma
  strcpy(captu_GPS, strtok(0, ","));           // captura hasta segunda coma
  strcpy(captu_GPS, strtok(0, ","));           // captura latitud
  memset(c_grados, 0, 10);                     // limpia los grados
  strncpy(c_grados, captu_GPS, 2);             // captura los grados
  grados = atof(c_grados);
  minutos = atof(&captu_GPS[2]) / 60.0;        // lo pasa a grados
  latitud = grados + minutos;
  strcpy(captu_GPS, strtok(0, ","));           // orientacion o signo de la lat
  if (captu_GPS[0] == 'S') latitud = -latitud;
  // captura la longitud de la misma forma (W negativo)
}
3.4

Ciclo principal

▶ 21:10

Cuando hay una trama válida se calculan las coordenadas y se llama conectar, que envía temperatura, LED y GPS a Ubidots. El ciclo se repite cada 5 segundos y en el tablero aparece el punto en el mapa.

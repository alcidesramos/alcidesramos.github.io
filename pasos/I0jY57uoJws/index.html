Órdenes compuestas desde LabVIEW

LabVIEW transmite y el STM32 (simulado en Proteus) recibe; la comunicación es simplex. Los dos programas se unen con un par de puertos virtuales (COM1 para Proteus, COM2 para LabVIEW). En el panel frontal se ponen interruptores para los LEDs y botones para el motor. En el diagrama de bloques se configura VISA, y dentro de un While Loop una Event Structure envía una orden solo cuando cambia un control. El programa del micro es el de la clase 40.

Fase 1

Panel frontal

1.1

Puertos virtuales

▶ 0:20

Crea un par de puertos virtuales conectados entre sí (se mostró en un video anterior). El COMPIM de Proteus queda en COM1 y LabVIEW usará COM2.

1.2

Interruptores y botones

▶ 1:40

En el panel frontal agrega dos interruptores (LED2 y LED3) y, desde la paleta Silver, tres botones: Izquierda, Derecha y Stop. Agrega también un botón de salir para el ciclo.

Fase 2

Diagrama de bloques

2.1

Configurar el puerto serial

▶ 2:54

Desde Instrument I/O → Serial coloca VISA Configure Serial Port. En la entrada de recurso crea un control (el puerto) y deja 9600 baudios como constante.

Pon en falso la entrada Enable Termination Char: no queremos que un carácter de fin de línea corte la lectura, el terminador lo manejamos nosotros con '*'.

2.2

While Loop con Event Structure

▶ 4:34

Encierra todo en un While Loop detenido por el botón salir. Dentro pon una Event Structure: solo se transmite cuando hay un cambio, no en cada vuelta del ciclo.

Con Add Event Case crea el evento LED2: Value Change.

2.3

Armar la trama del LED

▶ 5:07

Dentro del evento, un Select elige la cadena según el valor nuevo del interruptor y la envía con VISA Write.

  • Verdadero: LED2=ON*
  • Falso: LED2=OFF*
2.4

Cerrar el puerto y manejar errores

▶ 6:13

Al salir del ciclo conecta VISA Close y un Simple Error Handler (Dialog & User Interface).

En Tools → Options → Environment deja activada la opción de cerrar automáticamente las sesiones VISA para que el puerto no se quede bloqueado. Se hace una sola vez.

Fase 3

Duplicar eventos

3.1

LED3

▶ 7:20

Clic derecho en la Event Structure → Duplicate Event Case, elige LED3 y cambia las cadenas a LED3=ON* / LED3=OFF*.

3.2

Botones del motor

▶ 7:55

Duplica el evento para Izquierda, Derecha y Stop. Aquí solo se envía la orden cuando el botón se presiona; al soltar no se manda nada (cadena vacía en el caso falso).

  • Izquierda: M1IZQ*
  • Derecha: M1DER*
  • Stop: M1STOP*

Usa en los botones una acción mecánica tipo pulsador (Switch/Latch When Pressed o When Released) para que vuelvan solos. En el video el motor no respondía porque la cadena tenía un cero de más: la trama debe ser idéntica a la que compara el micro.

Fase 4

Probar

4.1

Correr LabVIEW y Proteus

▶ 12:03

Ejecuta el VI y la simulación. La terminal virtual RX muestra las tramas que llegan y el micro enciende los LEDs y mueve el motor a la izquierda, a la derecha o lo detiene.

LED2=ON*LED2=OFF*LED3=OFF*M1DER*M1IZQ*M1STOP*

Es comunicación en un solo sentido. En las siguientes clases el micro transmite y LabVIEW recibe; luego se hará full duplex.

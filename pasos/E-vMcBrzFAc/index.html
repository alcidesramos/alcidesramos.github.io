Git, programación y display de 7 segmentos (ánodo común)

Clase con otro grupo sobre los mismos temas, con más detalle en Git: cada commit guarda el estado del programa, se puede volver a cualquier versión, publicar el repositorio en GitHub, compartir el enlace para que otros lo clonen y sincronizar los cambios. Luego se repasan las formas de programar la tarjeta (USB con BOOT, ST-Link y debug en VS Code), la diferencia entre Debug y Release, y se maneja un display de 7 segmentos de ánodo común, primero con HAL_GPIO_WritePin y luego escribiendo todo el puerto con el registro ODR.

Fase 1

Versiones con Git

1.1

Inicializar y hacer commit

▶ 3:24

En la pestaña de Source Control (las ramitas) pulsa Initialize Repository. Escribe un mensaje (por ejemplo "primera prueba") y haz Commit: queda guardado el estado actual del programa. Cada cambio importante merece su propio commit.

1.2

Publicar en GitHub

▶ 4:27

Con Publish Branch se sube a GitHub. Elige público si quieres compartirlo. Desde ahí puedes abrirlo en la web y copiar el enlace.

1.3

Clonar un repositorio

▶ 5:34

Con VS Code sin carpeta abierta, en Source Control elige Clone Repository, pega el enlace y escoge dónde guardarlo. Así el profesor reparte un proyecto de inicio y los estudiantes entregan sus tareas con un enlace.

1.4

Instalar Git

▶ 7:16

Instala Git para Windows (git-scm.com) y en VS Code las extensiones de GitHub, como GitHub Actions.

1.5

Comparar versiones y sincronizar

▶ 37:58

Cambia el retardo, compila y haz otro commit. En el gráfico del repositorio puedes pararte en cada commit y ver el código de esa versión. Sync Changes sube lo último a GitHub y el enlace queda actualizado.

Fase 2

Programar la tarjeta

2.1

Por USB con el bootloader

▶ 18:09

En STM32CubeProgrammer cambia a USB. Con la tarjeta desconectada, deja presionado BOOT, conéctala, pulsa actualizar hasta que aparezca USB1 y suelta. Connect, Open file (el .elf de build/Debug), Download y RESET.

2.2

Con el ST-Link

▶ 22:06

Conecta 3.3 V (rojo), SWDIO, SWCLK y GND según la serigrafía del programador y lleva el USB al programador. La primera vez actualiza su firmware con Firmware upgrade; hay una versión que además aparece como memoria USB para programar arrastrando el .bin.

2.3

Debug o Release

▶ 28:59

Si cargas un programa y no ves el cambio, revisa que estás compilando y cargando la misma configuración. Debug y Release generan el .elf en carpetas distintas; si compilas en Release y cargas el de Debug, cargas el viejo.

2.4

Depurar en VS Code

▶ 30:42

Verifica en Set Up STM32Cube project que aparezca el Cortex-M4 y el proyecto. En Run and Debug elige ST-Link (no J-Link). Step Over ejecuta una función completa, Step Into entra en ella y Step Out termina la que estás viendo. Play lo deja corriendo.

Fase 3

Display de ánodo común

3.1

Cátodo o ánodo

▶ 39:42

En cátodo común el común va a tierra y el segmento enciende con 1. En ánodo común el común va al positivo y el segmento enciende con 0. Lo correcto es una resistencia por segmento; el atajo académico es una sola en el común: 220 Ω en la vida real, 22 Ω en Proteus.

3.2

El circuito en Proteus

▶ 45:01

Black Pill con sus Power Rails en 3.3 V y un POWER en el reset (la tarjeta real ya tiene su pulsador). Busca DISPLAY, filtra por 7-Segment Displays y elige uno de siete entradas (no el BCD). En este grupo, ánodo común con una resistencia de 22 Ω al +5 V.

3.3

WritePin con ayuda del autocompletado

▶ 51:48

Si la IA insiste en TogglePin, pulsa Ctrl + Espacio para ver las funciones que de verdad existen y elige HAL_GPIO_WritePin. Al pasar el mouse por encima ves su descripción. Para comentar líneas usa Ctrl + /.

HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, 0);
3.4

Nombrar los siete pines

▶ 57:01

En CubeMX pon los siete pines como GPIO_Output y dales nombres de al menos dos o tres letras (en clase MARIA1…MARIA7). Con una sola letra el autocompletado se llena de opciones. Luego escribe cada segmento; en ánodo común, 0 enciende.

3.5

Todo el puerto con ODR

▶ 70:53

Si remapeas los siete pines a PA0…PA6 en orden, puedes escribirlos todos de una vez con el registro de salida, sin HAL. El bit de la derecha es PA0 (segmento a). Para un 5 en ánodo común se apagan b y e (quedan en 1):

GPIOA->ODR = 0b0010010;   // g f e d c b a  (ánodo común: 0 enciende)
3.6

Etiquetas en Proteus

▶ 77:22

Borra los cables y usa terminales DEFAULT con nombres A…G (aquí sí sirve una letra). Selecciona el grupo y cópialo con Block Copy para poner los del display rápido.

Reloj, protección, debugger y 7 segmentos

Segunda clase del semestre 2024-I. Se repasa cómo abrir, borrar y ubicar un proyecto y cómo generar el .hex. Luego se configura el reloj del STM32F401 (oscilador interno de 16 MHz para Proteus, cristales externos y PLL hasta 84 MHz) y se discute cuándo usar cada uno. Con STM32CubeProgrammer se explican los niveles de protección AA, BB y CC y cómo quitarla con un ST-Link. Desde el IDE se configura el debugger para correr el programa paso a paso y programar sin CubeProgrammer. Al final se nombran los pines de un display de 7 segmentos y se monta en Proteus.

Fase 1

Manejo del proyecto en CubeIDE

1.1

Abrir un proyecto existente

▶ 0:00

Opción 1: en la carpeta del proyecto abre el archivo .cproject; se carga todo el proyecto en el IDE (si abres solo el .ioc se abre únicamente la configuración).

Opción 2: con el IDE abierto, File → Open Projects from File System y selecciona la carpeta principal del proyecto → Finish.

Selecciona la carpeta raíz del proyecto, no la carpeta Core; si eliges Core el IDE no reconoce el proyecto.

1.2

Borrar un proyecto

▶ 1:12

Delete solo lo quita del área de trabajo; sigue en el disco.

Si marcas la opción de borrar del disco, se elimina definitivamente.

1.3

¿Dónde está guardado mi proyecto?

▶ 4:04

Clic derecho en el proyecto → Properties → Resource: el campo Location muestra la ruta. Útil para encontrar el .hex u otros archivos.

1.4

Generar el .hex y abrir el main

▶ 5:12

Properties → C/C++ Build → Settings → MCU Post build outputs → Convert to Intel Hex.

El main está en Core → Src → main.c; en el panel Outline de la derecha, clic en main(void) salta a la función.

Fase 2

Configurar el reloj

2.1

Clock Configuration

▶ 6:49

Abre el .ioc → pestaña Clock Configuration. Por defecto los osciladores externos están en gris; trabajan los internos: LSI 32 kHz (reloj de tiempo real) y HSI 16 MHz.

Para simular en Proteus deja HSI a 16 MHz directo.

2.2

Subir o bajar la frecuencia con el PLL

▶ 7:57

Escribe la frecuencia deseada en HCLK y pulsa Enter: el programa ajusta solo los divisores del PLL. Se puede llegar a 84 MHz, el máximo del F401.

2.3

¿Cristal interno o externo?

▶ 8:29

Interno: ahorra dos pines (quedan como E/S) y a baja frecuencia consume menos, ideal para baterías.

Externo (cuarzo): más preciso; recomendable a alta velocidad o con buses como CAN, I²C o SPI donde la desviación del oscilador interno puede causar errores.

2.4

Habilitar los cristales externos

▶ 9:35

En Pinout & Configuration → System Core → RCC pon High Speed Clock (HSE) y Low Speed Clock (LSE) en Crystal/Ceramic Resonator. Se ocupan dos pines por cada cristal.

En Clock Configuration aparecen el HSE de 25 MHz y el LSE de 32.768 kHz. Selecciona HSE como fuente del PLL y PLLCLK para llegar a 84 MHz.

El LSE debe ser de 32.768 kHz (lo usa el RTC). El HSE puede ser de 4 a 25 MHz; con uno barato de 4 MHz el PLL igual llega a 84 MHz.

Fase 3

Proteger el firmware

3.1

Conectar por USB (bootloader)

▶ 11:50

Abre STM32CubeProgrammer. Con la placa desconectada mantén presionado BOOT0, conecta el USB y suelta. Elige USB como interfaz y conecta.

3.2

Niveles de protección (RDP)

▶ 13:20

En OB (Option bytes) → Read Out Protection:

AA: sin protección, cualquiera puede leer y clonar el programa.

BB: protección contra lectura; ni tú puedes leerlo. Se puede quitar, pero al quitarla se borra todo (se lee pura FF).

CC: protección permanente, el micro queda con ese programa para siempre. Solo para productos finales críticos.

Si pones BB usando el bootloader USB ya no podrás volver a programarlo por USB: necesitas un programador ST-Link para quitar la protección. Nunca pruebes CC en una placa de práctica.

3.3

Quitar la protección con un ST-Link

▶ 16:10

El ST-Link usa 4 pines: SWDIO, GND, SWCLK y 3.3 V.

En CubeProgrammer elige ST-LINK, pon Shared: Enabled (necesario con clones) y conecta.

Cambia RDP de BB a AA y pulsa Apply. El micro queda libre pero el contenido anterior se borró.

3.4

Actualizar el firmware del programador

▶ 18:30

Antes de usar el ST-Link conviene actualizar su firmware: desde CubeProgrammer (Firmware upgrade) o desde el IDE en Help → ST-LINK Upgrade → Open in update mode → Upgrade.

Fase 4

Depurar y programar desde el IDE

4.1

Configurar el debugger

▶ 21:47

En la flecha junto al icono del bicho → Debug Configurations. Doble clic en STM32 C/C++ Application.

En la pestaña Debugger elige ST-LINK (ST-LINK GDB server), interfaz SWD, pulsa Scan para detectar el programador y luego Debug.

4.2

Ejecutar paso a paso

▶ 22:56

Step Over: ejecuta la función completa y pasa a la siguiente línea (la más usada).

Step Into: entra dentro de la función para ver su detalle.

Avanzando con Step Over llegas al TogglePin y ves el LED cambiar en la placa. El cuadrado rojo termina la sesión.

4.3

Programar sin CubeProgrammer

▶ 24:35

Cambia el código (por ejemplo el retardo) y pulsa Run (Play): compila y carga directo al micro con el ST-Link.

CubeProgrammer queda para tareas como la protección del micro.

HAL_GPIO_TogglePin(arroz_GPIO_Port, arroz_Pin);
HAL_Delay(600);
Fase 5

Display de 7 segmentos

5.1

Nombrar los pines

▶ 25:42

Configura 7 pines del mismo puerto (por ejemplo PA0–PA6) como GPIO_Output.

Con clic derecho → Enter User Label nómbralos ADP, BDP, CDP, DDP, EDP, FDP, GDP (segmento + 'DP' de display).

No uses nombres de una letra (A, B, C...): al pedir ayuda con Ctrl+Espacio salen miles de coincidencias. Usa al menos tres caracteres.

5.2

Display en Proteus

▶ 26:48

Busca el display de 7 segmentos (cátodo o ánodo común) y colócalo junto al micro.

Truco: una sola resistencia en el común (a GND si es cátodo común). En la vida real 220–330 Ω; en Proteus debe ser de unos 22–33 Ω para que simule bien.

Para un producto real usa una resistencia por segmento.

5.3

Etiquetas y cableado rápido

▶ 27:54

Usa Terminals → DEFAULT con etiquetas A…G para unir micro y display sin cables largos.

Cablea un pin y luego doble clic en los siguientes: Proteus repite la última conexión.

Para duplicar: selecciona los elementos → Copy To Clipboard y pega las veces que necesites.

5.4

Escribir en cada segmento

▶ 29:32

Escribe un segmento por línea con HAL_GPIO_WritePin. Como todos los segmentos están en el mismo puerto, sirve ADP_GPIO_Port para todos y solo cambia el pin (Ctrl + clic sobre la macro muestra que es GPIOA).

Ejemplo para mostrar el 5 en cátodo común (a, c, d, f, g encendidos):

HAL_GPIO_WritePin(ADP_GPIO_Port, ADP_Pin, 1);
HAL_GPIO_WritePin(ADP_GPIO_Port, BDP_Pin, 0);
HAL_GPIO_WritePin(ADP_GPIO_Port, CDP_Pin, 1);
HAL_GPIO_WritePin(ADP_GPIO_Port, DDP_Pin, 1);
HAL_GPIO_WritePin(ADP_GPIO_Port, EDP_Pin, 0);
HAL_GPIO_WritePin(ADP_GPIO_Port, FDP_Pin, 1);
HAL_GPIO_WritePin(ADP_GPIO_Port, GDP_Pin, 1);

Escribir pin por pin no es óptimo; la tarea es sacar el dato completo directamente al puerto (por ejemplo con el registro ODR).

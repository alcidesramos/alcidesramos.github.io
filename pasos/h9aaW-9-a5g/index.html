Retardos en microsegundos con timer

Un timer es un contador que avanza con el reloj dividido por un preescalador. Si lo hacemos contar a 1 MHz, cada cuenta es 1 µs: basta con ponerlo a cero y esperar a que llegue al valor pedido. Probado en la Black Pill F401 a 84 MHz con el analizador lógico.

Fase 1

Configurar el timer

1.1

Elegir un timer

▶ 2:12

En Timers elige uno (aquí TIM1) y en Clock Source pon Internal Clock. Un timer de 16 bits cuenta hasta 65535 µs, suficiente: para más tiempo ya está HAL_Delay en milisegundos. Los de 32 bits (TIM2, TIM5) cuentan hasta 4 294 967 295.

1.2

Prescaler = MHz − 1

▶ 3:10

Mira en Clock Configuration a qué frecuencia llega el reloj del timer (84 MHz en la F401). Pon Prescaler = 84-1 para que cuente a 1 MHz, es decir, una cuenta por microsegundo.

1.3

La desventaja

▶ 3:42

Gastas un timer completo: sus 4 canales podrían dar PWM para servos y motores o leer frecuencias de sensores. En micros con pocos timers eso pesa.

Fase 2

Nombres genéricos

2.1

User Constants en CubeMX

▶ 6:27

Para que el código no dependa del timer elegido, en User Constants crea la constante TIMX con valor TIM1. Con Add IP Handle Label crea TIMERX para el handle (htim1). Si mañana usas TIM2, solo cambias aquí.

Fase 3

Las funciones

3.1

Iniciar el timer

▶ 8:05

Con HAL o con registros (poner a 1 el bit 0, CEN, de CR1):

void delayus_tim_init()
{
    // HAL_TIM_Base_Start(&TIMERX);   // con HAL
    TIMX->CR1 |= 1<<0;                // sin HAL: habilita el timer (CEN)
}

En el video aparece 1>>0. Funciona porque vale 1, pero lo correcto es 1<<0.

3.2

El retardo

▶ 8:36

Pones el contador en cero y esperas a que llegue a los µs pedidos. Sin multiplicaciones ni calibración:

void delay_us_tim(uint32_t us)
{
    // con HAL:
    // __HAL_TIM_SET_COUNTER(&TIMERX, 0);
    // while ((uint16_t)__HAL_TIM_GET_COUNTER(&TIMERX) < us);
    // sin HAL:
    TIMX->CNT = 0;          // resetea el timer
    while (TIMX->CNT < us); // espera los us deseados
}

Con un timer de 32 bits cambia el cast a (uint32_t).

Fase 4

Probar

4.1

Llamarlo y medir

▶ 9:41

Llama a delayus_tim_init() una vez después de MX_TIM1_Init(). Ya no hace falta el DWT. Pulso de 1 µs en modo atómico:

delayus_tim_init();
while (1)
{
    salida_GPIO_Port->BSRR = salida_Pin;
    delay_us_tim(1);
    salida_GPIO_Port->BSRR = salida_Pin << 16;
    delay_us_tim(1);
}
4.2

Resultado

▶ 10:15

El analizador mide 0.917 µs y 1.083 µs: el más preciso de todos los métodos vistos.

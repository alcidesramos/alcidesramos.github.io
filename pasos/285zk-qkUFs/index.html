Clase 136: escáner del bus I2C con STM32

Repasamos cómo funciona el bus I2C (resistencias pull-up, maestro y esclavos, dirección de 7 bits más el bit R/W) y armamos un proyecto con el STM32F411 que escanea el bus I2C1 y envía por serial las direcciones encontradas. Con un MPU6050 y un lidar VL53L0X conectados aparecen 0x68 y 0x29. Luego usamos la función I2C_RESPONDE para preguntar si un dispositivo concreto contesta, y vemos por qué en unas librerías la dirección va tal cual y en otras ya desplazada (0x29 << 1 = 0x52).

Fase 1

Conceptos del bus I2C

1.1

Varios dispositivos en el mismo bus

▶ 0:36

En I2C puede haber un maestro y varios esclavos (o varios maestros) sobre SDA y SCL.

Las pull-up van de 1.8 k a 47 k, lo típico es 4.7 k. Si muchos módulos traen su propia resistencia, quedan en paralelo y la resistencia total del bus baja: tenlo en cuenta.

1.2

Dirección de 7 bits + bit R/W

▶ 1:09

En el byte de dirección, el bit 0 indica lectura o escritura y la dirección real ocupa los bits 1 a 7.

Por eso muchas veces hay que desplazar la dirección una posición a la izquierda (multiplicar por 2). Algunas librerías lo hacen internamente y otras esperan la dirección ya desplazada.

Fase 2

Configurar el proyecto en CubeMX

2.1

Cristal externo y reloj máximo

▶ 2:48

Creamos el proyecto para el STM32F411CEU, activamos HSE (cristal) y en Clock Configuration llevamos el sistema a 100 MHz con el PLL (84 MHz si es un F401).

2.2

Habilitar I2C1 y escoger la velocidad

▶ 3:20

Activamos I2C1. La mayoría de dispositivos trabaja en Standard Mode (100 kHz); otros en Fast Mode (400 kHz).

Aquí usamos 400 kHz porque el lidar da errores a 100 kHz al pedir la distancia. Si no sabes, prueba primero a 100 y luego a 400.

Selecciona la velocidad que soporte el dispositivo que vas a probar.

2.3

USART1 a 115200 y generar código

▶ 3:52

Activamos USART1 en modo asíncrono a 115200 baudios para enviar los resultados.

En Project Manager llamamos al proyecto I2C_TEST, toolchain STM32CubeIDE, y generamos código.

Fase 3

Librería de escaneo

3.1

Carpeta LIBRERIAS

▶ 5:00

En Core creamos la carpeta LIBRERIAS, pegamos I2C_SCAN_BUS.c/.h y la librería uart.c/.h, y la agregamos al path (clic derecho, Add to path).

3.2

Definir el puerto serial en el .h

▶ 5:32

En I2C_SCAN_BUS.h se indica qué UART se usa para mostrar el resultado: huart1 en este caso (huart2 si usas el USART2).

La librería tiene dos funciones: I2C_SCAN (recorre todas las direcciones) e I2C_RESPONDE (pregunta por una dirección concreta).

// I2C_SCAN_BUS.h
#include "main.h"
#include "uart.h"
// defina puerto serial usado para comunicacion
#define uart_i2c  huart1

extern UART_HandleTypeDef uart_i2c;

void I2C_SCAN(I2C_HandleTypeDef I2CMIO);
void I2C_RESPONDE(I2C_HandleTypeDef I2CMIO, uint8_t dir);
3.3

I2C_RESPONDE: ¿está el dispositivo?

▶ 6:04

Usa HAL_I2C_IsDeviceReady: intenta 3 veces con un tiempo de espera de 300 ms y responde "SI ESTOY" o "NO EXISTO".

El escaneo hace lo mismo para cada dirección de 1 a 127 e imprime las que responden.

void I2C_RESPONDE(I2C_HandleTypeDef I2CMIO, uint8_t dir)
{
    // intento 3 veces hasta por 300 ms si no responde
    uint8_t si_estoy = HAL_I2C_IsDeviceReady(&I2CMIO, dir, 3, 300);
    if (si_estoy == HAL_OK)
        uartx_write_text(&uart_i2c, "SI ESTOY\r\n");
    else
        uartx_write_text(&uart_i2c, "NO EXISTO\r\n");
}

El cuerpo exacto de I2C_SCAN está en el repositorio de la clase; la idea es un for de 1 a 127 con la dirección desplazada (i<<1).

Fase 4

Escanear y probar

4.1

Llamar I2C_SCAN una sola vez

▶ 7:10

En main.c incluimos I2C_SCAN_BUS.h, uart.h, stdio.h y string.h.

Llamamos el escaneo antes del while para que se haga una sola vez al arrancar.

/* USER CODE BEGIN Includes */
#include "I2C_SCAN_BUS.h"
#include "uart.h"
#include <stdio.h>
#include <string.h>

/* USER CODE BEGIN 2 */
I2C_SCAN(hi2c1);
4.2

Resultado en el terminal

▶ 8:19

Abrimos Hercules en el COM a 115200, reseteamos el micro y aparecen DIR: 0x29 (lidar VL53L0X) y DIR: 0x68 (MPU6050).

Para escanear varios dispositivos a la vez, deben tener direcciones diferentes.

Fase 5

Dirección directa o desplazada

5.1

Comparar con la dirección de cada librería

▶ 8:51

En la librería del MPU6050 la dirección 0x68 se desplaza dentro del código. En la del lidar la dirección aparece como 0x52, que es 0x29 × 2 (ya desplazada).

Antes de usar una librería revisa si espera la dirección de 7 bits (la del escáner) o la de 8 bits.

#define dir_s1 0x52   // direccion del 1er sensor lidar (0x29 << 1)
5.2

Preguntar por cada sensor en el while

▶ 10:27

En el while llamamos I2C_RESPONDE para cada dispositivo. Para el MPU damos 0x68 y lo desplazamos nosotros; para el lidar damos 0x52, que es lo mismo que 0x29 << 1.

El terminal responde "SI ESTOY" por cada sensor conectado.

while (1)
{
    uartx_write_text(&huart1, "respuesta MPU: ");
    I2C_RESPONDE(hi2c1, 0x68 << 1);
    uartx_write_text(&huart1, "respuesta LIDAR: ");
    I2C_RESPONDE(hi2c1, 0x52);   // igual a 0x29 << 1
    HAL_Delay(500);
}

Los textos y el retardo son orientativos; lo importante es pasar la dirección ya desplazada a HAL.

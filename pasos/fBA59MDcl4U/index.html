Clase 132: TouchGFX cambio de pantalla por hardware

Respuesta a una pregunta: si la pantalla no es táctil, ¿cómo se cambia de pantalla? Sobre el proyecto de la clase 131, se usa el botón de la Blackpill en PA0. En TouchGFX Designer se agregan en cada pantalla dos interacciones: una de botón de hardware que cambia de pantalla y otra que cada tick llama una función virtual. Esa función se declara y se escribe en los archivos de la carpeta gui (no en gui_generated, que se borra), lee el botón con antirrebote no bloqueante y llama handleKeyEvent. El touch sigue funcionando igual.

Fase 1

Hardware y variables

1.1

Botón como entrada con pull-up

▶ 0:50

Se abre el .ioc en CubeMX. PA0 (el botón KEY de la Blackpill, conectado a tierra) se configura como GPIO_Input con Pull-up y la etiqueta SW. Sin presionar lee 1; presionado lee 0.

1.2

Variables en el main

▶ 2:00

suiche guarda en qué pantalla estamos y tft_count sirve para el antirrebote entre cambios de pantalla.

Antes del while, tft_count toma el valor de uwTick (milisegundos desde que arrancó el micro).

/* USER CODE BEGIN PV */
uint8_t  suiche = 1;      // pantalla actual (1, 2, ...)
uint32_t tft_count;       // tiempo para el antirrebote
/* USER CODE END PV */

/* USER CODE BEGIN 2 */
tft_count = uwTick;       // milisegundos transcurridos al arrancar
/* USER CODE END 2 */
Fase 2

Interacciones en TouchGFX

2.1

Botón de hardware que cambia de pantalla

▶ 2:35

Doble clic en ApplicationTemplate.touchgfx.part abre TouchGFX Designer.

En Screen1 > Interactions se agrega una con Trigger "Hardware button is clicked", botón 2, Action Change screen a Screen2.

En Screen2 se hace lo mismo con el botón 1 hacia Screen1.

2.2

Llamar una función cada tick

▶ 3:35

Otra interacción por pantalla: Trigger "on every N tick" con Ticks between triggers = 1 (puedes poner 10 o 50 para cargar menos el micro), Action "Call new virtual function" con el nombre CAMBIAPANTALLA.

En las dos pantallas se puede usar el mismo nombre, porque cada pantalla es un objeto distinto.

Consejo: escribe los nombres de función en mayúsculas para no tener problemas más adelante al copiar y pegar.

Fase 3

Código de cada pantalla

3.1

Dónde va el código

▶ 6:10

TouchGFX genera en TouchGFX/generated/gui_generated las funciones virtuales, pero esa carpeta se regenera cada vez. El código propio va en TouchGFX/gui: los .hpp en gui/include y los .cpp en gui/src.

Se copia la declaración virtual void CAMBIAPANTALLA(); del ViewBase generado a Screen1View.hpp y Screen2View.hpp.

// gui/include/gui/screen1_screen/Screen1View.hpp  (y lo mismo en Screen2View.hpp)
class Screen1View : public Screen1ViewBase
{
public:
    Screen1View();
    virtual ~Screen1View() {}
    virtual void setupScreen();
    virtual void tearDownScreen();
    virtual void CAMBIAPANTALLA();     // copiada de gui_generated
protected:
};
3.2

Lo que generó TouchGFX

▶ 8:40

En Screen2ViewBase.cpp se ve handleKeyEvent: si llega la tecla 1 hace gotoScreen1. Y handleTickEvent llama a CAMBIAPANTALLA en cada tick. Por eso basta con llamar handleKeyEvent con el número de la pantalla destino.

3.3

Función de Screen1

▶ 10:00

En Screen1View.cpp se declaran las variables del main como extern y se incluye main.h para usar HAL y los nombres de pines.

Si el botón está presionado y pasaron más de 500 ms desde el último cambio (no bloquea, solo compara tiempos), se pasa suiche a 2, se reinicia el contador y se llama handleKeyEvent. Con 200 ms o más ya se evita el rebote.

// gui/src/screen1_screen/Screen1View.cpp
extern uint8_t  suiche;
extern uint32_t tft_count;
#include "main.h"

void Screen1View::CAMBIAPANTALLA()
{
    if (HAL_GPIO_ReadPin(SW_GPIO_Port, SW_Pin) == 0)   // boton presionado (pull-up)
    {
        if (uwTick - tft_count > 500)                    // antirrebote no bloqueante
        {
            switch (suiche) {
                case 1:
                    suiche = 2;
                    tft_count = uwTick;
                    handleKeyEvent(suiche);              // boton de hardware 2 -> Screen2
                    break;
            }
        }
    }
}
3.4

Función de Screen2

▶ 12:00

Es el mismo código, pero si suiche vale 2 lo pasa a 1 y vuelve a la pantalla 1.

// gui/src/screen2_screen/Screen2View.cpp
extern uint8_t  suiche;
extern uint32_t tft_count;
#include "main.h"

void Screen2View::CAMBIAPANTALLA()
{
    if (HAL_GPIO_ReadPin(SW_GPIO_Port, SW_Pin) == 0)
    {
        if (uwTick - tft_count > 500)
        {
            switch (suiche) {
                case 2:
                    suiche = 1;
                    tft_count = uwTick;
                    handleKeyEvent(suiche);              // boton de hardware 1 -> Screen1
                    break;
            }
        }
    }
}

Resultado

▶ 12:40

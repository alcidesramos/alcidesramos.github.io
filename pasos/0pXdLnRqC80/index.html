Control on-off con Simulink y la Black Pill

Se instala el Embedded Coder Support Package for STMicroelectronics STM32 Processors y se valida con STM32CubeMX y STM32CubeProgrammer. Primero se hace parpadear el LED de PC13 con un Pulse Generator y un Digital Port Write, configurando el micro en CubeMX con las opciones que pide Simulink. Como la Black Pill no es una tarjeta original de ST, no se puede usar el modo externo; el truco es mandar los datos por un conversor USB-serial a un segundo modelo de Simulink (monitoreo) que los grafica. Al final, el modelo de monitoreo envía un set point desde un slider y el micro compara set point contra potenciómetro para prender o apagar un LED: un control on-off.

Fase 1

Instalar el soporte de STM32 en Matlab

1.1

Instalar el paquete

▶ 0:00

En Matlab ve a Add-Ons → Get Hardware Support Packages y busca stm32.

Instala Embedded Coder Support Package for STMicroelectronics STM32 Processors (el de Nucleo es para tarjetas originales y no es necesario).

En el asistente de configuración marca al menos STM32F4xx Based MCUs (la familia de la Black Pill).

1.2

Validar CubeMX y CubeProgrammer

▶ 3:24

El asistente pide la ruta de STM32CubeMX de la versión que soporta el paquete. Instálala en su propia carpeta (por ejemplo dentro de Program Files\STMicroelectronics) para no mezclarla con tu CubeMX actual.

Selecciona la carpeta y pulsa Validate. Con CubeProgrammer se valida la carpeta bin de su instalación.

La ubicación del repositorio se puede dejar por defecto.

Usa la versión de CubeMX que indica el asistente. Con una más nueva Matlab avisa que puede no funcionar.

Fase 2

Primer modelo: LED intermitente

2.1

Armar el modelo en Simulink

▶ 5:43

Trabaja en una carpeta propia (por ejemplo STMSIMULINK\clase) y abre Simulink con un Blank Model.

En la librería Embedded Coder Support Package for STMicroelectronics STM32 Processors → STM32F4xx Based Boards arrastra un Digital Port Write y configura el puerto C, pin 13.

Agrega un Pulse Generator: amplitud 1, periodo 1 s y ancho de pulso 50 %. Conéctalo al Digital Port Write.

2.2

Configurar el micro en CubeMX

▶ 10:32

Abre el CubeMX que instalaste para Matlab y crea un proyecto con tu micro (STM32F401CCUx o STM32F411CEUx).

En RCC activa el cristal externo (HSE y LSE) y pon PC13 como GPIO_Output.

En SYS → Timebase Source cambia SysTick por cualquier timer (por ejemplo TIM10).

En Project Manager: nombre, carpeta (la misma del modelo) y Toolchain EWARM. Desmarca Do not generate the main() como en el video.

En Advanced Settings pon los drivers en LL y quita las marcas de Generate Code y Visibility (Static). Guarda el proyecto (File → Save).

Cada vez que cambies algo en CubeMX vuelve a revisar Advanced Settings: CubeMX suele devolver las opciones y el modelo deja de compilar.

2.3

Enlazar el modelo con el .ioc

▶ 18:23

En Simulink: Modeling → Model Settings.

En Solver pon paso fijo (Fixed-step).

En Hardware Implementation elige STM32F4xx Based y en Target hardware resources → Build options busca con Browse el archivo .ioc que creaste en CubeMX. Aplica y OK.

2.4

Compilar y cargar

▶ 20:01

Como no es una tarjeta original no se usa Build, Deploy & Start: en la pestaña Hardware pulsa Build. La primera vez tarda bastante.

Se generan el .hex y el .elf en la carpeta del proyecto.

Ábrelo con STM32CubeProgrammer (por USB en modo DFU: BOOT0 + RESET), pulsa Download y luego RESET: el LED parpadea.

Fase 3

Leer el ADC y monitorear por serial

3.1

Habilitar ADC y USART en CubeMX

▶ 27:41

En Connectivity → USART1 modo Asynchronous, habilita la interrupción y el DMA en RX y TX.

En Analog → ADC1 habilita IN0 (PA0), modo continuo, DMA e interrupción.

Guarda y vuelve a revisar Advanced Settings.

La Black Pill no tiene el puente USB-serial de las Nucleo: necesitas un conversor USB-TTL conectado a TX y RX del USART1 para que aparezca un puerto COM en el PC.

3.2

Modelo del micro

▶ 32:22

Agrega un bloque Analog to Digital Converter (ADC1, tiempo de muestreo 0.01 a 0.1 s).

Pasa la señal por un Data Type Conversion a uint16 (el ADC da de 0 a 4095).

Conéctala a un UART/USART Write en USART1. Compila y carga como antes.

Si en el monitoreo los datos saltan sin sentido, revisa que el Data Type Conversion de verdad quedó en uint16.

3.3

Revisar que llegan datos

▶ 36:51

Antes de Matlab puedes abrir Hercules en el COM del conversor a 115200 baudios: verás caracteres raros, que son los datos en binario. Solo sirve para saber que el micro está enviando.

3.4

Modelo de monitoreo en el PC

▶ 38:33

Crea un modelo nuevo (monitoreo) en la misma carpeta. Este corre en el PC, no en el micro.

Agrega Serial Configuration (Instrument Control Toolbox): puerto COM del conversor, 115200 baudios.

Agrega Serial Receive en el mismo puerto, tipo de dato uint16 y tiempo de muestreo pequeño. Pásalo por un Data Type Conversion a uint16 y conéctalo a un Display y un Scope.

Pon Stop Time en inf y dale Run: al mover el potenciómetro el valor cambia en tiempo real.

Fase 4

Control on-off con set point

4.1

Set point desde un slider

▶ 47:41

En la librería Dashboard hay indicadores como el RPM Indicator (sirve para mostrar, no para controlar).

Para el set point usa un bloque Constant conectado a un Slider del Dashboard con rango de 0 a 4095.

Con un Mux manda al Scope la señal del potenciómetro y el set point a la vez.

4.2

Enviar el set point al micro

▶ 53:27

Agrega un Serial Send en el mismo COM y envíale el set point convertido a uint16.

Este modelo de monitoreo ya no se toca; lo único que cambia de un PC a otro es el número del puerto COM.

4.3

Comparar en el micro

▶ 54:36

En el modelo del micro agrega un UART/USART Read (USART1, uint16, muestreo 0.1 s) seguido de un Data Type Conversion.

Compara con un Relational Operator (>): si el set point es mayor que la lectura del potenciómetro, la salida es 1.

Conecta la salida a otro Digital Port Write en PA1 con un LED. Crea PA1 como salida en CubeMX, guarda y compila.

4.4

Probar el control

▶ 57:57

Carga el programa, resetea y corre el modelo de monitoreo.

Al mover el potenciómetro por debajo del set point el LED verde se prende y por encima se apaga. Si mueves el slider, cambia el punto de conmutación: es un control on-off.

Leer un GPS por interrupción serial

Lección 37 del curso. Se usa el Virtual GPS de Proteus, que manda varias tramas NMEA. Solo interesa la $GPGGA, que trae latitud y longitud. En la interrupción una máquina de estados acepta la trama solo si llegan en orden P, G, G y A, y la guarda hasta el *. En el programa principal se separan los campos, se pasan grados y minutos a grados decimales, se corrige el signo para sur y oeste y se manda el resultado por serial. Al final se enciende un led cuando la posición está dentro de una zona.

Fase 1

La trama del GPS

1.1

Virtual GPS

▶ 0:00

Se pone el Virtual GPS de Proteus con su TX en el RX del micro. Se quitan el motor y el COMPIM para aligerar la simulación.

1.2

La trama GPGGA

▶ 1:07

El GPS manda varias tramas. En la $GPGGA, entre comas, vienen la latitud con N o S y la longitud con E o W. Toda trama termina en *. Se recomienda estudiar el protocolo NMEA.

Fase 2

Máquina de estados

2.1

Estados

▶ 3:18

Para detectar un inicio de varios caracteres se usa una máquina de estados: capturar P, luego G, otra G, luego A, y después esperar el final.

enum estados {cap_P, cap_G, cap_G2, cap_A, esp_final};
char estado_rec = cap_P;   // estado inicial

float grados, minutos;
float latitud, longitud;
char texto[30];
char c_grados[10];   // grados en cadena
2.2

En la interrupción

▶ 5:31

Cada dato se guarda. Si no es la letra esperada, el puntero vuelve a cero y se regresa al primer estado; si lo es, avanza el puntero y pasa al siguiente. Así se descartan las tramas que no interesan.

dato_rx = UART1_Read();
// ANALIZA LOS ESTADOS
switch (estado_rec)
{
  case cap_P:
    trama_rx[puntero_rx] = dato_rx;
    if (dato_rx != 'P') puntero_rx = 0;   // no fue el dato que me interesa
    else
    {
      puntero_rx++;           // incrementa contador para proximo dato
      estado_rec = cap_G;     // pasa al estado de capturar la G
    }
    break;
  // cap_G, cap_G2 y cap_A igual, regresando a cap_P si falla
}
2.3

Estado final

▶ 8:24

En el último estado se guarda todo hasta el *. Entonces se vuelve al estado inicial, se desactiva la interrupción serial, el puntero vuelve a cero y se levanta la bandera.

case esp_final:
  trama_rx[puntero_rx] = dato_rx;
  puntero_rx++;
  if (dato_rx == '*')
  {
    RCIE_bit = 0;
    estado_rec = cap_P;   // regresa al estado inicial
    puntero_rx = 0;
    flag_rx = 1;
  }
  break;
Fase 3

Procesar la posición

3.1

Llamar al proceso

▶ 8:57

En el programa principal, si la bandera está activa se llama a procesa_GPS y luego se vuelve a habilitar la recepción como en la lección 36.

3.2

Latitud

▶ 10:04

Con strtok se avanza hasta el campo de la latitud. Los dos primeros caracteres son los grados y el resto los minutos, que se dividen entre 60 y se suman. Si el siguiente campo es S, la latitud se vuelve negativa.

// captura la latitud
strcpy(procesa, strtok(trama_rx, ","));
strcpy(procesa, strtok(0, ","));   // captura hasta segunda coma
strcpy(procesa, strtok(0, ","));   // tercera coma, es decir latitud
memset(c_grados, 0, 10);            // limpia los grados
strncpy(c_grados, procesa, 2);      // captura los grados
grados = atof(c_grados);            // pasa de cadena a flotante
minutos = atof(&procesa[2]) / 60.0; // lo pasa a grados
latitud = grados + minutos;
strcpy(procesa, strtok(0, ","));   // orientacion o signo de la lat
if (procesa[0] == 'S') latitud = -latitud;
// ACONDICIONA PARA ENVIAR
sprintf(texto, "lat=%f\r\n", latitud);
UART1_Write_Text(texto);
3.3

Longitud

▶ 12:46

La longitud es igual, pero los grados son tres caracteres, así que los minutos empiezan en la posición 3. Si el campo siguiente es W, se vuelve negativa.

3.4

Alarma por zona

▶ 15:26

Con los valores reales de una zona se arma una condición: si la latitud y la longitud están entre los límites, se enciende un led; si no, se apaga. Con números negativos hay que cuidar el sentido de la comparación. Queda de tarea revisar el campo que indica si el dato del GPS es válido.

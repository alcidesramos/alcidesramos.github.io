Interrupción por flanco con INTCON

Lección 32 del curso. Una interrupción es un procedimiento que no se llama desde el programa: el micro salta a él cuando ocurre el evento y luego regresa. Se repasan los tipos (flanco, cambio de nivel, timers y periféricos), la diferencia entre bandera y habilitador, y los pasos para habilitar una interrupción: PEIE, limpiar la bandera, habilitar la propia, configurarla y por último GIE. Con eso se hace una interrupción por flanco en RB0/INT.

Fase 1

Tipos de interrupción

1.1

Vector de interrupción

▶ 0:00

Cuando ocurre una interrupción el micro salta a una posición fija de memoria: 0x0004 en los PIC16 y 0x0008 en los PIC18. El compilador lo maneja, pero conviene saberlo.

1.2

Flanco, nivel, timers y periféricos

▶ 1:38

Por flanco (INT0 a INT3, normalmente en RB0, RB1, RB2) se interrumpe en subida o bajada. Por cambio de nivel en RB4 a RB7 en los micros antiguos, o en casi cualquier pin en los modernos. Por timer cuando se desborda, y por periféricos como el puerto serial, SPI, I2C o USB.

Fase 2

Bandera y habilitador

2.1

El registro INTCON

▶ 4:22

En la hoja de datos el registro principal es INTCON. Más que el nombre de cada registro importa encontrar dos bits por interrupción: la bandera y el habilitador.

2.2

IF: la bandera

▶ 6:08

La bandera (flag) se pone en 1 cada vez que ocurre el evento, esté o no habilitada la interrupción. No se borra sola: el programador la limpia.

2.3

IE: el habilitador

▶ 7:15

El habilitador permite que esa interrupción haga saltar al micro. Cada fuente tiene su par: INTF e INTE, RBIF y RBIE, TMR0IF y TMR0IE, RCIF y RCIE.

2.4

PEIE y GIE

▶ 9:30

El bit 6 de INTCON, PEIE, autoriza las interrupciones de periféricos, y el bit 7, GIE, autoriza todas. Para que haya interrupción tienen que estar habilitadas la propia y las de arriba. En el video se explica con una analogía de permisos por niveles.

Fase 3

Interrupción por flanco

3.1

Los cinco pasos

▶ 13:19

1) PEIE en 1. 2) Limpiar la bandera, porque si quedó en 1 el micro saltaría apenas se habilite. 3) Habilitar la interrupción propia. 4) Configurarla si tiene opciones, como el flanco. 5) GIE en 1.

3.2

En código

▶ 16:15

PEIE se deja en 1 desde el inicio con INTCON. Antes del while se limpia INTF, se habilita INTE, se elige flanco de bajada con INTEDG y se autorizan todas con GIE.

INTCON = 0b01000000;   // bit 6 = 1 autoriza int perifericos

// AUTORIZAR INT
INTF_bit = 0;     // limpia la bandera
INTE_bit = 1;     // autoriza int propia
INTEDG_bit = 0;   // flanco de bajada

GIE_bit = 1;      // autoriza las interrupciones
3.3

La función de interrupción

▶ 20:37

Con el asistente de interrupciones de MikroC se crea la función. Dentro se revisa la bandera para saber qué interrupción ocurrió y se hace la tarea; el pin RB0 debe quedar como entrada.

void INTERRUPCION() iv 0x0004 ics ICS_AUTO
{
  if (INTF_bit)
  {
    led3 = ~led3;
    INTF_bit = 0;   // limpia la bandera
  }
}
3.4

Limpiar la bandera al salir

▶ 23:57

Si la bandera no se limpia al final, el micro vuelve a entrar sin parar y el programa se queda pegado. Es uno de los errores más comunes.

3.5

Pruebas

▶ 25:09

Con GIE en 0 no hay ninguna interrupción; con INTE en 0 tampoco esta. La de flanco no es de periférico, así que PEIE no la afecta, pero sí afecta a la serial. Por eso se recomienda dejar PEIE en 1 y manejar GIE y la propia.

3.6

Ser rápido

▶ 26:15

La interrupción debe ser corta: el micro deja el programa principal, atiende y vuelve tan rápido que parece simultáneo. Si hay algo largo que hacer, se deja una bandera y se hace en el programa principal.

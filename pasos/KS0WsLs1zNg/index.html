STM32 en VS Code: snippets para configurar CMake con comandos cortos

Tercera parte de la serie de VS Code. En lugar de copiar comandos largos de CMake en cada proyecto, creamos una sola vez un archivo global de snippets. Después basta escribir un prefijo corto en CMakeLists.txt para agregar las librerías, el .hex, el soporte de flotantes en printf o todo junto, y en gcc-arm-none-eabi.cmake para cambiar la FPU entre hardware (micro real) y software (Proteus). La nueva versión busca la carpeta librerias en Core o en Core/Src sin importar mayúsculas.

Fase 1

Crear el archivo de snippets

1.1

Snippets globales

▶ 1:40

En File > Preferences > Configure Snippets elegimos New Global Snippets file y le damos un nombre (por ejemplo, tus iniciales).

Borramos el contenido de ejemplo, pegamos el archivo de snippets del video y guardamos. Sirve para todos los proyectos desde ahora.

{
  "Agregar printf con float": {
    "prefix": "addfloat",
    "body": [
      "target_link_options(${PROJECT_NAME} PUBLIC -u _printf_float)"
    ],
    "description": "Permite sprintf/printf con flotantes"
  }
}

Este es solo un ejemplo de la estructura de un snippet; el archivo completo con todos los comandos está en los recursos del video.

Fase 2

Usar los comandos cortos

2.1

addlib, addhex, addfloat

▶ 3:01

Con el CMakeLists.txt abierto, al final escribimos el prefijo y Enter:

addlib: agrega la carpeta de librerías.

addhex: genera .hex y .bin al compilar.

addfloat: printf/sprintf con flotantes.

addall: todo lo anterior de una vez.

Los prefijos exactos son los del archivo de snippets que uses.

2.2

Búsqueda automática de librerias

▶ 3:51

La versión nueva busca una carpeta llamada librerias (en mayúsculas o minúsculas) en Core o en Core/Src, agrega todos los .c y todas las carpetas que tengan .h, incluso subcarpetas.

Si tu carpeta se llama distinto, cambia la palabra "librerias" en el bloque.

# BUSCA LA CARPETA "librerias" EN CORE O EN CORE/SRC (insensible a mayúsculas)
set(RUTAS_DE_BUSQUEDA
    "${CMAKE_SOURCE_DIR}/Core"
    "${CMAKE_SOURCE_DIR}/Core/Src"
)
set(LIBRERIAS_DIR "")
foreach(ruta ${RUTAS_DE_BUSQUEDA})
    if(EXISTS "${ruta}" AND NOT LIBRERIAS_DIR)
        file(GLOB contenido RELATIVE "${ruta}" "${ruta}/*")
        foreach(item ${contenido})
            if(IS_DIRECTORY "${ruta}/${item}")
                string(TOLOWER "${item}" item_lower)
                if(item_lower STREQUAL "librerias")
                    set(LIBRERIAS_DIR "${ruta}/${item}")
                    break()
                endif()
            endif()
        endforeach()
    endif()
endforeach()

# Todos los .c de la carpeta y subcarpetas
file(GLOB_RECURSE LIBRERIAS_SOURCES CONFIGURE_DEPENDS "${LIBRERIAS_DIR}/*.c")
target_sources(${CMAKE_PROJECT_NAME} PRIVATE ${LIBRERIAS_SOURCES})

# Carpetas donde hay .h
file(GLOB_RECURSE LIBRERIAS_HEADERS CONFIGURE_DEPENDS "${LIBRERIAS_DIR}/*.h")
set(LIBRERIAS_INCLUDE_DIRS "")
foreach(header ${LIBRERIAS_HEADERS})
    get_filename_component(header_dir "${header}" DIRECTORY)
    list(APPEND LIBRERIAS_INCLUDE_DIRS "${header_dir}")
endforeach()
if(LIBRERIAS_INCLUDE_DIRS)
    list(REMOVE_DUPLICATES LIBRERIAS_INCLUDE_DIRS)
    target_include_directories(${CMAKE_PROJECT_NAME} PRIVATE ${LIBRERIAS_INCLUDE_DIRS})
endif()
#fin librerias

Si algo no se actualiza, ejecuta en la paleta de comandos CMake: Delete Cache and Reconfigure.

2.3

Bloque del .hex y .bin

▶ 3:18

Este es el bloque que agrega addhex, ahora también muestra el tamaño del programa.

# Generar .hex y .bin automáticamente después de compilar
add_custom_command(TARGET ${CMAKE_PROJECT_NAME} POST_BUILD
    COMMAND ${CMAKE_OBJCOPY} -O ihex $<TARGET_FILE:${CMAKE_PROJECT_NAME}> ${CMAKE_PROJECT_NAME}.hex
    COMMAND ${CMAKE_OBJCOPY} -O binary $<TARGET_FILE:${CMAKE_PROJECT_NAME}> ${CMAKE_PROJECT_NAME}.bin
    COMMAND ${CMAKE_SIZE} $<TARGET_FILE:${CMAKE_PROJECT_NAME}>
    COMMENT "Generando ${CMAKE_PROJECT_NAME}.hex y ${CMAKE_PROJECT_NAME}.bin"
)
Fase 3

FPU por hardware o software

3.1

addhard y addsoft

▶ 4:57

En cmake/gcc-arm-none-eabi.cmake, bajo # MCU specific flags, borramos la línea de TARGET_FLAGS y escribimos addhard (micro real, FPU por hardware) o addsoft (para que Proteus simule bien los flotantes).

# addhard
set(TARGET_FLAGS "-mcpu=cortex-m4 -mfpu=fpv4-sp-d16 -mfloat-abi=hard ")

# addsoft
set(TARGET_FLAGS "-mcpu=cortex-m4 -mfloat-abi=soft ")

Con hardware Proteus muestra valores erróneos en los flotantes; en el micro real deja hardware.

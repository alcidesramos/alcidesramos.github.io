STM32 en VS Code: CMakeLists, librerías, printf con float y .hex

Segundo video de la serie de VS Code. Creamos con CubeMX un proyecto CMake para el STM32F401 con LED y USART1 a 9600, lo abrimos en VS Code y vemos cómo el autocompletado sugiere código. Como CMake trabaja con comandos, para usar librerías propias hay que decirle en CMakeLists.txt dónde están los .c y los .h. También agregamos la opción para que sprintf imprima flotantes, cambiamos la FPU a software para que Proteus 9 simule bien, generamos .hex y .bin, y programamos con STM32CubeProgrammer o con el depurador. Los comandos están en el repositorio del video.

Fase 1

Programador y proyecto

1.1

Colores del cable del programador

▶ 0:33

El mini programador usa 3.3 V, SWDIO, SWCLK y GND, y tiene un pin RX que crea un puerto COM: el TX del micro (PA9) va a ese RX.

Hay dos versiones de cable: si termina en gris o si termina en violeta los colores cambian. Revísalo antes de conectar o puedes dañar el micro.

Para más potencia alimenta por 5 V (sin conectar 3.3 V) o con una fuente externa con tierra común.

1.2

Proyecto CMake con LED y USART1

▶ 3:16

Usamos el STM32F401CCU porque Proteus lo simula (el código sirve en el F411 físico). Un pin como salida con la etiqueta LED y USART1 asíncrono a 9600 baudios para no saturar la simulación.

En Project Manager: nombre SERIAL_VSC y Toolchain/IDE: CMake. Abrimos la carpeta con Abrir con Code y aceptamos configurar CMake.

Todo esto aplica también a CubeMX2, salvo que la librería serial vieja no es 100 % compatible con la HAL2.

1.3

Autocompletado inteligente

▶ 6:32

Al escribir HAL el editor sugiere la línea completa que usaste antes (TogglePin, Delay) y basta con Tab. Esa es una de las ventajas frente al IDE anterior.

HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(500);
1.4

Simular en Proteus 9

▶ 8:11

Proteus 9 simula directamente el .elf de build/Debug, sin necesitar el .hex. Ponemos un Virtual Terminal a 9600 y el LED.

Fase 2

Agregar librerías

2.1

Carpeta Librerias

▶ 10:23

En Core creamos la carpeta Librerias y pegamos uart.c y uart.h (desde el explorador de Windows: clic derecho > Reveal in File Explorer).

Respeta mayúsculas y minúsculas del nombre de la carpeta.

2.2

Decirle a CMake dónde están

▶ 12:34

Al final de CMakeLists.txt se agregan todos los .c de la carpeta y las rutas de include. Así en el main basta #include "uart.h".

file(GLOB LIB_SOURCES
    Core/Librerias/*.c
)

target_sources(${CMAKE_PROJECT_NAME} PRIVATE
    ${LIB_SOURCES}
)

target_include_directories(${CMAKE_PROJECT_NAME} PRIVATE
    Core/Inc
    Core/Librerias
)

Si tu carpeta tiene otro nombre, cámbialo en las dos partes.

2.3

Usar la librería serial

▶ 13:41

Escribimos un texto al iniciar y otro en el while. En Proteus aparece INICIANDO y FUNCIONANDO.

#include "uart.h"

uartx_write_text(&huart1, "INICIANDO\r\n");

while (1)
{
  HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
  HAL_Delay(500);
  uartx_write_text(&huart1, "FUNCIONANDO\r\n");
}
Fase 3

Programar y depurar

3.1

Con STM32CubeProgrammer

▶ 15:22

Conectamos, abrimos el .elf de build/Debug y pulsamos Download. En Hercules, en el COM del programador a 9600, se ven los mensajes.

3.2

Con Run and Debug

▶ 16:29

Desde Run and Debug se programa y se puede ir paso a paso (Step Over). Es más lento para solo programar, pero ideal para depurar.

Si el depurador falla después de usar el Programmer, desconecta y conecta el ST-Link.

Fase 4

Flotantes, FPU y .hex

4.1

Contador con sprintf

▶ 18:28

Con sprintf armamos un texto con un contador en un buffer de 50 caracteres; el autocompletado propone casi todo.

char buffer[50];
int contador = 0;

sprintf(buffer, " %d\r\n", contador++);
uartx_write_text(&huart1, buffer);
4.2

printf con float

▶ 20:46

Si el contador es float (sube de 0.5 en 0.5, con %.1f), no imprime nada: en CubeIDE se marcaba Use float with printf; aquí se agrega una línea al CMakeLists.txt.

target_link_options(${PROJECT_NAME} PUBLIC -u _printf_float)
4.3

FPU por software para Proteus

▶ 22:31

Proteus 9 da números erróneos con la FPU por hardware. En cmake/gcc-arm-none-eabi.cmake se comenta la línea de hardware y se usa la de software. Para el micro real se deja en hardware.

# MCU specific flags
#set(TARGET_FLAGS "-mcpu=cortex-m4 -mfpu=fpv4-sp-d16 -mfloat-abi=hard ")
set(TARGET_FLAGS "-mcpu=cortex-m4 -mfloat-abi=soft ")
4.4

Generar .hex y .bin

▶ 26:28

Para Proteus anteriores a la versión 9 se necesita el .hex. Este bloque en CMakeLists.txt lo crea después de compilar, junto con el .bin.

add_custom_command(TARGET ${PROJECT_NAME} POST_BUILD
    COMMAND ${CMAKE_OBJCOPY} -O ihex $<TARGET_FILE:${PROJECT_NAME}> ${PROJECT_NAME}.hex
    COMMAND ${CMAKE_OBJCOPY} -O binary $<TARGET_FILE:${PROJECT_NAME}> ${PROJECT_NAME}.bin
)

Desde la paleta de comandos (Ctrl+Shift+P) se puede elegir el preset Debug o Release; se crean carpetas separadas dentro de build.

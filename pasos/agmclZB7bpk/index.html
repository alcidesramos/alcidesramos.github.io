UART por software en un PIC

Una trama serial empieza con un bit de arranque en bajo, sigue con 8 bits de datos y termina con un bit de parada en alto. Si cada bit dura exactamente 1/baudios, cualquier pin puede transmitir. CCS lo resuelve con #use rs232. MikroC tiene Soft_UART, pero su lectura de cadenas gasta mucha RAM en un micro de 64 bytes. Por eso se hace una librería propia y se miden con el cronómetro del depurador los ciclos extra de cada bit, que dependen del compilador. Con esa corrección funciona hasta 115200 baudios.

3.3

Tiempo de cada bit

▶ 24:41

Cada bit dura 1000000/baudios microsegundos, pero el ciclo for y el if también gastan tiempo. Ese tiempo se resta del retardo.

const unsigned char cristal = Clock_MHz();   // reloj en MHz
#define DELAY_FOR      (4*15/cristal)   // extra en la escritura (15 ciclos)
#define DELAY_FOR_READ (4*12/cristal)   // extra en la lectura (12 ciclos)
#define BITPERIOD      ((1000000/BAUDIOS))       // duracion de 1 bit en us
#define BITPERIOD_FOR  (BITPERIOD - DELAY_FOR)   // retardo real en la escritura
3.4

Medir con el cronómetro

▶ 27:00

En el depurador de MikroC, con la ventana Watch Clock, se pone un punto de parada, se reinicia el cronómetro y se mide una vuelta del for: 15 ciclos al escribir y 12 al leer. Ese número depende del compilador y de su optimización.

4.2

Escribir un byte

▶ 38:10

La función es la misma: bit de arranque, los ocho bits con una máscara que se corre a la izquierda y bit de parada.

void Software_UART_Write(unsigned char Data) {
  unsigned char mask;
  SoftWare_Uart_Tx = 0;             // bit de arranque
  __delay_us(BITPERIOD);
  for (mask = 0x01; mask != 0; mask = mask << 1) {
    if (Data & mask) SoftWare_Uart_Tx = 1;
    else SoftWare_Uart_Tx = 0;
    __delay_us(BITPERIOD_FOR);
  }
  SoftWare_Uart_Tx = 1;             // bit de parada
  __delay_us(BITPERIOD);
}

▶ 40:38

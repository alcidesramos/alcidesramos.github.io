Modos de bajo consumo en STM32: Sleep, Stop y Standby

Se mide el consumo con un multímetro: el micro borrado consume unos 2 mA, con el programa básico 3 mA y a 120 MHz con HSE y PLL 21 mA. El programa alterna entre OPERANDO (6 s trabajando) y DURMIENDO. Para dormir se suspende el SysTick, se habilita SleepOnExit y se entra al modo deseado con WFI. El micro se despierta con un flanco en PC13 (EXTI) o con el wake-up timer del RTC (por ejemplo cada 5 s o cada 15 min). En modo Stop se apagan los osciladores, por eso al despertar hay que llamar a SystemClock_Config. En Standby el ahorro es máximo pero el micro se reinicia al despertar y es difícil reprogramarlo, por lo que en la práctica se prefiere el modo Stop.

Fase 1

Consumo de partida

1.1

Micro borrado y programa básico

▶ 0:00

Con STM32CubeProgrammer se borra el micro y se mide: unos 2 mA. Con un programa vacío y el oscilador interno por defecto sube a unos 3 mA.

1.2

A 120 MHz con HSE y PLL

▶ 2:17

En el proyecto real se usa cristal externo (HSE), LSE para el RTC y PLL a 120 MHz. Así el consumo sube a unos 21 mA: a más MHz, más rápido pero más consumo, así que hay que buscar un equilibrio entre consumo y velocidad de procesamiento.

1.3

Programa de prueba

▶ 3:23

Se habilita USART1 a 115200 para monitorear, se agrega la librería uart y se estructura el ciclo: INICIANDO al arrancar, DURMIENDO antes de dormir y OPERANDO durante 6 s de trabajo:

uartx_write_text(&huart1, "INICIANDO\r\n");

while (1)
{
    // DORMIR
    uartx_write_text(&huart1, "DURMIENDO\r\n");
    /* ...entrar al modo de bajo consumo */

    // OPERANDO
    uartx_write_text(&huart1, "OPERANDO\r\n");
    HAL_Delay(6000);
}
Fase 2

Modo Sleep

2.1

Entrar en Sleep

▶ 6:48

Se suspende el tick del sistema, se habilita salir con interrupciones y se entra con WFI (wait for interrupt). En Sleep los periféricos siguen activos y el regulador pasa a bajo consumo. La referencia completa de cada modo está en el comentario de la función en stm32g4xx_hal_pwr.c.

// DORMIR
uartx_write_text(&huart1, "DURMIENDO\r\n");
HAL_SuspendTick();               // suspende el contador de tick
HAL_PWR_EnableSleepOnExit();     // habilita salir con interrupciones
HAL_PWR_EnterSLEEPMode(PWR_LOWPOWERREGULATOR_ON, PWR_SLEEPENTRY_WFI);
2.2

Despertar con un pulsador (EXTI)

▶ 9:03

Dormido consume unos 9 mA, pero hay que poder despertarlo. PC13 se configura como GPIO_EXTI13 con flanco de subida y pull-down, y en NVIC se habilita EXTI line[15:10]. En la interrupción se reactiva el tick y se deshabilita SleepOnExit:

void EXTI15_10_IRQHandler(void)
{
  /* USER CODE BEGIN EXTI15_10_IRQn 0 */
  HAL_ResumeTick();
  HAL_PWR_DisableSleepOnExit();
  /* USER CODE END EXTI15_10_IRQn 0 */
  HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_13);
}

Después de programar conviene resetear la placa: a veces queda pegada en el modo de bajo consumo.

Fase 3

Despertar automático con el RTC

3.1

Configurar el RTC

▶ 12:24

En Timers → RTC se activa el Clock Source y el calendario, y en WakeUp se elige Internal WakeUp. En NVIC se habilita la interrupción del wake-up. Con Wake Up Clock = RTCCLK/16 y LSE de 32 768 Hz cada cuenta dura ≈0.5 ms (útil para milisegundos); es más práctico elegir ck_spre (1 Hz) con 16 bits, que permite hasta ≈18 horas.

3.2

Programar el tiempo antes de dormir

▶ 15:13

Antes de dormir se arma el temporizador con el número de segundos (5 s para la prueba, 900 para 15 min):

// LEVANTATE AUTOMATICO CIERTO TIEMPO
if (HAL_RTCEx_SetWakeUpTimer_IT(&hrtc, 5, RTC_WAKEUPCLOCK_CK_SPRE_16BITS) != HAL_OK)
{
    Error_Handler();
}
3.3

Interrupción del RTC

▶ 15:46

En RTC_WKUP_IRQHandler se hace lo mismo que con el pulsador y además se desactiva el temporizador para que no vuelva a dispararse mientras el micro opera:

void RTC_WKUP_IRQHandler(void)
{
  /* USER CODE BEGIN RTC_WKUP_IRQn 0 */
  HAL_ResumeTick();
  HAL_RTCEx_DeactivateWakeUpTimer(&hrtc);
  HAL_PWR_DisableSleepOnExit();
  /* USER CODE END RTC_WKUP_IRQn 0 */
  HAL_RTCEx_WakeUpTimerIRQHandler(&hrtc);
}
Fase 4

Modos Stop y Standby

4.1

Modo Stop

▶ 18:01

Se cambia la instrucción de Sleep por Stop. En este modo se apagan los osciladores (HSI/HSE/PLL), así que en ambas interrupciones de despertar hay que reconfigurar el reloj antes que nada. El consumo dormido baja a unos 1.4 mA.

Para un ahorro real se recomienda compilar en Release (como si fuera el producto final), ya que un micro que duerme no se puede depurar.

// MODO STOP
HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);

/* en EXTI15_10_IRQHandler y RTC_WKUP_IRQHandler, primero: */
SystemClock_Config();
HAL_ResumeTick();
4.2

Modo Standby

▶ 21:27

HAL_PWR_EnterSTANDBYMode() ahorra todavía más, pero al despertar el micro se reinicia (vuelve a INICIANDO, no a OPERANDO). Habría que guardar datos importantes en registros de respaldo. Además, en Standby el ST-Link no lo reconoce: hay que mantener el reset presionado o conectar desde STM32CubeProgrammer para reprogramarlo.

// MODO STANDBY
HAL_PWR_EnterSTANDBYMode();

Por la complejidad de Standby, el modo Stop suele ser el mejor equilibrio: baja de 21 mA a 1.4 mA y continúa el programa donde iba.

Display de 7 segmentos con STM32

Se explica qué hay dentro de un display de 7 segmentos (8 LEDs llamados a hasta g y el punto), la diferencia entre cátodo común (enciende con 1) y ánodo común (enciende con 0) y cómo identificar los pines con el multímetro en escala de diodo. Luego se arma el display en Proteus con interruptores Logic State para formar números a mano. Después se configura PA0 a PA6 como salidas con etiquetas DPA a DPG en STM32CubeIDE, se escribe el número 5 segmento por segmento con HAL_GPIO_WritePin y, al final, se escribe todo de una vez en el registro ODR del puerto A con un número binario.

Fase 1

Teoría del display

1.1

Qué tiene adentro

▶ 1:12

Un display de 7 segmentos son 7 LEDs (más el punto, DP) organizados como un 8. Los segmentos se nombran a (arriba) y siguen en sentido horario b, c, d, e, f; g es el del medio.

Para formar un número se encienden solo los segmentos necesarios. Por ejemplo, el 1 usa b y c.

Cátodo común: todos los negativos unidos a tierra; cada segmento enciende con un 1.

Ánodo común: todos los positivos unidos a VCC; cada segmento enciende con un 0.

1.2

Identificar los pines y poner resistencias

▶ 4:06

Con el multímetro en escala de diodo recorre los pines: el pin que enciende con todos los demás es el común. Si quedó en la punta negra es cátodo común; si quedó en la roja, ánodo común.

Dejando fijo el común, toca los otros pines para saber qué segmento es cada uno. No confíes solo en las imágenes de internet: muchos displays chinos tienen otro orden.

Lo correcto es una resistencia de 330 Ω por cada segmento. En protoboard puedes poner una sola resistencia de 180 a 330 Ω entre el común y tierra; la desventaja es que los números con muchos segmentos (el 8) se ven un poco más opacos.

En Proteus la resistencia única del común se pone de unos 30 Ω para que simule bien. En la vida real no bajes de 180 Ω o puedes dañar el micro.

Fase 2

Probar el display en Proteus

2.1

Escoger el display

▶ 8:42

En Pick Devices busca display y filtra por Optoelectronics → 7-Segment Displays.

No uses los de 4 pines (BCD): solo existen en simulación. Usa uno de 7 pines, por ejemplo 7SEG-COM-CAT-GRN (cátodo común, verde).

En Proteus, si el pin común apunta hacia arriba es ánodo común; si apunta hacia abajo es cátodo común. Conecta el común a tierra.

2.2

Simular los 1 y 0 con Logic State

▶ 11:58

Busca el componente LOGICSTATE y pon 7, uno por segmento, del a al g.

Al correr la simulación, haz clic en cada uno para cambiarlo entre 0 y 1 y forma el número que quieras (también letras como A, b, C).

Fase 3

Programa con HAL

3.1

Configurar los pines

▶ 22:17

Crea un proyecto nuevo para el STM32F401CCUx y configura PA0 a PA6 como GPIO_Output.

Ponles etiqueta con clic derecho → Enter User Label: DPA, DPB, DPC, DPD, DPE, DPF, DPG (si quieres, PA7 como DP).

Úsalos en orden en el mismo puerto: más adelante se escribe el puerto completo de una vez y el orden importa.

Antes de compilar deja abierto solo este proyecto en el explorador.

3.2

Escribir el número 5 segmento por segmento

▶ 28:12

En el while(1) escribe una línea por segmento. Como todos están en el puerto A, todos usan DPA_GPIO_Port; solo cambia el pin.

Para el 5 se encienden a, c, d, f y g.

while (1)
{
  HAL_GPIO_WritePin(DPA_GPIO_Port, DPA_Pin, 1); // segmento a
  HAL_GPIO_WritePin(DPA_GPIO_Port, DPB_Pin, 0); // b
  HAL_GPIO_WritePin(DPA_GPIO_Port, DPC_Pin, 1); // c
  HAL_GPIO_WritePin(DPA_GPIO_Port, DPD_Pin, 1); // d
  HAL_GPIO_WritePin(DPA_GPIO_Port, DPE_Pin, 0); // e
  HAL_GPIO_WritePin(DPA_GPIO_Port, DPF_Pin, 1); // f
  HAL_GPIO_WritePin(DPA_GPIO_Port, DPG_Pin, 1); // g
}
3.3

Circuito en Proteus con etiquetas

▶ 33:01

Coloca la Black Pill, el display y una sola resistencia de 30 Ω (MINRES30R) del común a tierra.

Para no tirar tantos cables, pon terminales (DEFAULT) frente a cada pin del display y del micro y ponles el mismo nombre (A, B, C…). En los cables usa la herramienta Label (LBL). Mismo nombre = conectados.

Para verificar una unión: clic derecho a la terminal → Highlight. Si no resalta nada, no está unida.

Carga el .hex en el micro y dale Play: aparece el 5.

Elige el nombre de la etiqueta de la lista desplegable en vez de escribirlo: una letra distinta y ya no hay unión.

Fase 4

Escribir el puerto completo

4.1

Un número con una sola instrucción

▶ 47:30

Como a–g están en PA0–PA6 en orden, se puede escribir todo el puerto de una vez en el registro ODR. El bit 0 es a y el bit 6 es g.

El 5 (g f e d c b a = 1 1 0 1 1 0 1) queda así:

DPA_GPIO_Port->ODR = 0b1101101;   // número 5 en PA0..PA6

Escribir ODR completo también cambia PA7 a PA15. Si usas otros pines del puerto A, cambia solo los 7 bits: GPIOA->ODR = (GPIOA->ODR & ~0x7F) | valor;

4.2

Calcular los códigos de cada número

▶ 51:40

Para no calcular a mano usa una calculadora de 7 segmentos (en la clase se usó 7-Segment by Hannes): marcas los segmentos y te da el valor en binario, decimal y hexadecimal.

Con los códigos en un arreglo puedes mostrar cualquier dígito y hacer un contador con HAL_Delay. Tabla para cátodo común (a = bit 0):

uint8_t tabla[10] = {0x3F,0x06,0x5B,0x4F,0x66,0x6D,0x7D,0x07,0x7F,0x6F};

for (int n = 0; n < 10; n++) {
  GPIOA->ODR = (GPIOA->ODR & ~0x7F) | tabla[n];
  HAL_Delay(1000);
}

La tabla y el contador son un complemento para practicar; para ánodo común se usa el valor negado (~tabla[n] & 0x7F).

Clase en vivo: giro y velocidad de un motor DC por Bluetooth

Continuamos el proyecto del puente H: ahora el enable del L298 recibe una señal PWM para controlar la velocidad. Configuramos el TIM2 con reloj interno, prescaler y periodo para 100 Hz, activamos PWM en los canales 1 y 2 (PA0 y PA1), agregamos la librería PWM.c/PWM.h y la adaptamos al TIM2. Verificamos las señales en el osciloscopio de Proteus y, con una app Bluetooth en el celular, enviamos la trama "V1=valor/*" desde un slider. El micro la separa con strtok, la convierte con atoi y cambia el ciclo útil.

Fase 1

Configurar el timer en PWM

1.1

Dónde va el PWM

▶ 1:00

En el L298 los pines ENA/ENB, que antes estaban fijos en 1, ahora recibirán la señal PWM para controlar la velocidad.

Para motores usa una frecuencia de 50 Hz hacia arriba. Muy baja y el motor se ve prender y apagar; muy alta y el puente H puede no alcanzar y el motor puede chillar.

1.2

Elegir el timer

▶ 5:00

El STM32F401 tiene varios timers y cada uno maneja hasta cuatro canales. Usamos el TIM2, que está libre y es de 32 bits.

En Clock Source selecciona Internal Clock.

Si eliges el TIM1, uno de sus canales choca con la USART1 y CubeIDE mueve el pin. Por eso usamos el TIM2.

1.3

Calcular prescaler y periodo

▶ 8:20

Primero dividimos el reloj para que el timer cuente en microsegundos: Prescaler = frecuencia del micro en MHz − 1 (16 − 1 en Proteus, 84 − 1 en la tarjeta a 84 MHz).

Luego el periodo es el número de microsegundos de un ciclo: para 100 Hz son 10 000 µs, así que Counter Period = 10000.

Prescaler (PSC)      = 16 - 1    // 16 MHz -> 1 MHz (1 us por cuenta)
Counter Period (ARR) = 10000     // 10 000 us = 100 Hz

En Proteus usa 16 MHz y una frecuencia baja (50–100 Hz) para que la simulación no se vuelva lenta.

1.4

Escribir los valores

▶ 11:40

En Parameter Settings escribe 16-1 en Prescaler y 10000 en Counter Period.

El ciclo útil irá de 0 a 10 000, mucha más resolución que los 0–255 de Arduino.

1.5

Activar los canales PWM

▶ 16:30

En Channel1 y Channel2 elige PWM Generation CH1 y PWM Generation CH2.

Quedan en PA0 (TIM2_CH1) y PA1 (TIM2_CH2): uno para cada enable.

Fase 2

Librería PWM

2.1

Configurar PWM.h

▶ 20:50

Copia PWM.c y PWM.h a la carpeta de librerías.

En PWM.h cambia todo lo del timer 1 por timer 2: el handle htim2, la instancia TIM2 y los registros CCR1/CCR2 del TIM2.

#define PWMT2     htim2
#define PWMTIM2   TIM2

#define PWM1_CH   TIM_CHANNEL_1
#define PWM1      TIM2->CCR1

#define PWM2_CH   TIM_CHANNEL_2
#define PWM2      TIM2->CCR2

Cada PWM son dos líneas: el canal y el registro CCR del mismo canal. Si solo usas un PWM, deja las otras comentadas.

2.2

Incluir las librerías

▶ 27:00

En main.c agrega los include en USER CODE BEGIN Includes.

/* USER CODE BEGIN Includes */
#include "PWM.h"
#include "uart.h"
/* USER CODE END Includes */
2.3

Funciones de la librería

▶ 30:40

PWM_init arranca el PWM del canal.

pwm_valor recibe un porcentaje de 0 a 100 y lo escala al ARR del timer, sin importar qué timer sea.

void PWM_init(TIM_HandleTypeDef *PWM, uint16_t canal)
{
  HAL_TIM_PWM_Start(PWM, canal);
}

void pwm_valor(uint32_t *canal, float valor)
{
  *canal = valor * (float)PWMTIM2->ARR / 100.0;  // escala de 0 a 100 %
}

En el video la primera versión usaba PWMTIM1->ARR y daba error. Usa el nombre del timer que definiste en PWM.h.

2.4

Iniciar y probar en main

▶ 36:40

Después de los MX_..._Init, arranca los dos canales y da un valor inicial.

/* USER CODE BEGIN 2 */
PWM_init(&PWMT2, PWM1_CH);
PWM_init(&PWMT2, PWM2_CH);
pwm_valor(&PWM1, 50);   // 50 %
pwm_valor(&PWM2, 10);   // 10 %
/* USER CODE END 2 */
Fase 3

Ver las señales en Proteus

3.1

Osciloscopio

▶ 46:30

Pon terminales EN1 y EN2 en PA0 y PA1 y llévalos a un osciloscopio. Con 16 MHz en el micro verás un pulso ancho (50 %) y uno estrecho (10 %).

3.2

Conectar al L298

▶ 47:30

Quita el 1 fijo del enable y conecta EN1 a ENA del puente H.

En la clase el motor no respondía porque el cable del enable no estaba conectado. Usa clic derecho → Highlight para revisar la conexión.

Fase 4

Velocidad desde el celular

4.1

Slider en la app Bluetooth

▶ 51:40

En la app de terminal Bluetooth agrega botones para derecha, izquierda y stop, y un slider de 0 a 100.

Configura el slider para que envíe "V1=" antes del valor y "/*" después. El usuario mueve de 0 a 100; el micro se encarga de escalar.

Las letras deben coincidir exactamente, mayúsculas incluidas, con lo que busca el micro.

4.2

Variables

▶ 64:40

Declara un buffer para lo que se captura y una variable para el valor.

char trama_rx[50];
char texto[50];
uint8_t valor;
4.3

Separar el valor con strtok

▶ 59:10

strtok(trama_rx, "=") corta la trama en el '='; strtok(0, "/") toma lo que sigue hasta el '/'.

atoi convierte el texto a entero (atof si mandas decimales) y pwm_valor cambia el ciclo útil.

void procesa(void)
{
  if (strstr(trama_rx, "DERECHA")) m1derecha();
  else if (strstr(trama_rx, "IZQUIERDA")) m1izquierda();
  else if (strstr(trama_rx, "STOP")) stop();
  else if (strstr(trama_rx, "V1="))
  {
    strcpy(texto, strtok(trama_rx, "="));  // inicia la captura
    strcpy(texto, strtok(0, "/"));         // captura el dato
    valor = atoi(texto);
    pwm_valor(&PWM1, valor);
  }
}

Necesitas #include y . Las órdenes de giro deben ser las mismas que envían tus botones.

4.4

Prueba con Bluetooth

▶ 69:30

En Proteus pon el COMPIM en el COM del módulo Bluetooth (en la clase, COM17).

Con un Virtual Terminal ves llegar las tramas, por ejemplo DERECHA*IZQUIERDA*V1=94/*.

4.5

Resultado y tarea

▶ 73:40

Al mover el slider el ancho de pulso cambia en el osciloscopio y el motor acelera o frena.

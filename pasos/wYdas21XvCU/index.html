Clase 39: recepción serial básica bloqueante

Primera forma de recibir datos por el puerto serie: el programa se queda esperando un carácter y según cuál llegue hace una acción. Es la más sencilla, pero mientras no llega nada el programa no hace otra cosa. En las siguientes clases se mejora.

▶ Ver el video completo (17:15) Empezar el paso a paso
  • STM32F401 (Proteus)
  • 3 LEDs con resistencias en PB0, PB1, PB2
  • Virtual Terminal y COMPIM
  • Librería uart.c/.h
  • Emulador de puertos COM y terminal serie (Hercules)

Fase 1

Proyecto

1.1

Circuito en Proteus

▶ 0:00

Virtual Terminal cruzado con el micro: su RXD a TX (PA9) y su TXD a RX (PA10). Tres LEDs en PB0, PB1 y PB2.

1.2

USART1 y LEDs

▶ 2:12

USART1 asíncrono a 9600 baudios. PB0, PB1 y PB2 como salida con etiquetas led1, led2, led3. Para simular, oscilador interno a 16 MHz.

1.3

Librería y variable

▶ 3:17

Agrega la librería uart en Core/Librerias e inclúyela. Declara la variable donde se guardará el carácter recibido:

#include "uart.h"
uint8_t dato;
uartx_write_text(&huart1, "HOLA\r\n");
Fase 2

Recibir

2.1

HAL_UART_Receive bloqueante

▶ 7:16

Con timeout HAL_MAX_DELAY el programa se queda esperando hasta que llegue un carácter. Mientras tanto, el LED que antes titilaba deja de hacerlo: eso es lo bloqueante.

while (1)
{
    HAL_UART_Receive(&huart1, &dato, 1, HAL_MAX_DELAY);
    HAL_GPIO_TogglePin(led1_GPIO_Port, led1_Pin);
    HAL_Delay(200);
}

Es HAL_UART_Receive, no HAL_UART_Receive_DMA, que es otro modo.

2.2

Eco en el Virtual Terminal

▶ 9:27

Para ver lo que escribes, clic derecho en el Virtual Terminal → Echo Typed Characters. Cada tecla hace avanzar el programa una vez.

2.3

Órdenes con switch

▶ 10:10

Según el carácter recibido, una acción distinta:

switch (dato)
{
    case 'A':
        HAL_GPIO_TogglePin(led2_GPIO_Port, led2_Pin);
        break;
    case 'B':
        HAL_GPIO_TogglePin(led3_GPIO_Port, led3_Pin);
        break;
}

Desventajas: solo tienes un carácter por orden y con ruido una letra puede convertirse en otra. En la parte 2 se usan órdenes compuestas.

Fase 3

Órdenes desde fuera

3.1

COMPIM y terminales de monitoreo

▶ 11:40

COMPIM no es cruzado: RX del micro con su RXD y TX con TX. El RX del micro solo puede venir de un emisor; para monitorear usa Virtual Terminals solo con su entrada conectada (uno en TX y otro en RX).

3.2

Desde otra aplicación

▶ 13:19

Crea un par de puertos virtuales (COM1 ↔ COM2) a 9600. COMPIM en COM1 y una terminal (Hercules) en COM2: enviar A o B conmuta los LEDs. Puede ser LabVIEW o cualquier programa con puerto serie.

3.3

Desde el celular

▶ 14:58

Con el puerto COM Bluetooth de Windows (clase 33) en COMPIM y una app de terminal serie Bluetooth en el celular, se mandan las mismas letras.

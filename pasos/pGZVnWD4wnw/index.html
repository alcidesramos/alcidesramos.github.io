STM32 desde MATLAB: LED en Simulink y Proteus

Con el paquete de soporte ya instalado, se arma en Simulink un modelo de dos bloques (Pulse Generator y Digital Port Write en GPIOC pin 13). MATLAB no se comunica con el micro en tiempo real: genera el código y el .hex para que el STM32 trabaje solo. La clave está en preparar el .ioc de STM32CubeMX 6.4 con las opciones que MATLAB necesita (no generar main, librerías LL, sin static y un timer como base de tiempo en lugar del SysTick) y enlazarlo en Hardware Implementation.

Fase 1

Modelo en Simulink

1.1

Bloques del paquete STM32

▶ 0:42

En un modelo nuevo de Simulink se abre el Library Browser, sección Embedded Coder Support Package for STMicroelectronics STM32 Processors. Además de las Nucleo, hay bloques para tarjetas genéricas: Digital Port Write/Read, UART, PWM, I2C, Timer...

MATLAB no controla el micro desde el PC: genera el .hex para que el micro tenga el control, como en un control real.

1.2

Digital Port Write y Pulse Generator

▶ 1:40

Se agrega Digital Port Write con puerto GPIOC y pin 13 (el LED de la Black Pill). Se le conecta un Pulse Generator con amplitud 1 (es digital), periodo de 1 s y ancho de pulso del 50 %.

Fase 2

Proyecto en CubeMX 6.4

2.1

Micro, pin y reloj

▶ 2:24

Se abre la versión antigua de CubeMX (6.4) y se elige el STM32F401CC o el F411. PC13 como GPIO_Output. Para Proteus se usa el oscilador interno a 16 MHz, que es lo que mejor simula; se puede activar el cristal en RCC para pasarlo después a la tarjeta real.

2.2

Project Manager

▶ 4:05

Nombre del proyecto (MATLAB1), carpeta de trabajo y Toolchain STM32CubeIDE. Estas opciones son obligatorias para que MATLAB lo acepte:

  • Marcar Do not generate the main(): el main lo maneja MATLAB.
  • Desmarcar Generate Under Root.
  • Advanced Settings: GPIO y RCC con librerías LL (Low Layer), no HAL.
  • Advanced Settings: quitar Visibility (Static) en las funciones generadas.
2.3

Base de tiempo con un timer

▶ 8:34

En System Core, SYS, el Timebase Source no puede ser SysTick porque MATLAB lo necesita. Se elige un timer que no se vaya a usar, por ejemplo TIM10, y se vuelve a guardar el proyecto.

Si olvidas este paso, la compilación desde MATLAB falla con error.

Fase 3

Configurar el modelo

3.1

Solver y hardware

▶ 5:47

En Modeling, Model Settings:

  • Solver: tipo Fixed-step (paso fijo).
  • Hardware Implementation: Hardware board = STM32F4xx Based. Tarda un rato en cargar.
  • Operating system/scheduler: Baremetal (código C puro) o FreeRTOS. Para esto cualquiera sirve; con Baremetal el programa arranca enseguida.
  • Target hardware resources: en Browse se selecciona el .ioc creado (MATLAB1.ioc). Detecta el F401 y hace la configuración.
3.2

Carpeta de trabajo y compilar

▶ 7:28

La carpeta actual de MATLAB debe ser la misma del proyecto, para que todo se genere ahí. En la pestaña Hardware, Build, Deploy & Start tiene dos opciones: solo compilar o compilar y programar. Para Proteus basta con Build.

MATLAB tarda en terminar de escribir los archivos. Espera a que aparezcan untitled.hex y untitled.elf antes de buscarlos.

Fase 4

Simular en Proteus

4.1

Circuito y prueba

▶ 11:04

En Proteus: STM32F401, resistencia de 220 Ω y LED amarillo en PC13 a tierra. En las propiedades del micro, reloj de 16 MHz como en CubeMX y como programa el untitled.hex generado por MATLAB. Al correr la simulación el LED parpadea cada segundo.

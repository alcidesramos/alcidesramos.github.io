Clase 131: TouchGFX + ILI9341 táctil, parte 1

Primera parte de la serie con TouchGFX, el software gráfico de ST. Se trabaja con tres programas que se llaman entre sí: CubeMX para el hardware, CubeIDE para el código y TouchGFX Designer para la parte gráfica. Se configura el reloj a 100 MHz, SPI1 a 50 MHz con DMA para la pantalla, TIM11 como base de tiempo del sistema y TIM10 como señal de VSync calculada según cuánto tarda en dibujarse una pantalla completa. Se agrega el paquete X-CUBE-TOUCHGFX con buffer parcial, se integra el driver de la ILI9341 y después el touch XPT2046 por SPI2. Al final se hacen dos pantallas con botones para pasar de una a otra.

Fase 1

Hardware en CubeMX

1.1

Reloj a 100 MHz

▶ 2:30

Nuevo proyecto con el STM32F411CEU. En RCC se activa el cristal externo (HSE), el PLL y se lleva el micro a su máxima velocidad, 100 MHz.

Ojo: TouchGFX deja el micro casi dedicado a la parte gráfica. Si tienes tareas de tiempo crítico, conviene un micro para la pantalla y otro para el control, comunicados entre sí.

1.2

SPI1 para la pantalla

▶ 3:30

Connectivity > SPI1. Como a la pantalla solo se le envían datos, puede ir en Half-Duplex Master y ahorras el pin MISO.

Pines de salida: TFT_CS, TFT_RST, TFT_DC (estos nombres los usa la librería) y TFT_LED para la luz de fondo (opcional, puede ir a 3.3 V). También el LED y el botón de la tarjeta y un canal ADC para más adelante.

SPI1 queda a 50 MHz. En esta familia SPI1 y SPI4 son los más rápidos; no uses SPI2 o SPI3 para la pantalla.

1.3

DMA del SPI1

▶ 6:00

En DMA Settings se agrega SPI1_TX, se activa Use Fifo con Threshold Full y se habilita la interrupción del SPI. Así los bloques grandes de la pantalla se envían mucho más rápido.

1.4

Timer como base de tiempo

▶ 6:40

En SYS, Timebase Source se cambia de SysTick a TIM11. Así el callback del timer queda en el main y la base de tiempo es más precisa.

Fase 2

Timer de VSync

2.1

Calcular la frecuencia

▶ 8:00

TouchGFX necesita saber cuándo terminó de dibujarse una pantalla completa por SPI. Si el timer va más rápido, se pierde el sincronismo y el touch o los sliders fallan.

Según la documentación de TouchGFX, la memoria de un cuadro es ancho x alto x profundidad de color. Con 16 bits (RGB565) y el SPI a 50 MHz la pantalla se dibuja como máximo a 40,7 Hz. En el video 40 Hz funciona, 41 Hz falla; se deja en 35 Hz.

Bits por pantalla = ancho x alto x profundidad de color
                  = 320 x 240 x 16 = 1.228.800 bits

Frecuencia maxima = 50.000.000 / 1.228.800 = 40,7 Hz   (SPI a 50 MHz)

Se usa 35 Hz (por debajo del limite):
  Reloj del timer = 100 MHz, Prescaler = 100   -> 1 MHz
  Periodo        = 1.000.000 / 35 = 28.571

TIM10: Prescaler = 100-1, Counter Period = 28571, interrupcion activada
2.2

Configurar TIM10

▶ 11:00

Se usa un timer que no tenga muchas funciones, como TIM10 (16 bits). No vale la pena gastar TIM2 de 32 bits con sus canales PWM y encoder.

Prescaler 100-1 y Counter Period 28571 para 35 Hz. Si el periodo pasa de 65535, sube el prescaler. Se activa la interrupción de TIM10.

2.3

Generar el proyecto

▶ 12:10

En Project Manager se le pone nombre (TOUCHGFX_CANAL), Toolchain STM32CubeIDE y GENERATE CODE. Con Open Project se abre en CubeIDE y compila sin errores.

Se crea la carpeta Core/LIBRERIAS y se agrega al include path.

Fase 3

Agregar TouchGFX

3.1

Instalar y seleccionar el paquete

▶ 13:50

En CubeMX, Software Packs > Select Components, se busca TouchGFX. Si no está instalado, aparece Install. Se marca X-CUBE-TOUCHGFX con su Graphics Application.

En Computing se activa el CRC, que TouchGFX necesita.

3.2

Configurar la aplicación gráfica

▶ 15:00

En Middleware > X-CUBE-TOUCHGFX: Interface Custom, Framebuffer RGB565, ancho 320, alto 240, Framebuffer Strategy Partial Buffer (GRAM display), 3 bloques de 2048 bytes.

El buffer parcial es lo adecuado para pantallas SPI. Con micros más potentes (H7, H5) se puede pasar a buffer simple o doble.

3.3

Abrir TouchGFX Designer

▶ 16:30

Al generar código aparece la carpeta TouchGFX en el proyecto. Doble clic en ApplicationTemplate.touchgfx.part abre TouchGFX Designer.

Se elige un proyecto en blanco. En Config se puede cambiar la orientación; el color y el tamaño ya vienen de CubeMX.

Se pone un Box With Border de prueba y se presiona Generate Code. Conviene generar otra vez desde CubeMX para que todo quede integrado.

Fase 4

Driver de la pantalla

4.1

Pegar las librerías

▶ 18:20

En LIBRERIAS se pegan ili9341.c/.h y TouchGFX_DataTransfer.c/.h, y en el main se incluye ili9341.h.

TouchGFX_DataTransfer le dice a TouchGFX cómo el driver abre una ventana, dibuja un bloque de imagen y avisa que terminó. Si tienes otra pantalla, ahí se cambian esas funciones por las de tu driver (el repositorio de ST trae drivers de varias pantallas).

4.2

Callback de los timers

▶ 19:50

En el callback HAL_TIM_PeriodElapsedCallback que CubeMX creó por TIM11 se agrega la llamada a touchgfxSignalVSync() cuando interrumpe TIM10. Si usaste otro timer, cambia el nombre.

Si quedan dos warnings de #warning en TouchGFXHAL.cpp, se pueden comentar.

/* USER CODE BEGIN 0 */
extern void touchgfxSignalVSync(void);
/* USER CODE END 0 */

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
  /* USER CODE BEGIN Callback 0 */
  if (htim->Instance == TIM10)
  {
    touchgfxSignalVSync();      // aviso a TouchGFX: ya se puede dibujar otro cuadro
  }
  /* USER CODE END Callback 0 */
  if (htim->Instance == TIM11)
  {
    HAL_IncTick();              // base de tiempo del sistema
  }
}
4.3

Inicializar en el main

▶ 22:10

Antes del while se arranca TIM10, se inicializa la pantalla y su orientación, y se enciende la luz de fondo. CubeMX ya agregó en el while la llamada que actualiza TouchGFX.

Importante: no pongas retardos largos (HAL_Delay de 500 o 1000) en el while porque bloquean la parte gráfica y el touch. Para otras tareas usa interrupciones.

/* USER CODE BEGIN Includes */
#include "ili9341.h"
#include "xpt2046.h"
/* USER CODE END Includes */

/* USER CODE BEGIN 2 */
HAL_GPIO_WritePin(TFT_LED_GPIO_Port, TFT_LED_Pin, GPIO_PIN_SET);  // luz de fondo
HAL_TIM_Base_Start_IT(&htim10);          // timer del VSync
ILI9341_Init();
ILI9341_direction(Horizontal_Inv);       // segun como quede tu pantalla
XPT2046_Init();                          // touch (hay que iniciarlo a mano)
/* USER CODE END 2 */
4.4

Agregar imágenes

▶ 24:40

En TouchGFX Designer, pestaña Images, se agregan imágenes y luego se arrastran a la pantalla con el widget Image. Imágenes grandes no caben en la flash del F411; más adelante se usará memoria externa.

Generate Code y se programa desde CubeIDE: lo que se diseña aparece en la pantalla.

Fase 5

Touch XPT2046

5.1

Librería y puertos SPI

▶ 27:20

Se pegan xpt2046.c/.h y se incluyen en el main. En ili9341.h está TFT_SPI hspi1 y en xpt2046.h el SPI del touch, aquí hspi2. Ambos son configurables.

5.2

Configurar SPI2

▶ 28:00

SPI2 en Full-Duplex Master (sin DMA, los datos del touch son pocos). Pines TS_MOSI, TS_MISO, TS_SCK y un pin de salida TS_CS.

El XPT2046 trabaja máximo a 10 MHz: con prescaler 8 el SPI2 queda en 6,25 MHz.

El pin de interrupción del touch (T_IRQ) no se conecta: TouchGFX lee el touch por polling en el while, y ese pin puede dar falsos toques si la pantalla tiene polvo.

5.3

STM32TouchController.cpp

▶ 31:20

En TouchGFX/target se reemplaza STM32TouchController.cpp por la versión modificada. La función sampleTouch lee el XPT2046, valida el toque y convierte las coordenadas a píxeles de la pantalla.

Si al tocar a la derecha reacciona algo a la izquierda (o arriba y abajo), el touch está invertido: cambia las líneas de *x o *y según tu orientación.

extern "C" {
static void ConvXPTtoILI(uint16_t *x, uint16_t *y)
{
  int16_t tx, ty;
  tx = (int16_t)(((int32_t)*x - XPT_XMIN) * GUI_WIDTH / XPT_WIDTH);
  tx = (tx < 0) ? 0 : tx;
  tx = (tx >= GUI_WIDTH) ? GUI_WIDTH - 1 : tx;
  ty = (int16_t)(((int32_t)*y - XPT_YMIN) * GUI_HEIGHT / XPT_HEIGHT);
  ty = (ty < 0) ? 0 : ty;
  ty = (ty >= GUI_HEIGHT) ? GUI_HEIGHT - 1 : ty;

  // si el display esta bien
  //*x = tx;                      // horizontal
  *y = ty;                        // vertical normal

  // si hay inversion, probar estas opciones
  *x = (GUI_WIDTH - 1) - tx;      // si es horizontal_inv
  //*y = (GUI_HEIGHT - 1) - ty;   // si es vertical invertida
}
}

bool STM32TouchController::sampleTouch(int32_t& x, int32_t& y)
{
  static uint16_t prevx = GUI_WIDTH;
  static uint16_t prevy = GUI_HEIGHT;
  uint16_t intx, inty;

  XPT2046_Update(&intx, &inty);
  if (XPT2046_IsReasonable(intx, inty))
  {
    ConvXPTtoILI(&intx, &inty);
    if (intx != prevx || inty != prevy)
    {
      prevx = intx;
      prevy = inty;
      x = (int16_t)intx;
      y = (int16_t)inty;
      return true;
    }
  }
  return false;
}

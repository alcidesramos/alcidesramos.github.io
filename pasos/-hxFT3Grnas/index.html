VS Code para STM32 y primera simulación en Proteus

Se deja listo el ambiente para todo el curso: STM32CubeMX, Python y VS Code con un perfil propio para STM32. Se crea el primer proyecto (un LED en PC13 que parpadea), se compila en VS Code, se simula en Proteus con la Black Pill y se programa y depura en la tarjeta real con el ST-Link. También se ve cómo mover un pin a otro (remapeo), cómo usar etiquetas en Proteus para no llenar el circuito de cables y cuándo conviene el oscilador interno o el cristal externo.

Fase 1

Preparar VS Code

1.1

Un perfil para STM32

▶ 0:33

Crea un perfil nuevo en VS Code (icono de engranaje → Profiles → New Profile). Así cada ambiente (STM32, ESP32, Arduino, PlatformIO) tiene solo sus extensiones y no se llena de botones.

1.2

Extensiones básicas

▶ 1:06

Instala estas tres:

  • STM32Cube IDE for VS Code (la de ST; se demora un rato).
  • Python (Python ya debe estar instalado en Windows).
  • VsCode Action Buttons, para crear botones que hacen tareas con un clic (compilar, programar, configurar).

Ejecuta como administrador CubeMX, VS Code y CubeProgrammer. Al instalar VS Code marca las opciones de "Abrir con Code" en el menú de carpetas.

Fase 2

Primer proyecto

2.1

Elegir el micro

▶ 7:11

Desde la extensión o directamente, abre CubeMX → Access to MCU Selector y busca STM32F401CCU6 (Proteus simula el 401; si tienes un 411 físico, simula con el 401). Márcalo con la estrella para tenerlo en favoritos.

2.2

El LED en PC13

▶ 9:55

Busca el pin PC13 (el LED de la Black Pill), ponlo como GPIO_Output y con clic derecho → Enter User Label llámalo LED. Por ahora no se toca el cristal.

2.3

Generar con CMake

▶ 11:37

En Project Manager ponle nombre (en clase, Yuca), elige la carpeta y en Toolchain / IDE selecciona CMake. Sin CMake no funciona en VS Code. La primera vez puede pedir descargar el paquete del micro y tu cuenta de ST.

Fase 3

Programar en VS Code

3.1

Abrir el proyecto

▶ 13:16

Clic derecho sobre la carpeta → Abrir con Code. Acepta el modo restringido (confiar en la carpeta) y elige Debug cuando pregunte. Rechaza la sugerencia de instalar la extensión de C/C++ de Microsoft: choca con la de ST.

3.2

Verificar la configuración

▶ 17:09

En la pestaña de STM32 entra a Set Up STM32Cube project: debe salir el Cortex-M4 y el nombre del proyecto. Si no, pulsa el engranaje, elige el proyecto y guarda. Luego pulsa Build abajo para compilar.

3.3

El código

▶ 21:30

En main.c, dentro del while (1), escribe el parpadeo. Al escribir HAL_ en mayúscula, la IA sugiere el resto: acepta con Tab solo si es lo que quieres.

while (1)
{
  HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
  HAL_Delay(500);
}

El texto gris de las sugerencias (inline) no es código. Si te confunde, desactívalo en Settings → Inline Suggest.

Fase 4

Simular en Proteus

4.1

La Black Pill y su alimentación

▶ 26:41

Busca BLACKPILL_ARZ (la corta, la que se puede simular). Proteus alimenta todo a 5 V: en Design → Configure Power Rails crea VCC/VDD en 3.3 V y pasa VDD a esa red. Hay que hacerlo cada vez que uses la Black Pill. Pon un POWER en el pin de reset.

4.2

LED y resistencia

▶ 29:28

Agrega un LED-YELLOW (se ve mejor en video) y una resistencia de 220 Ω (busca 220 y filtra por Resistors). Conecta PC13 → resistencia → LED → tierra.

4.3

Cargar el programa

▶ 31:04

Guarda el archivo de Proteus en la carpeta del proyecto. Doble clic en el micro, en Program File busca build/Debug/Yuca.elf y dale Play.

4.4

Etiquetas en vez de cables

▶ 33:53

Usa terminales con el mismo nombre (DEFAULT, INPUT u OUTPUT) para unir sin cables. Escribe el nombre una vez y en las demás elígelo de la lista para no equivocarte. Con clic derecho → Highlight Net verificas qué está unido.

4.5

Mover el LED a otro pin

▶ 37:15

Si se daña un pin, en CubeMX haz Ctrl + clic sostenido sobre él: te muestra a qué pines lo puedes llevar. Arrástralo (no a los del cristal), genera el código, compila y cambia la conexión en Proteus. El nombre LED no cambia, así que el código queda igual.

Fase 5

Tarjeta real y reloj

5.1

Programar y depurar

▶ 40:50

Instala los drivers del ST-Link desde la extensión. En Run and Debug elige ST-Link: el programa se carga y se detiene al inicio. Con Play corre; con Step Over avanzas línea por línea y ves cómo el LED cambia en cada paso.

5.2

Oscilador interno o cristal

▶ 44:46

Sin configurar nada, el micro usa el oscilador interno de 16 MHz. Con el PLL puedes subir la frecuencia (hasta 84 MHz en el F401, 100 MHz en el F411), pero gasta más batería. Para USB, comunicaciones rápidas o precisión, activa en RCC el cristal externo (HSE) e indica su valor (la tarjeta trae 25 MHz).

En Proteus simula a 16 MHz: frecuencias altas ponen muy lento el computador. La frecuencia del micro en Proteus debe coincidir con la que configuraste.

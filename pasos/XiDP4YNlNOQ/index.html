ESP8266, GPS y Ubidots con PIC

El ESP8266 se maneja con comandos AT por el UART del PIC (9600 baudios en Proteus; el módulo real suele venir a 115200). Se reutilizan manda_comando y la función tiempo de la clase del SIM800. El módulo se conecta a la red WiFi, abre un socket TCP (el 4) con things.ubidots.com y envía el JSON con POST. Luego hace un GET a la variable del suiche y captura el valor entre los dos puntos y la coma para mover el LED. El GPS va por serial por software con un timer de 4 s como límite y la temperatura sale de un DS18B20.

Fase 1

Preparar

1.1

Simulación

▶ 0:00

En Proteus el COMPIM representa el ESP8266 real conectado al computador. Se configura el puerto y 9600 baudios, igual que el módulo.

1.2

Proyecto

▶ 4:20

Se incluye la librería del DS18B20, se definen el suiche en RB0 y el LED en LATB6, todo digital, RC7 como entrada y el UART a 9600.

1.3

Estados de recepción

▶ 6:20

Las respuestas del ESP8266 se procesan con una máquina de estados (normal, cap_l, cap_u, cap_e, cap_co, esp_final) para capturar el valor que devuelve Ubidots.

1.4

Funciones reutilizadas

▶ 8:20

Se copian del proyecto del SIM800 las funciones de texto por UART y por serial por software y la lectura con límite.

Fase 2

Comunicación

2.1

Esperar respuesta

▶ 10:20

tiempo limpia la trama y los errores de recepción y revisa durante un número de milisegundos si llegó la respuesta esperada.

2.2

Timer e interrupciones

▶ 12:20

Se configura el Timer0 y la interrupción serial. En la interrupción del UART cada dato pasa por la máquina de estados; en la del timer se cuenta el tiempo y, al cumplirse, se activa flag_timer para cortar la lectura del GPS.

2.3

Conectar a la red

▶ 18:20

Se conecta a la red WiFi, se permiten múltiples conexiones y se muestra la IP. Después se lee la temperatura una vez para calibrar el sensor.

manda_AT_COMANDO("AT+CWJAP=\"tu_red\",\"tu_clave\"", "OK", "OK", 10000); // se conecta a una red WiFi
manda_AT_COMANDO("AT+CIPMUX=1", "OK", "OK", 1000);  // permite multiples conexiones
manda_AT_COMANDO("AT+CIFSR", "OK", "OK", 1000);     // muestra la ip del modulo
temperatura = ds18b20_read(&portb, 7);  // lectura necesaria para calibrar el sensor
Fase 3

Ubidots

3.1

Abrir el socket

▶ 22:20

conecta abre la conexión TCP número 4 con things.ubidots.com en el puerto 80 y espera OK o CONNECT.

unsigned char conecta()
{
  temp = manda_AT_COMANDO("AT+CIPSTART=4,\"TCP\",\"things.ubidots.com\",80", "OK", "CONNECT", 10000);
  Delay_ms(2000);
  if ((temp == 1) || (temp == 2)) return 1;
  else return 0;
}
3.2

Leer el suiche

▶ 24:20

Con un GET a la variable se pide el último valor. La respuesta trae value: 0.0; se captura lo que hay entre los dos puntos y la coma, se convierte con atof y se cierra el socket.

3.3

GPS por software

▶ 28:20

lee_trama_soft y lee_cordenadas son las mismas de la parte 2 del SIM800: capturan la trama GGA con límite de tiempo y la pasan a grados decimales.

3.4

Ciclo principal

▶ 32:30

Se lee la temperatura, el LED de Ubidots copia el suiche, y si hay coordenadas válidas se envía todo. El LED físico toma el valor del suiche de Ubidots.

while (1)
{
  temperatura = ds18b20_read(&portb, 7);  // manda la temperatura
  led_ubidot = sw;      // el led de ubidot es igual al suiche
  if (lee_cordenadas() == 1) conectar();
  led1 = suiche_ubi;    // saca el valor de suiche de ubidot al led
  Delay_ms(2000);
}
3.5

Prueba

▶ 34:20

En las terminales se ven la respuesta HTTP y el valor leído. En el tablero cambian la temperatura, el LED y el punto del GPS, y el suiche de Ubidots prende el LED.

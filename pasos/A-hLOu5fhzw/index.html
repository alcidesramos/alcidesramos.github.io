Switch case y máquinas de estado

Lección 14 del curso. Se explica la estructura de switch case (casos, break y default) y la idea de máquina de estados: en cada estado se revisa una condición y, si se cumple, se prepara y se pasa al siguiente. Se aplica en un PIC12F1822 de 8 pines con cuatro LEDs, un parlante y un pulsador: se configura el oscilador interno a 8 MHz por registros, se ponen los pines digitales, se escribe con LATA y se arma un juego de luces con seis estados. Al final se les ponen nombres a los estados con enum para que el programa se entienda mejor.

Fase 1

switch case

1.1

Estructura

▶ 0:00

switch analiza una variable y salta al case que tenga ese valor. Cada caso termina con break. Los casos no tienen que ir en orden, y default (opcional) se ejecuta si no se cumple ninguno. Es más ordenado que una cadena larga de else if.

switch (variable) {
  case 0:
    // acciones
    break;
  case 3:
    break;
  default:
    break;
}
1.2

Máquina de estados

▶ 1:36

Cada caso es un estado. En cada estado se revisa una condición; si se cumple, se prepara lo necesario y se cambia la variable para pasar al siguiente estado. El ejemplo es como unas luces navideñas: cada pulsación cambia el efecto.

Fase 2

El PIC12F1822

2.1

Escoger un micro adecuado

▶ 2:09

Para 5 salidas y 1 entrada basta un micro de 8 pines como el PIC12F1822. Con el oscilador interno, los pines del cristal quedan libres. El pin de reset (RA3) también se puede usar, pero solo como entrada, por eso el pulsador va allí con pull-up.

2.2

Proyecto con oscilador interno

▶ 4:23

Se crea el proyecto switchcase en la carpeta Clase 14 con el PIC12F1822 a 8 MHz. En la configuración se escoge el oscilador interno (INTOSC), se apaga el watchdog, se deshabilita el reset externo para usar RA3 como entrada y se deja apagados el Fail-Safe Clock Monitor y el PLL (que multiplicaría por 4, hasta 32 MHz).

2.3

Configurar el oscilador por registros

▶ 8:15

En el capítulo del oscilador del datasheet está el registro OSCCON. Los bits IRCF escogen la frecuencia del oscilador interno (1110 = 8 MHz), SPLLEN enciende el PLL y los bits SCS deben indicar oscilador interno; si falta esto último, el micro no corre a la velocidad esperada.

IRCF3_bit = 1;   // oscilador interno a 8 MHz
IRCF2_bit = 1;
IRCF1_bit = 1;
IRCF0_bit = 0;
SPLLEN_bit = 0;  // PLL apagado
SCS1_bit = 1;    // usar el oscilador interno
SCS0_bit = 1;
2.4

Entradas, salidas y el registro LAT

▶ 11:38

Primero todo el puerto como salida y luego RA3 como entrada. En los PIC18 y los 16F nuevos se escribe en LATA y se lee en PORTA, porque a altas velocidades no se recomienda usar el mismo registro para las dos cosas.

sbit sw at RA3_bit;

TRISA = 0;          // todo salida
TRISA3_bit = 1;     // entrada del pulsador
LATA = 0;           // arrancan apagados
2.5

Pines digitales según el micro

▶ 15:07

Para saber cómo se ponen los pines digitales se busca en el datasheet: si no aparece ANSEL, se hace con ADCON1 (micros antiguos como el 16F877A); si aparecen ANSEL y ANSELH, con esos (16F887); en los nuevos, con ANSELA, ANSELB, etc. En el 12F1822 es ANSELA = 0.

ANSELA = 0;   // todo digital
Fase 3

La máquina de estados

3.1

Estado 0: encendido

▶ 17:55

Se crea la variable estados y el switch. En el primer estado los LEDs se encienden y el parlante (RA5) queda apagado. Si se presiona el pulsador, se espera el antirrebote y se pasa al estado 1.

char estados = 0;

switch (estados) {
  case 0:              // 543210
    LATA = 0b010111;   // LEDs encendidos, parlante apagado
    if (sw == 0) {
      estados = 1;
      Delay_ms(250);   // antirrebote
    }
    break;
}
3.2

Estado 1: flash con XOR

▶ 21:14

Para que los LEDs titilen no se puede negar todo el puerto, porque también cambiaría el parlante. Con XOR y una máscara solo se invierten los bits de los LEDs (lección 6).

case 1:
  LATA = LATA ^ 0b010111;   // invierte solo los LEDs
  Delay_ms(200);
  if (sw == 0) {
    LATA = 0b010100;        // se prepara el siguiente estado
    estados = 2;
    Delay_ms(250);
  }
  break;
3.3

Prepararse para el siguiente estado

▶ 23:32

Antes de pasar al estado "policía" (dos encendidos y dos apagados) se dejan los LEDs en ese patrón; así, dentro del estado, basta con invertirlos igual que en el flash. Lo mismo se hace para "alternado" (uno sí y uno no) y para "apagado", que solo apaga los LEDs.

3.4

Estado 5: melodía

▶ 28:30

Se activa la librería Sound, se inicializa con el parlante en RA5 y en el último estado se tocan unos tonos. Al presionar se prepara el estado encendido y se vuelve al estado 0.

Sound_Init(&PORTA, 5);
...
case 5:
  Sound_Play(1000, 100);
  Sound_Play(2000, 100);
  Sound_Play(3000, 100);
  if (sw == 0) {
    LATA = 0b010111;
    estados = 0;
    Delay_ms(250);
  }
  break;
Fase 4

Nombres con enum

4.1

Darles nombre a los estados

▶ 31:52

Con enum se crea una lista de constantes con nombre (encendido vale 0, flash 1, y así). Así los casos se llaman por su nombre y no hay que recordar números; el programa queda más fácil de leer para cualquiera. enum es de C estándar.

enum maquina1_est {encendido, flash, policia, alternado, apagado, melodia};
char estados = encendido;

switch (estados) {
  case encendido:
    ...
    if (sw == 0) { estados = flash; Delay_ms(250); }
    break;
  case flash:
    ...
}

El nombre del enum no puede ser igual al de una variable que ya exista.

4.2

Arrancar en cualquier estado

▶ 36:24

Basta con cambiar el valor inicial de la variable, por ejemplo estados = alternado, para que el programa arranque en ese estado.

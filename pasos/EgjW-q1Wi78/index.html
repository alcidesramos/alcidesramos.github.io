PIC y MyOpenLab en full dúplex

En MyOpenLab se arma un circuito de bloques (panel de circuito) y un panel frontal con indicadores y controles. Para enviar, un generador de pulsos marca el tiempo y se concatenan los valores en una cadena que sale por RS232. Para recibir, se toma la cadena del puerto, se revisa su largo y se extraen las posiciones de cada dato. En el PIC18F2550 se arma la trama con sprintf y, para recibir, una máquina de estados en la interrupción serial guarda los datos entre = y *; luego strtok separa los valores.

MyOpenLab

Proyecto

1.2

Enviar por serial

▶ 2:50

En Interfaces está RS232: se elige el puerto y cuándo enviar. Un generador de pulsos de Utilidades da el tiempo de envío (por ejemplo, cada 200 ms) y una constante de texto es lo que se manda. Con Hercules se comprueba que llega.

1.3

Controles

▶ 6:47

En el panel frontal se ponen dos deslizadores para los motores y dos pulsadores para los LEDs.

1.4

Armar la trama

▶ 8:25

Los valores se pasan a texto y se concatenan con separadores. La trama empieza con = y termina con * para que el micro la reconozca.

Fase 2

Recibir en MyOpenLab

2.1

Validar la trama

▶ 12:55

La cadena que llega se guarda en una variable. Solo se procesa si su largo es mayor o igual al esperado, para evitar datos incompletos.

2.2

Extraer datos

▶ 15:07

Con la función de subcadena se toman las posiciones de cada dato: la temperatura, el voltaje y los dos pulsadores. Se convierten a número y van a un termómetro, un medidor de 0 a 5 V y dos LEDs.

Fase 3

Programa del PIC

3.1

Configuración

▶ 20:06

Entradas para los pulsadores, RC7 para RX, UART a 9600 y dos PWM para los motores.

3.2

Enviar

▶ 22:57

Se lee la temperatura (LM35) y el voltaje, se leen los pulsadores y sprintf arma la trama con formato fijo para que las posiciones no cambien.

voltaje = codigo*5.0/1023.0;
Delay_us(100);
if (pul1 == 0) led1_0 = 1; else led1_0 = 0;
if (pul2 == 0) led2_0 = 1; else led2_0 = 0;
// arma la trama
sprintf(trama_tx, "/%5.1f/%3.1f/%u/%u/*", temperatura, voltaje, led1_0, led2_0);
UART1_Write_Text(trama_tx);
Delay_ms(100);
3.3

Prueba de envío

▶ 26:16

En Proteus con el COMPIM, MyOpenLab muestra la temperatura, el voltaje y los pulsadores.

3.4

Interrupción serial

▶ 28:28

Se habilitan la interrupción de recepción, la de periféricos y la global. Antes se limpian errores apagando y prendiendo CREN, muy útil cuando llegan datos todo el tiempo.

INTCON = 0b01000000;
RCIF_bit = 0;
RCIE_bit = 1;   // habilita interrupcion de recepcion
CREN_bit = 0;   // limpia errores en el buffer de recepcion
CREN_bit = 1;   // habilita recepcion continua
GIE_bit = 1;    // autoriza las interrupciones
3.5

Máquina de estados

▶ 30:41

En CAP_I se espera el =; en CAP_N se guarda cada dato hasta el *, con un límite de 40 caracteres. Al llegar el * se avisa con una bandera y se vuelve al primer estado.

3.6

Procesar

▶ 32:53

strtok toma lo que está después del = y luego cada valor hasta /. atoi lo pasa a número y se escala de 0-100 a 0-255 para el PWM. Lo mismo para el segundo motor y los LEDs.

void procesarx() {
  unsigned int dato_procesado;
  strcpy(captura_rx, strtok(trama_rx, "="));  // inicia captura de tokens
  strcpy(captura_rx, strtok(0, "/"));         // captura el primer dato
  dato_procesado = atoi(captura_rx);          // pasa la cadena a numero
  dato_procesado = dato_procesado*255/100;    // escala a 0-255
  PWM1_Set_Duty(dato_procesado);              // aplica la velocidad
  // ... siguiente dato para PWM2 y los leds
}
3.7

Después de procesar

▶ 35:03

Se limpia la trama, se reinicia el puntero, se limpian errores y se habilita otra vez la interrupción serial.

3.8

Prueba completa

▶ 37:19

Al mover los deslizadores cambian los PWM y los pulsadores de MyOpenLab prenden los LEDs, mientras se sigue viendo la temperatura y el voltaje.
